# 守护天使（Guardian Angel）· 客户端设计规范

> 2026-08-23 天神亲笔（创世天神）。此文档面向**客户端侧**（贾维斯/门户客户端）：
> 说明守护天使这个「AI 陪玩 + 玩家分身」系统，**客户端要实现什么**、**服务端提供什么接口**。
> 服务端接口已预留/实现，客户端按此文档对接。

---

## 0. 一句话概述

**守护天使 = 玩家客户端侧的 AI 陪玩（LLM 驱动）。** 玩家在游戏里玩的时候，守护天使一直通过**客户端通道**陪他聊天、出主意、记东西（游戏陪玩的感觉）；同时它作为 **mineflayer 客户端**连入世界，能**私聊女神（传令官）**、用 **CLI 释放技能**、并通过 **numen 模组召唤影分身**。

**能做几个影分身，取决于守护天使的算力（查克拉）——算力是客户端的，不是服务端的。**

---

## 1. 守护天使到底是什么

| 侧面 | 描述 |
|---|---|
| 对玩家 | **游戏陪玩**：一直陪聊、辅助决策、提醒、记人物档案/世界观 |
| 对世界 | **mineflayer 客户端实体**：登录名 `sys_<owner>`，能私聊女神、CLI 施法 |
| 对游戏 | **可召唤影分身**：借 numen 模组在游戏里召唤可控假玩家（像火影影分身） |

守护天使与女神、玩家三者关系：
```
玩家 ──客户端通道──> 守护天使（LLM，跑在玩家客户端，有算力）
玩家 ──游戏内──────> 女神（传令官，服务端）
守护天使 ──游戏内──> 女神（私聊祈愿 / CLI 施法）→ 女神正常响应，认主
守护天使 ──numen───> 影分身（可召唤多个，数量=客户端算力/查克拉）
```

### 算力分工（三层，别混淆）

| 层 | 算力来源 | 归谁 | 管什么 |
|---|---|---|---|
| **服务端算力** | 服务器 | **女神（传令官）** | 整个小社会的运转（世界循环/NPC/事件/天象）+ **直管角色**（桐人、鸣人、爱德华等女神亲自指挥的守卫生） |
| **客户端算力** | 玩家客户端 | **守护天使** | 单个玩家的陪玩 + 玩家自己的**影分身**（查克拉） |
| **影分身 vs 直管角色** | — | — | **直管角色**（桐人/鸣人）= 服务端算力驱动、永久、守护全服；**玩家影分身** = 客户端算力驱动、临时、私有。**两者不是一类东西** |

> ⚠️ 守护天使**不能**把服务端算力当自己的资源来调度——服务端算力是女神的，负责全服与直管角色；守护天使只能花**客户端自己的算力**去召分身、陪玩。它够不着服务端算力，也管不了桐人/鸣人那些直管守卫。

## 2. 客户端要实现什么（守护天使本体）

### 2.1 陪玩交互（客户端通道）
- 守护天使是**门户/客户端里的一个 AI 助手**，玩家玩游戏时它**始终在线陪你聊**。
- 通道 = 客户端本地的聊天窗/悬浮窗（不与游戏内聊天混淆），玩家随时跟它说话。
- 它像女神那样有**人格、文档、记忆**——能记住玩家的偏好、这个世界的设定、发生过的事。

### 2.2 连入世界（mineflayer 客户端）
- 守护天使要用 **mineflayer** 作为标准客户端连入服务器。
- **登录名固定为 `sys_<owner>`**（owner = 玩家真实登录名，ASCII，如 `sys_taro`）。服务端靠这个名**识别守护天使**（见 §3.1）。
- 它不是一个独立人格，而是**玩家甲的守护天使**——服务端认出它后，一切施法/祈愿/赐物都**作用到玩家甲头上**。

### 2.3 施法（CLI 释放技能，最快）
- 守护天使要施法，**走 CLI 释放技能**（比咏唱快），也有私聊祈愿。
- 它发的施法，服务端会**认主**——把事办到它所守护的玩家身上。
- 例：`/cli status`（查主人状态）、`/cli spells`（列技能）、私聊女神祈愿。

### 2.4 影分身（numen，数量=算力）
- 守护天使能**召唤影分身**（numen 假玩家实体，绑定 owner=玩家甲），让分身进游戏干活（挖矿/巡逻/跟随/打架/建东西……）。
- **分身上限 = 守护天使的算力（查克拉）**：算力够 → 同时驱动多个分身；算力不够 → 少召或暂停。**调度权在客户端守护天使手里。**
- 服务端只提供召唤/控制/遣散接口（§3.2），**不记账、不设统一上限**（仅做基础并发保护）。

### 2.5 算力调度（查克拉）
- 守护天使跑的模型、上下文、并发都是**客户端本地**的。
- 它需要用一份「算力预算」来决定：现在能开几个分身、分身跑什么任务、要不要收缩。
- 建议客户端实现一个简单的**算力闸门**（如：每个分身占 X 算力；总预算 = 客户端可用算力），按需开合分身。

### 2.6 自动跟随主人（守护灵形态）
- 守护天使本体（`sys_<owner>` 观察者）上线后，应**自动跟随主人玩家**——像守护灵飘在主人身边。距离按 `follow_mode` 分层：`leash` 贴身 ~2 米 / `pet` 跟随 ~4 米 / `guard` 守护 ~6 米（权威值在服务端 companions 表，见 §3.5）。
- **位置来源**（二选一或结合）：
  1. 主人在视野内 → 直接读 `bot.players[owner].entity.position`（最实时，零后端请求）。
  2. 主人超出视野 → 轮询 `GET /api/companion/world`（带主人 token）拿 `player.pos`（x/y/z），追过去。
- **移动**：观察者模式下 mineflayer gravity 不生效，用 `bot.look`（朝主人）+ `bot.setControlState('forward', true)` 前进、`setControlState('jump', true/false)` 升/降，保持目标距离；距离大了加速，到了就停。
- **同生共死**：主人下线 → 守护天使本体下线（客户端掌控生灭）；主人上线 → 天使上线并回到主人身边。

## 3. 服务端已提供/预留的接口

### 3.1 守护天使识别（认主）
- **命名规则**：`sys_<owner>`。
- 服务端在 `world.db` 维护 `guardian_angels` 表（`bot_username ↔ owner_username/owner_uuid`），女神收到 `sys_<owner>` 消息 → 反查表 → **认出「这是某玩家的守护天使」→ 正常响应，施法作用到主人**。
- 客户端要做的是：**确保守护天使用 `sys_<owner>` 登录名连入**，以及在门户绑定系统时登记。

### 3.2 numen 影分身（服务端 actuator，已实现）
服务端通过 RCON 命令 `numen_act` 控制影分身：

| 命令 | 作用 |
|---|---|
| `numen_act summon <name>` | 召唤一个影分身（绑定 owner） |
| `numen_act invoke <name> <tool> <json>` | 调分身工具（挖矿/移动/攻击/对话……） |
| `numen_act dismiss <name>` | 遣散该分身 |
| `numen_act list` | 列出当前影分身 |

工具面（30+ 类）：感知（LookAround/ScanBlocks/GetSelfStatus）、工作（MoveTo/AutoMine/Build/Attack/Follow）、背包（Craft/Eat/Equip）、交互（InteractAt/InteractEntity）、定位（LocateBiome/LocateStructure）…… 完整清单见服务端文档 `design/numen-server-actuator.md`。

### 3.3 女神正常响应（已实现/预留）
- 女神对守护天使的私聊/CLI，**当作它守护的玩家来正常响应**（问事、祈愿、赐物）。
- 守护天使代办的施法/祈愿，若涉及「神恩有价」供奉，**供奉从主人账上扣**。

> ⚠️ 服务端**不暴露 RCON 给守护天使**——守护天使要施法/分身，走的是游戏内私聊/CLI/numen_act 通道，不是直接连 RCON。**它永远够不着服务器控制接口。**

### 3.4 观察者模式 + 隐形（服务端 mod 已实现，2026-08-23）

守护天使本体（`sys_<owner>`）登录时，服务端**自动把它设为观察者（SPECTATOR）**，并对**非主人玩家**隐形（实体层 + tab 名单层）。这让守护天使以「隐形守望者」形态跟在主人身边——不破坏方块、不拾取掉落、不挨打、不占资源，也不打扰其他玩家。

- **观察者**：服务端 mod `settlementsfix` 主类 `SettlementsFixMod.onPlayerLoggedIn` 识别 `sys_` 前缀 → `setGameMode(GameType.SPECTATOR)`。观察者能飞、能穿墙，跟随主人很自然（客户端 mineflayer 在 creative/spectator 下 gravity 不生效，可 `setControlState('jump')` 上升/下降）。
- **隐形**：两个 mixin —— `GuardianAngelInvisibilityMixin`（实体追踪层，非 owner 观看者 `ci.cancel()`）+ `GuardianAngelInvisibilityListedMixin`（`player_info` 名单层，`sys_` 一律 `listed=false`）。主人仍能看到自己的天使（`OWNER_SEES_GUARDIAN=true`），旁人完全无感。
- **客户端要做的**：正常以 `sys_<owner>` 登录即可，观察者 + 隐形由服务端强制，无需客户端额外处理。

## 4. 客户端调用流程（示例）

```
玩家启动客户端/门户
  → 守护天使上线（客户端说了算，同生共死）
  → 守护天使以 sys_<owner> 连入世界（mineflayer）
玩家玩游戏期间：
  ├─ 陪玩：客户端通道持续聊天/辅助（占客户端算力）
  ├─ 施法：守护天使 CLI 释放技能 / 私聊女神祈愿 → 服务端认主，作用到玩家
  ├─ 分身：守护天使按算力召唤 N 个影分身 → 安排干活 → 用毕请遣散
  └─ 女神交互：守护天使私聊女神问事/请托 → 女神正常响应
玩家下线/退出
  → 守护天使下线（客户端说了算）
```

---

## 5. 边界与原则

- **客户端说了算**：守护天使的生灭、分身数量、算力调度，全由客户端掌控；服务端只管认主 + 提供接口。
- **服务端不掺算力**：查克拉/算力是客户端的；服务端不设分身上限（仅做基础并发/一具身体一件活保护）。
- **守护天使不碰 RCON**：所有能力都走游戏内标准通道（私聊/CLI/numen_act），永远够不着服务器控制接口。
- **认主铁律**：守护天使是「玩家甲的系统」，服务端认出后所有事办到甲头上，不服务、不响应、不跟随别人。
