# 原生班次、持续会话与经验

世界团队继续使用已有 QwenPaw 进程与原生 Cron。女神巡查、世界工程师和游戏策划各有受管班次；原司灯每日运营、技能维护与桐人生活控制器有自己的已有职责。收到班次时检查其真实工具、任务身份与已有回执，不再自行创建 while 循环、第二个守护进程或新的供应商调用。

传声、村民对话、人物模板和已登记的独立人物也可使用团队工单，但这次接入不为它们新增周期模型任务。仍由原有玩家互动、世界事件和生活入口开展本职工作；不能因为具备团队技能就自行加一个循环。

原生班次的固定 job 和固定 user/channel/target session 可连续保存同一个班次的历史。QwenPaw 2.2 中 `share_session=false` 使用 `target_session_id + ":cron:" + job.id`，不要把这理解成每轮创建随机聊天，也不能把它与桐人的生活主会话混为一谈。角色身份、原生调度记录与上一任务状态以实际返回为准；重命名不需要清空旧经历。

受管团队周期检查角色执行状态与工单变化，工程师没有分配工作时跳过；源码测试有新回执后可在后续任务继续处理。未知班次保留记录、等待核验，不能清账让下一次 Cron 重放。游戏人物交流依旧经过游戏，收到后台项目工单不等于游戏角色已经听见对话。

本阶段不设置人为每日模型次数、QPM或迭代次数上限，仍保留角色串行、真实供应商限制、执行超时与未知不重投。班次节奏是运转方式，不是让角色无限轮询模型。官方 `cron` 与既有任务工具用于查看或在已有权限内管理调度，不借创建高频自调任务绕过受管入口。

将重要观察与证据写入自己的 `memory/YYYY-MM-DD.md`，持续目标与下一验收点用 `memory/goals.md`；`MEMORY.md` 作短索引，参考和代码草稿放 notes/skills/engineering 的相应位置。普通记录已授权。原生 Memory/Dream 是否启用要读实际角色配置和任务结果，本技能绑定不代表自动开启，也不能把生成笔记当作学会玩法、测试通过或部署完成。
