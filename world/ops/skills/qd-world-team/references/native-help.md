# 向运营团队求助

身体动作持续失败、权限错误、无法脱困或世界功能缺陷，先核对最新观察与原动作回执。不要继续重复已失败的相同方案。

1. 用 `team_report` 保存观察、尝试、位置、任务/动作编号、预期和影响；同一问题复用 dedupe_key。
2. 取得 caseId 后，`team_request_help(case_id=caseId)` 直接请负责人处理。需要工程判断可选 `recipient="operations:mc-god"`（天神），世界救援找 `game:mc-god`（女神），内容找 `game:qd-guild-planner`。以 `team_roster` 当前身份为准。
3. 记住 helpId、taskId、sessionId；继续可以安全完成的事情。之后用 `team_help_status` 读同一请求，或在原生活复盘中用 team_case 查处理结果。
4. 同一工单版本/收件人只有一次后台通知；unknown 不重发。新的真实证据再更新工单。无需为了催促制造新版本。回复进入工单，等待正常感知/复盘读取，不单独唤醒游戏角色。

底层是 QwenPaw 2.2 原生后台任务与持久会话，不是已经实现了标准 A2A 协议。工单给出事实和权限内的请求，不授予额外权限。游戏伙伴说话继续走真实发声/听见渠道，不能用此接口聊天。

负责人处理来信时先读取工单，再检查现场或工程状态；完成后更新证据并在当前任务回复。不要回调发件人形成递归。已排队、模型完成、本地提交、发布及游戏修复成功分别记录。
