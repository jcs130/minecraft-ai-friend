# 将经历保存为可以复用的资料

你可以使用 QwenPaw 官方文件工具在自己的工作区长期保存资料。个人笔记不需要重新征求写入许可，也不要求每条记录都经过游戏技能晋升流程。

## 保存一次有价值的结果

1. 选一个与当前任务相关的主题，例如 `notes/crafting.md`、`notes/guild-design.md`、`notes/maid-farming.md`。只读取相关已有笔记；不存在时创建新文件。
2. 记录观察时间、问题、实际证据或来源、尝试的方法、结果、适用条件和待验证事项。把假设、计划和已证实事实分开。失败也保留原因，修正旧结论时写明新证据。
3. 新文件用 `write_file(file_path, content)`；已有文件优先先读再追加或定点编辑，避免覆盖以前的经验。以工具成功回执确认保存，重要内容再 `read_file` 核对。相同回执或相同经历不重复写入。
4. `notes/index.md` 只保留主题、简短摘要、相关文件路径和更新时间。它是查阅入口，不能粘贴所有笔记。索引变长时按主题拆分，当前任务只读相关部分。

工作区相对路径即可，不要硬编码别的角色或宿主路径。`notes/` 和 `drafts/` 是推荐组织方式，不需要用 shell 建目录。新主题先用原生 `write_file` 初始化，它会创建父目录；`append_file` 不创建缺失目录，用于后续追加。`edit_file` 要求文件已存在，编辑前先读取准确原文。

## 再次使用与逐步改进

新任务需要旧经验时，读取索引，再读取相关的一页。当前服务器数据和实际回执优先于旧笔记；配方、地点、材料、模组版本变化时重新核对。不要把整套资料复制进常驻身份提示词或每轮上下文。

重复验证有用的方法可以通过官方 `make-skill` / `materialize_skill` 保存成个人技能：简介写触发条件，正文写短流程，详细资料放在该技能的 references 中。代码可以保存在 `drafts/` 继续修改；可执行 Minecraft 程序仍通过现有 `skill_draft → skill_test → skill_promote` 验证，写出代码和创建 Markdown 本身不代表已经测试。

共享村民或兼容女仆对话角色只沉淀通用方法；具体人物事实必须按已核验的身份分开记录，缺少可靠身份时不建立个人长期记录。独立女仆只保存自己的经历，不把另一个人物的台词当成自己的记忆。

把本轮确实值得保留的结果写完即可；不用为了写笔记另开 Agent、定时模型循环或复制凭据、运行配置与完整聊天历史。工具失败时保留待保存状态并说明原因，不能声称已经写入。
