# 用真实证据迭代技能

在当前角色的正常复盘中使用此页，不另开模型循环。优先读取 learning_status 或 skill_catalog 的索引，再读取相关版本和实践；不要遍历文件夹收集全部上下文。

## 一次迭代

1. 从实际任务的成功、失败、unverified 记录选一个可重复问题，保存确切任务/实践 ID、版本、前置条件、观察到的结果。未确认动作先对账，不能作为失败重试。
2. 找出现有最相近技能。说明哪条前置条件、动作参数、反馈解释或终止条件可能有错；一次只检验一个假设。优先删去错误规则、修订原技能，不复制改名形成重复库。
3. 用现有 draft 接口生成不可变新版本，引用原实践。程序明确初始条件、每步 memory、已确认回执、实际效果、停止/让位条件；Jev 候选只引用已有准确动作，不把分类当执行成功。
4. 保存原成功用例和本次失败用例，另外保留未用于编写修改的场景，例如不同材料数量、已装备物品、终态未确认、距离不足、已完成目标。用 skill_test 真正运行。样例通过仅说明样例通过，不能冒充跨任务收益。
5. 在下一正常身体租约中用原 skill_start 做一次有界试运行，核对原生动作回执与前后变化，保留旧版。对照需要相近条件；两次不相同的任务不能称 A/B。没有保留场景的效果证据时将收益标为待验证。
6. 下一次复盘按实践 ID 记录保留、继续修订或回退的理由。程序通过原测试/晋升接口进入目录；Markdown 用原 learning_validate/activate/feedback，注明后者只是流程检查。不要手改索引、测试报告或历史结果。

## 区分修补技能与改造运行体系

L1 的动作失败先核对真实材料、距离、权限与任务终态。L2 提炼跨正常任务可复用的规则/程序；一次修复不等于掌握。只有多个任务反复暴露同类机制问题时，才提交给原运营/工程流程做 L3：限定感知、工具、上下文、执行循环或验证中的一个模块，附正反轨迹、改进假设、预期收益、回退版本和保留场景。

实现错误不必否定整个方向；假设被证据否定则应停止该方向。未选中的建议保持待验证，不能记成已拒绝或已完成。评审结论必须来自原结构化回执；不要在模型的推理文字中搜索“通过/拒绝”来决定上线。不要复制上游的自动接受、扩大权限或反复试错设置。
