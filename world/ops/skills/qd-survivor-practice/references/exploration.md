# 探索与成长：当前身体能做什么

在你因兴趣、经历、装备缺口、公会承诺或附近机会选择探索目标时读取本页。它是当前接口的能力地图，不是出发命令、固定坐标或必须完成的科技树。先根据本轮实际工具和世界事实判断目标是否可行；不为轮换活动而放弃尚有价值的目标。

## 获取可验证的线索

| 想弄清的事情 | 当前入口 | 事实边界 |
| --- | --- | --- |
| 自己在哪里、是否遇到危险 | `status` 的位置、维度、生命、饥饿、空气、水/岩浆、`bodyControl`、任务状态；`look(radius=4..12)` 的附近地形、实体、敌怪、时间天气 | 都是当时的局部观测。缺失不等于安全；实体扫描可能含遮挡目标，不等于可见、可达或可攻击。 |
| 群系与结构线索 | `status.biome`、`status.structures`，配合 `look` 和实际移动后的新观测 | structures 表示当前地点的结构归属，不证明已经找到入口、进入房间或搜完战利品。没有全世界结构清单。 |
| 附近资源、工位、地形细节 | `scan_blocks(block_ids, radius<=16)`、`inspect_block(x,y,z)` | 扫描只覆盖已加载世界，最多返回最近16处，并标注截断/未加载；单次未发现不能证明周围或地下不存在。施工和交互仍需精查实际目标。 |
| 村民与任务机会 | `look` 得到真实实体；`villager_offers` 查询当前报价；`guild_board` 查询今天本人可接合同 | 角色名、历史地点和公示文字不证明报价、接单资格、物资归属或已完成任务。 |

当前没有向桐人开放 `locate_structure`、`locate_biome`、通用地图定位或跨维度旅行工具。`knowledge_read('world_atlas')` 可作为历史地点知识，文章中出现的旧工具名不成为权限。模组结构与机制可能超出历史攻略；无法核实就保留未知，不编造最近据点坐标、房间布局或宝箱内容。

## 把探索拆成有出口的小阶段

从已观察线索选择一个值得验证的问题，例如入口是否可达、某个工位能否使用、附近是否有本目标所需材料。阶段结束以新位置、实际方块/实体、物品变化或任务系统状态为依据。把“线索已确认”“通路已验证”“任务已完成”分开记录，不用内部计数推算探索面积。

先根据当前坐标与最终目标算 `dx=目标x-当前x`、`dz=目标z-当前z`：正 X 向东、负 X 向西、正 Z 向南、负 Z 向北。位置变化后重新核对方向和剩余距离，不能沿用旧笔记的“继续向东”。绕障可以暂时远离目标，但要有已观察的通路依据和返回主方向的条件。

`move` 每步水平最多24格，不挖不搭；普通通路选已观察的数格至十几格落脚点，障碍或高差不明确时才细分。1.5格到达容差内的目标可能直接 completed 而身体未动，不能据此声称前进；对照新坐标与剩余距离。只有可靠观察脚部高度时才传 `y`；省略 y 只接受目标列附近高度的已知可站立点，找不到会拒绝。同一 x/z 不证明上楼，落点候选也不证明整条路径安全。工作区与维度限制仍生效，预检不能保证整条路径不越界。

身体越界时，`areaPreflight.recovery` 提供 nearestInside、delta、direction 和 suggestedStep。它是计算得到的回程方向，不是地形观测；先核查建议落点与路线，再逐步靠近工作区。中间落点仍在外但更接近工作区可以作为回程步骤，不必原地等待一次跨越全部距离。

`motor.bodyAccess=queued` 时，`motor_queued` 后保存下一步并结束本轮，让快循环执行；不要 status 忙轮询，也不把依赖尚未知结果的下一步提前排队。下次输入的回执、最新位置和剩余距离共同决定接续。直接租约受理后才用一次 `status(wait_seconds=10,detail="brief")` 核对精确 taskId/epoch；仍在途就结束等待事件。明确失败须按 code、实际障碍和落点候选改变方案。

危险、材料或空间不足、无法确认入口、超出已开放能力都可以成为转向条件。记录具体缺口和来源，选择返回、补给、另一条已观察通路、另一项有价值的目标或反馈问题。相同 `protected_area`、路径失败或未知回执不靠重复调用解决。`home`、`sky_walk` 和部分铁魔法位移目前缺目的地适配，不能假设它们是脱困入口。需要结衣协助时沿用游戏内交流；请求帮助不等于已经获救。

## 成长途径与当前限制

**装备与补给。** `lookup_recipe` 查询当前服务器的标准配方，`craft` 用真实背包材料执行工作台类合成，`equip` 验证实际装备槽。合成数量每次1–16，3×3需要附近工作台。炉类可经本人或授权的 `open_container → inspect_container → transfer_items → close_container` 加工，再按真实进度取出成品。查询到锻造、切石或模组配方不代表已有对应执行工具；候选材料简称也不是完整物品ID。按需读 [制作与加工](../../qd-minecraft-guide/references/crafting.md)。

**据点物资。** 建造和农耕仅在允许建设区进行。当前容器接口只接受本人放置记录或明确授权的容器，双箱需完整授权而当前会拒绝。看见天然遗迹宝箱、村民储物箱或模组机器不等于可以开取；仅与归属已获确认的储物设施交互，取得实际物品回执后才记录获得战利品。接口不足时将所需交互与实际方块证据作为改进反馈。

**公会与原生成长。** 看板支持的普通 `gather`、`hunt`、`visit` 合同分别是实物收购、新增击杀、实际到访。先检查 `claimable`、`blockedReason`、本人资格、柜台距离和任务前置条件，再按需 `guild_claim`；不再合适可 `guild_release`。收购用 `guild_deliver` 和原回执验收；讨伐/到访由原公会按真实统计或位置自动验收，不能调用交货强行结算。完成后回读本人看板状态和奖励结果。当前主动攻击入口缺失，不能因能接讨伐就假定可以主动狩猎；旧召唤BOSS、造景、组队战利品合同也未开放。详细读 [交易与公会](../../qd-minecraft-guide/references/trading-guild.md)。

**战斗与法术。** Numen 原生身体有近身危险自卫与换气等反射，但这不是无伤保证，也不等于模型具备主动 `attack`、指定敌人或独立瞄准接口。当前没有这些主动入口，也没有自动进食反射；食物在包里仍需按真实需要 `eat`。选择战斗相关目标时先核对实际武器、防具、补给和可退通路，不能靠走近敌人冒充已验证的狩猎方法。

`game_skills` 查询本人的特色修为、技能学习条件、实际铁魔法装备与原生属性；`game_learn` 只能按真实携带且已识别的特色技能书学习，`game_cast` 按目录、等级、资源、冷却和区域规则施放。等级足够的开放主动技能可按原规则首次施放收录；铁魔法必须取得并装备真实来源，不由 `game_learn` 免费授予。铁魔法当前不接额外目标参数；施放受理不证明命中、击杀或奖励。`game_skill_receipt` 加实际变化才是结果依据。当前没有通用附魔、属性加点或任意物品使用接口；按需读 [法术与人物成长](../../qd-minecraft-guide/references/magic.md)。

## 保留经验，避免把设想写成成果

用已有 `remember` 保留简短阶段目标、已证实线索、尚缺条件和下一次验收点；长期经验继续用原生文件与记忆流程整理。原生等级/属性、装备、公会功勋、游戏技能和 JS 程序能力分别记录。

需要复用已理解的重复步骤时，再按 [程序实践](program-practice.md) 读取确切版本、测试、晋升和实战记录。`programReportedDone` 不等于 `objectiveObserved`；观察到一次目标也不等于跨场景掌握。一次侦察、一次自卫、一次换装备都不自动证明已经清理据点或掌握完整冒险流程。

接口依据：`world/survival/mcp_server.py`、`numen_gateway.py`、`world_actions.py`、`game_skills.py`、`recipe_lookup.py`、`world/sidecar/guild_requests.py`。本页不增加任何工具或管理权限。
