# 游戏设计内置知识

以下内容已吸纳进 `game-production`。按讨论问题选择相关章节，不要从头到尾机械执行。

## 1. 全局设计一致性

适用于立项、重大改版和跨专业冲突。

1. 用一句可观察行为描述核心体验，避免宣传语。
2. 检查机制、故事、美学和技术是否共同支持该体验。
3. 用关键体验节点画兴趣曲线，定位平直、突变、过载或缺少收束。
4. 将结论收敛为保留、修改、删除，并报告范围和依赖。

吸收 Jesse Schell 的核心体验、四元组、兴趣曲线与迭代思想。

## 2. 乐趣与重复疲劳

适用于“好不好玩”、内容消耗过快、难度失衡和创新方向。

1. 列出玩家识别、学习、组合和掌握的最小玩法模式。
2. 判断无聊来自模式耗尽、重复无变化、选择无意义还是挑战不足。
3. 判断挫败来自信息不足、反馈不清、学习断层还是挑战过高。
4. 优先重组现有规则或情境，再考虑新增系统和内容。

制作决策必须包含目标玩家、最小实验、停止条件和内容成本。不要规定玩法原子数量，也不要把心流当作唯一目标。

吸收 Raph Koster 关于学习、模式、精通、新奇与包容性的有效部分。

## 3. 核心机制与玩法循环

适用于核心机制、选择、成长、难度和教学。

1. 定义玩家动作、状态变化、反馈和玩家要作出的判断。
2. 写出“情境 -> 选择 -> 行动 -> 结果 -> 新情境”的核心循环。
3. 检查每个选择的收益、代价、风险和替代方案。
4. 区分内容数量、系统复杂度和策略深度。
5. 核心循环未成立时，不扩展角色、装备和关卡数量。

每新增规则都要报告它解决的问题、生命周期、默认行为、失败模式，以及为何不能复用现有结构。

吸收核心机制、玩法循环、选择、成长、难度和情境教学方法。

## 4. 形式规则与公平性

适用于规则冲突、策略退化、滚雪球、多人信息和作弊收益。

1. 分开记录建构规则、操作规则和隐式规则。
2. 描述信息是完整或不完整、对称或不对称、概率已知或未知。
3. 识别正负反馈、资源循环、优势累积和恢复机制。
4. 检查稳定策略、无效选择、串谋和破坏行为的收益条件。
5. 修改一个底层原因，并推演对系统、UI、AI、网络、教学和 QA 的传播影响。

吸收有意义玩乐、规则层级、信息结构、反馈系统和博弈分析方法。

## 5. 玩家认知与 UX

适用于玩家看不见、学不会、记不住、误解或过早流失。

1. 区分感知不到、注意不到、无法理解、没有记住、动机不足和操作困难。
2. 检查界面、空间、反馈与玩家既有心理模型是否一致。
3. 设计最小干预：减少竞争信息、分段教学、及时反馈或恢复路径。
4. 用观察、访谈和行为数据交叉验证，不用单一留存指标解释认知原因。

不要照搬固定记忆容量、遗忘比例、点击次数或菜单层级作为通用标准。

吸收注意力、记忆、学习、感知、动机、可用性和玩家研究方法。

## 6. 游戏感与反馈

适用于手感、打击感、移动感和交互反馈。

1. 记录输入、状态切换、运动、命中确认和反馈出现的帧或时间。
2. 分离输入、响应、规则、载体、空间参照和润色。
3. 先修状态、运动、碰撞或时序，再增加动画、声音、镜头、特效和触觉。
4. 一次改变一个高影响变量，保留基线并做 A/B 测试。

报告目标设备、性能预算、跨专业依赖和可访问性风险。不要用通用延迟阈值替代项目实测。

吸收输入、响应、规则、载体、空间参照和润色的游戏感分析方法。

## 统一输出

对所选透镜输出：观察事实、根因假设、最小改动、范围与依赖、验证方法、成功信号、反证、停止或回滚条件。

## 理论来源与使用边界

本参考综合并重组以下公开游戏设计思想，不复制原书章节或长段原文：

- Jesse Schell, *The Art of Game Design*：核心体验、四元组、兴趣曲线与设计透镜。
- Raph Koster, *A Theory of Fun for Game Design*：学习、模式、精通与新奇。
- Troy Dunniway 与 Jeannie Novak, *Gameplay Mechanics*：核心机制、循环、成长与教学。
- Katie Salen 与 Eric Zimmerman, *Rules of Play*：有意义玩乐、规则层级、信息与反馈。
- Celia Hodent, *The Gamer's Brain*：注意力、记忆、学习、动机与玩家研究。
- Steve Swink, *Game Feel*：输入、响应、运动、空间参照与润色。

将这些框架作为提出假设和设计验证的工具，不把书中案例、时代背景或经验阈值当作当前项目事实。
