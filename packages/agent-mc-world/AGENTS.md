# Independent Minecraft core

- Java 1.21.1 is the primary maintenance, default viewer build and acceptance target. Keep actual-connection version matching and explicit legacy compatibility tests; remove obsolete feature gates only when payload or codec capability checks establish support.

- This package is the primary product, and this directory is its single source; build and test it independently of the server project at `world/`. All general Minecraft capabilities belong here, including observation/information discovery, actions/navigation, inventory/crafting, scripts/skill libraries, game memory, learning/evaluation evidence and fast-decision state/candidate contracts.
- Implement and fix general capabilities in the core first, expose them through shared SDK/MCP/public extension contracts, verify packed consumers, then update their pinned dependencies. A need found in Cormy or a host plugin does not justify a separate implementation. Keep model and host choices interchangeable through explicit ports; document backend capability differences rather than implying parity.
- Host adapters depend on this package. Core source, default entry, declarations and build must not import Cortico, DSH, N.E.K.O or Qiandengji adapters.
- Preserve `agent-mc/v1` event delivery, tool barriers, explicit turns, task identity/terminal states, facts/archive, deduplication and cancellation. Acceptance is not goal completion.
- Host owns personality, model calls, learning decisions and personal memory. The core owns reusable game-learning/skill-evolution mechanisms and may persist explicitly requested game-only notes and historical observations, isolated by realm/account/agent, without claiming current facts or verified learning. No hidden model loop, server discovery or performance endpoint scanning.
- Shared SDK/MCP operation evidence, bounded local lesson recall and explicit reflection belong in this core. Preserve actual selection/adoption/execution identities, negative evidence and nulls; recording or a completed method must never automatically promote a skill, replay an unknown effect or authorize a new action. Keep personal host memory separate and link it by references.
- Viewer source stays in `jcs130/mc-visual-console`; prepare locked release inputs explicitly. Do not commit derived game/viewer assets, runtime state or credentials here.
- Full package tests, public declaration checks and build verification precede commit. Test consumers against a packed package in isolation.
- Source migration does not authorize production restarts. Report source, package, deployment and live gameplay evidence separately.
