# Native tool latency

Short JavaScript programs can return their observed result and confirmed native cleanup within the same `mc_script` reply. `waitMs` waits on the **original** run:0 returns immediate admission, 1–30000 waits up to that duration. Native default is1000ms, configurable with `javaClient.methodWaitMs`; the Mineflayer tool keeps immediate admission by default and accepts explicit `waitMs`. Longer work continues in the background under its original runId. Waiting neither starts another model call nor resubmits the program. Cancelling a wait does not silently cancel accepted work; use explicit stop/cancellation and reconcile the original receipt.

Native program completion is terminal only after native cleanup is confirmed. Cleanup that remains pending or unknown keeps the execution nonterminal. Syntax validation, program completion, dispatch and task goal completion remain distinct. Full method evidence retains its source hash and original archive reference. Failed programs no longer require an extra model turn solely to discover their already observed terminal.

Modern native `method_read` already checks UUID/server and expected connection generation on the client thread. Its generation-tagged reply is validated by the adapter without another full inventory/state RPC before every read. Older replies without generation metadata retain the guarded fresh-state fallback; mismatching replies are rejected. Body operations keep their existing checks and single queue. This is not a cached world observation or permission to relax identity checks.

`mc_state detail:body` returns fresh body, GUI identity, pending/unknown action summary and compact held-item/inventory counts without repeating every stack. `detail:summary` preserves the existing compact full summary. Default remains summary unless the owning deployment sets `javaClient.stateDetail:"body"`. Use `mc_bag` for current stacks, component queries for details, and the original state archive for exact evidence. Unknown inventory stays null; an omitted stack list is not an empty inventory.

For a known small operation, combine sequential reads, condition checks, supported body calls and readback inside one bounded shared program. Preserve the32-call limit and allocate room for execution/readback; use supported `findBlock(s)` with actual registry IDs instead of repeatedly scanning entire volumes through `blockAt`. Normal navigation can use the compatible `goto` step when the actual bridge advertises navigation. Acceptance and terminal program status do not establish arrival or overall goal success without the matching observations.
