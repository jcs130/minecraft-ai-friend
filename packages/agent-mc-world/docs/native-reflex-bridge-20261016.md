# Native body bridge for shared reflex and combat kernels

The Java1.21.1 body now advertises `agent-mc-reflex/v1` only when its optional native walking driver is actually available. The JS adapter constructs the existing `CombatSession` and `Reflexes`, together with the existing candidate generator, tactical program runner and scoped combat notebook. It does not log in a second Mineflayer player, create a model loop, simulate positions or reimplement tactical decisions in Java.

The internal body facet projects measured position, velocity, health, inventory, collision shapes, visible actors and original damage source packets. Degrees/radians, native/standard inventory slots and air ticks/shared oxygen levels are converted explicitly. Internal collision samples are not exposed as visible block observations to the Agent. Missing/unloaded geometry stays unknown. Damage received before attachment is not replayed as a new hit. Actual damage source IDs and native names remain distinct from registry indices.

Native inputs use an ordered connection-scoped stream with a400ms maximum lease and a500ms sample bound. Duplicate inputs do not execute or renew; ended sequences cannot revive. The game thread rechecks authorization, entity UUID, visibility, three-block measured attack reach and actual attack cooldown. Attacks sent do not prove hits. Expiry, GUI takeover, death or loss of authorization releases inputs. Normal task, method and navigation records keep their original IDs while paused by survival; their paused time is excluded from internal navigation/method watchdogs. Low-health destructive preemption and deep-fall cancellation address only the sampled original task.

A temporary public Baritone process pauses an owned route without replacing its original goal. It does not cancel a foreign navigator. The same no-dig/no-place walking policy is leased and restored. Background slow-model generation does not hold this body lane. Read-only tools do not suspend it; a validated newly admitted body task can ask the shared combat controller to stand down under its existing survival gates. `mc_stop` uses the shared stop-attacking-and-withdraw behavior.

The common tactical tool schema is available before connection. Its `runtimeAvailable` hint prevents hosts from assuming native combat support merely because a tool exists. A native body lacking this capability remains explicitly unsupported. Shared custom tactical programs use the existing immutable host version/library workflow. Selection receipts and metadata-only control transitions retain a request reference; combat results remain observations requiring review, not automatic learned skills or victories.

Body lifecycle scope is distinct from the transport generation. Respawn, dimension transfer or replacement of the actual player/world object invalidates old tactical choices and queued body dispatch, without inventing a network reconnect. Native absorption is forwarded with health damage evidence; air supply is scaled from actual ticks to the shared 0–20 scale. Packet and absorption mappings are checked against the [Fabric Yarn 1.21.1 damage packet](https://maven.fabricmc.net/docs/yarn-1.21.1%2Bbuild.1/net/minecraft/network/packet/s2c/play/EntityDamageS2CPacket.html) and [LivingEntity API](https://maven.fabricmc.net/docs/yarn-1.21.1%2Bbuild.3/net/minecraft/entity/LivingEntity.html#getAbsorptionAmount()).

Current primitive coverage includes movement, view, native walking, measured melee dispatch, observed main-hand selection and inventory-verified consumption. Offhand/armor equip, offhand use, reflex block breaking, water-bucket block interaction and server spell providers remain explicit gaps. The shared drowning, lava avoidance and combat fallback paths continue to use their supported primitives. These gaps are not silently converted into successful operations or generic server commands.

Offline tests run the real shared kernels and collision physics for combat, low-health withdrawal, air conversion/drowning, tactical choices, authorization revocation and historical-damage exclusion. The Java build additionally checks native deduplication, ordered methods, inventory authority, navigation ownership, server authorization and reflex lease lifetime. Source, packed consumer, native loading and live behavior are recorded separately. No model inference is used by this bridge or its background sampling.
