# Minecraft 具身学习路线与渐进部署

核对日期：2026-10-18。目标是能从真实交互中改进的游戏具身 Agent。核心同时维护观测、动作、执行回执、学习证据与评估接口；宿主选择任务、模型、训练时机和具体采用版本。当前规则控制器可提供示范与回退，后续以独立测试和实际接管结果决定替换范围。

## 调研结果与采用判断

以下是对官方代码、文档和论文的核对；“采用”指工程设计判断，不代表已经集成其模型或复现论文成绩。

| 项目 | 已提供的机制 | 对本项目的用途与边界 |
| --- | --- | --- |
| [MineStudio](https://github.com/CraftJarvis/MineStudio) | 模拟器、轨迹数据、策略、离线训练、在线 RL、推理、批量评测 | 最贴近完整训练系统的参考。复用分层接口与实验流程；其 MineRL/JDK8 环境不能直接替换我们 Java 1.21.1 的身体。 |
| [MineRL](https://github.com/minerllabs/minerl) | Gym 环境、游戏动作与示范；v1.0 使用 1.16.5 的像素和键鼠控制 | 借鉴任务、episode、动作空间和基准。保持我们 1.21.1 的 Gymnasium 桥，另做动作／物理迁移验收。 |
| [VPT](https://github.com/openai/Video-Pre-Training) | 有标签动作训练逆动力学模型，用视频扩展预训练，再微调游戏策略；有代码与权重 | 证明大量交互数据可以形成通用身体策略。我们先收集可核对的执行动作；视频推断动作是伪标签，不能冒充实际按键。 |
| [STEVE-1](https://github.com/Shalev-Lifshitz/STEVE-1) | VPT + MineCLIP 条件控制、事后目标重标、短程文本／视觉指令 | 借鉴“任务条件化技能”，尤其从已实现结果重新生成结构化目标；事后目标须独立标记，不能改写原任务是否成功。原权重与我们的输入／版本不直接兼容。 |
| [JARVIS-VLA](https://github.com/CraftJarvis/JarvisVLA) | 视觉语言模型的游戏动作后训练、SFT 与评测脚本 | 专用游戏模型微调的直接参考。适合研究技能和交互决策；已有 7B 示例不是本地高频运动速度的保证。 |
| [JARVIS-1](https://github.com/CraftJarvis/JARVIS-1) | 多模态规划、低层执行与游戏经验记忆 | 参考慢规划／快执行和情节记忆关联。语言反思改善检索，不等于策略权重已经训练。 |
| [DreamerV3](https://github.com/danijar/dreamerv3) / [Diamond 环境](https://github.com/danijar/diamond_env) | 从交互经验学习世界模型，在想象轨迹上训练 actor／critic；提供 Minecraft 任务环境 | 中期优先评估的模型式 RL 路线。需要连续的状态、动作、奖励与终止数据；与“把困难场景复制到仿真反复练习”互补，但环境／模型迁移和算力成本须单独实测。 |
| [Craftax](https://github.com/MichaelTMatthews/Craftax) | JAX 上的开放任务强化学习基准 | 可做探索、记忆与奖励方案的快速小实验；它是另一套简化游戏环境，成绩不能当成 Java Minecraft 实服效果。 |
| [LeRobot](https://github.com/huggingface/lerobot) / [HIL-SERL](https://huggingface.co/docs/lerobot/main/hilserl) | 数据集、模仿学习、离线到在线 RL、人类干预；[DAgger 采集](https://huggingface.co/docs/lerobot/main/hil_data_collection)保留自主与纠错片段 | 优先借鉴学习者实际访问状态上的纠错和干预归因。MCAP 是原始事件档案；对齐后的 episode 可另外导出 Parquet／视频视图，不能只改文件扩展名就称兼容。 |
| [SmolVLA](https://huggingface.co/blog/smolvla) / [异步推理](https://huggingface.co/blog/async-robot-inference) | 小型 VLA 和动作预测／执行解耦 | 参考分段动作与异步缓冲，减少等待慢模型时的停顿。机器人动作头需要换成游戏动作，不能直接输出鼠标／施法。 |
| [Octo](https://github.com/octo-models/octo) / [OpenVLA](https://github.com/openvla/openvla) | 更换观测／动作接口、微调、LoRA 等 | 借鉴可替换编码器和参数高效训练；机械臂坐标、动作归一化和预训练技能不会自动迁移到 Minecraft。 |

基础算法：[DAgger](https://arxiv.org/abs/1011.0686) 用学习者分布上的专家标注减少模仿学习的分布偏移；[Policy Distillation](https://arxiv.org/abs/1511.06295) 将教师策略压缩到较小网络。这里的规则寻路是有误差的教师，不是环境真值；用世界变化和任务判据评价教师与学生。

实施优先级：近期采用现有 BC／PPO、分布纠错采集与影子／小比例试用；中期评估 DreamerV3 式世界模型和技能蒸馏；像素端到端 VLA 留在有足够对齐视频与动作之后。观测与动作协议共用，实验后端可替换，不先绑定某个旧版模拟器或一个大权重。

## 三类可训练能力

| 层次 | 输入与输出 | 首轮训练与后续改进 |
| --- | --- | --- |
| 运动 | 当前局部体素、速度、姿态、最终目标 → 短时转向／移动／跳跃 | 现有寻路示范 BC → 学生访问状态上的 DAgger → 隔离 1.21.1 仿真 PPO。教师路线与服务端真值不进入学生输入。 |
| 技能／战术 | 任务阶段、最近观测、可用动作／程序、装备资源、历史结果 → 技能／参数／执行时长 | 从慢模型、人类和经验证方法蒸馏小分类器或小模型；覆盖采集、合成、跟随、交互、战斗、飞行、闪现、法术。分别学习适用条件和结果，不把未开放能力编成动作。 |
| 分解与恢复 | 结构化目标、任务图、工具回执、已采用经验 → 子目标／重试／改路／求助 | 审核后的任务轨迹 SFT／LoRA；失败保留为恢复任务；同状态有可靠优劣对照后才构造偏好对。复杂新任务继续交给宿主慢模型。 |

优先训练快层，让熟悉任务免于每一步走大模型 ReAct。大模型生成较低频的任务和方法；本地策略持续执行短段，带时效和所有权交接。不可仅以“无思考”推断端到端延迟已经低。

## 数据闭环

1. 原始档案保留感知输入、真实已执行动作、原始任务／子目标 ID、候选菜单、选中和实际采用的策略、版本、概率、执行 ID、取消／覆盖原因、结果和独立任务判据。环境真值是单独通道，并注明来源与时刻。
2. 规则、模型、人类、回退动作分别标记。记录召回的记忆和真正采用的记忆，方法带精确版本。采集既保留成功，也保留失败、接管和未知，不把不动、受伤、取消直接标成错误决策。
3. 游戏状态、候选和动作构成结构化蒸馏输入／目标，无需保存提示词、回答或思考正文。决策时的输入不能包含事后状态、最终回报或教师完整路线。
4. 校验时间对齐、缺失、版本、重复、观测覆盖和动作效果。数据量按独立任务／episode 统计，重复帧不等于多份经验。训练／验证／测试按 episode、世界／种子和任务族隔离，不能随机拆相邻帧。
5. 在冻结的保留集比较旧策略、新策略与教师：完成率、实际目标成功率、受伤／资源、回退和取消率、耗时／停顿、推理 p50/p95。先看各任务，再看总体；报告窗口、样本和置信区间。
6. 通过验证的模型作为候选进入真实使用，低比例逐步接管。纠错片段回流下一轮训练，回退保留旧版本。持续运行增加证据，并不保证每个新权重都更好。

大量数据也需要覆盖面：自然在线使用提供真实分布和失败；独立仿真负责长尾场景、可重置任务与受控探索；人工纠错提供少量高价值示范。不会为了扩大条数而在可米身上循环无意义操作。

## 当前实现与逐步部署

公共 `agent-mc-world/learning` 提供：

- `selectPolicyProposal`：显式 `shadow / canary / active`；同 scope、experiment、episode 固定随机分组；可选候选比例；缺失／不适用／停止时用基线。它只返回提议，身体所有权、最新环境和取消交接仍由现有宿主与派发器验证。
- `OperationAttribution.policy`：记录实际提交动作的来源、层次、策略版本和实验关联。SDK、MCP 的 `agent-mc/v1` 元数据及 World 工具包装共用该契约。S1/S2 仅表示推理职责，不能当作规则／学习来源。
- `summarizePolicyUsage`：按唯一操作和修订去重，分别统计选择、提交、准入、已开始、完成、进展信号与目标成功。未知有独立分母，来源不明时不伪装规则占比。每个策略／版本单列。
- 目标成功必须有调用方提供的 `PolicyGoalWitness`：作用域、原操作、实际执行 ID、任务判据版本与证据引用。它是显式评估器提交的结论，统计器不自行核验外部证据。没有评估器时成功率为 null，完成率仍单列。
- `MotorPolicyShadow`：只读取显式哈希锁定的本地最终目标模型，基于正在执行的单一 goto（可伴随 look）与新鲜局部体素推理；无有效目标／观测就跳过。建议写独立 `/gameplay/policy-shadow` FlatBuffers 通道。没有身体控制端口，不调用 LLM，不借用未来坐标或上轮目标，不为建议计算虚构的成功率。
- 录制状态包含最近一小时 `policyUsage` 和本进程 `motorShadow`。本地推理耗时只覆盖网络前向计算，不能当成整个操作时延。影子历史的在线计数从当前录制进程开始；完整原始记录仍保留在 MCAP。

显式私有采集配置可加入：

```json
{
  "motorShadow": {
    "policyFile": "<本地导出的最终目标模型 JSON>",
    "sha256": "<文件精确 SHA-256>",
    "experimentId": "motor-shadow-v1",
    "targetMaxAgeMs": 30000
  }
}
```

下一阶段按**任务类型**小范围 canary：例如干燥平地 goto，先做影子观测，再显式采用 5% 的符合条件 episode，通过保留集与真实窗口验收后调整比例。危险、断连、身体已被占用和未知执行状态仍走现有交接契约。5% 是候选实验配置，不是当前已接管值，也不是训练目标。训练目标是更高成功率和更低成本，不能追求接管比例本身。

当前连续在线数据尚缺完整逐 tick 执行动作、S1 候选采用关联和独立任务评估。原始日志不会自动变成可监督的标签。现有 BC/PPO 小运动模型与预备实验见 [motor-training.md](motor-training.md)，档案契约见 [gameplay-learning.md](gameplay-learning.md)。模型微调和正式接管的实际验证要独立记录，不能以采集上线替代。
