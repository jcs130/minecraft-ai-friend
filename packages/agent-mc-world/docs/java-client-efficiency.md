# JavaClientWorld event delivery and short action execution

`src/client/java-client.ts` uses cooperative delivery for routine native observations. Action terminals use `flush`: idle consumers wake immediately, while an active decision is not cancelled by its own result. System chat uses `debounce`, HUD observations use `piggyback`, and signed player chat uses `preempt`. Disconnect and missing-message warnings retain interruption. Original events, timestamps, task identities, execution metadata and archive references remain deliverable; scheduling does not mean an event was discarded or a goal completed.

`javaClient.actionWaitMs` defaults to 1000 ms (0–2000). A short `mc_do`/`mc_script` action can return its actual terminal in the original tool reply, avoiding a separate model decision just to query it. `mc_do.waitMs` overrides this for one call. Expiry returns the original accepted/running action; it never resubmits or marks the goal complete. Caller cancellation or adapter stop cancels the wait, not an independently admitted body action. Explicit action cancellation and lease release remain separate operations.

When Minescript 4.0 is explicitly enabled, `mc_probe` selects a fixed read-only program. It batches up to 512 absolute samples, or observes a nearby bounded volume (default 196 blocks). Nearby results are ordered by distance. Namespaced names, properties, absolute positions, observation time, unknown count and truncation remain explicit. It uses the same native controller, queue and action ID; it never moves, digs, requests new chunks or runs a model. Its script report remains partial until a host verifies a gameplay goal separately. No optional helper installation is required by this tool.

`mc_evidence part:script` pages the exact program report while retaining the full original's digest and size. This avoids paging through a large inventory/book snapshot to reach a small result. `part:full` remains the default. An `mc_script api` request only reads the requested reference, even if a caller supplies placeholder code; the reply explicitly says that code was not executed.

## Validation

The integrated core preserves upstream `84ee91e` automatic/on-demand viewer changes. Its default/schema includes `auto`; an explicitly selected viewer mode retains its own failure policy. Core full suite: 97 files / 750 tests, public typecheck, standalone build and packed SDK/MCP checks passed. Tests cover cooperative event delivery, actual short terminals, long admissions, cancellation without replay, API-only queries, bounded probes and exact script evidence projection. The generated probe program was executed against an offline Python API fixture, including negative coordinates, state properties, nearest-first order and incomplete/unknown reads. No game or model was needed for those checks.

The pre-change live 15-minute sample contained 177 rounds, including 98 preempted rounds, 789.5 seconds of model time and 20.4 seconds of tool time. This identifies wasted work; it is not an after-deployment speed result. Live host-only settings stopped replaying previous reasoning and made routine choices inherit the existing non-thinking connection; deliberate reasoning stayed at its configured high effort. Model endpoints, player identity, goals and long-term memory were preserved. The code candidate is reserved for the coordinated viewer/body deployment, with activation and actual gameplay reported separately.
