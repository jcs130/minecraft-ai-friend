# Read-only voxel scene evidence

`captureVoxelScene` is exported from the root SDK/client and extension entry points; its versioned types are also exported from `agent-mc-world/contracts`. It reads an explicitly bounded client region and retains canonical names (including mod namespaces), state IDs, properties, collision shapes, unknown cells, camera coordinates and coverage. It never connects an account, calls a model or substitutes a gray category for an unknown block. The cell order is x, then y, then z; -1 is unloaded/unknown and must not be treated as air.

`readVanillaBlockRegistry('1.21.1')` exports the installed minecraft-data registry: 1,060 canonical types and 26,684 state IDs, including property schemas and state ranges. The version must match exactly; no newer/older registry is silently substituted. This vanilla registry is not a server mod registry or an assertion that every block entity has a complete visual renderer. Do not paste the complete registry into every model prompt: resolve the observed states locally, then attach the visible classes and corresponding rendering evidence.

`ViewerGameplayObserver` also accepts `archive=null` for a passive reader with no dataset writes. After `start()`, `readScene({radius,below,above,eyeHeight,fovDegrees})` reads the pinned player's loaded viewer chunks. It requires fresh matching player identity and clears cached chunks on world/connection changes. `stop()` remains single-use and cancels reconnects. Scene export does not require a demonstration label or make unknown controls/expert actions known. `source.realmVerified` preserves the existing scope/binding evidence; a matching username/UUID alone never proves the server address.

This is historical client evidence, not independent server truth. The region is finite, serialized columns are bounded, and absent columns remain unknown. Collision shapes are not exact visual meshes. Rendering resources, server mod models and YSM appearance/animation need their own explicit sources. No camera-control action is sent: the projection is a consumer-supplied virtual camera based on the observed player pose.

For generative rendering, save this evidence with the proxy and paired first frame. A renderer may use natural material colors plus a separate semantic raster/legend for the image editor. EdenLive's released proxy interface reads RGB video through DINO; adding raw block IDs to a JSON file does not add a semantic-control channel to that model. Model providers, prompts, artistic materials and the choice to create an image remain consumer concerns.
