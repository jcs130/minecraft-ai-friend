# `core/game-memory-service.ts` and `core/perception-sight.ts`: notebook and observation settings

The core supplies game notes and retrieval. The host supplies persona, preferences, model routing and decisions. There is no automatic world scan, model inference, training or skill adoption in these settings.

`memory.mode: "local-vector"` adds offline CPU token-vector/keyword reciprocal-rank retrieval to the existing versioned notebook. It uses normalized word and Chinese character n-gram vectors. It downloads no model and is **lexical similarity, not a neural semantic embedding model**. Local documents remain authoritative. `local` keeps keyword search; `vector` uses an explicitly configured embeddings endpoint/model and existing indexing/fallback behavior; `remote` retains the existing provider contracts. No persona, credentials or unrelated files are indexed.

Agent tools retain `mc_memory` (or the consumer's namespace). Record resources with `kind: "resource"`, points of interest with `kind: "place"`, and other findings with the existing note kinds. `remember` requires top-level summary/content/source; a resource/place needs an explicit dimension. Keep coordinates, actual discovery time, source receipt and remaining uncertainty in the bounded content. Search returns summaries, `get` returns details. `revise` and `archive` require the expected revision, so an operator cannot overwrite a concurrent Agent update silently. History never establishes current stock, visibility or permissions.

SDK operator UIs can use `await client.notebook(args, signal?)` for local note operations without changing the current decision turn. When offline, it uses the same existing notebook path/scope without opening a game connection. When online, it calls the same core notebook as the Agent. It never dispatches body actions or service-learning workflows. HTTP/MCP hosts remain responsible for authenticating their owner UI. The DSH owner endpoint attributes its changes as `user_report`, not runtime evidence.

Notes are isolated by realm, account and Agent; dimensions filter places/resources. An optional stable `memoryAgentId` keeps a host's notebook independent of a display-name change. Omit it to preserve legacy namespaces. Remote realms without a server identity remain bound to the configured server address; changing aliases or replacing a world at that address does not prove that the notes belong to the same world. Do not merge other accounts automatically.

`perception.mineralVision` defaults to `false`. Public block queries hide occluded cells, including `findBlock`. Explicit `true` permits only loaded mineral blocks within 32 blocks through the read facade; it does not reveal unloaded terrain, entities or arbitrary block types. `observedBlock` still means actual sight and physical action safety remains unchanged. Enabling it does not create a visual x-ray or a complete vein census. The stable environment tells the Agent which policy applies.

`perception.entityView` defaults to `surroundings`: nearby entities with a clear loaded line of sight remain observable as the camera turns. `camera` additionally applies a 110° horizontal and 80° vertical cone. `perception.entityRange` defaults to 32 blocks and accepts integers from 1 to 64. Passive snapshots, attention and explicit entity queries share this policy; snapshots report their scope and retain the existing item limit. Unloaded rays, opaque walls, dead and invisible entities remain excluded. Screenshots, interaction reach and combat engagement keep their own contracts. SDK hosts can use `configureObservationPolicy` with a live configuration callback; explicit `observedEntity(..., true)` still requests the directional cone.

Block query facades retain up to 2,048 requested candidates before visibility filtering, so a large legitimate scan is not silently reduced to 512 candidates. Each returned block still requires a visible loaded face or the separately enabled mineral policy.

`configuredPlayerSkin({bytes, model})` validates a 64×64 or legacy 64×32 PNG, chunk CRCs, bounded scanline decompression, a 256 KiB limit and classic/slim model. It uses Node built-ins with no image-codec runtime dependency; the browser decodes the actual PNG for display. `setStoredSkin(bodyDataDir, "bot", bytes)` saves the local override. The core viewer serves the own avatar's content-addressed PNG on loopback; `skinModel` selects arms and `localSkinEnabled: false` disables the override while preserving the file. Shared rendering accepts that route only for the own avatar with explicit local provenance. No skin command is guessed and no Mojang account or other player's server-visible appearance is modified.

Release inputs may retain a previously verified deferred-audio index with the exact matching version manifests. Missing originals require matching SHA-1/SHA-256/size records, and unreferenced or mismatched records fail. Actual local bytes are verified and deferred normally. A new viewer identity updates the parent archive hash while preserving original audio hashes; downloading remains explicit. Public original BGM files remain packaged. This keeps code-only viewer updates independent of a multi-gigabyte source audio archive.
