# 聚焦选择与生活目标

维护者编写的通用资料，不是 Agent 的亲历或学习记录。宿主负责模型连接、目标和长期记忆。

## 什么时候调用 mc_choose

只有确实存在选择时调用。单一步骤、已知后续动作或运行中的有效方法继续执行，不为每一步增加模型往返。

| category | 候选来自哪里 | 执行前核对 |
| --- | --- | --- |
| route | 已测局部地形、支撑/净空、现有路线结果 | 区块可见、障碍、实际抵达；未知路段先观察 |
| survival | 当前生命、饥饿、氧气、食物与已见威胁 | 身体控制权与危险是否仍存在 |
| skill | 当前宿主/服务器公开的技能资格、耗费和冷却 | 目标可见、关系已确认；未知冷却不能当零 |
| method | 方法索引中的适用条件、源码版本和真实回执 | 固定方法版本、参数、校验、上次失败边界 |
| goal | 用户意向、未完目标、mc_life 的一条资料 | 保留原阶段与下一条件，不为多样性强行换目标 |

河流、湖面或较长水路还可考虑船；按需读 [水路与船](water-travel.md)。先看已有船与附近载具，再看实际配方、材料、下水点和上岸点。短涉水、桥面、乘船与绕陆都是候选，不把造船变成每次遇水都必须完成的前置任务。

调用形状：

```json
{"category":"route","goal":"到达河岸","candidates":[
  {"id":"bridge","label":"走桥面","evidence":"填写刚取得的支撑/净空和路线证据","ready":true},
  {"id":"water","label":"涉水","evidence":"深度与回岸处未知","ready":false}
]}
```

示例中的证据必须换成真实读数。`ready` 是调用方声明，不是引擎替你确认。最多 12 项；每项只写影响选择的条件、成本和证据引用。工具附带采样来源及最多 2400 字符的当前重点事实，按类别选取，不把地图或方法库全量送给快模型。

返回 `advice` 仅为建议，概率不是成功率。`inspect` 表示需补观察；`stale` 表示等候时现场变化；`unavailable/cancelled/busy` 保留当前有效工作。过期答案不得执行。主 Agent 通过正常行动接口提交选中方案，执行器再次检查权限、控制权和前提；目标完成需另有终态及世界净变化。

SDK 调用方通过 `MinecraftAgentClient` 的 `decisions` 注入中立 `DecisionPort`。Cortico 适配层默认继承宿主已保存的连接，可显式选择 MC 专用连接。核心不保存密钥、指定厂商、扫描端点或启动模型循环。

## mc_life 与长期连续性

先读索引，再读一条：打造装备、种田食物、探索、改善住处、拜访。它们是可改写的起点，不是活动排班或固定剧情。采用后在宿主保存目标 ID、阶段、完成证据、下一条件、方法版本和未完成项。等待作物/冶炼/别人回复时保留后台分支；已完成准备不重复。用实际抵达、补种、合成入包、方块变化或领取回执验收。

服务器专属剧情、命令、技能与冷却说明从显式服务器资料包按需读取，通用故事线不假设这些能力存在。

## 赠物

普通 `toss` 是抛出物品，不是放置矿车或保证送达。赠物用完整可见玩家名 `target`，与 `at` 互斥，先保持 2–4 格距离。目标走开或被遮挡时不盲投；无合适抛物空间时不退化成脚边丢弃。回执中的背包净减少、同类物品拾取和本次交付数量分别看；未知结果先查，不自动补投。
