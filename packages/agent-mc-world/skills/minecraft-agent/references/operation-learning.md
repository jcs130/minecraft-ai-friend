# Shared operational learning

Use `mc_memory {"action":"experience","operation":"help"}` for the current schema. Then `list` selects a bounded page, `get` expands one ID, and `stats` reports its stated recent window with no invented accuracy. All evidence is scoped to the game realm, account and Agent. Minecraft Java 1.21.1 is the primary maintenance target; discover actual runtime capabilities for other versions.

The companion `minecraft-learning` skill contains the full review cycle. When installed alone:

1. Search `mc_memory` for a relevant lesson/method; get exact versions. Keep useful running work while thinking.
2. Inspect current resources, geometry, permissions and cooldowns. Use `mc_help` / server help to discover mechanics. `mc_choose` compares ready candidates and recalls at most three local lessons. An unknown precondition is not ready.
3. SDK `call` and MCP `_meta["agent-mc/v1"]` accept optional `attribution:{controller,sessionId,decisionId,method:{id,revision},memoryRefs}`. Copy exact references, never fabricate proof. A `mc_choose` result's `meta.decisionId` links the later action. Retrieval alone is not adoption.
4. Read the real terminal receipt and measured world change. A cast acknowledgment, movement, animation or method returning is insufficient to establish the intended goal. Tool results include `meta.experience.id` when recorded. Storage errors appear in runtime `learning.recordingFailures`; they do not make a completed body action retryable.
5. `reflect` needs a stable requestId, 1–8 exact evidence IDs, summary, lesson, conditions, counterexample and verdict (helpful/harmful/unclear). A helpful review needs a completed operation and both measurements. The saved lesson remains your interpretation. Read its returned note ID and search it in a later applicable scene.

For flight, compare permission duration, path clearance, travel time, reserves and observed final position. If blink crossed a dimension or the position never refreshed, retain uncertainty. Failed and rejected attempts are useful counterexamples.

The core makes no learning-model requests. The host decides when to reflect or revise an executable version through `mc_script {"api":"methods"}`. Optional remote learning uses `mc_memory {action:"service",operation:"help"}` and that service's existing candidate review workflow.
