# 装备制造与使用

用于取得适合当前任务的武器、护甲、工具，或附魔与修理。Java 1.21.1 为基线；Paper/RPG 可改属性与费用，以当前工具帮助和服务端结果为准。这里是维护者知识，不是角色已经学会或亲历的记录。

## 先选路线

先读 `mc_bag` 的物品、附魔、耐久、名称，比较已有成品、已核实库存、合成和强化成本。`mc_options {intent:"equipment"}` 给方法入口；不要因为缺一把剑就忽略三叉戟、斧、弩或技能。按需要读 `mc_help {skills:["craft","enchant","anvil","grindstone","equip"]}`，不要展开整个手册。

原生近战已识别三叉戟和重锤。`attack` 可用 `weapon:"trident"` 指定本步近战武器；`mc_combat_tactic {meleeWeapons:["trident","iron_sword"]}` 调整默认近战偏好，未携带的条目跳过，`[]` 恢复默认。这些顺序不是伤害预测；附魔、冷却、敌人、距离和服务器自定义属性仍应比较。

自动远程控制目前是弓与普通箭。三叉戟的明确投掷走 `use`；忠诚、激流及离手后状态须按实际附魔和反馈判断。弩不属于自动弓控制器，可查 `mc_script {api:"weapons"}` 编写原生装填/发射方法。不能把已发包当命中或回收，也不能假设存在未公开的脚本方法。

## 附魔台

发现并核对真实附魔台格子，先查看当前经验等级、青金石和目标装备。`pick` 可以从同名多件里按名称、附魔或耐久挑选。

```json
{"skill":"enchant","at":[100,64,-30],"item":"iron_sword","pick":"实用剑"}
```

坐标与物品只是示例，需要替换成现场读数。省略 `index` 只放入查看三档报价并收回，不消费经验。选择后再给 `index:1`、`2` 或 `3`。显示的等级是门槛，原版实际花费为该档的 1/2/3 级和同量青金石；不要把“需要30级”写成“扣30级”。服务端只预告一条附魔，不能保证其余隐藏附魔。周围书架读数为本地观察，报价以服务器为准。

收到“结果未知”时先看原任务终态、目标物品附魔、经验和青金石，不换任务号重复点击。成功以新物品组件为证据，成品收回后再核对实际穿戴/主手；一次操作结束不代表整套装备准备完成。

## 铁砧、砂轮与修理

已有附魔通常通过 `anvil` 配合附魔书或同类装备合并。`pick/withPick` 分别选择两件物品，不把多本附魔书当成相同材料。保留任务需要的附魔与命名物品；不填新名字时按真实产物核对原名。`grindstone` 会去除普通附魔、返还经验，诅咒另有原版限制，不要把去附魔作为无条件前置。

## 交给制造 worker

宿主已有制造 worker 时复用它。交办信息包含：用途与完成条件、数量、当前物品引用、允许花费的资源、需保留的装备，以及相关帮助入口。主人格只需阶段和结果摘要；报价、配方和槽位细节留在该任务。查资料可并行，附魔、开窗、换装和移动仍使用同一身体队列。技能正文按需读取，不复制进每轮人格提示。

有重复工作时检索方法库；需要改法再用 `mc_script {api:"authoring"}` 校验、保存父版本、执行、读原始回执并复盘。记录实际净变化和失败条件，再选择复用版本。维护者提供接口和一次成功都不等于自主学习完成。

## 依据

- [Mineflayer API 与附魔台实现](https://github.com/PrismarineJS/mineflayer/blob/master/lib/plugins/enchantment_table.js)：窗口属性、选择档位和目标槽更新。安装版与网页 master 分别核对。
- [Java 1.21.1 EnchantmentScreenHandler](https://maven.fabricmc.net/docs/yarn-1.21.1%2Bbuild.3/net/minecraft/screen/EnchantmentScreenHandler.html)：附魔条目、消耗及窗口生命周期的版本接口。
- 实际参数与边界来自本包 `mc_help`；通用原版知识不能覆盖服务器自定义规则。
