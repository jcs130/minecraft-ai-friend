# Repair a connected body's web picture

Use `mc_connection {"action":"viewer-status"}`. A missing prebuilt vanilla pack automatically uses compatible materials with the actual connection's registry. `resources.mode:"compatible"` is a usable partial picture; keep useful game work running and do not repeatedly try to repair it. New materials can appear as visible placeholders and missing icons/fonts are local gaps. Never reconnect, start another account or replay pending actions just to improve presentation.

Only when exact resources are requested, follow the shared renderer's [optional preparation guide](https://github.com/jcs130/mc-visual-console/blob/main/docs/vanilla-viewer-resources.md). The helper downloads the requested official client, verifies its metadata/hash, exports original assets and validates models. Use the configured viewer root as `--output`; dependencies belong in a separate renderer checkout. Normal connection and compatible rendering do not require this preparation. No game login or server password is involved.

After successful preparation, call `mc_connection {"action":"viewer-retry"}` and verify `phase:"ready"` and `resources.mode:"exact"`. This refreshes the compatible/failed picture on the existing body. A preparation exit code alone is not proof of a rendered scene; verify health and visible terrain. Never relabel another version's numeric registry. Native/modded rendering keeps its strict matching contract and is not certified by compatible vanilla rendering.

For optional DSH enhancement, use an existing capability preset with filesystem/terminal tools; Minecraft tools do not grant shell access. If tools or write access are absent, report that the optional enhancement is unavailable and continue with the working picture. Give manual commands only if the user asks. Preserve goals, memory, model and identity.
