# 水路与船

维护者编写的通用工具资料，不是 Agent 的亲历、自动路线或已验证技能。根据实际目标和现场选择；不要求每次遇水都造船。

## 选择与准备

- 较长的河流、湖面或海岸水路可比较乘船、游泳、已有桥面与绕陆。先看已有船或附近载具，再核对造船成本；不要反复游同一段却不评估其他候选。
- 读当前背包、附近实体和相关水域。下水点、路线净空、落差与上岸站位尚未观察时保持未知；局部水面不证明整段可通航。急需换气时先处理当前氧气，再准备交通工具。
- 按需读 `mc_help {"skills":["craft","use","ride"]}`。宿主可能使用 `mymc_` 等命名空间，以实际工具表为准。
- 已有船可以使用，不必另造。没有船时用 `mc_scout` 试算 `craft`，按当前配方和回执补材料及工作台；中间材料不会自动补。Java 1.21.1 的橡木船物品是 `oak_boat`，本地标准配方为五块橡木板、需要工作台；服务器实际配方及执行回执优先。

## 工具链

以下坐标只展示参数形状，应替换成当前观察到的下水点与路线落点。每段结果会影响下一段选择，不盲目提交整条未经观察的航线。

1. 合成：`{"skill":"craft","item":"oak_boat","count":1}`。`count` 是新增船的数量；验收成品实际入包。
2. 放船：`{"skill":"use","item":"oak_boat","at":[x,y,z]}`。船通过使用物品生成实体，不能用 `build` 当普通方块放。回执中的库存减少与附近出现船是两条证据；只有库存减少时，船的位置仍未核实。
3. 上船：先读刚出现的实体；Java 1.21.1 的船实体类型为 `boat`，带箱船为 `chest_boat`，不是物品名 `oak_boat`。用 `{"skill":"ride","target":"boat"}`，核对当前载具读数；其他版本按实际实体 ID。
4. 驾驶：`{"skill":"ride","to":[x,y,z]}`。这是水平目的地，`goto` 不会驾着载具走。分段确认路线与实际位移，服务端纠偏、碰撞或没有进展时据回执调整方案。
5. 下船：抵达有合适站位的岸边后，`{"skill":"ride","off":true}`；再核对已下船、人的实际位置与支撑。仅到岸边不等于安全上岸。

如果要把这次经历留作可复用方法，记录造船、生成实体、乘坐、实际航行、上岸各自的终态与世界变化，并保留失败条件。维护者提供这份资料、保存脚本或一次接口成功，都不算自主学会。

## 有意潜水与返程预算

- 按需读脚本的 `api:"diving"`、`api:"read"`、`api:"setControlState"`。`await bot.read("breathing")` 返回氧气、生命、头/身浸水、位置/速度，以及客户端采样时刻、实际收到氧气/生命更新的时刻。更新时间缺失或原始氧气超出 0–20 时保留未知；旧读数不会因再次读取变成新服务端回执。
- 原生程序在 `await bot.setControlState("jump",false)` 后持续持有输入；连续 `await bot.read(...)` 和 `await bot.waitForTicks(...)` 之间不会恢复被动上浮。不要用许多互相独立、结束后立刻重开的短程序来潜水。完成、取消、断线和环境接管仍清理原输入。潜水动作不修改实体坐标、速度、碰撞或服务器属性。
- 先核对返程的实际净空和呼吸点，再决定是否下潜。低顶、水流或要先横移的路线不能用“深度÷上浮速度”代替。上浮速度、横移耗时和控制延迟应来自当前装备/效果下的实测；首次无可信估计时先在浅水建立样本。
- 多次新鲜水下样本计算氧气下降速度，取保守的实测消耗率。氧气剩余秒数约为“当前氧气÷消耗率”；返程预算为“实测回程时间＋不确定性余量”。余量接近预算时再返程，不因碰到水就结束潜水。静止或呼吸效果造成的读数不变不能解释为无限氧气。
- 生命下降速度独立计算，回血不能抵消已发生的伤害；生命预算只让返程更早，不能用来延长已无氧气的潜水。现场变化、碰撞无位移或读数失效时及时修订方案。现有 `surface`/防溺水用于危急兜底，不能替代脚本自己的返程判断。
- 包内 `examples/adaptive-diving.mjs` 是可审阅的预算计算参考，只返回建议，不自动下潜。应由 Agent 为当前目标编写/修改自己的控制程序，经 validate、真实执行、终态展开、深度/氧气/生命和上浮效果核验后保存方法版本。记录父版本、源码哈希、适用装备/水流/净空、失败样本；下次检索并验证复用后，才有学习收益证据。
