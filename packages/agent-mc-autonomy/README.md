### Shared host identity and context

and selected memories are budgeted once at the request tail. The budget reports
what actually fit. Current body facts and explicit user intent take precedence;
memories do not authorize actions or prove current world capabilities.

feedback, a different session, stale/disconnected state or an invalid review cannot
reuse it. Hosts invalidate it on opt-out or role changes. Public status and review
receipts contain counts/hash metadata only. No host SDK, implicit memory endpoint,
extra model loop or copied personality database is introduced. Without an attached
host, the explicitly configured standalone planner continues normally.

Local `mc_tool_help` names and JSON-pointer paths are resolved before any possible
body dispatch is journaled. A nonexistent property, invalid array index or
unavailable tool returns a known validation rejection with documentation lookup
guidance. It does not disconnect the body or create an unknown game outcome;
an unresolved real native failure remains available beside the failed read.

A tracked body task's successful terminal receipt and an actual submitted-goal
transition each allow one immediate planning handoff. They do not add a second
queue or speculative inference while native work is running. Ordinary observation
completions retain the configured decision throttle, and failed calls, provider
backoff, explicit stop and unknown dispatch retain their existing guards. This
removes an avoidable post-task cooldown; it does not remove model latency or prove
that a model's next plan is feasible.

### Optional local token counting

Embedders can pass `context_counter=counter` to `run_session` or `Controller`,
or attach the counter to their planner as `planner.context_counter`.
`HttpPlanner(..., context_counter=counter)` exposes the same port. A custom
standalone launcher can call `agent_mc_autonomy.cli.main(...,
context_counter_factory=factory)`; `factory(HttpPlannerConfig)` runs before the
planner is constructed, only for autonomous `run`. Returning `None` keeps the
default. Configuration files never load arbitrary module strings.

The exported `ContextCounter` protocol is a synchronous callable
`counter(messages, tools) -> int` with a stable public `name` (1–96 ASCII letters,
digits or `_.:/+-`, starting with a letter or digit). It returns nonnegative input
token counts; an optional `units` attribute must be `tokens`. It must perform no
network, model or game calls. The adapter owns
the selected model, tokenizer, template and protocol normalization; an
`HttpPlanner` adapter can use `model_protocols.request(config, messages, tools,
max_output_tokens)` to obtain the real wire representation. Count tools and
native replay data too. Do not tokenize serialized request JSON and label that
an exact provider count. The implementation must be deterministic and invalidate
itself when its model/template binding changes. No tokenizer library or
host-specific model path is required by the framework.

Diagnostics expose `counter`, `units`, `input`, `output_reserve`,
`framing_reserve`, `total` and `limit`. The framework independently retains the
configured output reserve and 1024 framing tokens; a current image still adds
the existing `image_reserve` after text assembly. This does not claim an exact
multimodal count. Cache hits still occupy context and are not subtracted.
An invalid count (including booleans) or counter exception restarts the entire
assembly using the existing byte bound, with only its failure type recorded as
`counter_fallback`. The default counter name and byte-budget behavior remain
unchanged, reported as `units=token_upper_bound` rather than measured tokens.

## Optional same-decision narration (0.2.1)

`NarrationPort` is an optional host-neutral output contract. A frontend subscribes
to the owned actor/body binding and claims fresh lines for its own voice service.
With a subscription, the projected `mc_do` schema accepts optional
`_spoken_text` metadata, including for tool-only models. It is stripped before
validation/dispatch against the original native schema. The existing planning
response may alternatively carry exactly `{"spoken_text":"a short natural utterance"}`
in assistant content alongside its normal tool call. Other analysis text is not
implicitly speech. The supplied
persona, selected memories and recent conversation stay in their existing context
ports; no second model call, host SDK import or native queue is introduced.

The durable outbox retains at most 32 records, paces ordinary lines, expires
detached subscriptions after 15 seconds and unsent lines after 30 seconds, and
binds delivery to actor, world/account, runtime, native run, intent revision and
death episode. Claiming happens once before transport; unknown delivery is never
replayed. Stop or changed bindings revoke the old line. Audio acceptance and
playback evidence are separate from native work completion. A host without this
optional subscription keeps the existing autonomous behavior and prompt.
