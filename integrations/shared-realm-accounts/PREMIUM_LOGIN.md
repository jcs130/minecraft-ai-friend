# SAO 正版免密与私有账号回执

0.1.0 将原服所有 OP 一概拒绝为 `RESERVED_ACCOUNT`，也把结构化回执直接显示在真人聊天框。0.1.1 分开核验系统身份、本人管理员身份和真实 Mojang 会话；真人默认只显示简短提示。

## 正版直接进服

千灯纪 LibreLogin 中已绑定的正版 UUID 是身份来源。首次关联还需要网站已核验的角色归属；已有关联可以在网站短时离线时读取原生绑定。名字大小写保持一致。

服务端在 DirectAuth 的异步账号预载阶段读取主服的当前身份，返回仅用于这次握手的 `UserData`。随后由原生 DirectAuth 发加密挑战并调用 Mojang 会话验证；只有连接上的 `MojangVerifiedConnection` 证明与绑定匹配时才允许认证。短时身份租约不是登录凭据，客户端报的名字或 UUID 不能代替会话证明。

实际游戏 UUID 使用原身体 UUID，Mojang UUID 单独用于证明所有权。LittleFish0510 的原身体 UUID 为 `9c1cde51-cf76-34a7-8574-19f37b63f50f`，不换档、不移物品、不取消千灯纪 OP；各服原有权限保持独立。

SAO 本地仍只保留随机影子密码和稳定身体 UUID，不保存主服密码、不把原生记录永久切到 premium。新关联先持久化身份绑定与强制适配器标记，标记 `premiumVerified=false`；实际 Mojang 验证成功后才记录通过时间。这个预备绑定本身不授予登录或游戏权限。原生宽限、旧影子密码和本地模式切换均不能跳过主服证明。

已有独立 SAO 账号仍需先证明原账号再显式关联。无法确认旧身体归属、主服离线或身份冲突时不按名字猜测，也不重置数据。

## 管理员与两步验证

主服原生 OP 名字和 UUID 必须同时精确匹配，SAO 身体也必须是同名同 UUID。离线管理员可用原生独立游戏密码证明本人，不再一律被挡；不能用自己的普通账号关联另一个 OP 身体。系统角色与 Eye 仍走专用入口。

TOTP 已开启时不会凭正版绑定免除第二因子。缺码返回 `TOTP_REQUIRED`，输入方式为 `/sharedaccount login 游戏密码 六位验证码`。原生 TOTP 验证器缺失时返回 `TOTP_PROVIDER_UNAVAILABLE` 并保持未认证；不会用自制校验器或忽略验证码替代。当前隔离夹具未启用该原生验证器，验收覆盖“正确验证码也不能绕过缺失的原生验证器”，不宣称 TOTP 成功登录已实测。

错密与错误验证码共用现有 LoginGuard 的失败账本、5分钟三次与10分钟锁定。原生 OP/TOTP 的改密继续留在千灯纪原生入口。

## 机器回执

Agent 向 `minecraft:register` 发送 UTF-8 的 `mcagent:account` 订阅。服务端对同一连接单播 JSON，字段保留 `schemaVersion`、`requestId`、`bodyUuid`、`state`、`reason`、`accepted`、`authenticated`、`linked` 等；最大16 KiB。没有密码、哈希或验证码，状态查询可能没有 requestId。

订阅按连接保存，注销或断线即清除。SDK 同时检查 schema、本人 bodyUuid、requestId 与字节预算，保留最多32条回执。普通真人不订阅，也不显示原始 JSON。`/sharedaccount format json` 仅用于明确要求旧聊天协议的消费者，不是默认模式。

接口受理、主服验证、身体关联与游戏认证分别表达。超时或未知继续按原 requestId 查询，不自动重放改密。

## 验证

纯 Java 策略测试覆盖本人 OP、别名拒绝、失败账本、实际会话证明的必填条件、UUID/名称/期限/TOTP 边界。原生隔离消费者覆盖普通账号、错误密码、管理员、TOTP 门禁、真人无 JSON、专用频道、重连格式清除与旁人不收回执。正版离线冒用实际收到原生加密挑战且不能出生。

这些检查不等同于小鱼真实启动器完成微软会话；真实正版进入仍需由实际登录结果确认，不能把纯策略断言或冒名被拒当成正向证明。最终部署与实机结果记录在同目录发布清单。
