# 桐人调用效率与真实结果（2026-10-30）

本页保留第一轮的成功和失败片段。后续施法修复及当前 1728 通过/25 跳过的测试结果见 [FAILURE_REPAIR.md](FAILURE_REPAIR.md)；不会把本页曾经失败的技能试验改写为成功。

本轮修改自主框架的工具展示、失败状态和回执处理，并更新 SAO 消费端；不是只给桐人加一段提示词。通用实现位于 `packages/agent-mc-autonomy`，版本 0.2.129；执行核心仍为独立构建的 rc.130。实验游戏服仍是回环 39676，未更换现役 Paper/Tau、JVM、权限、模组或端口。

## 改了哪些系统性问题

| 触发条件 | 原行为 | 当前行为 |
| --- | --- | --- |
| 参数错误后，同一操作改对并成功读取 | 旧错误仍留在当前上下文，模型误以为最新查询又失败 | 区分未派发的 schema 错误和实际游戏失败；匹配的成功调用清除旧 schema 错误，独立身体失败继续保留 |
| 长原生回执超过紧凑历史预算 | 主要保留聊天/排队文字，实际 `data` 丢失 | 保留有界结构化结果及原生请求/身体身份、时间和已知/未知标志；列出删减位置，完整原文仍可读取 |
| 已请求并使用一个高级工具 | 下一轮仍只有通用路由，直接调用原名被拒绝 | 成功帮助或显式只读调用后开放该项原生 schema；最多 4 项，不提前灌入所有模组内容 |
| 查询已完成任务以寻找奖励 | 反复翻完几十个任务再找待领项 | 列表提供准确的待领奖筛选和续页链接，保留章节、关键词及页大小 |
| 拼错任务 ID | 只知道失败，容易继续猜 ID 或读整份帮助 | 保留 `quest_not_found` 并提供安全列表查询；不自动选择或替换 ID |
| 从职业技能描述推测施放接口 | 拿任务详情查技能 ID，反复绑定或查询帮助 | 本人已装备且解锁槽位直接提供准确的 kind/slot 请求和单项帮助；不自动施放，不保证当前可用 |
| 共享坐标说明过长 | 精简 schema 删除整个 `at` 说明，模型混淆绝对坐标与相对分量 | 保留原生数值/坐标说明，明确裸 `-64` 是绝对值，`~-64` 才是相对分量；不改写输入 |
| `find` 初始扫描已经命中 | 简述让模型以为给 direction 就一定走过路 | 明确初始命中可以不移动；采集使用 `collect.block/count`，不是反复查询同一棵树 |

新增运行统计分开记录模型请求、工具调用、宿主校验拒绝、成功只读、原生任务受理、旧 schema 错误解除和身体变化采样。统计始终 `goal_verified=false`；任务结论另看原生终态、库存和位置证据。

## 实际模型验收

使用同一普通生存账号 `ag_Kirito`、线上 TokenPlan 的 `qwen3.7-plus`、文字工具模式。没有发管理员装备、没有复制探针背包，没有提供任务/奖励 ID 或目标坐标。维护者明确提交验收里程碑，不能称作模型独立选择了完整剧情。

| 里程碑 | 模型工具调用（包含最后 goal_report） | 含推理及执行耗时 | 实际结果 |
| --- | ---: | ---: | --- |
| 找到并领取武器奖励、装备主手 | 11 | 51.261 秒 | 原生奖励增加木剑 1 把；队列装备终态和服务端 SelectedItem 确认为木剑 |
| 从待领任务领取一种食物 | 8 | 41.510 秒 | 农夫乐事鸡蛋三明治 0→8，旧面包仍为 8；一次 rewardId 参数拒绝后下一次改成 reward_id，成功执行 |
| 在野外新增 4 个原木 | 46 | 237.995 秒 | 从水中脱困并走到树旁，实际采集 4 个橡木原木，库存 4→8，生命 20；没有绕过呼吸或路径门禁 |

耗时从该目标第一条模型请求开始，到模型提交报告为止，含原生执行等待；不包括启动/握手。第一项早于显式调用后的 schema 开放，前两项早于坐标说明保留；第三项早于最后的 find 简述补全。不同任务和不同阶段不能拿来算 A/B 加速比例。

原木验收前另有一次目标因 `['~','~','-64']` 被当作远处绝对落点而中止。原动作没有被偷偷改成 `~-64`，没有计为采木成功；正常停止后在原位置续测。后续原木成功仍用了较多查询和等待，尤其反复读队列/地形；不能把这 46 次调用包装成已经解决自由探索效率。

原生任务、装备和库存证明上述局部目标；框架的 `goal_report` 仍保留 `verified=false`，并未把模型自述升级为可信事实。正式片段、原请求 ID、服务器时期及库存增量见 [optimization-acceptance-20261030.json](optimization-acceptance-20261030.json)。完整日志保留在实验目录，不把密钥或所有模型上下文提交到仓库。

另一次技能复测已收到新的 `castRequest` 链接，但仍反复查询帮助/状态，累计 48 次工具调用后由维护者正常停止。原生剑技回执为 `native_cast_refused_check_resource_cooldown_and_target`，实际体力与冷却未见变化，明确没有计作成功。接口链接改善了参数发现，不代表已经解决模型的规划循环，也未据此修改服务器技能条件。之后恢复同一账号进行附近巡查。

## 回归与独立安装

自主框架全量 **1719 通过、25 跳过、6 失败**；6 项为既有 Windows 长路径夹具和 DPAPI 写入环境问题，上一轮已在未改动上游 `c7da224a` 复现同样失败。本次没有新增失败，也没有跳过或放松这些校验。新增 11 项覆盖旧错误解除、独立身体失败保留、按需 schema、结构化回执/未知标志、计数、身份切换和坐标语义。

SAO Node **39 项通过**，Python **3 项及 6 个子项通过**。正式 wheel 安装到新的私有虚拟环境后，以 `-I` 运行不注入源码路径的消费者，禁止网络与游戏/模型子进程，独立自主及纯队列循环通过。运行目录已安装同一 wheel 并逐文件核对；原 26 项联机历史回执重新只读核验通过，没有重放领奖等动作。

## 安装与兼容

先发出带固定 UUID 的正常 stop，确认 `stopped=true`、`pending=[]`、`uncertain=false`、`inflight_request=null`、原连接断开且独占租约已释放，再备份和更新私有虚拟环境。原信箱、请求账本、记忆与背包均保留。安装后核对 wheel、源码和冻结适配器哈希，再启动唯一控制器。PID 可能被操作系统复用，不能单凭一个旧 PID 还存在就认定原控制器没退出。

`mc_invoke` 旧链接仍可用，直接开放的工具仍验证完整原生 schema。仅当前已请求项会增加到 schema，不加载 934 个任务或所有技能。停止、未知结果、完整组件校验和保护规则保持；没有另建动作队列。

SAO 只读 ToolOutcome 现在使用 `data.response`，`text` 是简短状态。此前对 `text` 做 JSON 解析的消费程序须迁移；原始插件消息、普通 SDK 的 `read()`、原生动作 ID 与 `data.serverReceipt` 不变。历史验收读取器兼容新旧两种格式，原 26 项回执检查仍通过。

## 仍需实战推进

自由目标选择和跨轮工作记忆还会出现反复看指南的情况；大范围寻路、复杂水路和等待期间的无效轮次仍需继续按实际任务计数改进。Forge 配方目录/自动合成、特殊任务奖励、全部职业战斗及长期自给自足没有因此全部验收。新增运行计数提供测量依据，不表示已经自动学会或自我进化。
