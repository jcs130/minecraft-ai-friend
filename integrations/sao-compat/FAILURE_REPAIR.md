仅更新 SAO 回环实验服 39676/39689、自有 Forge 组件和私有 autonomy 0.2.130。旧 JVM 存档退出码 0；完整世界/配置/请求账本冷备后更换自有组件，未改角色等级、权限、物品、资源、技能门禁或其他服务器。

## 施法失败的原因

真实原生 `Combat.style()` 只识别 SAO 武器、呼吸武器和模组弓；普通木剑返回 -1。旧接口只显示槽位已装备/等级已解锁，随后给木剑提供了剑技施放请求。原生拒绝符合游戏规则，错误在接口没有表达武器前提。

另外，原生剑技的冷却字段是 `cd<武器风格>_<技能编号>`，旧接口却读 `cd<技能编号>`。旧成功判断比较整个 NBT，原生函数仅补写 `chargedFinisher=false` 也可能被误认为发动成功。

当前状态新增真实 `weaponStyle`、`mainHandItem`、已知前提的 `available/blockedReason` 和职业技能名。木剑会明确返回 `weapon_not_supported_for_sword_skill`，不会获得剑技 `castRequest`。这不影响木剑普通近战，也不要求管理员发新武器。职业技能照常通过原生处理器执行。

施法依旧按等级、槽位、武器、冷却、忙碌、角色状态及原生处理器校验；资源和其他模组条件仍由原处理器决定。已知前提不成立时返回具体原因。只有资源减少、准确的技能冷却增加或施法活动启动，才报告 `cast_started_not_hit_confirmed`；与施法无关的 NBT 变化不算成功。界面可用标记不是命中保证，也不绕过原生处理器。

## 六项失败测试的处理

两项长路径测试原本在测试夹具创建阶段就遇到 MAX_PATH，根本没有执行到待测安装器/校验器。现用 Windows 扩展路径创建与篡改真实文件，仍把普通路径传入产品函数，并继续模拟旧宿主限制，验证完整性检查能发现篡改。没有缩短样例、跳过或放宽校验。

四项凭据文件测试原本隐式依赖维护会话的真实 DPAPI。现在明确把它们作为临时目录里的文件/身份绑定单元测试，以假的加密端口隔离宿主状态；原生适配另测用户作用域标志、输出复制、输入擦除、原生内存释放、错误码和拒绝时不写入凭据。成功或拒绝均不能泄漏口令。

当前全量 **1728 通过、25 跳过、0 失败**，原来 6 个失败没有变成跳过。正式 wheel 在独立环境的 `-I` 消费测试通过，未插入仓库源码路径。

**实际 Windows DPAPI 仍不可用。** 本维护会话的 CryptProtectData 与 .NET CurrentUser Protect 均真实返回“拒绝访问”（错误 5）。测试转绿不代表该系统服务已恢复；程序现在保留 `windows_dpapi_error_5`，继续拒绝保存，未启用明文、机器作用域或其他弱化回退。实际账户环境/系统权限问题仍需在 Windows 会话中进一步排查。当前离线游戏及既有模型凭据不依赖这次密码写入，因此桐人可继续运行。
