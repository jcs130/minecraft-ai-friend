# 真人客户端进服卡住：ALI 与认证的循环等待

2026-10-30 23:14 已在现役 SAO 热修。Java JVM、监督器、世界和客户端安装包均未重启或替换；仍使用网站的 R2 `.mrpack`。本次修复的是登录前元数据同步，不能将登录超时直接解释为玩家忘记输入密码。

## 原因与证据

玩家反馈 `[ali]` 无法取得服务端掉落数据，并且窗口卡住后被认证超时断开。客户端与服务端均为 AdvancedLootInfo 2.2.0，JAR SHA256 相同，包的 Minecraft 1.20.1 / Forge 47.4.10 也一致。发布包的依赖哈希、内嵌模组及 OSS 下载入口已逐项核对，没有发现错发另一份客户端。

ALI 的 `GenericUtils.register` 先向服务端请求目录，再同步等待 Future；每次最多30秒，共三次。DirectAuth 原先将未认证连接的大部分模组请求留到认证完成后处理。ALI 因此等不到响应，客户端的配方查看器注册无法结束，玩家也难以操作登录，最终触发60秒认证超时。仅检查 TCP、Mineflayer 进服和服务端登录超时日志无法发现这个界面初始化依赖。

依据现役实际 JAR 检查：`AliMod` 先注册客户端接收消息，再注册服务器接收消息；因此 **请求 ID 是4**，不是1。`RequestLootDataMessage` 无参数，服务器唯一对应动作是同步已缓存的全局掉落与交易目录；它不控制玩家背包、世界、实体或认证。客户端接收1号数据分片、2号开始、3号完成消息；这些接收处理直接更新数据 Future，不需要先通过游戏登录。官方项目也说明目录由服务端采集后下发：[AdvancedLootInfo](https://github.com/yanny7/AdvancedLootInfo)。

## 修复范围

仅在 DirectAuth `heldPayloadExceptions` 中增加 `ali:network#4`，保留已有 `maw_agent:world_query`。没有放行整个 `ali:network`，也没有放行其他模组操作；游戏密码、登录次数、60秒超时、零宽限会话和原权限保持。SimpleChannel 的索引由 DirectAuth 自有 mixin 登记，因此该例外能精确匹配第4种消息。

`public/ali_login_compat.py` 固定现役 ALI 的完整 SHA256。模组更新后必须重新检查消息契约，不按旧编号猜测。默认命令只生成只读计划；应用前必须保存并核验 E/F 两份配置前像。应用只改该数组，然后通过监督器的正常控制台发送 `execute run directauth reload`。控制台的“已送达”回执不等于成功，必须看到原生 reload 成功及实际目录响应。

新部署的 `stage_public.py` 同样加入该精确例外，并在写入前核对 ALI JAR，避免重建后复发。现役网关的冻结文件未被热改；改动属于原生可重载配置，未修改鉴权组件 JAR。
