# Mineflayer 实机复测（2026-10-30）

本轮只使用 SAO 1.20.1 回环实验服。桐人仍是普通登录的 Mineflayer 玩家，不是 Numen 假玩家；自研 autonomy 0.2.130、core rc.130 和线上 qwen3.7-plus 保持，没有视觉模型输入、OP、传送或物品补发。Paper、Tau 与网络配置未操作。

## 实际结果

- 同一 UUID 重新登录，位置、背包和原生 FTB/职业数据保留。本次启动导出 261125 个方块状态、12037 个物品、940 个实体类型，并校验当前 JVM/epoch。
- Mineflayer 原始物品栏 46 个槽位逐一与服务端本人的原生 ItemStack 对照，16 个非空槽的类型、数量和数值 ID 全部一致。包括女仆魂符、农夫乐事三明治和 SAO 道具，没有替换成原版占位物。
- 模型先后两条路线被正常拒绝，随后沿现有通路完成两次步行。实际位置从 `(1459.3165,80,-1314.0454)` 到 `(1459.5032,80,-1318.4099)`，位移 **4.368 格**；终态说明没有挖掘或垫脚。完成附近到达条件，不宣称精确站上请求格。
- 模型发动职业技能“残暴连击”：原生回执体力 **100→88**、技能冷却 **4050ms**。`cast_started_not_hit_confirmed` 仅证明发动，没有命中或击杀验收。
- 再次断线重连后，普通客户端位置与服务端快照完全相同；只读查询原施法 requestId 返回同一原始观测时间和终态，没有重发施法。

复测里程碑从首次模型请求到 `goal_report` 用时 **142.399 秒**，产生 **15 次工具调用提案 / 15 次模型响应**，另保留 3 条参数校验拒绝记录。框架的模型自报 `verified=false` 保持；上述结论另由真实终态、资源变化及重连读回核对。不是完整剧情或长期生存验收。

## 发现与配置调整

刚开始实验 JVM 已不存在，旧宿主一直收到 `ECONNREFUSED`；本轮先停止旧控制器并核对无在途/未知动作，再恢复同一实验世界。旧进程消失的根因尚未确定，不能当成已修复崩服或开机自启。

第一次完整里程碑尝试未完成：模型重复查状态、把坡地目标高度写死，并在已知施法成功后再次施法。失败和人工纠正记录均保留。现场的一个目标明确缺少支撑；另一个寻路超时并不证明所有移动失效，未修改碰撞、权限或保护规则。

紧凑上下文当时几乎耗尽保守预算，最近事件全部被省略，多项身体事实和终态也被排除。SAO 新部署默认及当前运行配置将 `context_tokens` 从 65536 调整到 **131072**，仍用原有 `compact` 模式。没有新增记忆实现；框架、模型、动作队列和按需查询方式保持。这一字段在当前备用计数器下是 **UTF-8 字节上界**，不是实际模型 token 数，也不是强制每次填满。复测最后请求没有省略事实，事件覆盖恢复。

随后复测完成上述里程碑，仍有两次错误路线和参数纠正，不能称为无差错。两次测试含不同历史与人工反馈，不是受控 A/B，不能据此宣称通用成功率或提速比例。
