# SAO：真实信息与普通玩家操作

适用 Minecraft 1.20.1 / Forge 47.4.10 的 SAO。自有服务端组件候选 0.1.2、SDK 0.1.3；当前发布状态以本目录验收记录为准，不把源码版本当成线上版本。

Agent 不需要观看图像来辨认模组。SDK 在 Mineflayer 内部插件初始化前装入本次服务器 JVM 的真实注册表；普通 `blockAt`、物品栏、装备、移动、使用物品和攻击使用原生身份。专属菜单与玩法条件则按需读取服务端事实。静态类型表不包含世界区块；未观察到的区域仍未知，视线和建筑保护规则继续生效。

## 按需获取配方

```javascript
const capabilities = await bot.native.operations();
const recipes = await bot.native.recipes({
  outputId: 'farmersdelight:canvas', limit: 2
});
// 检查 ok/status、recipes、complete、nextOffset；是否续读由自己的控制器决定。
```

配方来自实际加载后的 `RecipeManager`，不直接扫描整合包中的 JSON 文件冒充可用配方。Forge 与 KubeJS 原生解码成功返回后，保存所用 JSON 对象的快照，并核对配方对象身份。本次审核 KubeJS `2001.6.5-build.26`，升级时需要重新验收读取钩子。其他代码再次替换对象、上下文不够或超预算时，明确返回定义不可用。被条件禁用或删除的配方不会被当作可合成内容。

可按 `recipeId / recipeType / outputId` 精确筛选，默认 6 项、最多 12 项、单包不超过 16 KiB。返回实际配方 ID、序列化器、输入及替代选项、声明成品、原始定义和完整性标记。有序合成包含宽、高和保留空槽的逐行顺序；烹饪配方有 tick 与经验声明。每个输入的替代品是任选之一，不是全部同时消耗。

`outputId` 只筛选原生声明的展示成品，不冒称覆盖随输入变化的最终组装结果或概率副产物。`outputScope` 与 `filterCoverageComplete` 说明范围。上下文不足的输出保留未知计数，匹配数可标为下界。

类型和序列化器读取 Forge 注册表。整合包中的未注册或不可读取类型保留未知计数，不能将其排除后宣称筛选覆盖完整；一个配方不可读取也不会拖垮其他可用结果。

分页保留 `matchedCount / returnedCount / remainingCount / nextOffset / complete`；定义缺失、筛选不完整与分页预算分别说明原因。每页带本人 UUID、服务端 epoch、配方代次及观测时间。续页是新观测，不代表一次不变的快照；重启或配方重载后应重新读取。SDK 不会自动读完全部目录。

同一查询也可通过自研运行时调用：

```json
{"section":"recipes","recipe":{"outputId":"farmersdelight:canvas","limit":2}}
```

这是 `mc_native` 参数。`mc_sao` 的 `sao.recipes` 使用同一筛选 schema 和同一个服务端读取器，也供既有 Numen provider 复用。先查询当前实际能力；不能将 provider 共享推断为每个 Numen 动作都已联机验收。

## 使用实际菜单

普通右键打开方块后，用 `bot.native.read('menu.current')` 读取当前菜单。槽位保留实际索引、坐标、归属、物品及组件指纹，追加原生 `active / maxStackSize / mayPickup / mayPlaceCarried`；光标为空时 `mayPlaceCarried=null`，因为尚未提供待放物品。`stillValid` 和 `bodyCanInteract` 反映当前菜单和身体条件。

这些是观测值，不是授权承诺。点击仍需当前窗口、状态号、服务端 epoch 与所观察物品完整组件的比较检查；保护、权限、距离及模组的原生 `clicked` 行为继续执行。SDK 的 `bot.native.click()` 发送普通容器点击语义，服务端处理的是原生菜单，不是替玩家发成品的管理员命令。

缺少菜单按钮、专用网络载荷或机器条件时明确报告缺口，不能凭图标推测槽位用途。配方定义只是操作依据；没有因此解除 `bot.craft/recipesFor/recipesAll` 的原版静态配方限制，也没有宣称所有机器可以自动制作。

菜单打开时，使用实际当前窗口的玩家槽位或原生菜单状态，不能将窗口外的旧背包缓存当作新观测。原生关闭接口现会下发原版全量玩家物品栏包，确保回到普通 Mineflayer 物品栏后数量也一致。SDK 可复用新近收到的 `currentMenu()` 和点击回执中的 `state`，无需每点一次前再重复查询。只读请求按上一条回执后的间隔发送，保留服务端限流；没有增加自动重试或放宽门禁。

## 身份与动作结果

登录前的私人状态、菜单和配方查询保持拒绝。每个查询和回执只属于发起连接；Numen 仍通过 Owner Token 和独占控制租约，不开放公网无鉴权 MCP。

模型、规划和记忆继续由用户自己的 Agent 运行时管理。写操作进入自己的唯一队列；动作受理、原生完成、任务目标完成分别核对。未知结果只按原 `requestId` 查询，禁止自动重放合成、点击、施法或转移物品。

升级只替换自有组件与 SDK，不增加客户端必装模组；原 Forge 客户端包、Java/Agent/基岩入口和账号来源保持。基岩的外观与专属界面仍需要各自适配，不能从 Mineflayer 查询通过推出基岩已完整支持。

## 隔离验收

完整 176 模组、无 OP、无图像、无模型推理的 SDK 消费者验证：登录前私人查询拒绝；按需查询真实帆布配方；真实工作台点击合成并核对 4 稻草消耗和 1 帆布产出；普通物品栏与原生库存数量一致；同 UUID 重连和原动作只读对账；其他账号不能读取该动作。另读取了真实农夫乐事烹饪类型、序列化器和苹果酒配方定义，没有将读取冒称机器已经煮制成功。
