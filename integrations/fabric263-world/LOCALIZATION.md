# 简体中文补全与验收

适用于本目录锁定的 Minecraft 26.3 / Fabric 0.20.1 组合。没有修改 SAO、千灯纪现役服或原模组 JAR。

## 已交付

`localization/zh_cn/` 保存 7,003 项已校验补全文本，其中：

- 5,763 项为客户端语言覆盖，包含 Village Quest 全部 4,553 项英文目录、JustQuests、Universal Shops、Easy NPC 配置、农夫乐事缺项、地下城奖励、Sodium 等。
- 50 项为 25 个内置任务的标题与描述。
- 1,190 项为后续自动委托的模板、89 类主题、线索、工具提示、消息等语料。另有 503 个当前已装内容的物品／实体名称，直接取经过校验的原版及模组中文语言数据，提供 526 个类型明确的名称映射。

`legacy-generated-zh_cn.json` 另外记录 20 项已审阅的旧委托显示文本迁移，以原英文摘要匹配；不更改任务 ID、目标、数量、条件、奖励、接取和完成状态。未知的旧英文委托不被猜译或清空，迁移器会要求明确补译。

品牌、作者署名、玩家名、按键名、命令、注册 ID、URL 和格式变量按原义保留。这里的“补全”指当前锁定组合的已知语言目录与委托生成语料，不包括玩家聊天和以后另装的模组，也不把每种第三方自绘界面都宣称为已逐屏验收。

## 显示链路

客户端的 `my-agent-world-zh_cn-0.1.0.zip` 只包含自有中文覆盖，不复制模型、贴图或供应商 JAR。Minecraft 26.3 的实际资源格式为 97.1；数据包格式为 121.0，均读取官方游戏元数据生成。

服务端数据包为 25 个内置任务补充 `zh_cn` 字段，保留原有语言和全部玩法定义。自有兼容组件 0.1.1 把中文加入 JustQuests 0.4.5 原生生成器的语言目录，不替换生成逻辑。

生成器对同一个路径的活物与食物进行区分。例如 `minecraft:rabbit` 的实体名为“兔子”，物品名为“生兔肉”；不会给 Agent 发出“繁殖生兔肉”的提示。采掘标题中的 Shift 按“采掘委托”处理，键盘标签中的 Shift 保留。

## 使用

推荐导入新的独立客户端包：

`E:/MC/releases/my-agent-world-fabric26.3-0.1.0-lab.3-zh_cn.mrpack`

它默认使用简体中文并启用本中文资源包。现有客户端也可添加独立中文 ZIP，选中后重新启动游戏。仅服务端放一个中文 ZIP 不会改变客户端的语言文件。

本机的匹配客户端和实验服已更新。游戏入口仍为 `127.0.0.1:39781`；没有开放新端口、替换旧服或上传到生产网站。

## 维护

```powershell
python localize.py audit
python localize.py build
# 关闭本实验客户端后安装：
python localize.py install-client
# 正常停止实验服并完成冷备份后安装：
python localize.py install-server
python build_compat.py --replace-built
python manage.py start
```

通常升级请先停止实验服并备份，再运行准备脚本。新建实例会在准备时同时装入中文资源。模型仅用于开发时编写缺失翻译；启动游戏、构建资源和运行服务不调用翻译模型，也不需要模型密钥。

`translate_missing.py` 是可选的开发工具：从明确指定的环境变量读取调用凭据，只发送公开模组文案；按源文摘要保存进度，校验占位符、ID、颜色码、换行及命令。作者应审阅 `overrides.json` 和译文，不能把通过结构校验当作语义已经完美。程序遇到鉴权或配额错误停止发出后续批次。私有凭据、调用记录、原文审计和缓存不进 Git 或客户端包。

## 真实验收

- 31 项回归通过。覆盖固定依赖、目录与哈希、动作对账、备份、资源选择保持、翻译变量、命令、重复构建及任务玩法定义不变。
- 真实 Java 客户端实际语言表与 5,763 项覆盖逐条核对：0 项不一致。
- 原生冒险日志标题为“冒险日志”，原生任务书标题为“任务”；两个真实界面均已截图。
- 客户端收到 38 个真实任务，25 项内置、8 项自有与当前 5 项自动委托均可读取中文标题和描述。
- 该服自然发生的自动委托轮换已生成含中文的六语言数据。再次冷启动后保持；没有通过强制完成或重发奖励来测试翻译。
- 原生 `TextBuilder` 的只读数据夹具验证活兔／兔肉、活鸡／鸡肉区分和采掘模板；此项不是实际繁殖或烹饪成绩。
- 界面验收使用无 OP 的专门测试账号 ChineseScout，临时设为旁观以避免闲置被怪物攻击，结束后恢复生存并退出。原 GraalScout 的完成记录保持。

GraalWeave 0.1.1 的 `str` / `print` 呈现钩子会把文本中看似小数的片段四舍五入，例如 `3.` 变成 `3.0`、`+0.75` 丢掉正号。首次文字校验因此出现 14 项假差异，失败回执已保留。验收脚本改为读取原始 Java String，并用 `sys.stdout.write` 输出结构化数据，重新逐条核对通过；未关闭字段写入检查，也未修改原始语言内容来迎合工具。其他脚本读取需要精确保持的字符串时也应沿用此方法。

原模组的固定宽度界面仍会对长标题使用省略号或工具提示；测试没有改动玩家的 GUI 比例、按键和其他资源包选择。建议正常分辨率游玩。资源全栈热重载的已知农夫乐事标签问题仍采用冷启动规避。

验收摘要和哈希在 `localization-acceptance-20261101.json`。完整回执、早期失败及备份位于私有实验缓存，不以 Python 执行成功代替游戏中的实际显示。
