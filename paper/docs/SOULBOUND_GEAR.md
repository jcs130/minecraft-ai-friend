# 专属装备绑定

AgentFriend 0.3.63 使用物品上的 `agentfriend:soulbound_owner` 保存主人 UUID。拥有者可正常穿戴、换快捷栏、攻击和施法；丢弃键、背包界面拖出、放入公共箱或个人箱、快捷键交换入箱都会被服务端取消。其他玩家不能拾取已经绑定的物品。玩家死亡时，即使将来关闭 `keepInventory`，已绑定装备仍随主人复活；目前正式世界本来也开启了死亡保留物品。绑定只限制所有权和转移，不赋予无限耐久或额外战力。

这套规则完全使用 Paper 的原版 ItemStack 和背包事件；Java、Geyser 基岩和 Mineflayer 都不需要客户端模组或资源包。客户端可见一行「灵魂绑定 · 仅主人可携带」说明，拒绝操作的提示只发给本人，2 秒内重复操作不刷屏。CortiEye 观战视角随原版物品同步，不新增聊天公屏消息。

首次安装后，玩家 `.MicroKQ`（Floodgate UUID `00000000-0000-0000-0009-00000d9f9c7b`）入服 2 秒时，插件只扫描她自己的 0–40 号背包/装备槽。符合女神骑士礼包**明确附魔组合**的钻石盔、胸甲、护腿、靴子、剑和弓会自动绑定；普通钻石装备、盾、粉色床、消耗品不会因类型相似而被绑定。已绑定的物品保持原主人，不重复加说明。此前已经掉在地上或放在箱里的物品不会被追溯绑定；需要先找回到本人背包。女神骑士礼包的原始附魔清单在运行脚本 `E:\MC\ops\goddess-act.mjs` 的 `KNIGHT_KIT`，本仓库不存放该运行脚本。

以后新增专属装备，服主在控制台或本机 RCON 精确绑定玩家当前槽位：

```text
/mycli admin bindgear <在线玩家> <槽位0–40>
/mycli admin bindgear <在线玩家> <同一槽位> apply
```

第一条只预览物品类型、数量、名称、主人 UUID；核对后立刻执行第二条。仅单件物品可绑定，已绑定物品不覆盖主人。0–8 是快捷栏，9–35 是背包，36–39 是靴、护腿、胸甲、头盔，40 是副手。命令只接受服务器控制台/RCON，不开放给普通玩家或游戏内 OP，防止误把别人的物品声明为己有。若玩家在预览和执行之间换了槽位，应重新预览，不要凭旧槽位执行。

隔离服验证：真实 Mineflayer 1.20.6 玩家收到 UUID PDC 和原版 lore；绑定胸甲的丢弃和向标准箱 Shift 点击被拒，普通圆石仍能丢弃，胸甲正常穿戴；临时关闭 `keepInventory` 后击杀并复活，胸甲仍在装备槽。测试脚本为 `paper/probe/soulbound-stage.mjs`。基岩真机仍需通过手柄丢弃键复核提示与物品保留。
