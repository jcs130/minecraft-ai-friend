# RPG 可用性与 Agent 指引检查

状态：修复已并入AF.25/桥0.2.4/Vortex qd29和Qwen频道0.3.2正式发布。见[发布记录](BASIC_SURVIVAL_RELEASE_20261028.md)及[实际部署清单](../manifests/current-deployment.json)；下方保留各轮候选的原验证证据。

服主随后明确七项基础生存技不应停用；后续[基础技能修复](BASIC_SURVIVAL_SKILLS_20261028.md)接续本批，更新基础技能集合与用法。下方`.24 / 0.2.3`的摘要和测试保留对应历史候选，不代表已部署。

## 已复现并修复

1. 原 `guild party status --json` 返回原生帮助；`create --json` 竟把 `--json` 当队名，`list` 又要求管理员权限。现统一解析格式旗标，裸命令/status/list 查本人队伍，create/invite/accept/leave 复用原 Vortex 队伍管理器和权限。队长权限不提升；个人结果与邀请不广播公屏。
2. 无目标的怪物攻击法术原先退化为位置目标，扣魔力、播放“射向目标”并报成功。对原生 monster-only 目标器，在空目标分支拒绝执行，复用原有失败退款、清冷却和失败回执；self/ray/location 类型不被这条规则改变。没有重写目标获取或技能效果。
3. 等级不足、点数不足、已经选职、已学习、冷却、待确认等仅返回简短原生文本，缺乏补救步骤。现有稳定原因码、明确说明和一个 nextCommand；冷却保留真实剩余时间。未知/保存冲突仍是结果未确认，不冒称“未执行”，不自动重放。
4. 已学节点仍提示再次学习；主动解锁节点只显示学习说明，缺少施法效果。现按本人真实状态展示“未学/已学”、被动常驻或主动技能的目标、效果、耗魔、冷却与施放命令。天赋同样读取原生分配记录，已学后不再推荐重复学习。
5. prepare 成功后没有可查的当前点击技。现 `skills status/list` 增加 activeSpell，仍沿原 Vortex 存档，不创建第二份准备槽。
6. 副本拒绝的顶层 nextCommands 与 guidance.nextCommand 有时相反。现在对已知准入/场次拒绝共用同一当前指引，保留原 reason 供兼容，primaryBlocker 明示优先处理的缺项。不放宽装备、地图、战备或活动限制。
7. 桐人原生频道只识别旧 `MC_STATUS`，裸查询又改为中文，正常角色也可能停在等待读数。候选心跳只对本人明确查 `status --json`，兼容 `MC_RPG/MC_STATUS`；缺少真实生命/饱食、非法数字或动作回执不会唤醒模型。仍用原生日常队列、记忆和动作账本，未修改模型、Key或生产频道。
8. 骑士 `fortify` 的原“奥术护盾”只执行周期恢复与粒子，台词却说增强防御。成功回调现补抗性I持续8秒，原耗魔、冷却和恢复保留，不覆盖更强抗性。实测同一攻击最终伤害5→4→5，分别为施放前、生效中与到期后；失败施法无增益。减免遵从原版抗性适用的伤害类型。
9. 锁定技能详情原来仍以 `cast` 收尾。现按本人等级、学习点和职业给出升级、学习或本职目录；已学主动节点同时返回真实 available 与施法ID。详情只读，不替玩家花点。
10. 正式服12:57实际出现罗盘职业菜单 `CustomModelDataComponent` 接口不兼容，与此前隔离复现一致；候选qd29包含qd28的1.21.1修复。另补充对运行期 `LinkageError` 的明确私有错误和安全查询入口，写操作同步失败也释放等待槽。故意在隔离服载入旧qd27复现，确认不再无回执或冒称已开菜单。

## 最小玩法流程

先 `/mycli status` 和 `/mycli --help`。未选职才查看 `profession list/info` 并由本人 choose；选职后的初始主动技已经可用。

- 技能：list → info ID；learn 花明示的学习点/天赋点，prepare 设置点击技，cast 才施放。已学被动自动生效。主动技仍须核对目标、魔力和冷却。
- 任务：list → info ID → accept ID；status ID 查真实缺项，达标后 claim ID。未知结果先查，重复领奖不能增加奖励。
- 组队：队长 create → invite 在线玩家，对方 accept；status/list 查本人真实成员。原生队伍是会话状态，**接受邀请不等于加入副本**。副本由每位队员按集结期 start/join；原副本的断线宽限与救援继续保持。
- 整备：公会门口共享箱用 guild shared 找位置；个人箱 arena stash，10页，成功远程开页2魔力。与随身背包和54格大背包分开；开箱不代表存取成功，核对槽位、总数和光标。
- 副本：先 list/info 看推荐等级、难度、入口与准备。穿齐四护甲，携带近战、弓弩或本人职业的真实法器。占用/故障按具体下一步处理，不在门口反复开场。

## 报错的处理

| 原因 | 处理 |
|---|---|
| class_required / class_already_selected | 查职业目录或本人职业，不自动重选 |
| level_required | 做当前等级的讨伐/探索升级；不反复学习 |
| insufficient_skill_points / insufficient_talent_points | 分别核对学习点/天赋点与前置；两者不混用 |
| already_learned | 查该节点主动或被动效果，不重复扣点 |
| cooldown / insufficient_mana | 等冷却或恢复，按回执查一次，不刷命令 |
| no_valid_target | 靠近符合技能条件的敌人后再施放；本次失败退款，不报命中 |
| skill_retired / unknown_skill / skill_node_not_castable | 分清旧技能停用、错误ID与被动节点；转本人可用目录或节点详情，不对旧ID重试 |
| operation_pending / save_conflict / service_unavailable | 结果未确认；查原操作状态，持续异常交服主处理，不重放 |
| equipment_required / site_busy / fault_paused | 按副本当前唯一下一步整备、改选或报障；不假定等待会推进 |

高级原生组队入口沿原命令保留，尚未适配格式的操作会在执行前拒绝 `--json`，不把旗标当聊天/队名。已勘察但未开业的城市设施不冒称可交易；试炼、考试与正式副本通关分别保存。

## 验收和发布边界

当前固定候选：AgentFriend `0.4.47.24-r2`、QiandengjiRpg `0.2.3-r9`、Vortex `1.2.2-alpha-qd29`，配套 QwenPaw 原生频道 `0.3.2`。摘要及实际部署前像见 [候选清单](../manifests/rpg-usability-candidate-20261028.json)，不是可执行安装计划。

| 范围 | 结果 |
|---|---|
| 语法、发现、旧命令兼容与失败规则 | 最终 JAR 454 项通过 |
| 主循环、六职业、装备准入、原地图副本、考试与存档 | 189 项联机断言通过 |
| 最终改动分支 | 38 项通过：恢复指引15、实际坦克防御15、原证书/已准备技能跨版冷读8（含重复回归） |
| r9最终包与故障注入 | 正常菜单/私有回执9项、原证书冷读8项；另在旧qd27故障注入下7项恢复检查通过 |
| QwenPaw 2.2.2 兼容 | 117 项通过，6 项既有独立联机 opt-in 跳过；最终真实 QA 的 MC_RPG 回执另验证可解析，无模型调用 |

189项核心链使用 AF `.24-r1`/桥 `.2.3-r4`，之后仅目录、目标中文和本次新指引/防御改动；38项使用 AF `.24-r2`/桥 `.2.3-r8`。r9仅再增加运行期接口不兼容的错误处理。AF r1→r2只有目录类变化，桥 r4→r5只有目标措辞，非本次所属条目按构建报告核验。不是每次重新打包都重复全量联机，不能把这些数字相加称为互不重复的测试或全部玩法覆盖。

测试计划与探针见 [RPG 可用性验收](../probe/rpg-usability/TEST.md)。非 OP Mineflayer 客户端执行真实服务器命令，用实际伤害/治疗、原生属性、经验、Vault余额、队伍成员与物品窗口验证。隔离夹具仅提供初始等级/装备/魔力和受控敌人，不能当作自主战斗平衡、真实 LLM 长期游玩或手机/Xbox真机验收。

伤害夹具在 MONITOR 读取新的事件序号、最终伤害和取消状态，不修改事件。被取消的受控攻击与旧 `lastDamageCause` 不计为生效证明；只在 QA 里有限重测攻击，不代表 Agent 可以重试消耗动作。早期测试的短标签、构建安装校验和同ID技能/节点字段断言失败均保留，最终通过报告单独冻结。隔离场景仍有旧 mask/相机缺失、Essentials版本与FAWE更新检查告警，不声称全日志干净。

测试代码与候选不会复制 QA 玩家存档到正式服。正式发布仍须当次维护授权、提前提醒、身份/副本门禁与 E/F 完整冷备后正常停启；不能全服 reload。此前 CLI 候选和失败测试证据保留，最终摘要清单单独冻结。

QwenPaw 插件目录当前受系统权限保护；本轮未提升权限、未改权限或读取私密配置。后续安装时须先按原生生命周期暂停该角色、备份实际运行频道和控制器，再更新、恢复；不可把仓库旧源码副本当作已完成的运行文件备份。服务端先发布，频道后载入。

新版发布后，给在线 Agent 一次私有短通知：`RPG交互已更新：先 /mycli status；用 skills info 查条件，按 nextCommand 处理；详情 /mycli --help。` 不把JSON、工具结果或技能目录广播公屏。不要通过反复弹通知让 Agent“记住”；以可查询的当前状态和明确拒绝为准。

## 文件与回退

服务端改动在 `VortexBridge`、`NativeParties`、`RpgFailure`、`SkillTransition`、`FortifyDefence` 及空目标窄补；AgentFriend只构建 `NativeRpg`、`AgentCliCatalog`、`AgentCliText`、`SiteDungeonManager` 四组所属类，保留577个其他条目。QwenPaw只改心跳状态解析及该精确只读命令的分类，未扩大可自动执行的写命令。新增测试见本页链接；CLI、Skill和MCP参考文档同时更新，公开下载包尚未重发。

回退需正常停启恢复三份原 JAR，保留最新世界、Vortex玩家/任务/天赋、奖励审计、证书及箱子数据；不倒回旧玩家库。QwenPaw先按原生日常角色生命周期停止，恢复届时取得的实际频道/控制器前像，再启动。E/F候选与原JAR静态副本不等于本次完整冷备；正式安装前仍须取得最新冷备和实际QwenPaw前像。不要重放以前已消费的维护脚本。
