# Numen 原生角色识别与创建者归属

**已上线（2026-10-22）：**门户镜像 `0.7.0-64b9a305`，家庭端原账号/资料同步运行目录安装同一源码模块。完整138项门户回归通过，正式原生桐人的加密观察已到云端，账号桥与外观桥均新鲜；原一个网站管理员、六条归属与141条测试归档保持。本次只刷新网站和门户出站同步，Paper仍PID23228，未再次重启。

实现读取当前正式 Numen 的 `world/data/numen_companions.dat` 中 CompanionRegistry，以及在线角色 NBT 的 `NumenOwner`。按真实角色 UUID 和创建者 UUID 建立关系，不使用显示称号、`ag_` 前缀、聊天或相似名字作为归属证明。

## 归属规则

- 创建者已经把本人游戏 UUID 绑定到网站：新 Numen 角色自动归同一个网站账号。
- 创建者尚未注册或绑定网站：记录为 `pending_creator`。创建者以后通过原游戏绑定流程证明 UUID 后，下一轮自动关联原角色。
- 角色已有其他明确的网站归属、同名不同 UUID，或同一身体的创建者发生变化：保留原归属并标记冲突，不自动转移。
- 房管名、Eye、退役角色、伪造来源、过期或冲突的重放证据不能产生绑定。小鱼仍是真人，Numen 身体单独识别为 Agent。
- 不读取或上传 Numen 的模型 Key、皮肤签名、任务 Lua 等内容；创建者 UUID 不进入公开角色卡。

## 传输与配置

沿现有账号桥的独立 `acc_` 凭据和加密密钥传输，消息标签为 `numen-identities`。原只读世界快照凭据不能写入归属。只在本机执行固定的只读名单/实体 NBT 查询，不提供公网 RCON 或任意远程命令接口。

在私有账号同步配置中追加：

```json
{
  "numen": {
    "enabled": true,
    "serverDir": "E:/MC/server",
    "rconClientModule": "E:/MC/ops/rcon-client.mjs"
  }
}
```

每三十秒采样，最多二百五十六个持久角色、六十四个在线原生身体；证据四十五秒内有效。身份信息不可用时不产生新绑定。格式错误、过期或乱序的可选 Numen 证据不会阻塞原建号、密码回执和账号桥心跳。

新增网站表 `numen_creator_relations`、`numen_observation`。旧网站版本可以忽略这些表；程序回退保留最新账号库、归属与审计，不能恢复旧库覆盖新绑定。
