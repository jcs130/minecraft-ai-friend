# 探索摄影与旅行艺术厅

状态：AgentFriend 0.4.37已于2026-10-14正式上线。艺术厅已在正式世界建成开放，并完成施工前后E/F完整冷备份及重启持久化检查。

## 玩家怎么玩

探索类 `survey_basic` 新考试要求完成原有实地走查，并为每个探索阶段拍到合格的当地照片。返程阶段不额外要求拍照。普通探索委托不因本次更新强制加照片；已在办考试使用其接题时冻结的规则。

1. `/mycli guild exam status` 查看考试；`/mycli guild status` 看当前委托阶段和目的地。
2. 到实地，面向当地地貌或遗迹，用技能罗盘的相机按钮拍摄，也可 `/mycli photo take <名字> first|third|top`。消耗沿用原相机的真实空地图。
3. 等服务器确认成图入包。`/mycli photo info <名字>` 查看是否合格与改进建议，`/mycli photo album` 看自己的纪念册。
4. 原有走查、行进时间和返程条件也必须满足；照片不能代替这些实际探索。`guild verify` 验收、`guild claim` 交付，最后 `guild exam submit` 提交考试。

照片太暗、几乎全白、只拍天空、近墙遮挡或目标不在画面中，会明确说明原因和调整方法。基本合格决定是否可用于考试；清楚且有前后景层次的作品增加「摄影·层次分明」纪念荣誉，不影响技能点或基础过关资格。这是明确的画面可辨识检查，不是主观审美模型。

## 署名、题目与故事

```text
/mycli photo title <本人照片名> <题目，最多64字>
/mycli photo story <本人照片名> <当地经历，最多400字>
/mycli photo exhibit <本人照片名>
/mycli photo gallery
/mycli photo withdraw <本人照片名>
```

作者署名来自真实拍照账号及 UUID，地点来自拍摄时服务器位置。题目和故事由作者填写，显示为普通文字，不执行命令。故事标注为作者描述，不冒充服务器验证的事件。

照片默认私有，投稿需要明确执行 `exhibit` 并填写故事。公开作品展示署名、地点、题目和故事，其他人不能改名、改署名或撤回。撤展保留作者原照片。记录过的原图不允许以原名刷新覆盖或删除；重新取景请拍一张新照片。

Java / Mineflayer / 基岩共用原生地图和菜单。玩家点击纪念册或右键墙上作品，可打开署名故事书。服务器不把作品 JSON 广播到公屏，Agent 私有数据经 `MC_PHOTO_ALBUM`、`MC_PHOTO_RECORD` / `mcagent:photo` 获取；对应 Eye 延用本人消息转发。

## 艺术厅与运营

内容 ID：`art_hall` / 千灯旅行艺术厅。

- 正式地点：主世界村庄西南河畔，建筑范围 `(-634,64,-388)` 至 `(-617,79,-370)`；入口朝东，外侧落脚点 `(-616.5,67,-378.5)`，原木门 `(-619,68,-379)`。
- 蓝图：服务器已安装 Better Villages 3.3.1 的 `minecraft:village/plains/houses/plains_library_1`，保留两层、楼梯、门窗和照明。尺寸 18×14×19，移除模板实体、方块实体数据、蜘蛛网和骷髅装饰，熄灭装饰营火。第三方蓝图不提交源码仓库。
- 原生展位：一层四个单地图展位，二层一个 2×2 海报展位。无空位时作品仍可从展览菜单阅读，不消耗或吞掉原图。
- 馆内归 Goddess 管理，访客可开门、参观、阅读展品，不能拆建筑或取走展品。保护仅限建筑范围。
- 正式施工前重新确认目标范围仅有自然地表与少量树木；与外部原道路分开，只在实际施工范围铺入口台阶与石砖地面。原住宅、领地、箱子和农田保持。原始施工前像与逐步操作记录留存在E/F维护目录。

展位是可配置的现有原生展示框，无须为另一个艺术厅改代码：

```text
mycli admin photo gallery-slot <稳定展位ID> <空展示框UUID>
mycli admin photo gallery-slot <稳定展位ID> <左上UUID,右上UUID,左下UUID,右下UUID>
mycli admin photo gallery-status
```

只允许控制台登记已加载的空框；不能挪走现有物品、重复占框或覆盖已登记展位。每人最多保留64份原图记录，最多64个展位。账本在 `plugins/AgentFriend/photo-journal.json`，采用原子写入，与 ImageFrame 原图及世界实体一起备份。区块重新加载时只修复该展位，不强行加载远处区块。
