## 问题与修复范围

小鱼点击原生肥鱼后收到 `not_owned / No NPC bound to this connection`。0.1.10-harness 的右键处理器向所有玩家显示“交谈”，生成的 `/qdmaid chat` 却先调用 `ownedLoaded`；小鱼不是可米，因此在模型请求之前被拒绝。隔离服用主人和非主人两个连接重现了同样的按钮和错误，供应商调用数为零。截图里的另一条 PvP 提示不是这次对话拒绝的原因。

0.1.11-social 把“交谈”与“主人管理”分开：

- 主人仍使用原 TLM 对话、历史、工具及原有 16 格范围。
- 同维度、8 格内的普通在场玩家可以和已开放的女仆交谈。仍只允许原肥鱼使用共享模型，其他女仆不会因此获得服务器 LLM 或 TTS。
- 访客使用原女仆当前选择的原生、DSH 或 Codex 客户端；不注册玩家、不生成替身、不另起自主模型循环。
- 访客请求没有工作工具，也不携带主人私聊、摘要或背包上下文。即使供应商擅自返回工具调用，也在回调处拒绝，不能改跟随、装备或工作。
- 访客短期上下文按真实访客 UUID 分开，最多 4 轮、64 组；重启清空此短期缓存。原主人 TLM 历史保持。操作回执持久保存，重启不自动重发不确定对话。
- 访客话语及回复带 `[附近·女仆]` 标记；仅在同维度 8 格范围内传递，回复时重新检查在场、距离及可见性。跨维度或已离开的访客不会收到迟到回答。不是自动监听全部公屏。
- 每只女仆同时处理一轮交流，访客至少间隔 5 秒；进行中更换运行方式会明确提示等待。失败、超距、未启用及重复请求都有真实回执。

另外补齐了 `NativeMaidTransport` 缺失的 `brain` 动作白名单：原来命令路径可用，但插件消息路径静默丢弃，导致客户端等到超时。

## 真人和 Agent 的入口

真人右键女仆，点击“与她交谈”，输入想说的话并回车即可。自动填入的是 `/qdmaid say <maidId> `，不要求真人手写请求编号。进度、回答和错误用简短中文展示；“查询这次对话”按钮读取原回执，不重新发送。机器接口仍保留原 JSON，不破坏现有 Agent。

Agent：

1. `/qdmaid nearby [queryId]` 查询附近可见女仆的真实 `maidId`、名字及是否开放交流；该目录不暴露主人记忆。
2. `/qdmaid chat <maidId> <requestId> <1–140字话语>`。`pending` 只代表已受理。
3. `/qdmaid receipt <maidId> <原requestId> [queryId]` 查询同一请求。`replied` 才是有效答复，`unknown` 不重放。

配套可选 MCP 支持 `mc_maids {action:"nearby"}`。原客户端未升级时，可继续通过已认证的普通命令发送能力访问上述入口；不能声称远端宿主已经自动升级。

装备、原生菜单、工作、脑选择、私有收件箱等仍只供主人使用。聊天公开不等于授权别人搬走物品或接管女仆。`talk` 仍保留旧宿主留言箱语义，不冒充原生模型对话。

## 适合作为 NPC 的边界

原生女仆是实体，不需要占一个 Minecraft 玩家连接；原模组已有工作、跟随、战斗、模型和对话扩展。此修复提供附近访客交流基础，不把它宣称为已建成整套任务 NPC。

当前没有自动监听 ASR／所有附近聊天，没有周期自主社交或为其他女仆开共享服务，也没有接通统一 TTS 音色。公开 NPC 人设、任务权限和长期公共记忆需要按具体 NPC 配置，不能复用私人主仆记忆。

原模组扩展依据：[官方 AI 架构](https://tlmwiki.cfpa.team/wiki/dev/ai/overview/)、[官方工具回调](https://tlmwiki.cfpa.team/wiki/dev/ai/tool/)。此次复用原生 `LLMCallback` 与所选站点；访客不调用原生私有 `chatManager.chat`。
