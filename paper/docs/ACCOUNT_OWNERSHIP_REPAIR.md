# 网站已有角色认领修复

生产发布基线：网站 0.8.3 / f44f12ef。此候选为 0.8.4，不含旧 0.9.0 多世界或其他对话未发布的 3D 改动。

## 修复内容

- 游戏 OP 是游戏能力，不自动成为网站的保留房管身份。普通 OP 玩家仍需原角色通过 LoginGuard 的本人认证和一次性绑定回执；房管保留名、其 ag_ 变体和 Eye 不开放认领。
- 旧云端资料中的 OP 分类在网站读取时兼容转换，保留原 UUID 和权限。家庭采集器同步采用新分类后可正常采集普通 OP 的保存资料。
- 服主可在私有运维程序中按已核实的原 UUID 审核旧角色归属。该程序没有 HTTP 路由；必须核对网站账号 ID 和名称、明确的审核依据，已归属他人或归档测试角色拒绝处理，整组事务原子提交、幂等并记审计。
- 同名旧身体分别保留 UUID，出现在本人私有档案并标记“历史身体（只读）”，不出现在公共角色墙，不生成登录配置，也不能按名字改密或换装。没有同步资料时明确显示不可用。
- Numen 原生身体/创建者 UUID 已证明的关系，不因另一身体复用名字而丢失；不覆盖原登录别名、不转移已归属其他用户的身体。
- 审核迁入的旧角色和 Numen 原生身体不占新建网站 Agent 的名额；正常自助角色和未确认的新建请求仍受原上限约束。

## 验证

196 项完整 API/DOM 测试、64 个模块语法检查通过；新增覆盖普通 OP 原认证后认领、房管/Eye 拒绝、审核幂等/冲突/整组拒绝、同名 UUID 分开和私有访问、历史身体禁止改密/换装/生成登录配置、名额以及同名 Numen 原生继承。

## 发布和回退

只正常替换云端网站容器。部署前后对网站 SQLite 做一致性备份，原账号密码、归属和内容行逐项核验；审核归属另在同一新版本上执行，只添加已核验的记录。家庭采集器只回补 game-data.mjs 的分类修复，不更换账号桥或游戏服务。

旧网站容器、私有配置和原采集模块均保留。回退网站代码时保留最新数据库，不用旧库覆盖用户的新注册、照片或归属。若必须撤销本轮归属，仅凭保存的审核清单和审计 ID 撤销本轮新添行；不能批量删除同名角色或玩家数据。Paper、登录代理和 FOM 无需重启。

具体账号和原 UUID 证据、迁入清单及发布结果只存私有 E/F 运维材料，不进入仓库。

## 同名历史档案展示候选 0.8.7（2026-10-23）

官网将当前角色与历史 UUID 资料同级平铺，导致多份旧同名身体看起来像重复在线角色。实查部署中的 Numen `Companions.summon` 会先查同一主人同名记录，召回复用 UUID；官方 Release 兼容入口也走此路径。当前原生名册只有一份 Fishy；旧缓存和已审核档案不代表同时存在的身体，也不能据此断言每次召唤都新建。永久遣散后再新建则可以产生新 UUID。

本候选只改角色墙和背包页展示：当前角色正常展示，历史资料进入默认折叠的“历史角色档案”，展开后可查看原 UUID 和保存背包。查询、筛选和刷新保持；历史资料仍受原私有访问与禁止改密/换装约束。不能按同名删除或合并，尤其要保留同名真人账号。数据库、归属、游戏文件与 Numen 均不改。

213 项门户测试通过，其中新增两个 DOM 用例覆盖同名真人、多个历史 UUID、搜索/刷新保留展开状态、仅有历史资料和按原 UUID 查看背包。隔离浏览器实际验证桌面与 390px 手机布局。正式官网仍为 0.8.6；重启发布前继续按服主当次确认执行，回退仅换网站代码并保留最新 SQLite。
