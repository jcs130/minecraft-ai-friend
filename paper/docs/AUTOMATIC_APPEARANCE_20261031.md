# 初始 YSM 自动分配

状态：**AgentAppearance 0.3.5 候选，未部署**。正式模型桥仍为 0.3.4 / Freesia af5 / YSM 2.4.1。新功能只在现有模型代理中分配初始外观，未更换游戏内核、登录鉴权或玩家身体。

## 玩家体验

当前连接已进入实际世界、原生模型状态确认为 `default`，且同一连接稳定五秒后，才尝试分配。优先选择没有其他 UUID 使用的模型；全部已用时选使用人数较少的，并私下说明。统计包含持久记录中的离线角色和当前原生状态，不能只按在线人数轮流抽签。

按 UUID 保存一次选择。重连和代理重启不会重新抽取；已有非默认外观、本人手动选装和明确选回默认模型均保留。不会为了消除历史重复而强制更换旧外观。玩家个人上传模型不进入公共初始池。观战身份按已确认的 UUID 排除，不按名字或 `ag_` 前缀推断。

live 是观战者，不参加玩家模型抽签；其旁观状态与专用无人机外观属于单独的观战配置，不能随机分到人形模型。DeepFish 的专属外观也不参加随机池。原作者《大肥鱼 1.1》加密包与重建的 `qd_dafeiyu` 兼容版是不同资源；当前 2.4.1 曾拒绝原包格式 32，本候选不宣称完成原包升级。

沿用原有入口，不新增一级命令：

```text
/appearance status
/appearance list
/appearance set <模型> [贴图]
```

`MC_APPEARANCE_STATUS` 继续表示实际原生状态；另一个私有回执 `MC_APPEARANCE_ASSIGNMENT` 表示初始分配策略。`issued` 是已持久预留、`unknown` 是结果未确认，均不是成功；只有实际模型及贴图匹配才记为 `applied`。未知结果先查询，不自动重放。原 `mcagent:appearance` 和资源协议不增加字段。

## 管理配置

在现有私有 `plugins/agentappearance/models.json` 中合并以下字段，保留 `publicModelRoot`、基岩状态文件等原设置。未配置或 `enabled=false` 时不自动分配。

```json
{
  "automaticAssignment": {
    "enabled": true,
    "models": [
      {"model": "qd_frieren", "texture": "texture"},
      {"model": "qd_lappland", "texture": "texture"},
      {"model": "qd_mega_knight", "texture": "default"}
    ],
    "excludedUuids": []
  }
}
```

模型池最多 64 个不同模型，只能使用当前原生及网页目录已验证的模型和贴图。正式候选选用十个已有公共预设，排除默认模型和私人形象。配置每五秒重新读取，不执行游戏服务器 `/reload`。

可选 `observerRegistryFile` 指向现有私有身份名册的绝对路径。只读取 `schema=1`、`accounts` 中 `kind=observer` 且 `source=owner_confirmation` 的 UUID，用于排除外观分配；不从该文件授予 OP、认证或维护权限。文件缺失、损坏、超限或符号链接时停止新分配。

同目录 `automatic-appearances.json` 为私有状态，结构是 `schemaVersion=1` 和按 UUID 索引的 `players`。首次启用应从实际 Freesia 保存记录采集已有非默认选择，并用新鲜在线确认状态补齐；默认状态不能当作历史人工选择种入。只读采集结果是候选前像，上线前仍须重新采集，不能覆盖玩家之后的换装。不要提交 UUID 账本、原生 NBT、模型原包或私有身份名册。

每三秒最多派发一次；没有唯一 Worker、当前 PLAY 代次不符、原生状态未知或无兼容候选时不改外观。原有三十秒选装冷却和重复抑制继续生效。预留以临时文件、刷盘和原子替换落盘；状态损坏或写入失败时停止自动派发，不覆盖损坏记录。最多保存 4096 个 UUID、状态文件不超过 1 MiB。

## 验证

最终独立桥构建包含原 8 项身体兼容、28 项本人选装和新增 37 项自动分配断言，共 73 项通过。只修改外观桥、共享选装预留及插件元数据；模型目录转换、基岩投影和原身体兼容类的 JAR 条目逐字节保持。

独立 Paper 1.21.1、原生 YSM 2.4.1 与 Freesia af5 的初次联机 6 项、正常冷启后 7 项检查通过：四个真实 Mineflayer 身体获得四种不同原生模型，原始网页／相机资源可用，结果匹配后才成功；池满选最少使用项，手动选装保留；重启保持 UUID／外观且不重发；新鲜观战身份及共享 UUID 名册均正确排除。测试服务均正常退出。

首次夹具误填了观战 UUID，负面回执保留；改用正确 UUID 的全新观战夹具后验证通过，未修改正式服身份或既有外观凑结果。网络夹具见 [automatic-appearance-stage.mjs](../probe/automatic-appearance-stage.mjs)。这些测试不是实际 Fabric 界面像素、基岩设备或所有 Numen 身体类型的验收。当前自动派发仍使用既有 Java 角色名限制，未扩展点号前缀的基岩名字映射。

## 上线与回退

E/F 两盘已核对 0.3.5 候选、0.3.4 配置/JAR 前像及私有初始记录；这些是静态前像，不是停服冷备。当前未写正式配置、未替换 JAR、未重启服务。

正式安装需要本次模型代理维护确认、真人及活动门禁、180/60/10 秒提醒和最新完整 E/F 模型链冷备。只正常停启现有模型代理与 Worker；玩家和 Agent 会短暂重连，Paper 和官网不用重启。安装前核对当前 JAR／配置摘要，重新读取已有外观及观战 UUID；不把它附加进已经冻结的相册维护脚本，不重放旧维护。

回退恢复旧桥 JAR 及原配置，保留最新原生模型存档和新分配记录。不能通过恢复旧玩家 NBT 撤销新外观、背包或游戏进度。禁用自动分配也不撤销已选择的模型。
