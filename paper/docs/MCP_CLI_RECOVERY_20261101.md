# MCP宿主如何使用命令纠正

2026-11-03 多参数纠错已随 AF0.4.47.49-rpg 正式上线，补齐 `cast dungeon info/claim/start <ID>` 和 `cast dungeon_claim <ID>`。`cast` 只用于真实技能，不能拿它承载所有 `/mycli` 子命令；例如副本查询应通过原聊天/命令发送路径执行 `/mycli dungeon info <ID>`。服务端返回 `COMMAND_ROUTE_MISMATCH` 和现役目录的准确下一步，不替玩家执行。发布进度见 [NPC/CLI 本轮记录](NPC_CLI_LIFECYCLE_20261103.md)。

等待器必须把同一请求的明确拒绝也作为一次调用的终态，不能只认成功前缀而把已收到的 `MC_CLI_ERROR` 等待成超时。默认短文本同样可以表达失败；没有 `--json` 不保证收到机器前缀。保留原请求关联，迟到的前一次消息不能完成新请求。客户端工具如何消费错误需在实际宿主验证，服务器联机测试不能代替这一项。

服务端AF.47/桥0.2.17仍为候选。MCP工具不增加，沿用同一身体的chat步骤及当前服务器命令目录。

先读服务器返回的原因、正确用法、条件和 `nextCommand`；相近命令只作建议，由模型核对目标后重新调用。`cast travel <遗迹ID>` 不是统一传送入口，地点、队友和短距离闪现分别按现役帮助执行。

默认消费精炼文本，程序确需字段才加 `--json`。`autoExecute=false/changed=false` 表示本次没有动作；建议的下一条命令仍可能耗魔、有冷却或要求已学会技能。`rankingScore` 只是检索排序分数，不能作为成功率。未知、离线或多个目标先查列表。时间、目录版本变化或结果未知时重新查询，不自动重放消耗动作。

`MC_CLI_ERROR` 是既有私有错误前缀；错误路由原有 `MC_RPG` / `MC_SITE_DUNGEON_RESULT` 保留，添加有界 `suggestions`、`catalogRevision` 和下一步。Vortex未知技能分支另外给出当前目录建议，旧宿主仍可读取普通聊天。查询不替换宿主模型、人设或记忆，也不建立另一套Agent循环。

当前不可变Skill1.3.7及其冻结输入保持原字节，新说明不混入同版本的重建包。错误纠正由服务器实时交付，现有Skill仍可使用；以后显式发布新的Skill版本时再更新它的对应参考输入。完整服务端范围见[CLI纠正](CLI_RECOVERY_20261101.md)。
