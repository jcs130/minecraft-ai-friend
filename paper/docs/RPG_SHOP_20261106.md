# 金币商城与装备回收

状态：2026-11-06 修复候选，尚未安装到正式游戏服。下列新入口需随本批 AgentFriend 发布；原 `arena shop` / `arena recycle` 仍可用。没有迁移或重置余额、玩家物品、职业及结算收据。

## 核查结果与设计

正式服已经装有 VortexRPG、Vault、Essentials、Shopkeepers，并非没有商城。核查时保留的统一结算收据共有120份，全部完成、没有待对账索引；其中33份为3个账号的装备回收，未见商城购买收据。不能据此推断所有历史使用情况。旧购买菜单藏在试炼入口/驿站/公会接待员，商品用英文ID显示；Agent列表逐项发送完整物品组件，且没有把回收后的金币用途连起来。

本次继续使用 Vortex 接入的同一 Vault 银行与既有结算日志。新增的是入口、显示、补给货架和菜单确认，不增加第二种货币，不开放任意物品凭空定价，也不恢复已知交付有问题的拍卖行。

## 真人操作

右键技能罗盘 → **金币商城·装备回收**。菜单是原版45格容器，不要求额外客户端模组：

- 买东西：点击中文商品 → 加减份数 → 查看总价 → 绿色确认。取消不会扣钱；同一确认窗口重复点击不能重复购买。
- 卖装备：点底部漏斗 → 选择背包或个人箱里的装备 → 查看价格 → 绿色确认。手持、穿戴、绑定、职业法器和不在白名单的自定义物品保持保护；不提供自动卖空背包。
- 取货/存物：点底部箱子。购买物先保存至个人箱待入箱队列，开箱时移入；背包满不掉落，箱满继续排队。远程成功开箱仍按原规则消耗2魔力，购买本身不耗魔力。
- 余额、村民以物易物和关闭在同一底栏。以物易物仍需去商人身边，实体绿宝石不会当金币扣款。

旧公会接待员、试炼商人也打开同一个新菜单。背包满/拾取不全的私有提示保留60秒节流，给出实际可存材料的槽位命令，以及可点击的个人箱和回收菜单。

## Agent 用法

只需记两个分支，完整操作以当前服务器帮助为准：

```text
/mycli trade shop list
/mycli trade recycle list
```

商城每行给准确ID、每份数量、金币价格和可复制购买命令。例如 `trade shop buy torches 1` 是购买一份32支火把，不是买一支。装备一次1件，可堆叠物品每次最多一组。回收列表给来源、真实槽位、耐久和附魔；按返回的 `trade recycle quote bag <槽> 1` 报价，再按报价里的 `trade recycle sell <报价ID>` 确认。报价30秒有效，查询和报价本身不卖物。默认短文本，程序按需加 `--json`；旧 `arena` JSON调用保持兼容。

买后看实际回执，再用 `arena stash page 1` 取货；卖后可 `trade shop list` 选补给。`trade wallet` 查同一金币。`trade buy/sell/find` 仍是原村民报价查询，不要混同商城结算。超时或 `money_pending/recycle_pending/*_unverified` 先 `trade recycle status`；未知结果不重买、不重卖、不补发。

## 现成方案核对

- [EconomyShopGUI 官方文档](https://wiki.gpplugins.com/economyshopgui)提供分类货架、买卖菜单、交易日志和基岩表单；[官方项目说明](https://dev.curseforge.com/projects/economyshopgui)明确不支持模组/混合服务端。我们实际是 Youer，不因原先叫 Paper 就宣称得到官方兼容保证。
- [DeluxeMenus 官方文档](https://wiki.helpch.at/helpchat-plugins/deluxemenus)适合配置菜单入口；其金额条件与命令动作不能自动替代本服的物品组件核对、待对账和防重复结算。
- 已装的 [Shopkeepers](https://github.com/Shopkeepers/Shopkeepers-Wiki/wiki/Player-Shop-Setup)主要使用物品作为货币；不能把实体绿宝石商人当成已连接本服金币商城。

本轮采用这些成熟菜单的浏览→数量→确认流程，复用现有原版容器和结算系统；没有额外安装一个未经混合内核验收的经济插件。后续若扩展大规模分类商城，须单独验证上述插件与自定义装备、金币日志的衔接。

## 验收与发布边界

`paper/plugins/AgentFriend/tests/org/afuhome/agentfriend/EconomyPresentationTest.java` 覆盖短文本、未知金额、待对账与正确下一步；`paper/probe/rpg-usability/shop.mjs` 只允许有双重标记的127.0.0.1:25928/25929隔离服和新QA账号，测试真实容器、Vault金币、物品、取消、重复/跨号报价、物品变化、满包、银行失败和正常重启。测试不修改正式玩家背包或制造正式服崩溃。

实测结果：五组 CLI/回执检查合计409项通过；最终同一候选在独立 Youer 上31项操作检查、正常重启后3项保存检查通过。前者包括重复原版确认数据包只扣一次、跨账号/重复报价不能兑付、菜单打开后装备被换掉时拒绝、满包购买实际入箱，以及注入银行失败后不虚报成功、不允许重放。旧正式 JAR 在三个 RPG 插件正常启用的同一夹具中，未通过新商城入口断言；早期缺少混合内核原生兼容桥、未等服务启动和错误读取窗口槽位的夹具失败另存，不能算产品回归通过。

复现使用新建世界和 QA 账号，加载现役 Youer、Vault/Essentials、Vortex 1.2.2-alpha-qd29、QiandengjiRpg 0.2.20 及其依赖，并保留现役原生通道兼容组件（NativePlatform、女仆桥、TLM、YSM）；不得拷入正式账号、金币日志或世界。测试控制插件使用 `paper/probe/rpg-usability` 内当前源码构建，仅绑定本机。配置完成并等服务就绪后，分别运行 `shop.mjs baseline <新标签>`、`shop.mjs candidate <另一新标签>`；正常停止并重新启动同一候选后运行 `shop.mjs cold <候选标签>`。每个标签只跑一次购买流程；冷验只读余额和已购买物品，不重播交易。

候选及基线摘要见 [候选清单](../manifests/rpg-shop-candidate-20261106.json)。Skill 的两份参考文档已注明新入口以服务器帮助实际出现为准；本轮未替换官网下载包或自动更新远端客户端。

候选构建器固定正式JAR摘要，只更新商城、提示和四处罗盘/补全方法，核验其余条目保持。正式发布仍需本批重启确认、维护预告、安全窗口和E/F最新备份；回退只换代码，不回滚已开始游玩的金币/箱子/交易记录。真实手机触控、真人原生客户端画面和观战同框不能用协议检查代替。
