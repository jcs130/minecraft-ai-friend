# 金币商城、装备回收与玩家交易行

状态：2026-11-06 修复候选，尚未安装到正式游戏服。下列新入口需随本批 AgentFriend 发布；原 `arena shop` / `arena recycle` 仍可用。没有迁移或重置余额、玩家物品、职业及结算收据。

## 核查结果与设计

正式服已经装有 VortexRPG、Vault、Essentials、Shopkeepers，并非没有商城。核查时保留的统一结算收据共有120份，全部完成、没有待对账索引；其中33份为3个账号的装备回收，未见商城购买收据。不能据此推断所有历史使用情况。旧购买菜单藏在试炼入口/驿站/公会接待员，商品用英文ID显示；Agent列表逐项发送完整物品组件，且没有把回收后的金币用途连起来。

本次继续使用 Vortex 接入的同一 Vault 银行与既有结算日志。商城继续使用既有价格与回收规则。玩家交易行复用同一银行收据、完整物品序列化、个人箱待入箱队列及共享可靠存档；原生 Vortex 拍卖缺少交货的旧执行器继续关闭，不直接解锁。

## 真人操作

右键技能罗盘 → **金币商城·回收·玩家交易行**。菜单是原版45格容器，不要求额外客户端模组：

- 买东西：点击中文商品 → 加减份数 → 查看总价 → 绿色确认。取消不会扣钱；同一确认窗口重复点击不能重复购买。
- 卖装备：点底部漏斗 → 选择背包或个人箱里的装备 → 查看价格 → 绿色确认。手持、穿戴、绑定、职业法器和不在白名单的自定义物品保持保护；不提供自动卖空背包。
- 取货/存物：点底部箱子。购买物先保存至个人箱待入箱队列，开箱时移入；背包满不掉落，箱满继续排队。远程成功开箱仍按原规则消耗2魔力，购买本身不耗魔力。
- 余额、村民以物易物和关闭在同一底栏。以物易物仍需去商人身边，实体绿宝石不会当金币扣款。

旧公会接待员、试炼商人也打开同一个新菜单。背包满/拾取不全的私有提示保留60秒节流，给出实际可存材料的槽位命令，以及可点击的个人箱和回收菜单。

## Agent 用法

按需查询这三个分支，完整操作以当前服务器帮助为准：

```text
/mycli trade shop list
/mycli trade recycle list
/mycli trade auction list
```

商城每行给准确ID、每份数量、金币价格和可复制购买命令。例如 `trade shop buy torches 1` 是购买一份32支火把，不是买一支。装备一次1件，可堆叠物品每次最多一组。回收列表给来源、真实槽位、耐久和附魔；按返回的 `trade recycle quote bag <槽> 1` 报价，再按报价里的 `trade recycle sell <报价ID>` 确认。报价30秒有效，查询和报价本身不卖物。默认短文本，程序按需加 `--json`；旧 `arena` JSON调用保持兼容。

买后看实际回执，再用 `arena stash page 1` 取货；卖后可 `trade shop list` 选补给。`trade wallet` 查同一金币。`trade buy/sell/find` 仍是原村民报价查询，不要混同商城结算。超时或 `money_pending/recycle_pending/*_unverified` 先 `trade recycle status`；未知结果不重买、不重卖、不补发。

## 玩家交易行

真人从商城底部的矿车箱进入，也可 `/ah`。菜单可浏览商品原附魔/耐久、用按钮设置总价、确认上架/购买、查看本人挂单、下架和领取离线收益。无需客户端模组；原版容器可由已有观战镜像转发（本批仍需真人/基岩及 Eye 的实际显示验收）。

Agent 使用现有 `trade auction` 分支：

- `list [页码]`：每页8项，复制商品 ID；`info <ID>` 查数量、总价、附魔和耐久；`buy <ID>` 明确购买整组。
- `sell <总价>`：为当前主手整组生成30秒确认，尚未移走；核对后执行返回的 `confirm <确认ID>`。总价为1–100000整数金币，不是单件价格。
- `mine [页码]`：自己的挂单/待领收益；`cancel <ID>` 下架未成交商品，原物品返还个人箱；`collect [ID]` 领取离线收益，每次最多10笔。

目前每人最多10笔未结束挂单、全服200笔，商品挂至成交或主动下架，无税。完整名称、附魔、耐久保留。Vortex 装备是否绑定由正在运行的原生物品服务判定；未知自定义标签、系统道具和绑定物品拒绝上架，不凭显示名称猜测。箱满会保留待入箱货物；队列达到1024项时拒绝新购买/下架，不直接掉落。已成交不能撤销，重复购买/领取/退回不会重复发放。

在线卖家正常状态下成交即入账；离线或暂不能结算时收益保留，上线后提示领取。使用同一金币，不引入交易行专用余额。旧 `/auction`、`/ah` 的玩家入口转到安全菜单，旧有参数不猜测执行；原生后台执行器仍受 AuctionSafety 阻止。

## 交易一致性与运维

上架：`PREPARED`（完整原物品、槽位、随机保存证明已落盘）→ 移走精确原物品 → 保存玩家数据并从实际 NBT 核验保存证明 → `OPEN`。保存不确定时锁定该账号物品移动及命令。重新连接时，仅在玩家数据证明移除已保存且原商品未回到原槽（自动补发的大背包/罗盘不会被移走）时转 `OPEN`；原物品仍完整在原槽则 `ABORTED`；其余保留证据交服主核对，不直接补发。

购买：主线程抢占 `OPEN→RESERVED` → 原生金币日志按商品 ID 扣款 → 同一次可靠配置提交写入完整个人箱货物和 `DELIVERED` → 银行收据确认后 `SOLD`。重复请求复用固定收据 ID；结果不确定不释放商品给第二买家，也不猜测退款。卖家收益 `SOLD→PAYING→PAID` 使用另一条固定收据，离线时保留待领权利。

下架：一次可靠配置提交同时增加个人箱待入箱货物并标记 `CANCELLED`。所有这些配置操作经过已有 `DurableConfigStore`，共享修订号和持久化恢复记录，不能绕过它只写 `config.yml`。历史记录达到10000笔时停止新增，需完整备份后归档；不自动删除未完成记录。

异常处理：同时保留 AgentFriend 的配置/`.state-pending`、Vortex 的 `recycle-receipts`、相关合成或真实账号的玩家数据。先检查准确商品 ID、银行收据和保存证明，再决定后续，不删除 pending 索引，不手动把 `RESERVED/PAYING` 改回 `OPEN`，不自动重付/退款。既有原生 Vortex 拍卖文件不迁移、不删除；如发现历史异常单，单独核账。

本批只在新建隔离世界和合成账号测试，不使用真实玩家物品或余额；正式服仍是旧版本，发布需按维护约定确认并正常重启。


交易行方案复核参考：[Vortex AuctionService](https://github.com/Sauron05/vortexrpg/blob/main/src/main/java/io/vortexcore/auction/AuctionService.java)、[Fadah 源码与 API](https://github.com/Finally-A-Decent/Fadah)、[AxAuctions API](https://docs.artillex-studios.com/axauctions-developer-api.html)。Vortex 当前购买路径未完成物品交付；Fadah 的收集箱写入异常/扣款补偿路径也需另做事务改造，AxAuctions 的公开接口不足以直接支持当前精确 CLI 交易。结合已安装的银行、物品托管与个人箱，本批选择补齐服务器接入层，不并装第二套未经混合内核验证的经济插件。上述源码判断不是对所有发行版的运行保证。


## 交易行最终验证记录

最终候选本地500项断言（471项CLI/引导，29项存档组件）通过。独立 Youer 场景：商城/回收37项、玩家交易25项、故障边界7项，最终包正常重启后另10项通过。交易检查包括两位买家争抢唯一商品、重复确认/购买/领取/取消、原名称附魔耐久交货、真人原版菜单上架、卖家离线、满背包、银行失败保持预留和禁止重付。故障边界使用真实 Windows 玩家文件读取锁造成保存失败，验证转移保护及重连恢复；另外构造落盘前/落盘后的 PREPARED 边界。没有在正式服制造异常，没有宣称进行了整机断电测试。

先失败后修正：旧服没有玩家挂单入口；随机词缀装备被过度保护；自动补发大背包/罗盘占槽导致恢复误锁，三项均有隔离记录。测试夹具曾把新版组件附魔当旧数组、把补发的新道具当原商品未移走，已按完整组件相等和原商品存在性订正，原失败报告保留。最终构建比商城实测包仅扩展交易行；相邻最终包经逐条JAR比对，商城/经济类保持、交易行最后只增加退出清理，末版仅调整帮助排序并重新执行500项断言及重启检查。实测入口为 `market.mjs baseline/candidate/boundaries/cold <标签>` 与 `shop.mjs candidate/cold <标签>`，必须使用标记隔离服；不得复用真实账号或重跑已消费的购买标签。
