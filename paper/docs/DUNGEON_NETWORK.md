## 试炼塔

**0.3.96 已上线规则：普通档恢复增强前的原配怪和武器。**第一层三僵尸，第二层两尸壳两蜘蛛，第六层原七怪（含原有一女巫）；生命 1.15、伤害 1.10 和深层递进保持原值。

**冒险、末日**前六层使用 `plugins/AgentFriend/trial-waves.yml`。第一层两女巫、两骷髅、两僵尸；后续有掠夺者、流浪者、烈焰人、凋灵骷髅、持斧精英，第六层有劫掠兽。配置生命值再乘既有难度系数。第七层仍休息，八至十五层沿用原主题；奖励与传送成本保持原语义。

增强波次每层最多十二只，当前前六层六至八只。白名单拒绝凋灵、监守者、唤魔者和恼鬼。活动波次保存具体快照；普通旧场次在0.3.96恢复时迁回原配怪，冒险/末日继续原快照。

## 组队倒地救援（0.3.96）

至少两名参赛队员时，致命伤害先倒地留场。存活队友靠近 **4格并连续停留10秒** 自动救起，或**清完当前层/室自动复活**；全队倒下才失败撤回入口。倒地不能移动、攻击、施法、操作物品或退出；保持聊天求援。单人仍走原版死亡。背包、既有奖励和场次身份保留，掉线/重启续接。

系统聊天告知Agent坐标和救援方法，`arena status` / `dungeon status` 返回 `MC_TRIAL_RESCUE_STATE`，原客户端无需修改。细则、提示词、隔离测试与回退见[组队救援](TRIAL_RESCUE.md)。

| ID | 地下城 | 首室脚下位置 | 房间 | 主题 |

## 怎么参加

技能罗盘「传送地点→遗迹地下城」，或以下私有命令：

```text
/mycli dungeon list
/mycli dungeon info undead_crypt
/mycli dungeon travel undead_crypt
/mycli dungeon start undead_crypt normal
/mycli dungeon join undead_crypt
/mycli dungeon status
/mycli dungeon claim undead_crypt
/mycli dungeon leave
/mycli dungeon menu
```

`travel` 需要学习基础传送、消耗八魔力。亡灵墓穴没有自然地面入口，传到已勘察的墓穴前厅；另外两处沿用地面外围传送，沿原建筑楼梯或梯井走到首室，再主动 `start`。不同地点可同时开队，每处同时一队，每队最多八人，发起后十秒内在首室主动 `join`。普通、冒险、末日分别用 `normal/adventure/apocalypse`。

依序进入各战斗室并清理本轮带名牌的敌人，最后返回首室登记凭据，再 `claim` 进入既有个人奖励箱。每室清场时本人必须在场；旁观、只到坐标或中途加入不能拿完整奖励。同一地点按上海日期每人每日奖励一次，各难度共用次数；重复挑战可以练习。退出留在原地，续接和进入下一室没有免费传送。

队伍全部离线或离开建筑时暂停，五分钟内步行返回续打。正常重启后已清理的房间保留，未清理的房间重新开始一波。正常挑战最多三十分钟，结束后地点冷却两分钟；故障暂停保留至处理或退出，不能放任不管。标记怪丢失、卸载或未知消失不能当击杀通关。未结算房间不发奖励，已登记凭据即使退出仍可领取。

满奖励队列会返回 `personal_reward_queue_full` 并保留凭据；磁盘写入失败返回 `data_unavailable` 并回退本次奖励变更。房间没有安全出怪位置或保存失败时明确暂停，不连续重刷；解决原因后队员 `dungeon resume`，或 `leave` 退出。`status` 的 `fault` 给出原因。

## 多队性能与保护

新地点挑战全服最多四十八只受管怪物、一百二十八个受管飞行物，飞行物最长十五秒，房间结束清理。只为当前波次所在区块持有插件票据。自然刷怪和原生刷怪笼仅在该处活动期间抑制；其他既有自然实体不清除。挑战期间禁止在挑战区拆建，怪物不攻击外人，药水对外人和其他生物无效；战斗怪不掉额外装备或经验。清理仅按本插件专用标签，原建筑战利品与玩家财产保留。

四十八是这三类遗迹的合计上限；旧试炼塔独立按每层十二只约束。不得据受控协议测试宣称十六个 LLM 已长期自主通关或性能全无尖峰。

## 运营配置与热更新

配怪和房间在两个 YAML 文件中配置，修改后控制台执行：

```text
mycli admin trialwaves audit
mycli admin trialwaves reload
mycli admin dungeons audit
mycli admin dungeons reload
```

有效热更新无需重启；无效配置保留上一有效定义。试炼塔活动时拒绝更换塔配怪，有任何遗迹挑战或待处理检查点时拒绝替换遗迹目录。`mycli admin dungeonaudit` 的第一行 `active=true` 同时包含新地点，原维护门禁会等待挑战结束。

`trial-waves.yml`：`schema-version: 1`，楼层键 1–15，第七层不能配置怪物；`mobs` 可用类型名或 `{type, count, health, name}`。单波最多十二只，生命值 10–500，数量 1–12；省略生命值则用原版基础值。

`dungeons.yml`：最多十六处、每处一至六室；`world/name/expedition/icon/hint/reward/rooms`。`expedition` 可引用现有六个勘察远征入口；也可配置 `entry: [x,y,z]` 指定当前建筑内已勘察的付费入口，支持后续建筑无需改代码。入口区块必须已生成，仅异步加载现有区块，落点安全且没有实体占位才消耗八魔力；不可借入口配置生成地形。房间配置 `name/center/radius/mobs`，半径 3–8，房间中心必须属于同一附近建筑。小房间不接受劫掠兽，出怪需要两格净空、安全实心地面且避开玩家。运营先在独立副本确认可达入口、房间连通、人数与出怪空间，再发布；不能只凭 `/locate` 坐标登记。

运行数据在 `config.yml` 的 `site-dungeons.runs/receipts/claimed/cooldowns`，必须随世界备份。目录定义改变时旧检查点保留并停止开放，服主应还原匹配定义并正常重启或审查处置，不删除检查点或重发奖励。
