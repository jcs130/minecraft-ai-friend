# 女神世界观察与 MCP

## 0.4.19 正式服务器已部署

女神的聊天桥在每次普通问答前附上提问者的当前世界、坐标、朝向、脚下方块与群系；空间查询会再读取本人位置，结果只代表其观察时间。空间问题继续调用服务器只读工具查证。玩家和 Agent 沿用现有游戏聊天入口，无须客户端插件，也不增加公网端口。

连接链路：游戏聊天 → `goddess-bridge.mjs` / `goddess-perception.mjs` → QwenPaw `mc_godness` → stdio `goddess-mcp.py` → 本机 RCON → AgentFriend 控制台观察入口。观察接口不能由游戏玩家或 OP 游戏账号调用。

## 九项只读工具

| 工具 | 返回什么 | 范围与限制 |
| --- | --- | --- |
| `read_player_world` | 在线玩家真实坐标、朝向、脚下方块/群系、生命/饥饿 | 精确账号；不含背包 |
| `inspect_world_block` | 方块 ID、门/半砖/作物状态、群系、亮度、危险与领地 | 仅已加载区块；不读箱内物品 |
| `inspect_world_area` | 材料统计与表层高度采样 | 半径1–12，高度上下各1–6，体积≤8192格；表层可能是屋顶或树 |
| `find_world_blocks` | 指定方块的位置和状态 | 同上，最多8种ID、24条结果；可能包含地下方块，不保证结果为最近的若干个 |
| `find_world_entities` | 附近实体、掉落物种类和数量 | 水平半径≤48，高差≤24，最多24条；不含玩家背包/箱内物品 |
| `find_public_places` | 当前公开分享点、公共箱、地标、商人/NPC与登记遗迹 | 不读私人家；登记遗迹的近似中心不是已核实入口 |
| `plan_local_route` | 分段步行/单格台阶/木门/连续梯子提示 | 当前同世界，每轴水平≤24、高差≤8；768节点；不操作角色 |
| `inspect_player_access` | 指定玩家在附近目标的实际保护判定和正确下一步 | 距玩家≤16格；不更改权限、不发玩家提示 |
| `read_recent_photo` | 本人最近实际成片的时间、位置、角度及可选PNG | 默认5分钟，最多15分钟；换世界或摘要不符拒绝；不是实时视角 |

群系从已加载区块的4×4×4原生群系单元读取实际注册ID，保留Terralith等自定义命名空间，不使用Bukkit的CUSTOM代替。

方块扫描最多12000次读取，按64次检查约8毫秒预算；超时返回部分结果与缩小范围的建议。接口至少间隔200毫秒，MCP串行协调间隔。观察不生成新区块，不执行 `locate`。无结果只说明本次已查范围，不能据此宣布世界里没有目标。

路线只使用已经加载的原版方块，核对木门使用权限。不会开门、挖掘、施法、传送或移动；半砖、游泳及复杂碰撞保守不规划，动态实体未验证。`found`是当时的局部建议，玩家执行前仍须确认现场；远距离返回未知并建议分段接近。

## 相机与模型能力

相机成功交付已有照片后，额外保存一份本人最近成片及元数据。缓存最多12位玩家、每图≤8MiB，固定UUID文件名，本机读取，无任意URL或文件路径入口。照片继续使用无游戏UI的既有渲染器，地图交付、费用和玩家拍照方式保持。

MCP可用原生Image内容把PNG交给支持视觉的模型。默认只返回照片元数据；当前问答模型的像素理解尚未验收，不能声称女神已经看懂实时画面。地形、物品位置及路线以服务器结构化观察为依据。照片只在玩家主动拍成后可读，不替玩家拍照或发放地图。

## QwenPaw 接线与权限

现有10项工具保留，新目录共19项。游戏聊天身份 `console / afu-game-bridge` 仅新增九项具名只读许可；原状态查询保持，默认拒绝和原管理身份规则保持。发物、改权限、天气等写工具不向聊天身份开放。QwenPaw原生Agent的开发文件工具属于另一个权限体系，此MCP策略不等于整机沙箱。

驱动卡的 `config.tools` 必须包含新工具，否则模型不会发现；仅修改Python不够。更新女神现役工作区的 `drivers/mcp/afu-goddess-server.yaml`，文件监视器对同一endpoint只刷新元数据，不能让旧Python进程重新加载源码；必须再通过原生API `PUT /api/mcp/afu-goddess-server`（`X-Agent-Id: mc_godness`，空对象保留配置）仅重载这个MCP连接，然后实际重新发现19项工具。无需重启整个QwenPaw。不要把旧镜像工作区当成现役。
