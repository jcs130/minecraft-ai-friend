Java 自动下发还需要客户端可访问的资源包 URL，本次没有配置公网接口或新端口，提供手动 ZIP。ViaVersion 允许其他 Java 版本登录，不代表这个原生 1.20.6 资源包兼容新版物品模型格式，尤其未验 1.21.4 及之后版本。

Web 外机需要拉取源码、安装这份资源、按原 `1.20.6/qiandengji` 预设重建并重启实际宿主。服务器发布不会自动更新另一台电脑的页面。机关弩当前为静态专属结构，使用原角色抬手／挥动动作，尚无自定义弩弦拉伸和装弹模型变体；Web 自定义武器的三维附魔流光尚未实现。

## Agent 可读信息

原命令保持：`/mycli inventory item hand`、`/mycli inventory status`。私有 `MC_ITEM`／`MC_INVENTORY` 新增可选字段：

```json
{"appearance":{"id":"qiandengji:frost_sword","customModelData":731001,"baseId":"minecraft:iron_sword","cosmeticOnly":true,"requiresResourcePack":true}}
```

继续用原 `baseId`／物品组件做交互，用真实名称和说明向玩家解释，不把它误称普通铁剑。外观缺资源不会赋予额外能力；Web 对未知保留编号显示不可用诊断，不悄悄绘制普通武器冒充。没有新增公屏机器消息。

## 源码与构建

- 单一目录、五件原创模型、跨端构建及可运行测试：[`paper/item-appearances`](../item-appearances/README.md)。
- 服务端：`ItemAppearances.java`；原战利品和法杖工厂调用 `decorate`，原私有背包回执补外观描述。
- Web：共享仓库 `packages/modern-viewer/renderer-src/src/modern-viewer/item-appearances.js`，使用 `asset-packs/qiandengji-items-1.20.6`。每份文件都有摘要，不能拿不同版本包拼装。
- 可选 `plugins/AgentFriend/item-appearances.json` 覆盖内置目录；省略则使用 JAR 内目录。`{"enabled":false}` 停止新增标记，已标记的物品保持原样。目录在启动读取，不支持热重载。

修改模型／贴图要一起构建 Java、基岩、Web，并提高资源包版本以刷新客户端缓存。不要重用已发布的物品编号。新增超出现有三种匹配方式的装备来源仍须实现服务器身份校验。
