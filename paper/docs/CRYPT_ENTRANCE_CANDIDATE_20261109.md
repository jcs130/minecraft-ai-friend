## 确认的缺口

`sites.creeping_crypt` 没有配置 `entry`，首室 `center: [1159,45,209]` 是房间中心，不是地面入口。`travel` 目前仍只能按既有规则抵达外围。

反馈位置 `(1159,58,212)` 上方还有多层实体地形；它是地下壳体旁的平台，不能因为比首室高就认定是室外入口。实测找到的原有内部楼梯可从首室附近一直上行到约 `(1165,86.5,229)`，上部建筑被屋顶封住；屋顶外侧 `(1165,94,230)` 与旁边自然草地相邻。

旧离线路线包含长段水下通道，不能用作普通步行入口的证据。110 个区块内的简化站立连通搜索未找到首室到露天地面的通路；这只是限定范围、限定动作的结果，不能推断所有远路、游泳或特殊动作都不可能进入。

另一个容易误读的字段：`DungeonArrival.describe()` 当前固定返回 `routeVerified=false`，含义是**本次查询没有验证路线**。它不是动态寻路结论，也不能用来证明地图绝对封闭。即使将来配置入口，也不要据此伪造 `routeVerified=true`。

## 最小建筑方案

候选数据见 [connector.json](../probe/crypt-route/connector.json)，只修改 34 个方块状态：在屋顶与原内部上平台之间接一条一格宽的折返楼梯，利用原有约 40 米高的内部楼梯进入首室。无箱子、方块实体或原楼梯实走轨迹交叉。

| 位置 | 世界与坐标 | 用途 |
| --- | --- | --- |
| 自然草地 | `world (1169,93,231)` | 已实走的室外接近点 |
| 屋顶入口 | `world (1165,94,230)` | 拟配置的 `entry` |
| 原内部上平台 | `world (1165,86.5,229)` | 接入既有楼梯，持续向下 |
| 首室中心 | `world (1159,45,209)` | 原中心保持；实际站立高度依楼梯碰撞箱变化 |

拟用路线说明：从山坡草地到屋顶入口，沿新增折返楼梯下到原上平台，再沿原有楼梯下到蔓藤前殿。不要朝首室中心直挖。拟用路牌文字为“蔓生墓穴 / 入口向下 / 沿楼梯至前殿 / 禁止破坏建筑”；牌子的具体摆放及原版、基岩、网页可读性尚未实装验收，不计入已验证的 34 方块。

配置差异只记录在候选 JSON 的 `configurationCandidate` 中，**没有写进默认 `dungeons.yml`**。必须先安装并核对实体入口，再启用对应坐标；不能先把玩家送到尚未存在的楼梯。

## 复测与四阶段边界

测试工具位于 `paper/probe/crypt-route/`；它们不是正式插件，不进入发布包。

1. 用全新、停止的合成测试服，确认 `.shop-qa` 精确为 `FRESH_RPG_SHOP_QA_NO_PLAYER_DATA`，绑定回环地址及上述独立端口。保存测试世界元数据前像，不复用含真实玩家资料的目录。
2. `geometry.mjs <不可变冷备的r.2.0.mca> <测试服> <输出摘要> <依赖package.json>` 生成去内容的几何。`CRYPT_QA_WORLD_NAME=world` 选择默认世界；不得覆盖已有区域。启动前完成，不在线替换区块。
3. 用 Java 21 和测试服 API、ProtocolLib、Gson 的既有类路径编译 `CryptRouteFixture.java`，仅安装到此测试服。`build.py --help` 给出参数；生成物不会自动安装或启动服务器。
4. 设置 `CRYPT_QA_STAGE`、`CRYPT_QA_REPORT_ROOT`、`CRYPT_QA_CLIENT_ANCHOR`、`CRYPT_QA_PATHFINDER`、`CRYPT_QA_RCON`。RCON 模块须导出支持显式 `port`、`properties` 的 `command()`，不得将正式端口混入环境。
5. 未改几何先运行 `walk.mjs --roof --dry`，保留失败回执；断开合成角色后，运行 `apply-qa.mjs`，它核对全部前像后才逐格修改并记录结果。任何未知或部分失败先核对原账本，不删除账本后盲目重跑。
6. 依次运行 `walk.mjs --roof --dry --candidate --reuse-loaded-geometry` 和 `walk.mjs --ground --dry --candidate --reuse-loaded-geometry`。服务端 `qdcrypt` 回执和本地输出共同验收。每个报告输出目录须为空，保留原测试结果。
7. 只移除应用账本中记录的新增强加载，再正常保存、停服、比较方块变化，归档证据。完整原生 `finish` 轨迹保存在测试服 `plugins/CryptRouteQA/`。

本候选的验收门槛仅为实体入口与原楼梯可走通。后续仍需：当次部署授权；当前地图前像逐格一致；无真人、无活动冲突；安装后的原版/基岩路径、保护、`dungeon info/travel` 和正式插件准入联测；最后才是原可米主人格的真实采用。不能用本轮合成角色结果替代这些验收。
