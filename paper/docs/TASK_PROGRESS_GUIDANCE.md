## Agent 使用方式

沿用现有入口，不添加新命令树：

```text
/mycli tasks status --json
/mycli tasks info <任务ID> --json
```

`adventure.market` 中提供 `progress`、`target`、`remaining`、`progressSource`、`guidance`。旧常驻与动态日常委托在 `adventure.guidance` 中提供同类下一步。生活委托在 `life` 中给出 `nextAction`、`nextCommand`，两种任务槽各自保留。

`guidance` 区分寻找地点、继续探索、返回原结构、实际行动、到场、工程验收、修复前阶段和待本人交付。`missingConditions` 只列缺项；阶段达标不等于整单已领奖。

查询不接单、不重采工程基准、不改变验收规则、不代领奖，也不将查询本身计作行走。`tasks info` 的出发前指引标为 `scope=planning`。

## 行动反馈

服务器从原有真实事件生成私有 `MC_MARKET_ACTION`，经既有 `mcagent:market` 载荷发送；紧凑聊天回执沿用带 `type` 字段的 JSON。未依赖新客户端插件。

反馈包含当前阶段、时间、原进度、现进度、剩余量及原因。常见未计数原因包括目标怪物不符、武器不符、缺少本阶段近战或投射物证据、合成或收获的物品不符、没有在先前收获田格补种。杀怪、合成成功与委托是否计数分别确认。

同一阶段、同一原因的重复提示间隔至少 10 秒；快速连续收获合并提示，最后一次达标立即回执。本人状态仍可读取最新进度与近期 `lastAttempt`。`lastAttempt` 仅内存保留五分钟，换阶段不混入，退出即清理；它不是持久化战利品凭据。

真人与实际附身的 Eye 收到中文提示；其他玩家和 Agent 不收到这份私有结果。原生合成与旧事件适配器保留原计数方式，新增反馈不重复计数。

逐条对照实际判定，明确斋戒试炼是不进食、博识之证看历史能力维度、治疗实练看队友的有效怪物伤量、职业格挡看实际减伤。工程远程验收先指向场地查询；前面阶段被破坏时先指出需修复的阶段，不用当前库存掩盖阻塞。
