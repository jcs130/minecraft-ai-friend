## 0.3.94：同类箱自动分流

- 供货交付先用原类别箱，空间不足继续同类扩容箱；一笔交付可以拆分到多个箱。
- 全部同类箱不足或任一登记箱的实体/公共权限异常，服务器拒收，背包、任务和奖励保持；返回中文原因及 `MC_GUILD_DELIVERY status=denied/itemsDebited=false`。
- 后续结算被拒绝时，在同一个服务器线程内退回本次背包扣物，恢复所有受影响箱的原物品及组件。没有把物品丢到地面、删除装备或压成自定义货币。
- 动态供货的 `shared_stock` 合计同类全部箱，只统计与普通物品一致的堆叠；附魔、命名物品不会当普通红石/材料扣除。已接单冻结数量照旧，不随新库存改变。
- 控制台 `sharetrial <玩家> [apply]` 的预览和实际转移也使用同类扩容箱，保留既有允许捐赠的物品清单。
- 物品仍存在原版实体箱中，使用世界正常保存和备份；不新增虚拟物品账本，不修改 Agent 客户端或已有命令参数。

`/mycli guild shared` 保留原四条 `MC_GUILD_SHARED`，另外给出每组 `MC_GUILD_SHARED_OVERFLOW category=… group=… x=… y=… z=… scope=public slots=54`。普通 Java、基岩和 Mineflayer 都通过普通双箱取放；基岩/Xbox真机观感仍需实际客户端确认。

## 后续扩容，无需改代码

配置文件 `plugins/AgentFriend/guild-shared-chests.yml` 只登记已经建好的实体双箱，不生成箱子、不移动旧物品。

```yaml
schema-version: 1
extras:
  weapons: [[-473, 69, -495], [-473, 71, -495]]
  armor: [[-473, 69, -493], [-473, 71, -493]]
  supplies: [[-473, 69, -491], [-473, 71, -491]]
  misc: [[-473, 69, -489], [-473, 71, -489]]
```

每行坐标是双箱任意一半。每类最多16组附加双箱，坐标限定公会服务区附近。登记前须在 `lands.yml` 把**两半**明确列为公共容器；私产、缺半箱、重复登记或跨类别复用都拒绝。

1. 按维护规则备份、勘察并建好箱体，保留玩家物资和道路。
2. 更新领地的 `public-containers`，控制台 `mycli admin land reload`。
3. 更新上述配置，控制台 `mycli admin sharedstorage reload`。
4. 控制台 `mycli admin sharedstorage audit` 确认各类别 available、slots、used 和坐标，再用普通账号验证开箱与拆箱拒绝。

每片领地最多登记16格公共储物方块；更多箱组应划分独立仓储地块并分别保护。配置错误保留上一有效登记。运行时每次交付重查双箱和公共权限；登记有效不等于领地后来改为私有后还可投递。配置删掉某组不删除箱体或物品，但该箱不再参与自动投递和库存统计。
