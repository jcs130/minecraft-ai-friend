# 11月3日晚间健康修复

状态：女神查询和两项原生巡检修复已生效；AgentFriend `0.4.47.51-rpg`、OlEncounters `1.7.0-qd-youer1` 已完成隔离验证，仍待本批正常重启批准。正式游戏当前保持 AF `0.4.47.50-rpg` 和 OlEncounters `1.7.0`，没有在线替换插件。

本次健康检查时，游戏总体20 TPS、约15 ms/tick，无新重启、Full GC 或持续协议异常；不能据此说所有玩法都没有问题。实际发现的是副本存档、随机事件选址和女神巡检的具体故障。

## 副本持久化与恢复

旧版在最终房间通关已落盘后，奖励原子替换遇到 Windows `AccessDeniedException`，仍把内存中的房间和参战记录退回上一段；暂停检查点随后又覆盖了已保存的通关状态。新版本区分“房间提交成功”和“后续奖励提交成功”，只回滚尚未提交的状态。后续登记失败时保留已经保存的房间和参战记录，暂停提示也会说明保留了什么。

配置先写入同目录独立临时文件并 force，然后仅做原子替换。Windows 短时拒绝替换时只重试同一份字节，最多四次，请求等待合计22 ms；不会重跑奖励、消耗或游戏动作。持续拒绝、其他I/O错误或线程中断仍明确失败，保持暂停，不降级成非原子覆盖。

玩家确认故障已处理后执行：

```text
/mycli dungeon resume
```

`resume` 是副本操作，不加 `cast`，也不加副本编号。对实际出现的 `cast resume dungeon <已知副本>` 等误用，纠错返回这条准确命令；不会自动执行建议。真实同名技能保持自己的验证路径，未知副本编号不能被补成已确认目标。

正式服旧故障场次目前保存的是2/3房间。新版不会凭日志补奖、推测已丢失的最终参战记录，或代玩家操作；既有检查点应保留，由参与者查看状态后明确继续。

## 随机事件的冷区块选址

OlEncounters 的异步搜索调用 Youer 的 Bukkit API；本机固定内核的该方法只返回已加载区块，对冷区块返回空，已有配置 `allow-chunk-generation: true` 也不能修复这一行为。与既有 [Youer #596](https://github.com/MohistMC/Youer/issues/596) 属于同一问题，不重复提交 issue。

兼容层仅替换固定 OlEncounters 1.7.0 的一个异步调用点：Youer 使用真实原生 FULL 区块 future，保留原选址预算、生成开关、世界身份和搜索终态；Paper 保留原异步调用。禁止生成时先核对已有区块，已结束的搜索不能再排入加载。完成回调回到主线程，单次兼容 future 最多等100 tick；不取消共享的原生 future，不使用同步生成替代，不添加永久强制加载。详见[兼容层源码与构建](../integrations/olencounters/README.md)。

选址日志中约9.7秒是一次异步搜索耗时，不能据此认定主线程连续阻塞9.7秒。

## 已生效的女神修复

现有 `peek tps`、`peek mspt` 和只读快照改用 `neoforge tps`，从唯一 Overall 行读取总体TPS/MSPT；空响应、无效数据和歧义不再被当成健康或零值。

原生日常巡检和滞留任务巡检改为读取一次有总时间预算的快照，再处理最多一个问题。完整证据保存在原目录，给模型的是有限摘要；不展开全历史、不在巡检中施工或反复尝试游戏动作。无需指定输出文件，默认生成新的独立快照，显式已有路径会拒绝覆盖。身份、模型、原任务ID、调度、900/600秒超时、派发渠道及其余五个任务保持原样。

两项原任务逐个实跑成功，约191秒和160秒，均留下本轮新鲜快照。调度成功只说明本轮巡检结束，不代表副本等游戏问题已经修好，也不是持续稳定性的长期证明。
