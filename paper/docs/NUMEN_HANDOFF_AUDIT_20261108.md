## 3. 按交接状态判定

| 状态转换 | 已核实 | 尚缺 |
| --- | --- | --- |
| 原客户端在线 → 申请托管 | 原生准入代码同时查 UUID/同名在线身体；传输回归确认拒绝后不开控制会话 | 正式原客户端在线时的拒绝回执及原连接未被挤掉 |
| 原客户端离线 → 同 UUID 接管 | 同身份绑定、同名不同 UUID 拒绝、原生注册表 hosted 隔离和新 epoch 停权已检查 | 正式原 UUID、背包/位置/权限前后对照，实际新身体加载回执 |
| Numen / Hub → 暂停 | 先 fence，确认 worker 和模型连接停止；暂停不调用保存下线 | 正式暂停终态、模型撤销、身体在线静止证据；暂停本身没有即时耐久存盘确认 |
| 暂停 → 退出 | 服务要求确认暂停、无未知动作、模型已撤销，再调用原生 dormant；原生走正常 disconnect 保存/移除 | 正式保存完成、身体下线与真人原客户端恢复证据 |
| 服务/游戏异常重启 | 真实服务进程崩溃后本地账本恢复待确认、不重投；原生租约初始暂停，到期不恢复旧控制 | Windows 监督进程树、Youer 实际重启、正式孤儿连接清理和角色保存恢复 |
| 模型权限/配额错误 | 独立 vault、精确模型、禁止共享 fallback、失败不激活、撤销失败阻止替换已测；原生 heartbeat 失败会转暂停的代码已检查 | 本人账户的真实供应商鉴权/模型权限/用量和失败回执；本轮真实模型调用数为 0 |

服务启动会把旧角色置为恢复待确认，不自动重新绑定模型或恢复身体。原生停止依赖实际任务/模型回调结束及租约到期；已有孤儿连接引用需要显式暂停/撤销流程。本轮没有证明“进程重启后立刻清除所有原生/Hub 活动凭据”。

## 4. 已复现的恢复缺口：退出完成但回复丢失

触发序列：身体已暂停、模型已撤销 → 原生保存并下线成功 → 该回复丢失 → 本机标记 `recovery_required`。随后状态只返回本地记录；再次退出先尝试暂停离线身体，原生 `body()` 又要求身体在线，因此无法通过原出口恢复为 `detached`。

本轮模拟该传输故障，确认保存下线操作只有一次，没有重建身体、重复下线或启动新控制器；但页面会一直停在恢复待确认。**安全保护通过，恢复可用性未闭环。** 这不是正式服事故复现，也不能据此说发生了物品损失。

建议由服务端补持久化的退出操作/保存完成回执及允许离线查询的受限恢复接口；只确认“玩家不在线”不足以证明保存已完成。不能靠重新 attach、伪造 detached、换请求 ID 或回灌旧世界/玩家数据消除未知。补回归要求：丢回复后只读原退出回执可确认原次完成；重启仍能查询；同 UUID 已由原客户端在线时不干预该客户端；保存失败继续保持未知。本轮只新增验证与只读采集工具，没有修复或部署此协议变化。

## 5. 正式现场补证与批准门槛

本轮正式角色、托管模式、模型账户均未指定，尚无可执行的角色接管批准请求。不要默认使用可米、桐人或任何正在游戏的角色。后续先读当前业务证据，复用已有真实交接记录；只验证仍缺的状态。

在请求服主明确批准前，必须将以下方案中的对象填实并展示：

| 项目 | 拟验收内容 |
| --- | --- |
| 角色 | 官网本人已绑定的普通角色：实际游戏名、完整原 UUID、当前控制器和在线情况；角色由本人选定，不新建替代身份 |
| 模式 | 每次明确一个：Numen 原生循环或独立 Hub OpenCode；另一模式在前一次退出确认后单独记录，不同时驱动 |
| 模型 | 本人官网输入并保管的供应商/精确模型；聊天和报告只记录 keyConfigured、脱敏错误及用量，不接触 Key 原文 |
| 执行 | 记录原状态 → 验证在线准入拒绝 → 本人原客户端正常离线 → 托管接管 → 一轮观察/发言 → 暂停 → 确认结算并撤销模型 → 保存下线 → 本人用原客户端登录核对 → 另行异常重启测试 |
| 影响 | 托管会消耗本人模型额度；角色在线会受游戏环境影响，模型也可能调用已授权动作。只读目标提示词不是工具权限或费用硬上限；验收窗口、费用边界和实际停止手段须先约定 |
| 停止条件 | UUID/归属不符、出现第二控制器、未知动作、撤销或保存未确认、模型拒绝/限流、非预期位移或库存变化、超过批准窗口，立即停止推进；不重投动作 |
| 回退 | 先暂停指定角色并确认旧任务终态，撤销其模型，读回原保存/下线回执，之后才允许本人恢复原客户端。退出结果未知时用服务端只读证据核对原次操作，不能为拿到成功回执重新接管 |

游戏整体重启另需当前真人/副本门禁、正常预告、当前恢复点和明确维护批准。回退只切代码，保留当前角色、世界、背包、金币、配置和动作回执；不得恢复旧业务库或旧世界来撤销已经发生的真实游玩。

现场最终需留存四类分开的证据：①模拟供应商测试；②本人真实模型调用及费用/模型身份；③正式角色驾驶权、保存和下线交接；④本人原设备登录与操作。任何一类成功都不能替代其余三类。
