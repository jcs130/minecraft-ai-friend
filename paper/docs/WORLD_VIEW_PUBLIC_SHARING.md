# 多人观战与主人公开开关

本批为 0.8.19 候选，尚未部署；包含 0.8.18 的断流恢复和观测服务独立限流修复。
首次 iframe 打开若收到临时 503 错误页，下次获得有效观看回执后会重新载入；
已正常运行的渲染页面和被拒绝的页面不会因此反复刷新。

官网「女神之眼」中，已绑定角色的主人可以选择「开启公开观战」，
随时关闭。默认保持私密，不自动公开可米、NEKO、桐人或其他角色。
网站管理员能看本人授权范围内的画面，但不能替未绑定到自己的角色
开启公开开关。游客只看到主人已公开的角色。

公开设置存在网站 `settings` 表，键为 `world-view-public:<uuid>`。
记录绑定网站主人；角色转交后恢复私密，由新主人自行选择。
不改游戏密码、权限或原角色数据。

接口：`PATCH /api/v1/live/<channelId>/visibility`，请求体
`{"public":true}` 或 `{"public":false}`。必须使用角色主人的网站会话、
同源和 CSRF 验证。修改前同步撤销旧发布器/流/缓存，再签发新作用域。
仅 UI 隐藏不算隐私边界；公开来源使用 `scene`，完整背包、私聊、私人
Agent 信息不进入公开画面。可见装备、人物动作和地形仍保留原渲染数据。

每个角色仍只用原身体，不新增 Eye 或玩家槽位。云端为观众共享一路
上行 SSE，后来者从云端接收完整地形检查点与后续增量，按各自视角渲染。
原模型/贴图按角色来源做有界缓存及并发去重；不同私有来源不共用
公开地址。32 观众/角色是本批连接上限，原游戏目标数上限保持。
官网每来源原素材缓存 16 MiB、检查点链 8 MiB、每观众待发送量 12 MiB，
适配现有 512 MiB 容器；不会按观看人数复制整份世界或无限保留旧场景。
关闭公开、来源失效及权限改变会结束对应流和缓存，不把旧画面标成在线。
慢观众有独立缓冲上限，不能堵住其他观众。

本机协议测试包含 32 个 SSE 观众只读一路上行、16 次并发原素材请求
只回源一次，验证后来者增量重建、换世界清空、关闭撤权、归属转交、
密码/归属原规则和大背包公开过滤。隔离测试不等同生产并发或手机验收。

发布只需同步匹配的官网和无账号观战后台，Paper、登录代理、模型服务
不用重启。网站发布前做最新一致性数据库和配置 E/F 备份，保留旧容器；
回退使用旧代码和匹配 renderer，保留最新账号/角色/照片/公开设置数据库。
旧 0.8.18 候选由本批取代，不单独部署旧确认脚本。
