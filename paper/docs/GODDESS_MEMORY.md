## 操作完成后的记录

先核对原始回执，再记当天 `memory/YYYY-MM-DD.md`，重要事项另建主题笔记，并更新 `memory/goddess-operations.md` 短索引。每条至少包含：

| 字段 | 要求 |
| --- | --- |
| 日期与事件 ID | 跨会话能关联到同一工作，原 request/action ID 若有则保留 |
| 操作主体 | 区分女神执行、玩家执行和代笔叙事人物 |
| 动作及对象 | 例如代笔、上架、建造、配置、发放；用稳定作品名或内容 ID |
| 状态 | `planned`、`attempted`、`verified`、`failed`、`unknown` 分开 |
| 实际结果 | 成功读回的内容、失败原因或待核验项 |
| 证据路径 | 对应命令、收据、核验记录；不把自己的答复当证据 |

原始记录留在工作区和私有运行审计中。公开作品的署名、发布事实可答；其他玩家私有背包、技能进度、私人对话及凭据不因记忆检索而公开。超时未知先对账，不重放历史命令、补发物品或重新施工。

## 回答历史问题

1. 用玩家实际问题中的短关键词检索作品、人物别名、动作；不要只依赖包含大量环境指令的自动查询。
2. 读取操作索引、对应日记和原始回执。自动片段不足时继续展开。普通游戏问答允许这些只读记忆工具；历史查询不授权写游戏状态。
3. 区分“我曾完成”“当时尝试”“故事中写到”和“现在现场仍然如此”。问实时地点、技能或库存仍须本次服务器查询。
4. 发现旧回答或自动摘要错误时，以实际回执和核验记录纠正，保留原始对话；将派生摘要标为已纠正，同时修改当天索引。不得为了保持口径继续复述误答。
5. 未查到时说明“暂未查到记录”，而非“我从没做过”。不创造作者、操作结果或未核验的剧情细节。

规则原文在 [当前答疑规则](GODDESS_CURRENT_RULES.md) 的“记住自己的工作”一节，同步到现役 `resource/GODDESS_CURRENT_RULES.md` 和 `AGENTS.md` 的受管理区；核心记忆只保留短索引入口。
