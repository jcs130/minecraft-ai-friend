## 修复内容

- 复用 `/voice status`：玩家不带参数时检查本人收听条件，给出安装模组、语音 UDP 未连接、收听关闭、权限缺失、隔离小组或连接就绪的具体说明。完成首次语音设置即可开启收听，麦克风可以保持静音。
- 原 `/voice status <请求ID>` 仍只查本人回执。控制台可只读查询 `/voice status <接收角色> [声源角色]`，包含实时同维度/距离判断；游戏玩家不能借此查询其他角色的回执。
- 音频准备错误区分媒体服务连接失败、超时、内部认证拒绝、繁忙、输入被拒绝和返回的音频格式错误。回执附 `nextStep`，日志只含请求编号、阶段与稳定错误码，不写音频、台词、令牌、响应正文或内部 URL。
- 每个本插件创建的音频通道记录 SVC 发送事件的包数和去重接收端数量。只保留有界汇总，不记录接收者名单。`packetOffers` 表示发送事件，发生在 UDP 发送之前，不是网络回包、解码或耳听确认。
- `sent` 保留原终态语义和幂等协议。零发送事件会附 `VOICE_NO_RECEIVER_CHECK_STATUS`；存在事件则附 `VOICE_SENT_HEARING_UNVERIFIED`。`actualHearingVerified` 固定为 `false`，未知旧回执不补造计数或改成成功。
- MC 核心原先仅保留 `state/reason`，会丢失服务端具体建议；候选将有界 `nextStep` 和发送汇总传到 SDK 和 `mc_voice` 原回执中。继续保留 `recipientHeard=unknown`、`goal_completed=false`，不自动重试、不新建连接、不增加模型循环。

## 验证

现役同版 Youer 与 SVC 2.6.27 的全新回环隔离服，使用合成角色和全新合成 WAV。测试客户端通过正常 Minecraft 连接申请本人的 SVC 密钥，完成独立 UDP 认证，接收并解密音频；密钥不写入证据。内部 `registerAudioListener` 回调发生在禁用/连接过滤之前，不能作为这个网络验收的替代。

- 修复前同一套集成检查：5 项通过、9 项失败，失败集中在无接收端诊断、收听状态、回执证据和音频准备错误分类。
- 修复后：14 项通过；附近开启收听的客户端收到 50 个音频包，远处、关闭收听和不同维度均没有收到音频。
- 正常重启后另 2 项通过：汇总与原请求恢复，重复提交不重播。
- Java 边界、账本与诊断共 60 项通过；原客户端 11 项和媒体服务 11 项通过。
- MC 核心新增 3 项先失败后通过；覆盖详细建议传递、非法计数/伪造听感丢弃，以及 Agent 工具回执始终保留“尚未确认听到”。
- MC 核心全量运行中 2,926 项通过、8 项按原条件跳过；另 2 项因环境默认 Java 17 无法编译 Java 21 客户端而失败。指定现役 Java 21 后这两项通过，连同声明消费/语音新回归共 8 项复核通过，未改测试断言。全部已执行用例最终通过，原环境失败记录保留。
- 独立构建与公开声明校验通过；实际打包解压后，隔离消费者经公开 `agent-mc-world/proximity-voice` 入口收到完整建议和计数，包内输入/输出哈希校验通过，没有连接游戏或调用合成服务。

集成入口 `paper/integrations/proximity-voice/tests/delivery-integration.mjs` 只接受显式隔离根目录，要求 `.voice-delivery-qa` 标识及 127.0.0.1:29520 游戏端口；RCON 29521、语音 UDP 29522，媒体夹具 29523。需要提供独立安装的 Mineflayer 依赖目录；有配方协议差异时显式提供已验证的客户端兼容模块。没有正式服默认地址，不使用真实玩家身份。

以上网络验收仍不等于正式 `live` 客户端实际播放或独立录音通过。收尾需完成客户端首次语音设置、确认实际跟随及声源实体加载，再以新测试句、新 ID 验证；原失败句及结果未知的请求不重播。真人麦克风到附近字幕仍需独立验收，不能用这次合成音频证明。
