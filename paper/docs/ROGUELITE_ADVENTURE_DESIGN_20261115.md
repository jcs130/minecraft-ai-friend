首个可玩章节已进入候选验证，实际规则、入口与回退见[艾恩葛朗特第一层 · 失联信标](AINCRAD_LOST_BEACON.md)。

状态：研究及小范围引导修复候选。调查基线为主干 `91890e88`，正式 AgentFriend 为 `.78-player-navigation`。本轮没有安装插件、重启、修改真实任务或世界；下文的分支远征、祝福和事件尚未实现。目标是让真人和 Agent 在一次冒险中持续选择路线与战术，并把经历积累为长期公会履历。

## 借鉴什么

《杀戮尖塔》的开发者介绍强调动态构筑、路线变化和遗物组合；GDC 讲解强调反复测试，并明确数据需要结合玩家反馈解释。千灯纪借鉴“路线选择产生不同局内能力”，保留 Minecraft 的即时战斗、地形与多人协作。[Mega Crit 的游戏介绍](https://store.steampowered.com/app/646570/Slay_the_Spire/)，[开发者设计分享](https://media.gdcvault.com/gdc2019/presentations/Giovannetti_Anthony_SlayTheSpire.pdf)。

更接近 Minecraft 实现的是 Wynncraft 的 Lootrun：信标指向探索或守卫等不同挑战，路线奖励影响后续能力。其后续更新还调整过过长场次和收益失衡，说明“无限叠加、无限延长”并不是直接可照搬的答案。采用短章、可选风险、有限叠加和明确退出。[官方 2.0.3 发布说明](https://forums.wynncraft.com/threads/2-0-3-full-changelog-lootrun-reworks-more.308462/)，[官方 2.0.4 调整](https://forums.wynncraft.com/threads/2-0-4-full-changelog-new-bank-lootruns-more.310535/)。

本次检索到的“永恒世界”为 `4.mcyyy.com / 1.mcyyy.com`，用户尚未确认是否同一服。其公开说明值得借鉴的是：菜单直接展示准入、费用、在场人数、首领状态；试炼结束自动返回；排行榜与奖励周期清楚。它的无尽刷怪和修仙数值体系不直接迁入千灯纪，也未取得或验证其私有插件实现。[秘境说明](https://4.mcyyy.com/features/mijing)，[无尽试炼说明](https://4.mcyyy.com/features/trial)。

设计过程参考公开的 [Roguelike Game Designer](https://github.com/Hanjo92/roguelike-game-designer-skill) 及其局内节奏、存档和验收材料：先确定玩家面对的选择，再确定房间和技术；将“规则成立”与“好玩、Agent 真正采用”分开验收。仅阅读资料，没有安装或执行第三方脚本。

## 三类玩法分工

| 玩法 | 主要价值 | 保持或调整 |
|---|---|---|
| 初始村试炼塔 | 学习远近程、格挡、控制、救援与职业配合 | 保留现有每次从一层开始、过关恢复、返程和奖励限制；先补清晰入口，不重置记录 |
| 艾恩葛朗特分支远征 | 一章一局，侦察、事件、精英、营地、Boss 形成不同经历 | 首期一章 7 个实际节点、两次路线分叉，目标 20–35 分钟；数值和时长是待实测假设 |
| 野外公会委托 | 发现地点、激活信标、解救、收集情报与共同记忆 | 与短局并行；支持保留原进度后换活动，不把填满一个计数条当作全部探索 |

长期职业、经验、技能、金币和装备仍由 VortexRPG 及现有桥负责。AuraSkills 保持基础被动定位；不再并排增加第二套职业、货币或账户。新远征使用既有 `SiteDungeonManager` 的参战、倒地、奖励与回执边界；是否抽取独立编排接口须在原经理中验证，不能运行两个同时发奖的控制器。

## 第一章的可玩方案

场景主题为艾恩葛朗特旧城外围的失联信标。利用已有建筑的楼梯、回廊、屋顶和室内掩体；制作验证过的房间模板，在隔离世界先灰盒走通。不得在有人使用的地图上实时拼接或覆盖建筑。

```mermaid
flowchart LR
  A[公会简报与初始祝福] --> B{选入口}
  B --> C[暗道侦察 取得首领情报]
  B --> D[正门突破 精英与额外战利品]
  C --> E[救援失联队员]
  D --> E
  E --> F[营地 改造祝福或领取补给]
  F --> G{选最后一站}
  G --> H[破坏供能祭坛 削弱首领机关]
  G --> I[宝库守卫 保留机关但增加奖励机会]
  H --> J[首领战]
  I --> J
  J --> K[结算 返程 可选留影]
```

起点、选中的入口、救援、营地、选中的最后一站、首领、结算共 7 节点。选择页先显示目标、风险、预计耗时、地图/世界、奖励类别及放弃的收益；怪物具体组合可以变化，已选路线和奖励不能在断线后重新抽取。

| 节点 | 实际动作与反馈 | 对后续的影响 |
|---|---|---|
| 暗道侦察 | 到真实标记点交互，避开可见巡逻，检查机关；不靠一句“我调查了”完成 | 提前显示 Boss 招式及一次安全窗口，收益较少 |
| 正门突破 | 优先击倒治疗者，利用回廊躲箭；敌人技能有粒子及文字预告 | 多一个祝福候选，但战斗更难、可能消耗挑战次数 |
| 救援 | 打开牢门并保护有真实生命值的救援对象走到安全区；单人也可完成 | 解锁营地补给；失败给替代目标，不让全局永久卡住 |
| 营地 | 免费选择一次强化、替换祝福或弹药补给；不给所有选项 | 提供修正构筑的机会；已有金币商城继续承担额外采购 |
| 祭坛 | 按提示处理多个不同位置的供能目标；法术/远程与近战都能完成 | 首领少一种区域封锁机制 |
| 宝库 | 接受提前展示的精英组合；不只是增加血量 | 增加一份有上限的材料/装备抽取机会，不保证顶装 |
| 首领 | 地面预告→动作→恢复窗口；小怪和场景机关配合 | 胜利写结算记录后发奖、自动返程；留影是可选动作 |

保留服主已要求的即时满血、满魔力和负面清除，所以营地不再把回血包装成有价值的选择。压力来自关内战术、有限失败次数、路线机会成本和能力搭配。沿用三次挑战/检查点规则；增援传送允许战斗中加入同一场次，其他独立队伍不能抢入同一 Boss 房。

## 局内祝福与装备

首期只做六种祝福、最多携带三种；给玩家三选一和跳过/替换选项。下面三个是待实现、待平衡的例子，不是当前已可施放的新技能：

| 祝福 | 触发及初始假设 | 策略与边界 |
|---|---|---|
| 霜息回流 | 已有霜环命中至少两个不同敌人，本次施法返 2 魔力，8 秒冷却 | 鼓励拉怪与控制；一次施法最多一次，不返超额魔力，不由衍生效果递归触发 |
| 护卫余辉 | 真实格挡成功，为附近一名受伤队友提供 2 点短时护盾，6 秒冷却 | 鼓励前排保护；护盾不叠加，不把无敌伙伴算作可刷触发的目标 |
| 猎手协奏 | 已有印记目标被两名不同参战者命中后，下一次直接远程命中获得小额加成 | 鼓励配合；单人提供明确替代触发，不能强制带某职业，女仆命中只按实际参战归属统计 |

祝福退出本局即失效，不能复制成永久背包物品、出售或带到 PvP。现有背包、稀有装备、已学技能和金币全部保留。首期不做脱装、替换背包托管或永久属性重置。每场结算的物资价值以现役同难度遗迹为上限基准；基础层以补给和材料为主，深层风险提高稀有品概率，继续遵守现役保底与重复领取边界。确切掉率需在候选表、金币来源/消耗和不同职业实战后确定。

## 任务与提示应怎样改

1. 用现有罗盘/冒险大厅做“当前目标、换个玩法、继续远征”三张卡。每张只展示目的地、难度/装备差距、预计时长、本人进度和下一步；列表详情渐进展开。
2. 保留 `/mycli` 主入口，不增加一套无关短命令。现有 `arena status`、`dungeon list/info`、`tasks status` 继续可用；新分支动作只能从服务器当前选项复制，尚未实现的 `choose` 不写进入服 Skill。
3. Agent 与真人读取同一状态和选择：真人点原生容器菜单；Agent 取得稳定的活动 ID、选项 ID、版本、`available/reason/nextCommand`。菜单过期时返回最新选项，不换新 ID 重试未知动作。
4. 长期委托不屏蔽所有独立活动。保持每小时一次等现有间隔、战斗/考试/操作箱子时不打扰；不代接单、不自动放弃、不增加后台模型调用。
5. 后续再实现多张探索委托暂存：先设计旧一槽的无损迁移和单次原子提交，保留冻结规则、阶段、原 run 和证据；当前这份小补丁不碰账本。
6. 完成的唯一任务不再次推荐；新推荐优先未完成、同世界/可传送、不同玩法类别。长期无变化只能提示“当前未产生新进度”，不能断言玩家卡死；允许本人忽略提醒。
7. 留影与日记在完成真实事件后低频出现。记录本场路线和真实参与者，照片仍由用户决定公开，不让 LLM 台词伪造任务完成或自动发布。

## 本轮候选与验收

已实现的小补丁仅调整个人低频冒险引导：在原五类后增加试炼状态入口，明确村庄训练与遗迹攻略的区别；当前委托占位时仍可提示独立遗迹、拍照或试炼状态，但不推荐冲突的接单/晋级考试。原活动安全判断、通知间隔、玩家选择权保持。原来被同一全局门禁拦住的完成留影提示也可正常进入原有条件检查。

- 旧版对新增测试的预期失败：`village trial is discoverable in the activity rotation`。
- 新版 `AdventureChoiceTest` 42 项断言通过，覆盖六路轮换、已有委托、不可用场地/相机、极端游标及无冲突建议。
- 原 `GuildAdventureGuideTest` 通过；完整 `AgentCoach` 对正式 .78 类路径编译通过。
- 这些是代码及规则验证，不是正式客户端收件或自主采用，也不代表分支远征已建成。仅本地候选，未合并、未部署。

分支远征采用最小可玩章节验收，而不是一次堆满百层：

| 阶段 | 必须拿到的证据 |
|---|---|
| 规则原型 | 两条路线对不同职业/补给状态都存在合理选择；第一次选择在 90 秒内；没有必选职业或必选祝福 |
| 地图灰盒 | 每个门、楼梯、出口原生角色可走；进出和增援落点安全；保护范围与目标一致 |
| 关卡联调 | 单人、二人、女仆伙伴分别完整完成；机关、怪物、治疗、返程与实际库存变化匹配 |
| 故障回归 | 节点选择、倒地、奖励提交前后断线/重启；原选择保留、旧回执可查、不重复扣费发奖、不抹掉旧检查点 |
| 终端验收 | Java/NeoForge/基岩/Mineflayer 能选择相同路线，Eye/Web 能看到目标、选项、战斗及奖励结果 |
| 真实游玩 | 至少三个职业和真人/Agent 两类测试者；记录路线、时长、失败原因、重复查询、选择依据；可米原主人格日志单独验证采用，不能用代操通关替代 |

规则版本、场次 ID、已展示选项、所选节点、祝福、剩余次数和已结算奖励必须持久化；随机种子只负责重现生成，不能代替当前状态。新旧场次按自己的冻结规则续跑，奖励按原请求/场次查询，不以新 ID 补单。

正式发布前先处理第一层旧故障的恢复/结算证据，再验证新内容，不将整图回滚当作方案。代码合并、候选实机、正式部署、真实自主游戏验收分别记录。仅 F 盘保存当次回退；有新进度后保留世界、物品和账本，回退功能入口/代码而非回灌旧存档。若出现重复奖励、进度丢失、不可退出、关键提示缺失或持续性能退化，停止新开场并保留现有场次供恢复。
