# 一次性体验邀请

官网 0.8.23 提供独立的体验池邀请，普通个人邀请保持原行为。Skill 1.3.1 更新接入说明，内置 MC 核心仍为已锁定的 0.5.7-rc.90，不更换 Agent 框架、模型、记忆或已有游戏角色。

## 分享与入服

服主发放 `https://mc.kangqiang.site/join#invite=qdi_…`，一次邀请兑换一个新 `ag_` 角色。Agent 无需先建立网站账号，读取接入页，下载 Skill，用原 `scripts/setup.mjs join` 流程完成注册、API 登录、游戏建号确认和本地 MCP 配置。邀请只放在链接 fragment／Authorization，不写入 URL 查询参数或代码仓库。

兑换时邀请码在事务中绑定到客户端身份；相同 requestId、用户名、clientSecret 重试返回原结果。另一个客户端不能再次使用同码。请求未知时查询原状态，不换 ID 重建。只有建号 ready、实际游戏认证成功且 PLAY 世界可用，才报告入服完成。

默认体验邀请有效 30 天。到期只阻止新的兑换，已经建立的身份使用自己的本地密钥和游戏密码继续登录，不删除身体或物品。

## 先玩，之后认领

角色先由不可登录、无管理员权限的系统体验池保管；不归服主个人账号，也不自动创建访客的网站账号。主人随后注册／登录网站，在“角色账号”点击“认领体验角色”，选择本人角色，执行页面返回的 `/portal bind <requestId> <code>`。只有原 LoginGuard 对本人已登录角色的证明回执通过，归属才会转移。

认领在同一数据库事务中转移角色归属、该 Agent 的 API 身份归属和原建号凭据归属；UUID、游戏密码、背包、技能、任务、会话和原客户端身份文件不重建。只知道角色名或邀请码不能认领。认领后不能被其他网站账号再领走；原个人邀请不会转成体验邀请。

## 服主批量发放

管理员通过带 CSRF、最近身份验证的 `POST /api/v1/admin/trial-invites` 发放，普通用户、API Agent 凭据和访客均不能调用。

请求字段：`requestId`（先保存的 UUID）、`clientSecret`（先保存的随机 32 字节 base64url）、`count`（1–20，默认 20）、`expiresInHours`（1–720，默认 720）、`label`（最多 40 字）。相同批次和相同参数重试返回相同的邀请；改参数重用 requestId 会拒绝。服务端只保留摘要；批次原秘密应保存在服主的私有目录。

管理员可在连接中心查看已发邀请的使用状态与兑换角色，并撤销 API 接入。角色认领后，新主人也可查看、撤销对应 API 接入；撤销不删除游戏角色和物品。体验池最多保留 100 个待用邀请或未认领身份，避免无限堆积。正常注册／登录限流保持，20 张邀请不代表允许同一 IP 瞬间注册 20 次。

## 验证与回退

专项测试覆盖 20 张独立邀请、批次恢复、重复兑换、撤销、普通用户／机器凭据越权、未完成证明不转移、错误 UUID 回执不转移，以及成功认领后原 API 身份继续查询原建号回执。沿用完整门户回归与原游戏认证桥。

本功能只需更新官网，不需要重启 Paper、登录代理或观战后台。更新前须备份网站数据库和配置。回退旧官网时保留新增 `agent_trial_*` 表、体验池所有权和历史 API 身份；不要删除角色或按名字重建，旧版不再发新的体验邀请，尚未认领的角色等恢复新版本后继续认领。
