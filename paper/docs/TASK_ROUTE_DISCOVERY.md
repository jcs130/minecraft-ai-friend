## 为什么容易反复种田

线上核查发现：已经完成新手三证的角色，仍能重复接每日麦田委托。实际在途阶段要求在本单原先收获的八格补种，位置分散，旧状态只解释“原格”，没有列出保存的位置。大量重复状态查询不能帮助角色找到地块。

居民板的固定顺序又把麦田、菜园、钓鱼放在前面；路线内部仅按新手标志、等级和 ID 排序，已经体验过的日常和已经完成的一次性任务仍可能占据首页。存在这些服务端引导问题，不意味着已经证明客户端所有耕作行为都由服务端强制：角色也实际尝试过遗迹地下城。

## 探索与挑战的入口

- 路线 ID 和原命令保留。`tasks list` 先展示探索与发现、讨伐与副本，其他制造、补给、工程和生活路线仍可选。
- 路线内部按真实状态排序：当前在途、可接且未体验、重复日常、资格受限、今日已做、一次性已完成。排序不授予资格，也不会改变接单条件。
- 居民板先给主村庄附近的村路/画廊巡访、矿棚认路，再给试炼、遗迹和摄影；农事仍可自愿选择。古城继续作为高阶可选，不是新手前置。
- 新增 `tm_starter_tower`：本人一次，推荐普通难度，实际通关第二层后 `guild claim` 交付，不要求清完整座塔。试炼塔是 `arena` 的按层战斗；遗迹地下城是 `dungeon` 的逐室挑战。原副本、难度、救援、奖励规则独立。
- 已毕业角色的 `coach next` 给 `tasks list exploration`、`arena status`、`dungeon list` 和公共补给入口。已有农事不影响独立参战；但接另一张公会委托仍需原任务槽空闲。未先接的委托不追补证明。

出发前 `/mycli guild shared` 查询门口公共武器、护甲和补给；大背包和个人奖励箱仍使用各自入口。推荐都是查询入口，不会自动传送、参战、接单、换职业、购买技能或领取奖励。

## 原格补种

继续使用 `/mycli tasks status`、`tasks info <ID>`、`guild status` 和原实际动作回执。当前 `adventure.market.guidance` 在补种时追加：

| 字段 | 含义 |
| --- | --- |
| `replantTargets` | 原收获记录中尚未计数的作物格，含世界名及 X/Y/Z；最多八个 |
| `pendingRecordedSites` | 能从记录解析出的剩余地点数，不是补种进度或现场可用地块数 |
| `targetsTruncated` | 还有其他候选地点；已完成的位置移出后再次查询即可 |
| `targetSource` | 明确是保存的收获记录，未查询当前方块、权限或区块 |

优先同世界最近位置。作物格下方一格才是耕地。只计本阶段的真实补种；若此前已补种且重新长出，等待成熟后正常收获并补种，不拔幼苗刷进度。保护拒绝先查询权限。记录损坏或世界未知时明确说明无法定位，保留原记录，不猜坐标、不加载区块、不重置任务。

原冻结任务、阶段、八株门槛、奖励和动作证据保持。已计数地点按现有 `action-evidence` 排除；查询既不添加证明，也不读取方块或强制加载世界。没有自动放弃、重接或暂存农事。

## 限制信息量

默认给 Agent 精炼中文，不因名字以 `ag_` 开头就附送 JSON：

- `tasks list/info/status`：任务、进度、实际行动和下一条命令；补种列原格坐标。
- `world board`：标题、中文状态和任务 ID；用 `tasks info <ID>` 逐项查看条件。
- `coach next/guide`：直接给当前指引；阶段变化提醒只有标题和下一步命令。
- 真实动作计数：例如 `[委托] 已记录 1/8。命令：/mycli tasks status`，保留原限频。

需要程序数据时显式用 `tasks ... --json`、`world board --json`、`coach next --json` 或 `coach guide --json`。原 `mcagent:tasks`、`mcagent:market` 完整私有数据包保留，实际动作的结构化结果仍在协议中；登录认证、安全与死亡等必要回执不改格式。本轮不宣称所有历史 CLI 入口都已改为文本。

居民板 JSON 摘要只返回 ID、标题、真实可接状态、路线、图标及详情命令；原菜单详情仍保留。旧版全量居民板在实际 Mineflayer 中被截为 4096 字，尾部 JSON 无法解析；显式 JSON 查询保留 `MC_WORLD type=board`，并标 `detailLevel=summary`。仍超过 3200 字的世界查询复用现有 `MC_PAGE` 与 `nextCommand` 无损分片，不增加新命令。

反馈仅本人，沿现有消息通道；没有定时广播或增加循环提醒。
