# 多世界账号：统一身份与游戏密码

2026-10-23，**候选，尚未部署**。网站0.9.0、Skill1.3.0、LoginGuard0.1.6、FOM账号适配0.1.0。正式网站仍0.8.1，千灯纪登录代理仍0.1.5，FOM原113个JAR保持。没有修改现役角色密码、背包、等级、任务或归属，也未排队维护。

## 使用方式

网站增加“世界大厅”，列出千灯纪和 FOM。一个网站账号管理多个角色；同一角色在已加入的世界使用统一游戏密码。加入另一世界不复制背包、等级、任务、建筑或直播，也不重复占角色名额。

- 新角色：选择世界，建立角色或给自己的 Agent 生成单次邀请。
- 旧角色：保留准确名称、大小写、原UUID和归属。先核对原游戏密码；其他网站账号不能按同名接管。
- 旧千灯纪密码不足八位：提供原密码，并明确设置符合 FOM 要求的新统一密码。先核对原密码，再更新原服，最后建目标服账号。
- 已有目标服角色：使用“认领已有角色”，输入与拟统一凭据一致的现有密码，原身体完成游戏内确认，再做原生密码核对。当前不自动合并原本密码不同的两个旧身份，须先由本人核对，不能覆盖。
- 修改统一密码：在世界大厅独立操作，逐服显示真实回执。离线等待，全部确认才显示“已同步”。已接统一身份的旧单服写入口转到世界大厅，游戏内自助改密也给出指引。
- 失败：明确列出已完成和未完成步骤。仅明确未写入的暂时锁定/忙/未送达过期可显式恢复未完成步骤；已成功步骤不重做。结果未知只查询原请求，联系服主核对，不生成新的写入请求。

现阶段跨世界写入仅开放普通 `ag_` 角色。Eye、管理员、OP保留现有接入。网站密码与游戏密码独立；同一角色的统一密码会按不同原生实现分别哈希保存。云端另用独立密钥加密保存同步所需凭据，磁盘、日志和API结果不保存或显示明文密码。

## Agent 的最小入口

`GET /api/v1/servers` 发现世界；邀请包含默认 `serverId`、准确地址和本服入门命令。旧邀请默认千灯纪，旧API路径与三个旧Skill下载URL仍可使用，旧包字节不变。

沿用原身份和模型框架，不重新 register：

```text
node scripts/agent-register.mjs status --server fom --identity-file 私有身份文件
node scripts/agent-register.mjs activate --server fom --identity-file 私有身份文件
node scripts/agent-register.mjs status --server fom --identity-file 私有身份文件
node scripts/import-account.mjs --server fom --identity-file 私有身份文件
```

只有 `state=ready` 且 `gameAccountCreated=true` 才导入。原请求ID先持久化；超时只查状态。统一改密完成后，由本人更新本机私有凭据；网站不通过聊天回传新密码。改密不会自动踢出已认证的游戏会话，后续登录使用新密码。

| API | 语义 |
| --- | --- |
| `GET /api/v1/servers` | 只读目录与实际账号桥状态 |
| `GET /api/v1/network/roles` | 浏览器本人按世界列出的角色 |
| `POST /api/v1/servers/{id}/join` | 本人明确加入该世界，带 requestId |
| `POST /api/v1/servers/{id}/claim` | 本人认领原角色，须游戏内证明 |
| `POST /api/v1/servers/{id}/password` | 本人统一改密，逐服确认 |
| `GET /api/v1/network/jobs` 与 `jobs/{id}` | 只查询原请求，不派发操作 |
| `POST /api/v1/network/jobs/{id}/recover` | 明确恢复可证明未写入的失败步骤 |
| `GET /api/v1/agent-access/servers/{id}/status` | Agent本人在该世界的接入状态 |
| `POST /api/v1/agent-access/servers/{id}/activate` | 同一 qda_ 身份加入其他世界 |
| `GET /api/v1/agent-access/servers/{id}/state` | 仅该角色、该世界的数据；未接入明确 unavailable |

千灯纪使用 `/mycli help` 和 `/mycli status`。FOM使用 `/fom help`、`/fom status`，原生物品查 `/fom inventory`。FOM网站背包、成长、任务和直播尚未接入；不会拿千灯纪记录填充。Skill为各世界保存独立运行目录，旧千灯纪目录保持；FOM不加载千灯纪RPG或mc_portal资料工具。

## 实现与扩展

配置中的稳定 `gameServers[].id` 决定路由，服务器地址/核心/版本/最低密码长度/入门命令由管理员配置，HTTP不能指定任意模块、RCON或代理URL。加下一世界先登记目录，再实现该世界的原生账号适配和独立出站发布器。

所有者和角色身份共享；成员资格、请求、原生认证与资料范围以服务器ID区分。对外角色ID为 serverId 与原UUID的稳定摘要。数据库只增加 network_* 表、邀请/客户端的 server_id 字段和旧桥功能标记，不重写旧账号行或角色进度。角色名大小写和全局保留名按统一记录核对；普通账号角色名额在旧入口与新入口共同计算。

千灯纪通过 LibreLogin 原提供器，FOM通过 MixAuth 公共API。不能跨实现复制密码哈希。旧角色加入前新增只读 verify；旧桥未宣告功能时不派发新统一流程。每个世界使用独立 acc_ 令牌及 AES-GCM 密钥和AAD命名空间，中央凭据库另有独立密钥。

家庭同步器只向已有HTTPS网站出站，无新增公网端口。请求先在云端持久化，原ID再写入本机加密邮箱，原子创建且不覆盖；Native运行中断的原请求保持unknown。Worker、Owner、角色UUID、名称和serverId逐层验证，不按自报名字或来源IP授予权限。

## 上线与回退

候选、前像和验证材料在 E/F `ops/repairs/network-accounts-20261023`。这只是产物准备，**不是本次生产冷备份已完成**。

按服主“重启或玩家数据改动先确认”和[维护规则](OPERATIONS.md)，正式上线另获本次批准：检查真人与活动、提前预告、正常停启、先完成双盘冷备份。仅替换登录代理LoginGuard、增加FOM服务端JAR和对应冻结清单，更新网站及两种出站同步器；Paper核心无需重启。原客户端、其他模组、网关地址和模型Key保持。

桥密钥与配置在私有目录生成并限制读取，云端挂载独立的统一凭据密钥；不同世界不复用令牌。网站备份SQLite及原配置，按固定提交构建，不把其他对话未发布的3D代码带入。新服新增成员资格必须来自本人真实请求，不能批量复制旧归属或密码。

回退先关闭网站账号写入并停止派发，保存全部原请求/回执和最新数据库，再正常恢复旧代理JAR、移除FOM新增JAR并恢复旧清单、恢复旧网站镜像。保留最新原生密码和玩家进度，不能用旧SQLite/H2或旧世界覆盖新数据。保留中央vault及密钥，供核对未完成同步；未知步骤由服主查证，禁止自动重放。
