## 运行配置与热更新

运行文件是 `plugins/AgentFriend/block-access.yml`：

```yaml
schema-version: 1
enabled: true
editors: [] # 本机填写完整、已核实的玩家 UUID，最多16人；不填显示名。
villages:
  - world: world
    min-x: -634
    min-z: -530
    max-x: -458
    max-z: -365
  - world: world
    min-x: -1146
    min-z: -638
    max-x: -1078
    max-z: -567
```

正式名单仅保存在本机配置；上例 `editors: []` 表示不额外授权建设者。源码默认 `enabled: false`，保留其他安装的旧规则。

仅控制台／RCON 可以执行：

```text
mycli admin blockaccess status --json
mycli admin blockaccess reload --json
```

`status` 只读；`reload` 完整验证所有配置及世界后保存，成功返回 `MC_BLOCK_ACCESS status=success`。错误保留上一有效状态；超时先查询，不自动重放。旧维护习惯的 `audit` 作为只读别名保留。玩家继续用 `/mycli protect break|place <x> <y> <z> --json` 和既有批量入口查询，无须另记命令。

## 一致性与回退

同一策略用于真实挖掘、放置、多方块放置、水桶、工具改造及保护查询。WorldGuard 通过独立 `qd_block_access_` 区域覆盖方块构建标志，原区域、主人和成员均保留。开放区域按两处保留范围的精确补集生成，不加载区块或修改地形；建设者覆盖只匹配名单 UUID，不授予 OP 或通配权限。
