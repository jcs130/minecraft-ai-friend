# 无账号观战：同角色数据、动作和自由视角

2026-10-25的0.8.20候选已并入2026-10-26的0.8.21，尚未部署。最新公开范围与发布组合见[世界足迹](PUBLIC_WORLD_TRAIL.md)。现役官网为 22:33 上线的 0.8.19。
共享前端已推主干 `8b89927d`。本批只更新共享前端与匹配的观察宿主，不更换 Paper 插件、不创建 Eye，
不修改玩家物品或游戏认证。后续0.8.21另按服主要求扩大公开范围。

## 参考 Eye，但不登录另一个账号

现有 `CortiEyeMirror/EyeInventoryMirror` 根据实际附身目标的 UUID、实体和
维度镜像背包、生命与快捷栏。无账号观察源沿用同一原则：显示目标本人状态。

`WorldObserverPlugin` 已复用目标真正收到的区块集合、可见实体，以及已发出的
方块更新、粒子、声音、受伤和挥手包；只读快照补充生命、背包、服务端姿态。
`world-observer/worker.mjs` 转为现代前端协议，一份观察源经官网云端分发给多人。
不把原始全部网络包交给网页：自己的移动主要来自客户端上行，Numen 身体没有
客户端连接，窗口 ID 属于各自连接，登录载荷、聊天和私人数据也不能公开转发。
因此是“复用实际包 + 必要的同角色状态”，不是复制另一个 Eye 的状态。

0.8.21按服主授权默认公开真实角色及背包、装备，主人仍可关闭；
云端过滤凭据和私人Agent运行信息，公屏对话通过世界足迹读取。

## 本批修复

1. 角色闲置时 Paper 不发送 `activeHand`。旧适配器产生 `undefined`，严格状态
   校验因此拒绝整组展示信息，导致护甲/背包/最大生命/动作同时缺失。
   缺省值改为 `null`，不降低原校验；实际适配器到共享宿主的测试重现并修复。
2. 插值使用源采样时间，却只缓冲到达间隔。150 ms 传输延迟下，50 ms 缓冲
   总是追到最新旧帧，人物逐包跳动。改为测得源龄加到达节奏，最多 500 ms、
   64 个姿态，保持单调、不预测未来；断流和切换身份继续清空。
3. Paper 原 YSM 漏了背包预览身份标记。补齐后复用实际角色的原骨骼与当前姿态，
   不加载替代小人。可显示护甲数值与装备槽；这些 YSM 身上的穿甲外观仍未适配。
4. 增加“自由视角”：在当前已接收区块范围内旋转、平移、缩放，返回第三人称
   即继续跟随。不会新建游戏/观战连接，不额外拉取区块，不穿过缺失区块查询。
   小屏工具栏可换行。

## 数据与缓存选择

- 动作和 HUD：内存里保留有界最新状态及短插值环，不把每秒 20 次动作写数据库。
- 当前地形：现有云端单上行、检查点和增量链供多人共享；慢观众独立背压。
- 原模型和贴图：按实际内容哈希复用有界缓存；公共下载继续 OSS。私人资源
  保留鉴权，不能为了缓存命中改成公开链接。
- 长期历史世界：如以后需要跨已离线区域浏览，可用“维度/区块/修订号”索引
  配合压缩不可变文件与配额/过期策略；本批没有上线全世界持久数据库。

参考 [Prismarine Viewer](https://github.com/PrismarineJS/prismarine-viewer) 的
浏览器渲染与状态分离、[BlueMap 的分块存储](https://bluemap.bluecolored.de/wiki/customization/Storages.html)
以及 [Snapshot Interpolation](https://gafferongames.com/post/snapshot_interpolation/)
对抖动缓冲的说明。这里继续复用现代 YSM 前端，不用地图预渲染取代实时角色。
WebRTC 本身不压缩方块数据，也不能修复缺失状态；目前先解决已测得的数据与
时间轴问题，后续用真实 WAN 队头阻塞证据决定是否另换传输。

## 验证与发布

共享渲染 1,336 项通过、37 项原条件跳过；原 NEKO/桐人/可米资源专项实际运行，
覆盖走路、跑步、停下、攻击、吃喝及骨骼连续变化。真实浏览器使用明确标注的
离线夹具，原地形/原模型加 150 ms 延迟，验到红心、护甲、背包、持物与自由视角。
这些不是生产 WAN、手机真机或完整 Java 动画一致性的验收。

发布必须冻结匹配前端和观察宿主、核对 bundle SHA，并保留 E/F 配置及网站
一致性备份。只需重连官网与 SYSTEM 观察后台；Paper、登录代理、YSM 服务及
玩家连接保持。回退原代码和 renderer 配置，保留最新网站数据库和用户设置。
旧 0.8.19 已完成脚本不得重放；当次维护许可和系统确认按现有运维要求办理。
