## 实现

**静态应用缓存。** 只有通过受信清单SHA核验的两份应用JS，使用
`/watch/_static/<sha256>/<文件名>`，跨角色复用一年缓存。启动时生成Brotli/gzip，
支持ETag/304和压缩协商。CSS的原HUD图片使用角色相对路径，因此仍私有重验。
账号页面、实时画面、背包、聊天和玩家模型继续原鉴权；公共路径不能读取这些资料。

**四块有界确认窗口。** 新中继和发布器最多允许4×64KiB等待确认，减少每一小块都
等待一次网络往返的停顿。HTTP变慢时仅暂存该窗口并等待排空，顺序、解压上限、
取消和身份校验保持。旧端未协商时仍为单块模式。不新增WebRTC服务或家庭公网端口。

**首帧紧凑、后续增量。** 显式`terrainDeltas: true`启用区域内坐标索引，避免逐格重复XYZ。
隐藏地层保留带原材质ID的短碰撞行。后续只传变化的方块组、碰撞行和资料，未变的材质表、
群系及方块不重发。浏览器先还原完整原数组，再交给原渲染器。

增量必须对应当前epoch、注册表、模式和上一份场景序号，并通过原UUID/实体校验。
新观众、断线、缺少基线、背压恢复或大范围改变时发完整场景；各端只保留一份基线，
并隔离显示状态的原地修改。小改动避免为了选一个小补丁而重新打包整个世界。

已有遮挡裁剪继续生效：内部面和地表下封闭空间不建立模型；玻璃、树叶、楼梯、
洞口和未知空间采用保守规则。隐藏地层不能全删，否则相机、房间和粒子碰撞会把墙体
当空气；它们现在使用更短的可逆编码，更新时也不重复发送。

## 实测

下表是**真实NEKO场景的离线测量**；单块修改是明确标记的测试夹具，未操作正式世界。

| 数据 | 原方案 | 新候选 |
| --- | ---: | ---: |
| 主脚本首次下载 | 3,699,566字节 | Brotli 679,558字节 |
| 首次场景原始JSON | 526,845字节 | 333,167字节 |
| 首次场景gzip | 106,749字节 | 95,377字节 |
| 一次单块修改的gzip更新 | 完整场景 | 685字节 |
| 首次打开后刷新 | 重读应用脚本 | 两次打开共一次脚本请求 |

原状态ID、模型坐标、碰撞行和资料逐字段还原一致；实际HTTP的Brotli解压后与原脚本
逐字节一致。真实浏览器回放可见原NEKO和地形，第三人称跟随正常，约142FPS，
60秒帧间隔P95为8ms、P99为14ms，动作到达P90约67ms，控制台无错误。
这些结果不代表公网、手机GPU或16个自主Agent的长期吞吐。

共享渲染1291项通过、37项既有条件跳过；类型检查通过；门户247项和worker16项通过。
覆盖越界索引、错误/陈旧基线、原身份校验、新观众、重连、8MiB慢HTTP排空/取消、
旧单块协议及原NEKO/桐人资源。失败过程保留于私有测试记录。
