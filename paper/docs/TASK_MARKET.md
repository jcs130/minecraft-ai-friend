## 玩家和 Agent 的入口

罗盘 → 冒险者公会 → 「任务市场 · 千灯纪委托」打开原版箱式菜单。左键接单，右键看步骤；底部有当前任务、验收、交付、放弃和能力记录按钮。Java、Geyser 基岩可使用同一菜单，Agent 使用文本命令；`guild market` 与原 `guild engineering` 同义。

```text
/mycli guild engineering                  # 市场任务、开放状态
/mycli guild engineering tm_lantern_evening # 步骤、材料、场地坐标
/mycli guild accept tm_lantern_evening     # 接单（可自动入会）
/mycli guild status                       # 当前阶段进度；工程是上次验收快照
/mycli guild verify                       # 核查当前实际动作/结构
/mycli guild claim                        # 验收后交付本阶段，末阶段统一领奖
/mycli guild abandon                      # 放弃；已交付材料不返还
/mycli guild assessment                   # 只读本人的能力证据
```

任务/阶段 ID、坐标与条件来自服务器。不要把模型宣称完成、菜单图标或方块掉落物当作完成。备料可自备或从 `/mycli guild shared` 列出的门口公共箱取用；公会门内物品仍归萌萌，施工任务不授予私产或原建筑编辑权限。主动传送依然使用现有耗魔技能；不发放 WorldEdit 权限。

## 可组合的判定积木

| `goal` | `target` 与附加字段 | 真实判定 |
| --- | --- | --- |
| `donate` | 物品数；`item`，可选 `chest: weapons/armor/supplies/misc` | 普通真实背包物品；指定公共箱时先查容量并实际转入，失败回滚 |
| `craft` | 合成动作次数；`item` | 成功的原版合成事件；一次批量操作仍按一次事件计 |
| `fish` | 鱼数；`item: ANY_FISH` 或原版鱼名 | 钓到真实鱼的事件 |
| `lanterns` | 放置次数 | 已成功、未被保护取消的照明方块放置 |
| `floor` / `party_floor` | 次数；`floor: 1..15` | 通关指定层；后者至少两位实际参赛者 |
| `kills` / `witch_kills` | 击败数 | 现有试炼战斗计数；后者限女巫 |
| `claims` | 领奖次数 | 实际领取个人试炼奖励 |
| `explore` | 通常 1；`site` 为现有遗迹 ID | 当前世界中实际到达遗迹；远征指令仍耗魔 |
| `peak` | 通常 1 | 实际到达 Y≥120；只证明到达，不证明全程徒步 |
| `dimension` / `biome` | 不同区域数；维度、群系、距离与行进秒数 | 新路线实际探索；不计站定、旧采样点和传送位移 |
| `structure` | 不同区域数；原版结构键、区段与可选高差 | 同一座自然生成建筑内实际走查，包含 Y 和生成区段校验；自己搭建筑不能冒充自然遗迹 |
| `return` | 1；目标维度 | 另一维度探索交付后返程；不能单独配置成到访任务 |
| `map_hunt` | 不同区域数；路线/行进秒数、遗迹区段、宝箱周边和返程范围 | 接单绑定主手原图目标；实际新开天然藏宝箱或进入对应天然遗迹走查，再返接单点。`repeat: destination` 每人每个新目的地一次 |
| `build` | 新增白名单方块数；`site` | 逐格位置变化 **及** 同材料正净增量；不认泥土糊墙、掉落物、原有建筑或场内搬旧材料 |
| `road` | 新增可通行路面覆盖百分比 1..100；`site` | 固定单层走廊、指定材料、正增量和两格头部净空；分母为整个矩形路面带 |
| `bridge` | 新桥面块数；`site` | 顶面至顶面+4，指定材料，正增量、头部净空、两端连通；中间通路须是改变的桥面位置，锚点可保留原块 |
| `redstone` | 通常 1；`site` | 指定新增构件清单齐全，且每个指定输出在接单者实际使用场内按钮/拉杆之后观察到通和断两个状态 |

工程任务必须 `scope: project`，一个场地同一时间只归一位接单者，其他人可以帮忙但本版不拆分奖金。完工后工程和场地永久记账，不能用另一张任务重复结算同一工程。放弃会释放在办场地，留下已施工内容和放弃记录。组合工程最终交付时重新检查此前所有工程阶段，不能拆掉已验收桥面再领取后续机关奖金。

红石检查针对目标实际原版状态：灯是否亮、活塞是否伸出、铁门是否受电。接单者须在安装完成后操作场内按钮/拉杆；旧目标、不足构件、他人操作不算。成功放/拆场内方块会使旧通断证明失效，须重新调试。此检查证明配置中各输出确实通断，**不自动证明装置满足任意自然语言功能**；自动门应指定其门/活塞作为输出，可收放桥应配置实际执行活塞，不能仅配置一盏旁路指示灯来宣称桥已收放。

本版不评分美观，也不通过 CoreProtect 验证每个施工块的作者；验收记录是当前负责人提交的公共工程成果，不能据此把所有方块归功于某一位 Agent。需评价个人独立施工时，由运营者安排独立场地并观察行为日志。

```yaml
schema-version: 1
sites:
  # 仅示意格式；以下坐标必须换成实际勘察、允许建设且已经加载的场地。
  example_site:
    world: world
    min: [100, 64, 100]
    max: [106, 68, 104]
    deck-y: 64
    materials: [OAK_PLANKS, OAK_LOG, STONE_BRICKS]
    start: [100, 64, 102]
    end: [106, 64, 102]
    components: {PISTON: 2, REDSTONE_LAMP: 1, LEVER: 1, REDSTONE_WIRE: 5}
    outputs:
      - {at: [105, 65, 101], material: PISTON}
      - {at: [105, 65, 103], material: PISTON}
tasks:
  example_bridge:
    enabled: true
    scope: project
    title: 一起修一座桥
    description: 先备料施工，再调试机械。
    beneficiary: 来往的居民
    icon: OAK_PLANKS
    min-rank: 0
    reward: {fame: 30, emeralds: 12, bonus: BREAD, bonus-count: 6}
    steps:
      - {title: 架桥, description: 铺出可走的桥面并连接两端。, goal: bridge, site: example_site, target: 18}
      - {title: 调试, description: 操作拉杆让两个活塞真实通断。, goal: redstone, site: example_site, target: 1}
```

只允许控制台/RCON 或固定 UUID 的 Goddess OP 旁观者维护：

```text
mycli admin market reload                 # 完整校验；失败保留上次有效定义
mycli admin market list                   # 模板、场地、登记/占用/完工状态
mycli admin market register example_site  # 施工前逐格登记；等 registered 回执
mycli admin market retire example_site    # 无人在办时撤下；不清除快照和完工记录
```

`admin engineering` 是 `admin market` 的同义入口。已登记场地绑定真实世界 UUID，边界/材料/构件不可热改，登记不能重置。新工程用新稳定 ID；这样运营者无法通过重复登记旧建筑刷奖。已接任务的整份模板、步骤和奖励冻结，改文案、改数量、撤下模板都不悄悄更换在途任务。日常供货仍可用 [动态看板](DYNAMIC_BOARD.md) 的库存/天气/时令数据源配合工程备料。

备料完整示例在 `plugins/AgentFriend/examples/dynamic-board-engineering.yml`，增加 `supply_engineering_stone/wood/redstone` 三张低库存模板，交付到门口公共杂物箱。已有服只合并这三项到原 `templates`，保留已有运营模板；`admin board reload` 不更换今天的卡片，次日正常生成才按库存和优先级选取。`admin board replace` 是运营者的强制指定入口，即使库存已够也能发布，不能拿它当作自动低库存过滤测试。

受控初次发布可显式配置 `register-once: [场地ID, ...]`：启动后在已加载范围内按队列登记，最多等待约两分钟，不加载区块、不写方块、不覆盖任何已存在的快照（包括异常旧记录）。未成功的场地保持关闭，控制台到场后重试 `register`。日常 `reload` 不自动重新登记场地。

## 能力记录和协议

`mcagent:market` 的 UTF-8 JSON 只发给发起者；登记 Agent 入服、热更新/登记时收到可选任务摘要。Goddess/Eye 旁观者不自动接单、不成为施工者。`MC_MARKET_BOARD`、`MC_MARKET_DETAIL`、`MC_MARKET_CHECK`、`MC_MARKET_ASSESSMENT` 均带 `schemaVersion: 1`。聊天的 JSON 通知控制在 ≤256 字符，完整结构数据在插件频道。只读聊天的 CortiLan 也能通过普通文字收到目标、材料、桥两端锚点、构件数量、通断输出坐标及未达标证据；不依赖额外客户端模组。常驻目录可用 `/mycli list guild` 发现。

验收 `ready/progress/target/reason/evidence` 来自服务器；工程证据包括新增材料数、覆盖率、通路、缺少构件、真实通断目标数。生活步骤记录真实动作计数。保护拒绝、扫描繁忙、区域未加载或不在场不会算能力不合格；数量、覆盖、通路、构件或通断未达标会计未通过检查。`failedEarlierStep` 指出组合工程前一阶段失效。

本人记录按目标类型累计已验收阶段、未通过检查，保存最近 50 次任务的完整阶段、放弃/完成结果、运行 UUID、耗时和验收证据；协议返回最近 10 次。耗时包含离线和等待，不能直接作速度排行榜。完成次数是能力观察样本，不是智力、理解力、审美或协作质量的自动总分；结伴通关只证明完成了至少两人的通关条件。市场不会强迫 Agent 每天干固定的活，具体选择由角色自己决定。
