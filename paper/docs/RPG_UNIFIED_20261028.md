## Agent 只需记当前一步

先 `/mycli status`，看真实缺项与下一步；职业技能 `skills status/info <ID>`，原生任务 `tasks status/info <ID>`。查询不代执行，不把 verifyCommand 当成已经走路、制作或击杀。

背包满时先看 `/mycli inventory` 或 `arena stash inventory` 获取服务器槽位，再 `arena stash putslot <0–35槽> <1–64数量>`。直接远程存入本人540格奖励箱，成功才消耗2魔力，无需开GUI或先传送。用 `arena stash list [1–10页]` 核对；取物打开 `arena stash page 1`，也可换页。箱槽为1–540，背包槽为0–35，不能混用客户端窗口编号。绑定物品仍按原规则保留。

自然拾取遇到空间不足会私发短提示，同一人60秒内最多一次，不广播、不自动卖物或扔东西。同类堆叠可能仍可拾取，不把“无空格”误报成所有物品都无法拾取。intro/status 可给实际可存材料的精确命令，尚未选物时不伪造可执行下一步。

多余武器护甲走既有 `arena recycle list` → `quote bag|chest <槽> [数量]` → `sell <报价ID>`。报价30秒，核对完整组件、数量、原槽与所有权；手持、穿戴、绑定/任务/职业法器不回收。石头木头等材料存箱，不虚构材料收购价格。成交后核对 `trade wallet`；旧 `arena wallet` 是同一余额的别名。

原补给商店 `arena shop list/buy <商品ID> [份数]` 改扣同一金币，商品进入本人奖励箱待入箱队列；打开箱页后核对真实物品。玩家委托 `commission` 保留原目标与进度，发布托管、交付报酬和取消退款统一金币，不取消旧任务或重新收费。

## 确认与性能边界

金融接口复用 Vortex 的 Vault provider 和持久 RewardJournal。单人待对账索引只查一个索引与对应收据，不随历史成交数扫描全部文件；它是恢复证据，不保存第二份余额。回收先持久化原物品证据再移走并入账；商店先核验队列容量，再扣款和持久化商品；委托复用原原子状态文件。

未知窗口保留原物品/请求证据，不自动退款、补发、重卖或重领奖；收入、扣款、数量未知时明确返回未知。`arena recycle status` 查统一银行和待对账状态，联系服主按原记录恢复。已完成的同场次同层奖励有稳定ID，不能在重连、重启或重复回调中再发。

原生拍卖已复现“扣钱不交物”，本批在已知原生命令、别名、命名空间和vrp转发入口前拒绝；**不能宣传玩家拍卖已修好**。可用的是已验收的补给商店、装备回收和玩家委托。
