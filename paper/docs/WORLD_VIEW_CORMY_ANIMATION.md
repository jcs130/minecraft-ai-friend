# 可米原模型与观战动作修复候选（2026-10-25）

状态：已验证候选，未部署。正式观战仍为 0.8.15，Freesia 为 af3；之前的 af4 源码和观战 0.8.16 候选均不能当作已上线。本候选合并此前加载优化与默认第三人称设置。

## 实查与原因

可米的原始 YSM 文件和 Worker 保存的 `cormy-winefox-cream` / `cormy-cream` 选择仍在，`mandatory=false`。实际 Worker 存档、模型文件和代理在线 UUID 对应，不能把客户端皮肤显示当成模型文件丢失。但当前代理内存没有可渲染的原生模型状态，外观桥明确返回 `YSM_WORKER_STATE_UNAVAILABLE`，网页因此显示服务器皮肤。

原 af4 恢复候选只处理无 YSM 的连接。已安装 YSM 的客户端可能完成版本握手而没有重新选择模型，此时同样会出现空缓存。af5 将其纳入恢复，但必须等真实 Worker 的模型缓存初始化包已转发，不能仅凭版本回复抢发模型状态。

恢复使用私有 Worker 的原生命令只读回查，沿用原保存回执和事件，不模拟客户端握手、不执行强制换模型。每会话最多三次，5 秒间隔；每次扫描最多四个查询，40 个玩家上限；拒绝多 Worker 歧义、过期回执、会话/实体替换和超限 NBT。异步回执不能覆盖稍后收到的真实原生模型选择。

动作链另有两个缺口：Paper 受力速度可能在网络玩家走路时为零；高频移动帧缺少部分姿态/使用物品字段。现代前端现在使用单独标明来源的连续服务器位置差计算动画速度，保留原受力向量；重复同一服务器 tick 不再伪造新的移动 tick。姿态、攀爬、挥手和使用物品走高频小帧，完整背包仍限频。

## 验证与边界

- 105 项 Java 检查：真实管理器路径、读取门禁、原 PLAY 生命周期；包括原生缓存初始化前禁止恢复、并发原生选择优先、重连拒绝旧回执。无网络连接或游戏账号。
- 1307 项共享渲染测试通过，37 项既有条件跳过。原可米模型九类动作、采样之间的连续骨骼变化、原几何/UV/贴图/尺寸及持物通过。旧 af4 在新原生客户端恢复用例下复现失败。
- 桌面浏览器原素材离线回放看到原模型、持剑/苹果/药水、行走和第三人称跟随；没有浏览器错误。回放动作是明确标记的夹具，不是生产角色操作。60 秒窗口帧间隔 p50/p95/p99 为 7/21/29 ms，含七次超过 100 ms；不能据此宣称手机和公网完全流畅。
- 原桐人素材缺少部分待机、攻击和进食动画时如实报告未适配，不编造原素材不存在的动作。完整 Java 动画一致性未验收。

## 发布与回退

需要匹配官网与观察后台的同一冻结渲染源码，并仅将 Freesia 代理 af3 更新为 af5。Paper、AgentAppearance 0.3.3、Worker、登录鉴权和玩家数据不替换；不夹带其他玩法候选。代理正常停启会让 Java 玩家短暂重连，须按 OPERATIONS.md 和服主此前要求另行确认这一扩大后的维护范围。

正式切换前双盘保存当前配置、原 af3、af5 和网站完整前像，核对摘要。启动后检查原生模型状态、同 UUID/entityId 的网页绑定、原生客户端入服与模型同步、第三人称动作及延迟，再宣布上线。若失败，正常停启恢复原代理 JAR 和相匹配的官网/观察后台；不回滚账号库、密码、模型选择、世界或背包数据。

共享渲染实现与测试见 mc-visual-console 的 `renderer-src/docs/paper-observed-animation.md`；私有模型、捕获、JAR、配置和凭据均留在 Git 外。
