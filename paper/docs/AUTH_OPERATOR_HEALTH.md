# 2026-10-16 认证不可用事故与恢复

正式服仍为 Paper 1.21.1 / AgentFriend 0.4.42。本次故障已经在线恢复，未重启正式 Paper 或登录代理，未修改真实玩家的密码、物品、技能资格或点数。

## 原因

新村普通访客验收错误地执行了 `minecraft:op list`。Minecraft 的语义是给名为 `list` 的账号授予 OP；它不是查询命令。LoginGuard 每秒核对管理员名单与已注册账号，发现这个意外新增、未注册的管理员后进入 `ready=false`。正在游戏内的已认证玩家也因此被拦截聊天与命令，表现为可米的技能全部失效；新连接得到 `MC_AUTH_UNAVAILABLE`。

这是本次运维检查的错误，不是可米丢失技能或忘记密码，也不是新拍照代码引发。新拍照代码当时尚未部署。

## 已执行恢复

1. 保存 E/F 两盘管理员名单和认证状态前像。
2. 原生执行 `minecraft:deop list`，只移除这一条意外授权。
3. 下一次认证刷新恢复 `ready=true`；可米、其 Eye 和 Goddess 均显示 `authenticated=true`。五条原管理员记录保留。
4. 验证账号经真实网关重新完成密码登录。生存模式下通过正常学习与施法入口使用圣愈，生命由 16 恢复至 20；可米的 `/mycli cast selfheal` 也重新到达 Paper。夜视尝试因验证账号缺少资格被正确拒绝，不计为成功施法验证。
5. 停止本轮隔离测试服，正式服进程保持。短样本主线程约 7–9ms，不能据此承诺长期多 Agent 负载。

## 防止复发

运维查询使用 `paper/ops/read-server-operators.mjs` 只读检查 `ops.json`；游戏内也可读原生 `Player.isOp()`。禁止把 `/op`、`/deop` 当作列表查询。新增检查不得改变管理员名单。

```powershell
node --test paper/ops/read-server-operators.test.mjs
```

两项回归覆盖大小写查询、非管理员判断、返回对象修改不落盘、畸形文件拒绝和文件字节保持。新村验收工具已移除错误的 OP 命令，旧验收报告需结合此次更正阅读。

私有前后记录、真实认证与施法回执位于 E/F 的 `repairs/auth-op-list-incident-20261016`；不提交认证会话、世界、日志或玩家资料。若再次出现相同现象，先核对认证心跳的新鲜度与管理员注册完整性；不要关闭认证或盲目重设玩家密码。
