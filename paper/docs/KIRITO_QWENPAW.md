## 原账号登记

新增管理员命令：

```text
/numen resident adopt <原玩家UUID> <原玩家名> <配置账号UUID>
```

这一步只增加原生名册登记，不生成新 UUID，不复制到另一个角色，也不修改原玩家存档。登记后再单独启用常驻。检查包括：角色离线、没有同名登记、原 UUID 与 Bukkit 保存的名字一致、存档位置和维度有效、角色存活、角色与配置账号均非 OP、配置账号不是另一具同伴身体。普通玩家不能调用。

## 外脑工具和消息

适配器源码在 `paper/integrations/numen-paper/qwenpaw/`。仅暴露当前身体的 `list_companions`、`lua`、`command`、`skill`、`todo`、`memory`、`say`、`events`；不提供新建／删除同伴或代答权限征询。原生 Brain 令牌仅覆盖桐人这一个 UUID，服务端只存哈希；明文令牌保存在受 Windows ACL 保护的服务配置中，随服务器插件目录一起备份。

- `command` 执行本角色的正常游戏命令，权限、消耗、冷却和保护照常生效。它取得同一次执行的原始命令结果，避免原生 Lua 表显示和6000字stdout把JSON截短；超限不重放动作。
- 入门先查 `/mycli help`、`/mycli status`、`/mycli tasks status`；职业用 `/mycli profession status`。接口按需用 `numen.api.help(...)` 学习。
- 游戏内私聊 `/msg ag_Kirito <内容>` 可进入原生收件箱。其他玩家的私聊通过原版 `/minecraft:msg <真实发送者> <答复>` 回复。
- 空收件箱不调用模型；系统查询回执和未提及桐人的闲聊不唤醒模型。原生查询和相关私聊、危险事件可唤醒；轮询等待 10 秒，事件轮次串行并间隔至少 15 秒。
- 本次调试配置关闭该 Agent 的定时心跳与模型自动重试，单轮最多 12 次迭代。没有宣称设置模型日硬限额。Shell、桌面等内置操作未启用，其他 QwenPaw Agent 配置保持。
- 动作超时标记结果未知，先查询实际状态；不自动重复游戏动作或重新提交不确定的模型轮次。网络恢复只重建连接与收件轮询。进程锁避免同一身体重复启动控制器。
- 收件内容短时防抖两秒，之后相同文字可作为新消息处理；依赖原生收件箱原子取件，不宣称具备跨所有故障的精确一次语义。日志轮转保留至多四份约 8 MiB 文件。

## 发布与回退

候选摘要和范围见 `paper/manifests/numen-kirito-qwenpaw-candidate-20261020.json`。本机 E/F `repairs/numen-kirito-qwenpaw-20261020` 保存固定产物、21 文件未排队计划、原配置和核验记录；这不是完整停服备份。

正式流程：取得本次确认 → 180／60／10 秒通知与原真人／活动门禁 → 原维护任务正常停服并完成 E/F 全量冷备份 → 固定摘要替换 → 原服务启动 → 管理员登记原账号 → 原生配置皮肤和单角色令牌 → 启用 QwenPaw → 再核对物品、职业、模型和实际私聊。引导脚本没有本次批准记录会拒绝执行。

回退先停用 `mc-kirito`，保存并停驻原桐人，恢复本次插件及服务器配置前像，再按原流程重启；原星灯可按原 UUID 重新召唤并启用常驻。保留桐人当前玩家存档、职业库、Minepacks 库和原生角色目录，不恢复整个旧世界或覆盖这些库。重新开放旧外部机器人前，应先在维护中解除该角色的原生登记并核对同名连接；不能同时开放两个控制器。QwenPaw 只回退该独立 Agent，不用旧全局配置覆盖其他 Agent 的新设置。
