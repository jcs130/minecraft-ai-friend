# 原生客户端与统一认证

状态：2026-11-02隔离候选，未替换正式后台。正式仍使用原NanoLimbo登录场景；不能将源码合并或隔离验收称作已上线。

完整客户端的基线是Minecraft1.21.1、标准NeoForge21.1.252、原版车万女仆1.5.3与原版YSM2.6.5。普通Java、基岩和Mineflayer继续由服务端适配，不要求安装这些Java模组。基岩版本更新另见[网关修复](CLIENT_COMPATIBILITY_20261101.md)。测试用客户端自动操作模组只负责正常登录、重生和查询，没有改协议，不进入分发包。

## 登录场景

NanoLimbo是原版协议，无法完成完整女仆客户端要求的NeoForge频道协商。直接去游戏后端又会绕过原有认证，因此不能作为接入方法。

候选复用LibreLogin官方的真实认证服务器入口：在Velocity注册同名auth服务器，使用与游戏相同的Youer和三个内容模组，运行独立、空白、旁观模式的登录世界。仍由原LibreLogin数据库及LoginGuard检查密码、失败次数、原UUID与授权状态。未认证时不能调用RPG指令或进入游戏；收到MC_AUTH_SUCCESS并能查询世界后才算完成。正式当前采用NONE转发模式，候选沿用它，不套用旧Paper的modern配置。

`paper/ops/build-native-auth.py`仅从当前实例复制内核、类库、模组和EULA，生成私有RCON凭据；不复制世界、玩家数据、OP名单或现有密码。资源使用独立文件副本，避免启动器写缓存时改动源服。认证场景只监听127.0.0.1，固定旁观模式，不能对公网直接开放。

LoginGuard只在未授权且当前位于auth时阻止移动包，保持登录场景的实际位置；其它登录协商数据不受影响。三项实机检查确认未授权移动不改变服务端位置、场景保持旁观模式，以及密码通过后能在真正游戏世界正常移动，避免登录阶段游走加载额外区块。

原有YSM后台的Windows Job现在可同时管理auth和proxy：先等待认证场景就绪，再启动登录代理；正常关闭先停代理再停认证场景。维持原后台、控制凭据和维护锁，不新增计划任务。认证JVM为1536MiB堆，允许1024–2048MiB；原模型状态仍来自真实游戏角色，空测试状态不会被标成模型已就绪。PowerShell5.1的停服、子端口检查和冷备路径包含新的认证场景。

## 无修改Mineflayer的场景切换

实测1.21.4切换后端时，旧处理只覆盖766协议；残留移动字节被当作CONFIG设置包，Velocity在ClientSettingsPacket抛出Bad VarInt。LoginGuard0.1.10复用Velocity实际版本的设置包解码器，只在CONFIG状态校验packet0。有效设置、其它包ID和全部PLAY阶段数据保持；不会执行任何游戏动作或放宽密码检查。

766、767、769、774四种实际编码器覆盖有效设置、额外字节、截断、残留移动、读指针及引用计数，25项通过。原来的Known Packs保护保留。

原失败次数在成功登录后没有清除，与提示中的“连续错误三次”不一致。候选只在原认证事件的密码、正版、管理员和观战身份检查全部通过后清除计数，并原子保存；保存失败则本次不放行。三次连续错误与十分钟锁定规则保持，不因发送login命令或连接成功而清零。

## 已完成的隔离验收

标准NeoForge完整客户端已从本机私有密码文件登录，收到MC_AUTH_SUCCESS，读取真实Vortex角色状态；女仆与YSM均实际加载。无补丁Mineflayer协议1.20.6、1.21.1及1.21.4分别通过旁观认证场景、未认证拒绝、错误密码拒绝、正确密码入服、真实游戏模式及RPG查询六项检查。首次缺少测试依赖、错误转发模式、未重生、旧配置包兼容和累计失败锁定的原始记录均保留，不计为成功。

新构建的空白认证场景与登录代理已由原Windows Job启动。正常冷停启、五项冷备摘要和两个JVM重新启动检查通过；最终Guard包下的三协议与原生客户端复测通过。连续三次“输错一次后正确登录”会清零，单独三次连续错误仍踢出并持久锁定十分钟，重连也被拒绝，共四项实际锁定检查通过。生命周期七项边界测试保持通过。物理基岩登录、原生模型视觉一致性与全部旧Java版本仍分别验收，不把它们包含在上述通过项中。

部署需当前组合的维护确认、原真人/副本门禁、180/60/10预告，以及E/F当前游戏和认证冷恢复点。回退只恢复代码和路由，保留发布后产生的账号、密码变更和游戏进度。不能重放已消费的维护入口。
