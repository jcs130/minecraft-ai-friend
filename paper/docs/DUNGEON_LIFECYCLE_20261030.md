## 实际故障窗口

Coobot 的亡灵墓穴在 06:26:28 开始，06:56:28 按原有 30 分钟时限结束，结束原因 `time_limit`，清理 2/3 室、战败 1/3 次。07:01:03 才发生被僵尸杀死的真实死亡。因此不是三次战败耗尽，也不能用 06:55 的活动状态作为 07:01 的救援保证。死亡坐标来自客户端报告；现有服务器日志不能独立证明当秒坐标。

原代码在 `SiteDungeonManager.tick/end` 删除活动场次、保存结果并清理本场怪物；`TrialRescueManager.releaseTeam` 只恢复已倒地角色。存活者依照既有规则留在原地。场次结束后不再有救援队伍，普通世界致命伤害走真实死亡。结束消息没有明确说救援失效，实时救援状态也没有显式的有效性字段，这是本候选修补的缺口。

## 最小行为修改

- 沿用存活者原地保留、倒地者走原有恢复流程的策略。结束/退出本人提示明确说救援已失效，并提示及时沿原路撤离；不强制移动存活者，不增设无敌、传送或奖励。
- 开场与 `dungeon info` 明示 30 分钟时限及适用范围，`status` 按实际时钟返回剩余秒数。当前运行故障暂停及已累计故障时间沿用原计时规则，掉线仍遵循原 5 分钟回场宽限。
- 超时、主动退出、其他队伍的新场次都不能恢复旧参战身份。历史结果保留，但显式标为 `ended`、`active:false`、`participant:false`、`rescueActive:false`。旧格式记录查询时只规范返回，不迁移或重写存档。
- 默认查询用短文本，结构化数据需显式 `--json`；保留待领奖下一步，不增加顶层命令。结束通知仍只发本场队员，日志记录结束事实，不广播 JSON。
- 原生 `mcagent:state` 的 `trialRescue`、原 RPG 上下文及观战 `rescue` 复用同一实时状态方法，无新定时器、后台进程、区块加载或实体扫描。

## 客户端读取约定

继续使用 `/mycli dungeon status [ID] --json`，不要把开场回执长期当作有效身份。

| 字段 | 含义 |
| --- | --- |
| `active` | 该地点当前是否有场次，可能属于别人 |
| `lifecycle` | 本人在所查地点的身份：`active`、`ended`、`none` |
| `participant` / `participantRun` | 本人当前是否登记，及当前本人场次 ID；未登记时 ID 为空 |
| `rescueActive` | 此刻是否符合原致命伤害拦截条件，包括身份、人数规则、维度/范围及生存状态 |
| `remainingSeconds` | 本人有效场次当前剩余时限；结束后不返回这个字段 |
| `endReason` / `endedAt` | 本人最近场次的已保存结束证据 |
| `lastOutcome` | 历史结果；其中的存档坐标和剩余机会不代表现在可用 |

原生救援快照增加 `active`、`team`、`rescueActive`。无有效队伍时 `active:false`、`team:""`、`rescueActive:false`，且没有 `checkpoint`。客户端应替换完整快照，清除旧检查点，不能把缺失字段合并成永久有效。旧 `rescueEnabled` 仍表示两人以上的队友救援；单人遗迹可以是 `rescueEnabled:false` 而 `rescueActive:true`，因为它适用存档点续关。

站在区域之外、处于其他维度或不满足生存状态时，可以仍有登记身份，但 `rescueActive:false`。它表示当前规则适用性，不保证未来不会死亡，也不代替每次危险行动前的最新观察。

`MC_SITE_DUNGEON_END` 日志保留原 `site/run/reason/clearedRooms/endedAt`，补充 `active:false`、`rescueActive:false`、`exitPolicy:standing_stay_downed_recover` 及原参战 UUID，便于核对哪个生命周期已结束。
