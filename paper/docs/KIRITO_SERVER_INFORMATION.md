真实 QwenPaw 已用两次工具调用读取任务和格挡详情，准确答出「当前无委托、一级 4 魔力/12 秒、学习需 2 点，解锁不等于学会」。这不是只对接口发请求的模拟测试。

`--json` 并非所有旧命令都支持；旧入口可直接返回 `MC_*`。先读该命令的 `--help`，不支持时会明确返回 `MC_QUERY_ERROR/UNSUPPORTED_FORMAT`，不能当作执行成功。命令数字返回值、回执 `complete=true` 分别只表示原命令返回值和传输完整，不代替任务 `success/status/reason` 或库存复核。

服务器内置身体没有客户端登录代理的观测。`authentication.status=unknown`、`authorized=null` 不等于未登录或掉线；身体在线情况用 `list_companions` 与 `numen.status.self()` 核实。

## 这次修复

1. **接管与首条调用的竞态。** 外脑连接发生在两个 tick 之间时，先接受的查询可能被随后一次 EXTERNAL 切换当成旧工作切断，留下后续调用一直忙。接收外部工具前先完成同一控制权切换；新增回归在旧版失败、修复后通过。
2. **长命令回执截断。** Lua 展示的 stdout 上限为 6000 字。复用已有 `Program.Outcome.returned` 保留原命令结果，经 MCP 可选 `structuredContent.commandReceipt` 返回，适配器只执行一次命令并读取完整结果；不靠重复执行拼页。普通 Lua 展示限制保持。原始命令数据上限 262144 字符，超限或旧端明确截断会报告不完整并要求只读核对，不自动重放动作。返回模型时正文只有一份，元数据只带完整性和行数。
3. **异步通知遗漏。** 满背包、维度变化、后台行动 done/failed/timeout/interrupted 可唤醒外脑；主动 stopped 和查询回执不会启动新的模型反馈循环。它们提醒重新判断，不证明任务自动成功。
4. **旧账号权限。** 上游 Numen 默认把 Bukkit 权限委托配置账号；本服没有 Vault，配置账号离线会导致 Minepacks 正常使用权限丢失。管理员明确 `resident adopt` 时才写入绑定原 UUID/owner 的服务端标记；Paper 保留该原账号已由 LuckPerms 注入的权限。新建同伴仍沿用上游委托方式，不授予 OP、不新增权限节点。隔离服普通大背包权限与原服既有 default 配置一致。

## 核心可以复用什么

运行时 `print(numen.api.help("numen"))` 返回 **18 组能力**，再按需查一个组或函数；无需把整份 API 和玩法手册塞进系统提示。

| 能力 | 现有入口 | 使用方式与验证边界 |
| --- | --- | --- |
| 身体与世界 | `numen.status` | 生命、饥饿、坐标、群系、维度、天气；已实际读取 |
| 周边感知 | `numen.scan` | 地面图、方块/实体、视线与容器；实体扫描已实读，其他查询按实际签名与许可使用 |
| 移动 | `numen.move` | 到点、跟随、避让、探索；之前已由真实模型完成行走；不宣称所有地形均已验收 |
| 随身物品和制造 | `numen.inv`、`numen.gear` | 计数、配方、合成、吃喝、手持与穿戴；本次读取库存，制造等接口只确认已登记 |
| 容器和世界交互 | `numen.gui`、`numen.use` | 原生窗口读写、开关、点击、床和实体；已验证本人大背包读与关，其余按玩家规则执行 |
| 采集、战斗、建造 | `numen.work`、`numen.fight`、`numen.build` | 现有执行器及结果回执可复用；本次未逐项实打、造屋或验证全部蓝图 |
| 行动计划和复用程序 | 原生 `todo`、`skill`、`memory`，`numen.module/task/time` | 计划、技能资料、记忆、Lua 模块、后台任务、提醒；原生 todo/skill 与公会委托/可施放法术是不同对象 |
| 千灯纪玩法 | `command` → `numen.mc.run` → `/mycli` | 委托验收、职业点数、法术、领地、摄影、补给都复用现有服务，保持原 UUID、权限、消耗、冷却与结算 |

`numen.locate` 与 `numen.creative` 虽在目录内，也不能因为存在就当作本服人人免费的定位或创造能力。普通生存中的特殊定位、飞行等先使用千灯纪已有技能和许可；不为能力测试开创造或放宽建筑保护。原生底层物品表按底材汇总，特色物品名称应补查现有 inventory 回执。

本次没有把 Boss 栏、材质、所有自定义载荷或画面包一概转成模型文本；任务和技能以服务端查询及原生收件箱为准。图形、相机、Web/YSM 继续走已有可视化桥，本次未做远端网页、Fabric/手机/Xbox 画面验收。Mineflayer 客户端的配方解析、客户端窗口确认屏障等补丁不装进这个服务器内置身体；物品名称、命令契约、进度和错误协议可共用。

## 验证与发布

952 项 common 单元、17 项适配器单元、6 项实际联机信息/容器检查通过；另有真实 QwenPaw 两查询、普通玩家私聊往返和系统提示不引发模型循环的证据。早期首查中断、6000 字截断、权限拒绝和测试夹具限流的失败记录均保留。Minepacks 可正常工作后会重新安放快捷头颅；检查真实物品和原库，不把快捷入口槽位固定在 0。

源码入口为 `paper/integrations/numen-paper/qwenpaw/`，原生变更仍收在 `patches/existing-player-qwenpaw.patch`。发布仍需本次维护确认、提前通知及原流程完整双盘冷备份，不能把隔离验收说成已在正式服接管。

正式控制使用独立的稳定事件会话，不沿用隔离测试对话；这不重置游戏进度或原角色记忆。
