# 真人语音的附近聊天转写

状态：QiandengVoice 0.1.3 代码候选，尚未部署。正式服仍为0.1.1；本候选同时包含 PR #86 的 Agent 连接状态修复，不需要先发布0.1.2再重启一次。官网、下载包和远端宿主没有自动升级。

## 玩家体验

真人使用 Simple Voice Chat 客户端说完一段话后，聊天栏显示：

```text
[附近][语音识别] 小鱼：一起去公会吧。
```

本人也看到识别结果，便于发现识别错误；即使附近没有其他玩家也可回显。无需再手工发一遍文字。同一实际世界、语音有效距离内的普通玩家、原版、基岩和 Agent 都可收字幕；普通语音最多48格，悄悄话按现有较短距离。未安装语音模组者能看文字，仍不因此具备原生语音收发能力。

`/voice captions off` 关闭本人转写接收，`/voice captions on` 恢复。说话者关闭字幕不妨碍附近其他人接收；没人符合接收条件时不调用 ASR。私有语音组仍不进入附近转写。

## 实现边界

复用现有 Simple Voice Chat 麦克风事件、Opus 解码、逐人分段及 CPU ASR。每段只识别一次，再用采音期间持续符合条件的听众交集分发；完成时再次校验世界、原连接会话和字幕开关。迟到者、换世界或重连的人不收到旧语音。原始麦克风 WAV 不持久保存。

只修改现有听众集合以包含说话者，并修改原生聊天标签。没有增加聊天插件、轮询、命令入口或模型调用种类。文字通过现有玩家系统消息发送，不能伪造真人签名聊天；不调用 `Player.chat()`，不重新进入普通聊天事件。因此识别文本里的 `!` 不会成为全服喊话，`/` 不会执行命令，也不会触发自动 TTS 循环。

显式订阅 `nearby_voice` 的 Agent 仍收到原 `speaker`、`speakerUuid`、`utteranceId` 和 `text`，不再重复投递聊天副本。事件类型即语音识别来源；按原 utteranceId 去重，不把自身回声当成他人来信。默认聊天适配器收到带标签的原生文字。网页聊天历史的主动收录不在本次范围内。

## 验证

- 0.1.2 隔离旧版：13项中4项失败，复现缺少明确标记、本人回显、悄悄话回显和独处转写；其余9项通过。
- 0.1.3 独立 Youer + SVC2.6.27：13项通过。六个合成账号覆盖本人、附近原版、结构化 Agent、150格外、同坐标异世界及关闭字幕；每帧和结束包都重复发送，仍只识别一次。悄悄话30格外收不到，4格内 Agent 可收。
- 正常停止隔离服并重新启动后，13项再次通过；Java边界、回执、诊断和连接状态共79项通过，兼容适配器11项通过。
- 开启合成说话者的自动配音设置再验，ASR文本没有调用TTS或音频归一化。全部测试只用回环端口、合成Opus和固定HTTP识别结果，没有连接正式服账号或使用玩家录音。

协议联测入口是 `paper/integrations/proximity-voice/tests/asr-chat-integration.mjs`，显式要求输出目录、`baseline|candidate|restart`、隔离根目录、Mineflayer依赖目录和兼容安装器。隔离根下 `lab/.voice-delivery-qa` 必须为 `LOOPBACK_ONLY_29520`；游戏/RCON/语音/ASR仅监听127.0.0.1的29520/29521/29522/29523，不能指向正式服。`synthetic-opus.json` 使用既有 `delivery-integration.mjs` 生成的合成音频帧。识别夹具返回 `!去公会集合 /spawn 只是识别文字`，记录 `asr-fixture-stats.json` 的 ASR 与其他请求计数，测试说话者的私有夹具配置开启 `auto-speak`。凭据随机生成且不入库。

这些结果验证识别文本的投递链路与边界，不代表真实麦克风、实际识别准确率或真人耳听已验收。上线后还需用一个新说话片段做真人验收，不重放之前失败或状态未知的语音请求。
