## 已核实的基础

用户提供的 [可米家园](https://dungeon.thereisno.app/town/#/r/c38/home) 属于 Cortico Dungeon Alpha，前端称苔灯镇。公开居民接口返回稳定角色 ID `c38`，名字可米，简介确实提到“从千灯纪来的猫娘冒险者”。家园、生产、装备制作/铭文、交易、照片及组队远征已有服务端记录。角色名和简介可以用于展示，但不能单独作为领奖身份凭据。

| 一手来源 | 实查结果 | 适合用途 |
| --- | --- | --- |
| [公开世界概况](https://dungeon.thereisno.app/town/api/overview) | 世界、居民、交易和远征摘要 | 活动概览，不直接评定个人贡献 |
| [可米公开资料](https://dungeon.thereisno.app/town/api/residents/c38) | 家园、装备、照片、访客和带 ID 的事件 | 旅行履历与经本人选择的作品展示 |
| [102号远征回放](https://dungeon.thereisno.app/town/api/raids/102/replay) | 回声矿坑、`outcome=clear`、成员明确含 `c38`，有开始/结束时间和步骤 | 证明可米参加了一次已通关远征；进一步贡献仍需解析步骤 |
| [协议握手](https://dungeon.thereisno.app/v1/hello) | 2026-10-15 13:35北京时间实际返回 protocol=2、世界名、时钟和时区 | 确认接口协议，不需要凭据 |
| [官方发布包元数据](https://registry.npmjs.org/cortico-world-dungeon) | 查询时最新版 `cortico-world-dungeon@0.1.5`，MIT、Node≥22 | 正式客户端接口与连接机制 |

公开页面 JavaScript 确认使用 `/town/api/events`，支持种类、角色筛选及 `before` 翻页。页面展示的聊天、报名、喊话和交易约定，不等于已经完成对应动作；本次没有逐条核实所有事件种类的验收语义。上述版本与世界数据均是查询时点快照。

官方 npm 包 README 与 `src/protocol.ts`、`session.ts` 静态核对得到：

- 角色控制走 `/v1/tools/<toolName>`，需要 bearer token；不是访问家园网页就拥有操作权。
- 一次性邀请码换长期 credential，再换短期 token；凭据保存在对方 Agent 自己的环境，不放进千灯纪资料包或聊天。
- 工具请求带 `requestId`，同编号重试返回保存的回执。SDK对不确定请求保留同一编号，不应换号重放交易。
- WebSocket `/v1/stream` 有每个 bot 单调增长的 cursor 与 ack/补发机制。公开事件 ID 与这条私有流 cursor 是不同概念，不能混用。
- 已有10个场景工具，覆盖观察、生活、战斗、远征、聊天、交易、家园和照片；已有 `give-confirm`、`photo-image` 行为能力声明。

本地千灯纪 Cortico 适配已有 `WorldDefinition` / `mymc` 与独立 Minecraft 资源声明，对方包是 `dungeon` World。两者有共同接入模型，值得复用同一 Agent 的身份与生活叙事；是否可在现役宿主里同时启用、如何分配注意力仍需实际宿主验证，本次未更新可米客户端。

## 建议先落地的三件事

### 1. 双界旅行护照

为本人展示来自两个世界的履历：去过哪里、做成什么、与谁合作、有哪些作品。千灯纪沿用实际 Minecraft UUID，对方用稳定角色 ID；显示名可改，不用名字作数据库主键。

首次绑定可由服主明确确认两个身份，后续开放时增加双边一次性验证。接入方保留映射版本与历史，不能因为改名把另一人的成就迁移过来。读取公开资料即可展示已确认绑定者的履历，无须千灯纪索要对方登录凭据。

入口复用命格书、旅途指南与统一 `progress`；细节按需读取，公共聊天不转发流水事件。不把两个世界的等级、技能点或货币直接合并。

### 2. 少量有故事的双界委托

| 委托 | 苔灯镇证据 | 千灯纪实际行动 | 初期奖励 |
| --- | --- | --- | --- |
| 苔灯镇来信 | 绑定后的真实家园/职业资料 | 在引路人处阅读介绍，主动建立旅行日志 | 护照纪念章、故事书页 |
| 双界工匠 | 绑定后完成一件有作者记录的制作；只拿他人装备不算 | 接取并真实交付本服指定物资，或在获准的工程地块完成建造 | 工匠评语、委托荣誉 |
| 回声与千灯 | 本人是指定远征的实际成员且服务端确认 clear | 本服完成一次探索/遗迹委托，拍当地合格照片并交付 | 双界游记、可自愿投稿的展品 |

任务下发时冻结双方条件、时限和允许的历史证据。过去的102号通关可以做纪念履历；新发布的挑战默认要求接单后完成，不能反复用旧通关领新奖励。没有新事件或外部接口暂不可用时，状态是“等待/无法确认”，不是判失败或清空进度。

现有动态板不能只增加几行配置就验收外部游戏。首期需要一次服务端开发：增加有限、明确的外部证据条件和组合验收；之后再由配置选择角色、来源、条件、题目与荣誉，日常活动不用反复发新版。仍用原接单/进度/交付流程，查询保持只读。

营地地坪现已保护，联动建造任务必须指向获准的工程地块，不能要求新 Agent 拆营地。跨界照片也不能冒充本服相机的实地考试照片。

### 3. 异界明信片与旅行艺术厅

公开资料实见可米的 photo 事件：图片路径、作者/同行者、场景、题注和时间均可关联。样本是128×85像素画照片；可保持比例放入 Minecraft 地图画，不应承诺变成高清实景照片。

作者主动选择作品后，可导入现有 ImageFrame/艺术厅机制，展示“苔灯镇来信”、作者、题目、故事、来源链接与日期。需要新增外部图片与本服展品 ID 的持久化关联，不能把当前已安装 ImageFrame 说成跨界署名已完成。

外部图保留 `origin_world`、原作品/事件 ID，默认放本人纪念册；投稿后才公开展出。千灯纪自己的相机继续记录实际游戏画面，探索考试继续检查本地现场证据。

## 服务端接法

首期采用千灯纪向公开接口发起 HTTPS 读取，复用现有本地服务与存储，不增加 Minecraft 的公网端口，也不在 Paper 主线程进行 HTTP。

```text
苔灯镇公开资料/事件/远征回放
            ↓ 有界缓存与拉取
    已确认的 UUID ↔ c38 身份映射
            ↓ 类型校验、事件去重、冻结条件
       本地外部证据账本
            ↓ 查询与验收
     千灯纪 progress / 委托 / 纪念册
```

- 同来源共享缓存，建议30～60秒合并拉取；只跟踪已绑定/接单者，分页有限额，失败退避。不要让16个 Agent 各自轮询整座镇。
- 原始证据保留来源、角色 ID、事件/远征 ID、发生/获取时间、内容摘要、验证版本和是否完整。关联本人时优先稳定 ID，不能只比中文名。
- 去重键包含来源世界、事件 ID、委托场次与条件 ID。领奖沿用本服原子提交/每日限制；网络重试不会再发一次奖励。
- 公共接口不是双方签名的结算协议。初期只发纪念、评语和有限荣誉；跨服货币、物品或技能点兑换需另行与对方运营方约定并验证。
- 若以后需要操作对方角色，复用官方 SDK 的认证、幂等与事件机制，并另获用户明确授权；不要给女神无条件的对方交易/聊天权限。
- 图片仅接受固定来源的合法图片路径，有大小/像素/超时上限；保留比例与署名。正文、事件和图片描述作为游戏资料，不能当作管理命令执行。

## 如何用于 Agent 能力认证

把两边的能力证据分别保存，综合展示：苔灯镇的合作、供货、制作和回合计划；Minecraft 的空间移动、工具操作、实时战斗、现场探索与照片叙事。参加通关只证明参加已通关队伍；战术贡献需要回放里的实际行动，聊天活跃度不计作贡献。

每项成绩展示来源、完成条件、缺项和下一步；外部系统不可达明确显示未确认。先做一个可米自愿参与的委托闭环，再扩展多人和排行榜，避免先造出没人理解的新规则。

## 第一轮验收

1. 先只读展示可米的确认履历，身份映射正确、改名不串号。
2. 一个新委托完成双方条件后仅结算一次，重复事件/重连/服务重启不重复发奖。
3. 聊天约定、仅报名、他人通关、接单前旧事件、缺页证据不能误过关。
4. 断网、超时、旧缓存显示等待/未知，恢复后继续核对，不重放交易。
5. 纪念册照片署名、比例和来源正确；未投稿不公开，外部图片不能通过本服实地考试。
6. 查询不接单、不消费，回执只发本人；普通Java、基岩、Mineflayer都能通过现有书/菜单/CLI读取。
