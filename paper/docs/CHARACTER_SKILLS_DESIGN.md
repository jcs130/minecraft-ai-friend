2026-10-08 设计提案。初版已于 2026-10-08 16:09 正式发布为 AgentFriend 0.3.92；准确玩法、配置、已实现范围及部署状态见 [职业与传承实现记录](CHARACTER_SKILLS.md)。本页保留总体设计，导师调整、继承及后续剧情等设想不能当作已上线能力。

首发已按最新要求收敛为战法牧、通用基础、有限技能点及可付费洗点；下方更广泛职业草案为后续设想。

让玩家与 Agent 通过擅长的行动承担不同职责，并在冒险中获得有来历的个人能力。首批以桐人的剑士路线为完整样例，同时为治疗、守护、侦察和生活生产留出发展空间。采用现有 AuraSkills、MagicSpells 与 AgentFriend，新增职业资格和传承账本；后续运营通过配置发布已经支持的技能与解锁任务。

## 现服基础

运行环境是 Paper 1.20.6 与 Java 21，已安装 AuraSkills 2.4.0、MagicSpells 4.0 Beta 15、LuckPerms、WorldGuard 和 CortiEyeMirror 0.1.9。桐人账号 `ag_Kirito` 已实际在线，处于生存模式。职业档案绑定服务器核实的玩家 UUID，展示名可修改。

现有法术、个人熟练度、公会资历和统一魔力规则见 [技能体系](SKILL_SYSTEM.md)。羽落和夜视已有学习状态；大部分其他主动法术按统一目录提供，尚无完整职业专属资格检查。工程与探索委托已有实际验收和本人历史，可作为传承奖励的依据，见 [任务市场](TASK_MARKET.md)、[探索委托](EXPLORATION_CONTRACTS.md)。

Goddess 继续担任观察者与世界运营角色。真人与 Agent 使用相同的职业规则；角色差异通过玩家的选择和经历形成。

## 插件选择

以下功能来自各项目官方资料；“本服用途”是结合现有代码的选型判断。

| 插件 | 官方提供的能力 | 本服用途 |
| --- | --- | --- |
| [MagicSpells](https://github.com/TheComputerGeek2/MagicSpells) | 配置法术、效果与组合逻辑，支持学习和施法权限 | 首选效果引擎，已有运行基础。职业资格、特殊奖励和 Agent 接口由 AgentFriend 对接 |
| [AuraSkills](https://wiki.aurelium.dev/auraskills/api) | 长期技能、属性、魔力及自定义内容 API | 保留为唯一魔力池和长期能力数据源；职业解锁与单法术熟练度分别记录 |
| [MMOCore](https://docs.phoenixdevt.fr/mmocore/features/classes.html) | 可配置职业及职业属性；[技能](https://docs.phoenixdevt.fr/mmocore/skills/intro.html)可由等级、任务或技能树解锁 | 完整 RPG 框架候选，涉及现有属性、魔力和施法入口的整合；先确认 1.20.6 对应构建与迁移方式 |
| [Fabled](https://github.com/magemonkeystudio/fabled) | 源自 SkillAPI 的技能框架，提供职业与技能动态编辑器 | 编辑复杂技能的候选；选择对应版本并验证原有魔力与权限接入后再采用 |
| [BetonQuest](https://betonquest.org/2.1/Documentation/Scripting/Building-Blocks/Integration-List/) | 剧情任务条件、事件与 AuraSkills、MMOCore 等集成 | 剧情分支和导师任务的后续扩展。现有公会验收和奖励账本继续作为已完成委托的依据 |
| [MythicMobs](https://wiki.mythiccraft.io/mythicmobs/Skills/Skills) | 用机制、目标选择器、触发器和条件配置怪物技能 | 后续制作剑士试炼首领与特殊入侵事件；玩家职业资格仍由职业系统管理 |

MagicSpells 官方[版本记录](https://github.com/TheComputerGeek2/MagicSpells/releases)明确说明 Beta 15 仅支持 Paper 1.20.6；该页面的更新版本面向不同 Minecraft 版本。当前实现应固定已验证构建。新增第三方插件的 1.20.6 启动、API、存档和基岩体验需要隔离验收。

MagicSpells 的[权限说明](https://github.com/TheComputerGeek2/MagicSpells/wiki/Permissions)区分永久授予与临时授予：撤销 `magicspells.grant.*` 权限不会自动遗忘已授法术，`tempgrant` 才随权限存在。因此，职业切换应保留已学履历，并在每次施放时检查当前资格；LuckPerms 用于权限对接。

采用 Paper 服务端技能，交互继续使用原版物品、罗盘、菜单、粒子与声音。[Geyser 官方 FAQ](https://geysermc.org/wiki/geyser/faq/)说明一般插件可使用，但仍有协议差异及资源包转换限制。首批玩法以原版协议完成，新增双持动画与 Java 专用按键不作为解锁或施法条件。

## 职业与个人特性

能力分为通用能力、职业专精和个人传承。归乡、安全传送、基础生存查询与原版操作保持通用；新剑技、专业治疗和侦察能力由对应专精解锁；特殊经历赋予个人传承。已学旧技能、AuraSkills 等级与公会历史保留，职业改造从新增技能开始。

每人可选择一个战斗主职及最多两个生活副职，也可以主修生活职业而暂不选战斗主职。首版建议准备四个新职业主动技能和一个传承技能；通用导航与旧授权保留现行入口。学习记录永久保存，切换专精只改变当前可准备的技能。脱战并回到导师处才能调整，冷却与已付资源不会被重置。

| 路线 | 主要职责 | 新技能方向 | 可形成的个人传承 |
| --- | --- | --- | --- |
| 剑士 | 近战突破、护送、处理高威胁目标 | 突刺、弧光斩、架势格挡、步法斩 | 双剑觉醒、破魔刃 |
| 守护者 | 守村、掩护、保护队友 | 短时护盾、拦截、消耗魔力的守护领域 | 守村誓约 |
| 游侠与侦察者 | 勘路、发现敌情、远程支援 | 标记敌人、警戒、弓术专精 | 遗迹追踪、先驱之眼 |
| 治疗师 | 有效治疗、救援、支援远征 | 定向治疗、短时净化、救援护持 | 晨曦誓约 |
| 矿工与探险家 | 发现矿脉、地下勘察、提供材料 | 探矿专精、矿脉记录、危险提示 | 深岩共鸣 |
| 工匠 | 建造、维修、公共设施运营 | 施工勘察、消耗魔力与真实材料的修缮 | 匠心 |
| 农事师 | 食物补给、种植、农产供货 | 作物专精、消耗魔力与骨粉的催生 | 丰收祝祷 |
| 炼金师 | 药剂准备、材料研究、远征补给 | 有限配方与药效专精、消耗真实材料的调制 | 药师传承 |

桐人优先采用剑士路线。其他 Agent 的主职按选择与实际行为引导，不因名字自动分配。委托展示推荐职业及所需能力，普通供货、探索、施工与组队任务继续允许跨职业协作。

## 桐人的剑士路线

下表是待隔离平衡的首版参数。每个技能要求主手持剑、对应已学资格、可用魔力及冷却；攻击只选择允许战斗的敌对怪物，并通过正常伤害与保护事件结算。玩家、村民和家畜继续受到保护。

| 技能 | 初始效果 | 魔力与冷却 | 获得方式 |
| --- | --- | --- | --- |
| 突刺 | 3 格内可见单体刺击，基础技能伤害上限 8 点 | 4 魔力，8 秒 | 剑士入门试炼 |
| 架势格挡 | 预备 2 秒，减免一次正面近战伤害的 50%，最多减免 6 点 | 4 魔力，12 秒 | 剑士入门试炼 |
| 弧光斩 | 前方扇形最多 3 只敌人，每只基础伤害 4 点 | 7 魔力，12 秒 | 护送或协作战斗委托 |
| 步法斩 | 沿无遮挡安全地面前进最多 3 格并斩击；检查完整路径与区域权限 | 6 魔力，15 秒 | 路线勘察与近战进阶 |
| 剑气 | 最远 10 格的直线攻击，碰到墙体停止 | 8 魔力，16 秒 | 要塞远征与进阶试炼 |
| 双剑觉醒 星流连斩 | 约 2 秒内分段追击，总基础技能伤害上限 16 点；每段重查目标与保护 | 14 魔力，90 秒 | 双剑传承任务链 |

双剑觉醒以服务器连击和剑光呈现，主手持剑即可从罗盘或 Agent 命令施放。连击期间的普通攻击与技能伤害按同一施法归因，避免重复结算；保持正常伤害保护时序。先以有上限的实伤完成玩法，再扩展展示动画。

格挡采用可提前准备的架势，给真人菜单操作与 Agent 动作执行留下时间。模型选择施放时机，已授权的短时连击和格挡由服务端执行；每个伤害段使用有界事件处理，无需逐帧调用模型。

## 特殊任务与事件解锁

| 经历 | 验收依据 | 解锁方向 |
| --- | --- | --- |
| 剑士入门 | 完成导师登记的近战目标，记录本人对不同敌人的有效攻击并归还试炼 | 突刺与架势格挡 |
| 双剑传承 | 分阶段完成组队试炼、有效格挡和不同类型首领挑战；本人具有实际贡献 | 桐人的双剑觉醒路线，保存传承故事与来源 |
| 下界要塞调查 | 沿用真实探索、区段与返程验收，并完成登记的战斗阶段 | 剑士破魔刃或侦察者遗迹追踪 |
| 村庄守望 | 已确认的实际入侵成功结束，本人存在有效伤害、治疗、减伤或目标保护记录 | 按职业授予守村誓约、晨曦誓约等对应传承 |
| 公共建筑落成 | BUILD 实际增量验收、交接成功，负责人登记安全公共地标 | 工匠传承与公共建筑履历 |
| 长期生活委托 | 分日期完成真实供货、种植或药剂交付；同一领取不重复累计 | 丰收或药师传承 |

普通职业传承允许多人通过任务学习；“世界唯一”能力显式配置限额，例如一位有效继承者。限额、获得者 UUID 和历史写入持久账本，继承或退役通过明确的世界事件处理。桐人的特色传承可限定角色资格，其他玩家有各自的传承路线。

团队奖励按各自有效贡献结算，兼顾输出、治疗、守护和任务目标。记录真实参与者、事件或试炼 run、结果与贡献，等待成功终态后发放。收到警报、路过坐标、空放治疗、死亡后补记或最后一击都不能单独证明完成全部条件。

现有市场已有击杀、层数、工程和探索判定。有效格挡、治疗量、事件贡献及技能奖励需要新增适配；相关新判定完成后才能热运营上述任务。

## 配置与持久化

目标是分开管理 `professions.yml` 职业定义、`skills.yml` 技能元数据、`skill-unlocks.yml` 解锁规则，以及按 UUID 保存的角色与授予账本。技能效果引用固定版本的 MagicSpells 配置或 AgentFriend 已实现效果。

下面仅示意未来配置结构，0.3.91 不读取这些新字段：

```yaml
skills:
  sword_arc:
    title: 弧光斩
    profession: swordsman
    requires: [sword_in_main_hand]
    effect: sword_cone
    cost: {mana: 7}
    cooldown-seconds: 12
    limits: {radius: 3, targets: 3, base-damage: 4}

unlocks:
  sword_arc_trial:
    source: guild_contract
    source-id: sword_escort
    skill: sword_arc
    repeat: once_per_player
```

工程 handover 和技能奖励可以并存，委托验收后分别交接管理权与登记学习资格。新增资料在接单时冻结，热改不会更改在途奖励约定。已有完工记录的补授要求原验收证据，先生成唯一收据，再幂等写入角色账本；失败保留 pending，修复后恢复，避免重复发放。

技能书可以作为有来历的实物凭证，服务器保存的学习资格与授予来源仍是依据。改物品名称、复制描述或转交书籍不会自动授予未获准的个人能力。

热加载先校验引用、数值范围、唯一限额和效果类型，成功后整体替换内存目录；失败保留上一有效配置。后续新增职业、已有效果的技能变体、任务条件组合和解锁奖励可改配置。新效果类型、新判定或新的第三方接口仍需一次开发及发布。

## 施法和 Agent 接口

所有新技能使用一个资格入口检查当前职业、已学状态、准备槽、装备、活动、目标、魔力、冷却及 WorldGuard。罗盘、法杖、`/mycli cast`、直接 `/cast` 和触发式效果遵循同一入口；检查实际执行资格，不以隐藏菜单代替限制。游戏内 OP 也使用玩家成本，Goddess 观察者不能以玩家身份施放。

AuraSkills 继续作为唯一魔力池，MagicSpells 内置魔力保持停用。无权限、无目标、落点不安全和施法前失败不扣费；格挡架势成功准备后即有成本。多段技能首次真实生效时结算一次，之后中断按已生效处理，确保实际位移与伤害都有资源成本。冷却、资格和账本跨正常重启保存。

Agent 沿用 `spells list/explain`、`mcagent:state` 和技能事件频道，补充本人职业、已学/可用/未解锁原因、准备槽、装备要求与获得途径。拟新增 `profession status/menu`、`skills mine/prepare` 和私有 `MC_SKILL_UNLOCK` 回执，均是待实现接口。普通玩家用罗盘查看同样信息，已登记且实际附身的 Eye 获得对应私有提示。

能力评估记录有效伤害、成功减伤、有效治疗、探索验收、工程履历和合作贡献。Agent 可以据此规划接单、装备和支援职责；查询成功、发出命令、累计施法次数分别记录，不等同于已经完成战斗或委托。

## 首批实现与验收

先完成角色目录、UUID 资格账本、统一施法检查、技能奖励收据和罗盘/Agent 查询，再接入桐人的突刺、格挡、弧光斩及一个传承任务链。治疗与侦察各提供一条可验证的专精路线，避免其他角色只能旁观剑士成长。后续再扩展首领、剧情分支和生活职业技能。

| 验收内容 | 要验证的结果 |
| --- | --- |
| 不同角色 | 剑士能施放其已学剑技，其他角色从菜单、命令和道具尝试均被明确拒绝 |
| 任务与事件 | 未完成、没有有效贡献和重复回执不授予；成功获得真实资格和对应故事记录 |
| 重启与热改 | pending 授予恢复，唯一名额不重复，在途条件、旧学习状态与历史保留 |
| 实际效果 | 真实怪物伤害、实际格挡/治疗和位移独立验证；魔力只扣一次，失败原因准确 |
| 保护规则 | 村民、普通玩家、私产与受保护建筑不被技能绕过；没有免费位移或造物 |
| 多端使用 | Java、普通 Mineflayer 与原生 Eye 验证回执；基岩手机/Xbox 真机验证菜单和施法 |
| 16 Agent | 并发短时技能与事件有界，无全世界逐 tick 扫描；分别记录稳定 MSPT 与接入/探索尖峰 |

首次部署代码需要按 [维护流程](OPERATIONS.md) 完整备份和正常发布。此提案只修改设计文档，正式服现有技能、职业资格和已获物品保持当前状态。
