# 动态粒子引导线

2026-10-12：已随 AgentFriend **0.4.27 正式部署**，同时包含商旅交易板和特色道具说明；发布与回退见[联合发布](COMPLETED_FEATURES_RELEASE_20261012.md)。下方隔离验证记录描述原0.4.26候选。

## 玩家体验

- 探矿、探敌、队友追踪、商人定位和能力考场的下一目标共用同一条规则：**从角色当前身体位置，完整连向真实目标坐标**。
- 探矿终点是矿块中心；探敌终点是最近活敌人的身体；移动角色或目标后更新。考场终点是当前检查点，不替玩家完成移动。
- 移除旧的“只画前10格、遇墙截断并画墙面方框”。长距离按全程均匀采样减少密度，保留起点和准确终点，不截去后半段。
- 这是一条方位直线，**不是寻路结果，也不保证可通行**。墙、深坑和领地仍须用正常操作绕过。原版粒子会受到地形遮挡；`longDistance` 只扩大客户端粒子距离，不提供穿墙渲染。
- 只发送给本人和当下实际附身的 Eye/live；附近玩家不会收到其他人的引导线。矿物消失、区块卸载、敌人死亡、停止追踪、跨维度、角色死亡或下线后停止；旧粒子按客户端生命周期消退。

## 原有规则

稳定技能 ID、扫描范围、原真实坐标回执、技能点资格、魔力和冷却均保持。探矿仍为6魔力/30秒、探敌仍为3魔力/15秒，无目标不扣费。Java 的原私有目标轮廓继续保留；基岩仍通过 Geyser 接收原版粒子与顶部方向提示，无需新资源包或修改 Agent 客户端。

不改正式玩家、背包、任务、领地或原世界。队友和商人定位仍受原可见性与已加载实体限制。

## 实现和预算

`GuideLine` 生成完整直线，正常间距约0.65格，每帧最多64点。`TargetGuideParticles` 统一维护最多128条临时引导，收到原玩法心跳才保留；每8tick尝试更新，源位置在渲染时读取，目标由玩法每10tick刷新。

全服每tick最多256粒子包，每连接每tick最多128包，每条线最多本人加3位实际附身观察者。不足时延后**整帧**，按轮转顺序处理，避免预算把线尾截掉。用标准 `END_ROD` 定点包直接单播，跳过旧 Eye 镜像的128包/秒限制，防止截断和重复转发。发送粒子不扫描地形、不加载区块、不生成实体；探矿持续检查新增已加载守卫，卸载后不再读取矿块。

距离参数参考：[Paper 1.20.6 Player.spawnParticle](https://jd.papermc.io/paper/1.20.6/org/bukkit/entity/Player.html)。

Web宿主与浏览器的批次上限一起由64提高到256，保留2048活粒子、80格距离和有限缓存上限；避免施法装饰与两条64点引导同帧时丢失终点。共享源码已适配，远端网页需要重新构建；本轮没有宣称远端实际画面验收。

## 验证与发布

- `GuideLineTest` 检查水平/垂直/斜向/远距离、精确两端和非有限输入。
- `paper/probe/target-guides-stage.mjs` 在固定回环隔离服核验真实配方兼容客户端、完整粒子坐标、移动、目标消失、实际附身 Eye、陌生人隔离及16组同时引导。
- `paper/probe/target-guides-bedrock-stage.mjs` 通过隔离 Geyser 核验基岩原生 `END_ROD` 坐标、移动和清理；不等于手机/Xbox实际画面验收。测试先用 `plugins/AgentFriend/tests/BedrockParticleMapProbe.java` 和固定 Geyser/服务器依赖核对2193真实枚举，再记录该JAR摘要到私有 `bedrock-particle-map.json`；诊断客户端的旧字符串标签不能代替真实事件编号。
- 私有结果位于 E/F `repairs/target-guides-20261012`。早期创造模式学习被正常拒绝、测试角色过密/首次位置回执/整数坐标自动居中及基岩诊断客户端旧粒子枚举标签的失败记录均保留；未以改生产协议修正夹具。最终原生47项、基岩13项、Web桥接/GPU15项和几何331断言通过。

发布需要另获本次 Paper 维护批准，并按 [维护规则](OPERATIONS.md) 预告、检查真人/活动副本、完成 E/F 停服快照后替换唯一 JAR。没有新增运行账本或迁移；回退代码可正常停服换回原 JAR，保留最新存档及原玩法数据。源码提交和候选构建不会自动部署。
