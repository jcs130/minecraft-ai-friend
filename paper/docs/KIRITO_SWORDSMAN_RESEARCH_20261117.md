## 本服采用的设计

职业显示为 **剑士**，桐人的独有专精为 **二刀流**，合并展示为“剑士·二刀流”。“黑之剑士”放在称号字段，不作为职业 ID。本服职业结构是对原作与官方游戏的改编，不声称原作存在同名固定转职体系。

成长优先敏捷，其次力量；定位为灵活的近战输出。依靠走位、攻击间隙和连段，生命与防护维持普通近战水平。常用单手剑，获得实际副手剑与专精后使用双剑。弓箭作为通用身体能力仍可使用，但不作为桐人的职业成长主线。

第一阶段技能设计如下。名称、数字效果与原作依据分别记录，所有本服消耗、冷却、距离和升级曲线必须在实现时实测，当前不公布虚构数值。

| 能力 | 设计作用 | 依据与边界 |
| --- | --- | --- |
| 二刀流专精 | 两把真实单手剑满足条件后，解锁双剑连段；仅一把剑仍能使用普通剑术 | 原作标志性能力。副手展示和副手实际参与攻击分别验收，不能拿装饰剑充数 |
| 剑步 | 短距离接敌或侧移，给连击创造位置 | 本服自创基础技，不冒称原作专有技能；遵守碰撞、落脚点及领地规则 |
| 水平方阵斩 / Horizontal Square | 前方近距离连续斩击，用于处理贴身敌人 | 以官方游戏剑技为依据；本服命中次数、扇形与硬直需另测，不默认附带眩晕 |
| 星爆气流斩 / Starburst Stream | 桐人代表性的双剑爆发技，具有启动条件、持续过程及收招代价 | 官方十六连击意象；实际受伤次数与粒子斩痕分别记录，不能用十六次特效伪装十六次有效伤害 |
| 技能连接 / Skill Connect | 后续成长：在合适窗口衔接两种已学剑技 | 来源是 ALO 技巧的官方游戏改编；首阶段不默认解锁，也不等于无限取消冷却 |

暂不为同一初始角色叠加飞行、神圣术、夜空之剑解放与所有后期形态。The Eclipse 可作为后续高阶内容，当前资料不足以直接锁定本服整套招式参数。

## 现有代码的实际约束

- 当前 Vortex `ClassSkillService.applyLiveAttributes` 中敏捷影响移动速度，力量影响攻击属性，体质影响生命与防护。**提高敏捷不等于已经提高攻击频率、闪避率或暴击率。** 新的剑术节奏必须有执行逻辑和实际命中证据。
- `classes.yml` 能登记独立职业 ID、名称、基础属性和初始法术，但技能树仍以原生 `VortexClass` 枚举分类，`unlockSkill` 也核对该分类。只给游侠或骑士换名会继承无关技能，不能算完成剑士专精。
- 必须同步扩展职业列表、独立技能树、学习条件、已学技能、施法门禁和居民发现接口，继续共用本人 UUID 的 Vortex 等级、学习点、魔力和冷却。
- 正式桐人当前的 `ranger` 档案尚未迁移。迁移需保存 UUID、记忆、经验、物品和旧技能记录，按真实已投入点数处理转换；不能靠重选职业重置或重复发初始装备。仅修改居民配置不会覆盖已有 Vortex 档案。
- 普攻、寻路和装备使用继续由身体执行；LLM 选择战斗目标和策略，不逐次请求模型挥剑。二刀流选择器不能沿用“超过五格必切弓”作为角色默认战斗风格。
- 剑技结果提供实际目标、伤害、消耗、剩余冷却、完成/打断状态。Java、基岩和 Web 共享服务端结果；YSM 双剑动作只是表现层，尚需独立验证。

## 上线前验收

1. 新职业按需可查询，原六职业的技能、点数与升级行为不变；剑士不能学到游侠弓术或骑士坦克树的错误分支。
2. 普通近战、双剑、失去副手、缺少资源、目标跑出范围、隔墙、友方、死亡和停止均有真实结果，失败不报告命中。
3. 连招的每次有效伤害通过原防护与敌我判定；Minecraft 受伤间隔不能被忽略。中途打断、离线和重启后不重放消耗或补发未发生伤害。
4. 新技能在学习点、魔力和冷却的原生档案中持久化；AI 能从 `skills info` 查到准确条件，而不是把完整技能表塞进人设。
5. 真人 Java、基岩及 Web 验证动作/声音/粒子与数值一致，再安排正式迁移。研究完成不等于这些验收已经通过。
