2026-10-26 实查与候选。正式官网仍为 0.8.25；以下新代码须冻结匹配的共享渲染源，再更新官网和观战后台。Paper 与登录代理不用重启。没有开通新的收费 CDN，也没有将未发布照片自动公开。

## 本次代码改动

1. **地形重叠复用。** 旧算法只有一段前后缀差分；视野移动一格会改变每行边缘，导致中间大量未变坐标一起重发。新增有界多段差分，按原始坐标/隐藏实体段找锚点，保留原顺序、原状态ID和碰撞信息。仅在更小时选用；断线、换维度/注册表、基线不符时仍须完整快照。浏览器与观战源必须一起更新。
2. **合并缓存排队。** 原有最多8个正在填充的资源，超过后直接回源，多个观众会重复取同一张材质。改为每个来源8个并行、256个有界等待项，同路径共享一个结果；满队列返回429，不另起不受控回源。撤权、换角色源和关闭会取消等待，响应前再次鉴权。内存仍按LRU限制，不写无限磁盘缓存。
3. **可测量。** 观战状态增加命中、未命中、合并、活动与排队计数。原单来源SSE分发、背包/动作分频、原资源SHA校验、gzip传输和客户端有界插值保留。
4. **聊天和内容。** 对话按时间显示头像、名字、气泡；正在观战的角色在右侧。更新保持原直播窗口和读消息位置。照片显示同步核对时间和公开照片补传数量；档案区分别说明“没有新作品”与“同步不可用”。导航后台刷新不再关掉正在操作的手机菜单。
5. **同步额度隔离。** 发布前检查捕获账号桥间歇性HTTP 429；账号、外观、照片和档案同步与同一出口下的网页访问共用300次/分钟额度，可能导致心跳过期。现在先校验指定同步路由的专用凭据，再使用其原有独立额度。账号30次/分钟、外观24次、快照/档案12次等上限不变；错误凭据、浏览器Cookie/Origin、错误方法或未知路由仍受公共限流。登录防爆破不变，不重放建号或改密请求。四项回归先复现旧代码失败，再验证公共额度耗尽后同步可用、独立上限仍生效。

### 对照回放

取真实NEKO场景的17,350个绘制方块，在同一捕获内截取7个相邻视野，逐帧还原后与原输入深度相等。没有操纵线上角色。

| 7个视野总计 | 旧算法 | 新算法 |
|---|---:|---:|
| 原始JSON | 2,600,423字节 | 1,251,943字节 |
| 同参数gzip | 503,483字节 | 215,622字节 |
| gzip节省 | — | 57.17% |
| 单帧编码本机样本 | 约16–23ms | 约25–30ms |

这是离线相同输入的带宽/CPU权衡，**不是线上首屏提速57%**。首次完整地形、原模型下载、手机GPU和长时间多人抖动需要部署后单独测量。保留有限窗口与原隐藏碰撞段，不把未知洞穴当空地，也不预扫描整个世界。

## 缓存部署方案

| 数据 | 推荐位置 | 更新和失效 |
|---|---|---|
| 公开下载、宣传片、版本化脚本 | 已有OSS；下一步可接独立静态CDN域名 | SHA路径，长期immutable；HTML/资源清单重新验证 |
| 原版材质和公开角色模型 | 当前浏览器SHA缓存 + 云端来源隔离LRU；确认可公开资源后再做OSS内容寻址 | 游戏版本、资源摘要与优先级一致；不可把私有角色路径无条件映射成公共URL |
| 当前地形 | 云端每角色单流、完整基线+有界差分；未来按世界/维度/注册表/区块修订共享只读瓦片 | epoch/sequence不符重取基线；角色动作不放进长期地形缓存 |
| 实时位置、动作、血量、背包 | 复用单来源的实时流和短期内存状态 | 不经CDN长缓存；慢观众不能堆积过期动作 |
| 照片、日记、事件 | SQLite持久索引与分页；原图按摘要去重 | 已有作者/时间索引，明确发布/撤回；不要把每秒20次姿态当永久数据库记录 |
| 登录、邀请码、凭据 | 当前鉴权链 | no-store；不可CDN缓存或混入公开流 |

资料库已经使用SQLite，不需要为了“有数据库”另加一套。只有实测多实例并发写或查询瓶颈后再评估PostgreSQL/Redis。地图长期历史浏览可借鉴BlueMap按瓦片生成和压缩的结构；不能直接把全世界预渲染与实时YSM/背包/技能画面画等号。

下一阶段CDN验收应只灰度公开静态目录，核对CORS、压缩Vary、304与内容SHA，记录冷/热首屏和命中率，再决定是否扩大。大陆加速域名须满足备案要求，计费和域名变更另行确认。WebRTC可用于未来视频或低延迟状态流，但它本身不解决重复地形或原素材缓存；本轮保留已有HTTPS/WSS链。

## 照片和故事为什么没增加

本轮游戏日志有24张照片，其中3张标记已发布；官网也有这3张，照片编号及原图SHA256逐张一致。21张未发布作品不会被同步器擅自展出。最新拍摄为10月24日；公开照片目录仍以10月21日及以前作品为主。

游戏档案库本轮没有`book`/`notice`作品，只有事件及照片版本；云端档案来源正常且核对时间新鲜，所以这次空书库并非有书未同步。官网4组共同回忆仍在，它们是用户提供的原图/重绘故事；系统没有凭空自动生成新回忆。玩家签名书、公开相机作品和网站发布回忆是三个入口，应各自显示真实来源。另发现的同步额度竞争会影响后续传送可靠性，已纳入候选修复，不能因本次目录一致而忽略。

## 研究依据

- [BlueMap外部Web服务](https://bluemap.bluecolored.de/wiki/webserver/ExternalWebserversFile.html)：将地图拆成预压缩瓦片交给独立Web服务；适合借鉴静态世界分发。
- [BlueMap实时更新配置](https://bluemap.bluecolored.de/wiki/configs/Webserver.html)：瓦片与标记更新可通过SSE推送。
- [阿里云OSS与CDN](https://www.alibabacloud.com/help/en/oss/user-guide/cdn-acceleration)：静态对象边缘缓存、更新和地域接入要求。
- [MDN HTTP缓存](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)：内容版本、条件请求及共享缓存边界。
- [SQLite适用场景](https://sqlite.org/whentouse.html)：当前单应用资料查询可继续使用本地数据库；部署时不要把数据库文件放网络共享盘。
- [Snapshot Interpolation](https://gafferongames.com/post/snapshot_interpolation/)：动作流需要处理到达抖动，不能简单按收到一帧就跳一次。
- [ws压缩说明](https://github.com/websockets/ws#websocket-compression)：压缩有CPU/内存成本；现有gzip块不再叠加未经负载验证的permessage-deflate。
