# 后台启动的控制台空输入修复

状态：启动参数候选，尚未用于正式游戏进程。紧凑信息栏和模型修复已经上线，当前正式状态以[部署清单](../manifests/current-deployment.json)为准。

普通后台启动继承了关闭的标准输入，交互式 JLine 控制台反复读取 EOF，重复输出 `> ` 并建立输入线程。正式线程采样中，控制台线程约670秒内消耗约265秒CPU、累计分配约9.5GB对象；这是累计分配量，不是常驻内存占用。游戏仍可运行，但会产生无用日志和GC负担。

`manage-server.ps1` 仅在现有JVM参数中增加 `-Dterminal.jline=false` 和 `-Dterminal.ansi=false`。原堆内存、GC日志、缓存补丁、服务端、角色、登录和RCON管理方式保持；没有在线替换类、停止游戏线程或修改系统权限。

隔离验证使用原版同内核与内容模组的游戏服务，启动后真实关闭标准输入，检查游戏继续运行、控制台线程退出，以及EOF之后的提示符和日志增量，最后通过原RCON正常停止。实测20秒内游戏保持运行、控制台线程退出，新增提示符与日志增量均为0，最后正常停服。普通日志中的 `-> MISSING` 不属于控制台提示符；首轮全日志子串计数的误判保留，最终只度量关闭输入后的增量。离线回归另核对常驻启动入口确实传递两个属性，保留原内存、GC及隐藏后台参数。

正式启用需要按既有维护门禁、180/60/10预告、最新E/F游戏及认证冷恢复点正常重启。运行文件应从正式现有脚本做精确增量，保留其独立改动，不能用仓库整份脚本覆盖。此前信息栏与模型维护入口已消费，不得重放；本项不能改玩家、职业、背包或凭据。
