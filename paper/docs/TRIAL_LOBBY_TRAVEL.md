## 原因与改动

旧 `WaypointManager.actor` 将两种条件一起当作 `in_activity`：
实际参加试炼/PvP/地下城，以及单纯站在受保护场地。试炼传送的入口走道
也属于保护范围，所以未参战访客被误拦；执行退出命令不会改变脚下范围，
于是继续收到“先离场”的错误建议。

0.4.23 将记录地点与离开地点分开检查：

| 情况 | 处理 |
| --- | --- |
| 未参战，仅在入口或固定场地内 | 可返回本人/分享/地标的已有安全地点，成功仍消耗六魔力 |
| 实际试炼、遗迹或 PvP 参战者 | 仍拒绝自定义传送，需按对应活动规则退出 |
| 在固定场地内新建、更新地点 | 仍拒绝，返回 `activity_area`，明确说明应在场地外登记 |
| 自定义点的目的地是活动场地 | 仍拒绝，改走对应官方入口 |
| 等待传送时状态变化 | 再次检查参战、移动、落点及保护规则 |

CLI、结果频道和既有原因码保持；不改 Agent 客户端，不给免费传送。
`in_activity` 表示已有活动资格（含竞技场排队、恢复），不由脚下位置单独触发；`activity_area` 的中文和 JSON 建议不再
把访客描述成正在参赛，不再建议对未参战者反复执行 leave。

未参战且需要离开入口的玩家也可使用
`/mycli goto village`（六魔力）返回村庄；成功后以实际位置和回执为准。
