# 艾因格朗特居民的住址与日常

住址让居民有固定的家。职业决定他们已经具备的技能，住宅旁的花圃、菜地、钓点和摊位则提供日常活动。一名居民可以去看望邻居、到公共钓点消磨时间，或者把真实收成带去交货。活动由居民按当天的观察与作息选择。

## 先登记实际住址

2026-11-20 现场核对了艾因格朗特营地的一处住宅。实测门口是 `(-672, 67, 825)`，外部门牌在 `(-671, 67, 823)`，牌上写的是「桐人的家」。`lands.yml` 的 `aincrad_kirito_home` 和对应的 WorldGuard 区域 `qd_land_aincrad_kirito_home` 均登记为桐人的原游戏身份。保护范围为 `(-675, 66, 826)` 至 `(-668, 73, 832)`。这处对外住址登记给桐人。

现役 `config/tlm-residents.json` 把同一门口、室内与女仆床配置为结衣的运行锚点。它供女仆身体回家、休息和安排工作使用。结衣的独立住址要等另一处实际房屋核验后再登记。既有原生住房接口会区分公开门口与内部床位、工作点。 [原生居民住房](../integrations/touhou-maids/standalone/RESIDENTS.md)

每套门牌以街道和楼层内稳定的编号标识。勘测时依次记录维度、楼层、街道名、房号、门口坐标和已走通的入口。上下两层的房间即使平面坐标相同，也用各自的门口高度区分。空屋保留门牌和空置状态。新入住在同一笔登记中检查该门牌和该居民是否已有有效入住记录。

入住归属以居民的 `characterId` 为准。`bodyId` 用于原生门、床、背包、领地和执行回执的授权。居民换用 Numen 或车万女仆时沿用原住址，并重新核验新身体的床、路线和权限。网页的房屋标记放在公开门口，实时居民标记仍取现场位置。公开信息只需要住户名、门牌、门口、楼层及公开职业。 [统一身体接入](../../packages/agent-harness-py/integrations/README.md)

## 入住登记和公开导出

从 `paper/integrations/agent-portal` 运行操作员脚本。先核对角色 UUID 和已勘测空屋的地址 ID。把入住请求和专用 SQLite 文件放在本地的私有目录。以下私有请求中的 UUID 和地址仅为格式示例。

```json
{
  "characterId": "7fa54de0-c402-4113-bff6-d95747a00001",
  "homeId": "surveyed-home-id",
  "resident": {"name": "栗灯", "profession": "园艺师"}
}
```

```sh
node scripts/aincrad-housing.mjs assign --db /path/private/aincrad.sqlite --request /path/private/occupancy.json
node scripts/aincrad-housing.mjs export --db /path/private/aincrad.sqlite --out /path/review/aincrad-addresses.json
```

两个命令默认读取 `public/aincrad-addresses.json`。可用 `--catalogue <文件>` 复核一份新勘测的目录。`assign` 可对原样请求安全重试。重复入住、地址占用、原请求的公开姓名或职业变化都会要求人工核对。随目录发布的已有住户保留原登记。导出在新文件中写入公开住址和住户资料，供审核后更新网站目录。私有请求和数据库留在操作端。

## 日常动作的现状

| 日常 | 可复用入口 | 已有证据与适用范围 |
| --- | --- | --- |
| 在家休息和工作 | 女仆 `home-check`、`furnish`、原生床与 `DAY` 作息 | 正式住房已有实例。门口、家具和领地按原体分别核验，女仆的回家锚点和公开住宿登记各有用途。 |
| 耕作 | 女仆 `body:native:task` 选择 `touhou_little_maid:farm`，按原生作息执行 | 隔离服已观察到小麦入包、原收获地块补种为 `age=0`，并验证保护拒绝时进度为零。启用需要角色许可、真实锄头与种子、可达耕地。当前结衣的任务目录只开了闲置与攻击。 |
| 钓鱼 | 女仆 `body:native:fish` | 现役肥鱼的工具目录已开放此动作。河岸或钓台需要现场可达，鱼竿和原生钓位条件通过后执行一次有时限的垂钓。`verifiedCatch` 和实际鱼获是完成证据。结衣尚未开放该动作。 |
| 种花 | 独立居民 `ResidentActions.place` | 原生放置已有真实库存、视线、白名单和领地校验。可先用允许放置的单格花卉，在实际花圃核验方块出现及原槽消耗。统一女仆桥目前没有 `place`，需为指定花圃接入这一动作并完成场景验收。 |
| 卖东西 | 居民公会交货或原生 `recycle quote` 后 `sell` | 隔离服已验真实鲜花交货、精确槽位回收旧铁剑、买食物并取入原生背包。花蔬摊位的货品、库存归属和玩家实际成交需要统一居民经济动作及验收。 |

现役桐人的 Numen 身体可用已登记的观察、行走、说话、进食及职业动作。耕作、钓鱼、种植和出售分别按 Numen 的真实接口追加并验收，两类身体共用住址、作息和目标。 [统一居民动作](../integrations/unified-npc/README.md) · [居民原生业务验收](NPC_GAMEPLAY_CANDIDATE_20261117.md)

## 逐个开放庭院与公共设施

1. **住宅。** 从街道实际走到门口，检查门、室内净空、床和所需区块加载。按原住户核对领地边界。网页公开门口位置。替居民设置女仆床和工作点时使用原来的住房检查和家具安装回执。
2. **菜地和花圃。** 划出宅旁实际可达的地块，记录边界、耕地或花卉依附方块，以及允许操作的作物。先用居民本体 UUID 核验领地许可，再验收一次实际收割补种或种花。原生女仆确认过的工作按原作息继续。
3. **公共钓点。** 核验从街道到岸边的路线、安全站位、水面、鱼竿、空闲背包和原生工作状态。确认完整的钓鱼回执和实际战利品，再把钓点加入可选日程。
4. **市场。** 先登记可走到的公共入口和住户获准使用的柜台。用一个真实公会订单验收交货。开放售卖时，核验物品、数量、原槽和报价，核对付款与库存实变，重读原回执也只结算一次。挂牌和提交订单分别对应各自的受理状态。 [现有公会交易](GUILD_SERVICES.md)

第一批可以从实测的桐人住宅、第一处通过核验的菜地和一个公共工作地点做起。先观察居民能否自行选一天中的实际动作并完成，再按街道扩大。验收使用位置变化、实际作物、背包、账本和原请求回执。换工作模式只能证明已经开始该模式，收成、鱼获和成交各看自身证据。
