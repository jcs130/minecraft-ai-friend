## 维护与校验

复用原维护锁、真人／活动副本检查、180/60/10 秒预告和正常停启流程。女神原生七项任务在维护期间暂停，结束后核对原任务定义及身份文件并恢复，不另建 Agent 循环。

先完成本次 E/F 双盘原生冷备，确认 `.complete`、备份时间及关键摘要，再固定保留这两个恢复点。历史备份保留策略只在游戏与登录服务停止时清理；不能因 NVMe 可用而恢复在线批量删除。

迁移模块只接受本表两组精确路径及本次一次性请求，拒绝已有目标、重放请求、路径内的重解析点和非 NVMe 目标。复制后保留至少 80 GiB 系统盘余量。所有 Paper 文件分别与双盘冷备比较；两个运行目录复制后逐文件核对名称、大小及 SHA256，并检查有效文件权限。

真实切换前再次核对源文件并写恢复阻断标记。两个原目录改名保留后才创建目录联接；只有目标核对通过才提交事务、消费请求和撤销阻断。任何未知回退状态都阻止自动开服。Windows 管理员确认只授权对应进程，前置程序退出后不能沿用已结束进程的提升令牌。

首次尝试因维护锁占用退出；第二次管理员确认通过，但启动包装器用 `Invoke-Expression` 加载原运维定义时没有脚本目录，因空路径在停服前退出。两次失败记录保留，没有搬移游戏数据。修正版明确解析原模块目录，已用实际 Windows PowerShell 5.1 只读加载及原真人／副本查询验证。

第三次正常停服后完成 E/F `20261029-022657` 全量冷备及过期清理（E 两份、F 十四份，包含中断残留），当前每盘八份完整恢复点。运行数据比较因文件数变化而保护性中止，没有创建 C 盘目标或更换 E 盘入口；原生流程正常启动了原服务。该恢复点已在两盘加 `.keep`，此前 RPG 固定恢复点保留。

独立复现确认：官网的 `ArchiveReader` 用 Node SQLite 只读打开冷备副本、执行查询并关闭后，数据库内容不变，但会生成 32768 字节 SHM 和空 WAL。修正版只将有真实 SQLite 文件头的 SHM 及零字节 WAL 视为可重建缓存；不删除文件，普通同名文件和**非空 WAL 仍逐字节检查**。复制、权限检查和失败回退保持。跨进程包装器的等待问题也改为在同一维护进程调用原运维函数，避免启动的常驻子进程拖住退出与任务恢复。

R4 在新观战账号未获维护确认时保护性退出；服主随后确认 CoobotEye 可自动重连，已按其真实 UUID 登记。原 `Afu-MC-DailyBackup` 实际使用普通账户、RunLevel Limited，并非 SYSTEM；它的真实 DACL 复制测试未通过，因此曾排入的迁移请求已撤回，未尝试搬移目录。R6 已独立通过管理员复制测试，复用原维护锁等待现有备份，不更改原任务的身份或权限。

修正版逐项复制有效 DACL，并转为受保护的访问规则，按子项到父目录的顺序应用，保留原有效权限，不引入 C 盘更宽的继承规则。不复制所有者或审计规则。新增隔离用例复现同盘移动保留旧继承权限、不同目标父权限、文件规则与父目录再次更新，30 项迁移检查通过。R7 会先在未启用的真实 C 盘副本上逐项验证权限，覆盖原报错文件，全部通过后才预告停服。

## 生效验收

目录联接和端口监听只是检查的一部分。还需核对全部插件与核心 JAR、原账号凭据字段、数据库完整性、新鲜且就绪的认证心跳、真实客户端重新认证并进入 Paper，以及女神原任务恢复。角色重新活动后存档自然会改变，不能把冷安装一致性说成运行后所有文件仍字节相同。

30 项迁移路径／摘要／SQLite 缓存／非空 WAL／有效权限／恢复门禁检查，以及原备份 13 项保留选择、4 项失败和 10 项离线清理回归通过，共 57 项。另验证了真实冷库副本的 Node 只读行为、独立目录的增量刷新及根目录有界复制。原均匀权限夹具不足以覆盖真实旧继承权限，不能用其通过替代逐项真实验证；R7 完整预检与切换后的玩家回连仍待完成。
