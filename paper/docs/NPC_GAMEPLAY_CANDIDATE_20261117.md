# 智能居民玩法闭环候选，暂不发布

这是居民扩展 0.3.3 / AgentFriend 0.4.47.85-npc-gameplay 的开发验收记录。用户要求完整打通后再上线；本轮没有替换正式 JAR、重启正式服、生成正式居民或改写正式记忆。现役身份、人物和世界继续保留。

另有原生权限桥 0.1.40-resident-permissions 与相机客户端 0.2.1 候选。权限桥基于现场 0.1.39-spell-policy 的摘要校验构建，只替换权限类及版本字段，不覆盖同包较新的语音/法术类。对应构建和检查归属见 [manifest](../manifests/npc-gameplay-candidate-20261117.json)。这是候选开发分支，不能直接执行历史维护脚本投放。

## 本轮补齐的业务能力

原生女仆是独立的参赛和财产主体。`ResidentCli` 将普通业务服务接到她自己的 UUID、真实女仆背包、装备与有限魔力；没有客户端连接、OP、玩家名额，也不借用创建者或队长的身份。

- `status` 读取实际身体、位置、装备、背包、职业资源；连续查询不递归嵌套旧状态。
- 公会加入、任务发现、接取、核验、交付、放弃沿用原业务规则；领取回执比较实际前后状态，接取不等于任务完成。
- 回收报价及成交、个人金币余额、购买、个人奖励箱存取沿用现有经济账本。默认女仆背包只有实际可用的 6 格，不能把锁定的扩展槽当空位，已装备物品不属于可回收背包槽。
- `arena stash collect` 将既有待领取奖励装入本人的个人箱；箱满的部分保留队列。`list/inventory/summary/take/putslot` 可直接使用；按实际转移量回执，不打开一个 NPC 无法点击的 GUI。
- `land here/list/info/members/trust/untrust` 以 NPC 本人身份执行。没有领地主人权限就不能授权他人。原生传送显式核对本人 WorldGuard 出入权限，不依赖只有真实玩家才会触发的传送监听器。
- 试炼塔和遗迹地下城将登记居民纳入附近参赛名单、目标选择、真实伤害贡献、倒地救援与个人奖励。远处未参赛居民不能领奖，重复领取不重复发奖。
- 伤害达到致命值时按场次进入倒地/救援流程，保留原实体和装备；倒地不能继续派发动作。不会生成替代身体继续假装完成旧动作。
- NPC 在遗迹中的实际战斗贡献进入既有耐久战斗账本，再按累计值投影到本人 `combatXp`；重连不重复加分。原生劳动/施法经验保留为 `workXp`。真人 Vortex 玩家经验路径不额外发放第二份经验。
- 原生种田仅在成熟作物实际被收获后增加 `workXp`，选择工作模式、未成熟和被保护拒绝都不算。收获/补种沿用本人公会账本；女仆提前补种只保存同次任务、本人收获地点、紧邻配对阶段的实际证据，不能将别人的工作算给她，也不会自动领奖。
- 常驻身体当前区块使用 NeoForge 原生运算 ticket；没有真人连接时作物仍按游戏规则生长。只覆盖当前区块，离开的 ticket 三秒过期，不提高正式 `randomTickSpeed`、不伪造连接、不替换自然生长为固定掉物。
- 原生 TLM 世界权限桥识别登记居民 UUID；普通宠物女仆沿用主人权限。驻民不能借用创建者权限，登记或权限模块异常时不放行。原生破坏/放置事件依旧有最终否决权。
- 购买成功明确标记商品仍在待领取队列；收集到个人箱与取到实际背包分别回执。公会验收未通过不会返回成功；限流保留真实原因、等待毫秒和安全查询，旧请求重读不重新成交。
- 相机可确认真实女仆实体和原生/YSM 模型就绪，并沿原 ImageFrame 上传、本人相册与个人奖励箱流程出片。拍照导航持有结束后可实际行走；没有用合成 PNG 代替原生客户端渲染。

这仍是 `resident_classes_v1` 职业曲线，不能描述成已经完整迁移 Vortex 的全部玩家技能。候选发现目录只列出已接到实际执行器的命令，不允许任意控制台命令作为兜底。

## 动作、断线与记忆

每笔写操作先保存原 requestId，再调用服务。完成回执不可被之后的楼层提示覆盖。异步受理和成功是不同状态；发生写后异常时保留 `unknown` 和身体阻塞，不能自动重放。

未知传送须先查原请求与实际维度/坐标。管理员使用 `travel-inspect` 提供原请求、独立核对 ID、准确的实际位置和说明，核对通过后身体保持暂停；再明确 `travel-resume`。原始未知回执不会被改写成成功，恢复也不执行旧传送。普通 CLI 未确认请求的核对同时解除对应业务阻塞，不能只清外层标记。

较长的结果和私有任务通知进入本人原始 journal。记忆导入使用有界摘要，注明原文件、原请求、摘要哈希和截断状态；完整证据仍保留。重复导入、Scope 隔离、远端故障和后续事件不被大结果阻塞均有回归。

## 已验收与发布门槛

构建摘要、具体组别、是否使用最终构建及本机原始记录索引见候选 manifest。一次检查的“通过”仅覆盖其具体场景，不等于所有客户端和长期生活完成验收。

已完成的原生业务、冷重启、农事/权限、相机及线上模型结果按组记录在 manifest；不同构建分别标注，不把早期检查冒称最新构建已重跑。双 NPC 遗迹实战 31 项、双 NPC 试炼实战 23 项为本轮较早构建的证据：两室遗迹通过真实攻击清场并原生寻路，未用管理命令清怪，第三位远处居民不获奖。最新静态/契约回归为 Java 108 项加 GPU 策略 10 项，Python 12 项，Node 26 项。

线上 Qwen Code 经 LiteLLM 的真实连续目标包含交付鲜花、回收铁剑、购买食物、从个人箱取入原生背包。曾 10 轮成功，但随后 14 轮复测在回收后转接其他委托，未完成购买；真实失败照实保留，不能以已执行若干动作宣称整项目标完成。关闭思考与启用思考的试验分开记录，输出预算与成本有明确上限。该测试不是长时间日程自主运行验收。

另有中间构建的入口拒绝/开放 7 项、未知传送核对与重启 11 项；这些须单独标注所属构建，不能冒称在每次最终构建上重跑。

继续阻止正式投放的项目：

1. 线上模型独立完成连续目标、处理失败和长期运行的观测，不能只凭人工逐条调用通过。
2. 全部玩家 CLI 与原生职业成长的映射；原生劳动、步行探索等任务事件不能漏记，也不能以设置工作模式替代成果。
3. 相机原生出片/照片入箱及实际取出已验证；仍需更广泛职业动作、原生合成/钓鱼/贸易事件、技能曲线与完整玩家 CLI 的统一。当前发现目录不广告未接入的能力。
4. Java、基岩与网页的实际模型、动画、气泡、菜单和操作链路；加密模型不能宣称已转换为相同的基岩/Web 外观。可暂不配置的日语音色单独记录。
5. 新居民逐个住房占用、工作范围、材料、身份/模型/人设/Scope 配置及对应验收。只在艾因格朗特初始化，允许按同一权限机制跨维度；不回灌测试世界或复制测试实体。

## 可复现回归

`standalone/tests/resident-gameplay-stage.py` 是仓库内的真实服务回归。先准备独立 Youer、当前候选及测试专用 `RecruitmentProbe`，使用测试脚本内的 `TASK_MARKET`，两个新合成居民、真实 Vortex/Vault 依赖和新数据库。AgentFriend `rpg-backend: vortex` 与 QiandengjiRpg `backend: vortex` 必须一致；否则后者会按既有双权威保护主动停用经济服务。不得移除保护来让测试通过。

环境必须带 `.resident-hybrid-qa`（内容 `SYNTHETIC_RESIDENT_HYBRID_ONLY`），游戏与 RCON 都在独立环回端口。运行前用测试夹具为两位居民准备真实库存，第一位背包 1 格是未装备铁剑、4 格可用于交付物；主手原工具保持。脚本会执行真实业务变更，因此只对这个新隔离场景运行。

```text
python paper/integrations/touhou-maids/standalone/tests/resident-gameplay-stage.py --stage <隔离服> --resident <测试UUID> --peer <另一测试UUID> --report <仓库外/gameplay.json>
```

正常停止、重新启动同一个隔离世界后，只读取原请求和原库存，不重建场景：

```text
python paper/integrations/touhou-maids/standalone/tests/resident-gameplay-stage.py --stage <原隔离服> --verify-restart <原gameplay.json> --report <仓库外/restart.json>
```

测试专用模组拒绝未标记目录，不打入发布 JAR。生产凭据、原始模型、照片、地图、测试世界和运行日志均不提交。

农事真实测试入口是 `resident-native-farm-stage.py --stage … --resident … --peer … --report …`。使用脚本内 `TASK_MARKET`，不加载其他覆盖任务定义；可选 `--protected-fixture` 要求 `resident_farm_gate` 区域 `(106,80,102)..(110,85,106)` 的创建者有权、居民初始没有权限。测试会真实收获/种植、授权/撤销、领奖；只在标记隔离服使用。测试世界短时 `randomTickSpeed=600` 用于真实生长验收，完成后恢复 3，未更改正式服游戏规则。

必须加载实际 TLM 原生权限桥和当前运行所需的 SVC 插件。早期漏装 SVC 时权限桥整体启动失败，不能把那组结果视为全依赖集成通过。隔离 SVC、ImageFrame、游戏和 RCON 使用各自回环临时端口。经济使用真实 Vortex/Vault，新数据库；相机另需 ImageFrame、Floodgate、独立原生 Java 相机及现有 `native-camera-media` 中的 pngjs，不复用正式玩家连接或相机目录。

相机入口是 `resident-photo-stage.py --stage … --resident … --peer … --report …`，实际图像经原生 GPU 客户端取得，需人工查看成片。显式新增 `rtxpro5000` GPU 配置仅供当前 QA 硬件；原 Intel 和 RTX3080Ti 配置保持严格匹配，不能接受任意 renderer 伪造成功。测试确认两条相机连接与无连接的居民身体分开统计。

启用思考 / 1024 输出预算对照多次触及网关 40 秒边界，未完成任务，已正常停止对应隔离世界并保存中断原因；没有拉长正式时限或重放未知动作。后续基准脚本遇到连续三次同因模型失败会停止并保留指标，普通业务拒绝另行处理。该运行配置不作为上线默认值。
