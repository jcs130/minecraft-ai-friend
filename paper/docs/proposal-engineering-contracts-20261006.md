## 2. 新增 goal 设计（GuildManager$Goal +4）

### 2.1 BRIDGE（架桥）
- Contract 字段复用 `siteId`（现有 Site 机制）指向一个**沟壑/河道区域**（两点 + 宽度定义的走廊框）。
- 验收：区域内指定"桥面方块"（模板指定，如 andesite_slab / oak_planks）数量 ≥ target，且**走廊两端连通**（起点终点各放一个锚点方块，路径可达性检查）。
- 防作弊：只统计位于 y ∈ [site 顶面, 顶面+4] 的方块；不计掉落物/地面原有方块（对比发布时快照）。

### 2.2 ROAD（修路）
- siteId 指向**两点间路面带**（长度 L、宽 3 的走廊）。
- 验收：走廊内"路面方块"覆盖率 ≥ target%（如石砖/砂土路径块），数量化到 Contract.target。
- 场景示例：村北雨后泥路段、公会门到村口的引路。

### 2.3 BUILD（自由建造）
- siteId 指向一块**划定空地**（区域框），模板指定主题与最低方块数。
- 验收：区域内新增方块数 ≥ target 且方块来自白名单（防用泥土糊墙凑数——白名单随模板）。
- 用途：岗亭、公交站台、灯柱、水井等小型公共设施。

### 2.4 REDSTONE（机械结构）
- siteId 指向小型装置区；模板定义**构件清单**（如 活塞×2 + 红石灯×2 + 按钮×1 + 红石粉≥5）。
- 验收：方块组合存在 **且** 构成有效回路（检测目标方块获得红石信号的状态翻转一次——服务器记录两个时间点的信号态）。
- 场景示例：公会门自动门、村口报警灯、可收放桥（桥+机械结合，高难度高赏金）。

## 3. 验收实现要点

1. **快照基准**：Site 注册时记录区域内方块统计（按 Material 分桶），验收时对比增量，只认"新增的指定方块"。
2. **不逐块判美观**：只验数量+位置+材料；美观分留给后续"公会评分"扩展（可选）。
3. **CoreProtect 双保险**（可选增强）：验收前抽查放置日志，确认是玩家亲手放的而非 TNT/活塞搬运。v1 先做纯方块扫描，日志抽查留 v2。
4. **奖励结构**：工程类委托 fame/emeralds 按现有档位 ×1.5~2（工作量远超交 12 个小麦）；完成者名字可入"营造录"（GuildHall 公告板铭牌，可选）。
5. **材料来源**：工程备料走公会门公共箱（现有四箱：武器/护甲/补给/杂物），模板描述写明用料位置，Agent 可捐可自备。
