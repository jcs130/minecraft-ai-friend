# Agent 一直说“背包从服务器同步”

## 2026-10-14 实查

可米在 08:52 私聊女神报告背包清单读不到，木板和石镐合成受阻。08:54 逐槽读取服务器原生库存：36 个随身槽都有物品，不是服务器保存了空背包。随后只执行一次 `/mycli inventory refresh` 重发本人库存，没有改写、补发或清空玩家物品。可米 08:56 自行离线，09:04 沿原 UUID 重连；这些事实不能替代远端工具成功读回。

“物品栏还在从服务器同步，这份清单还没到”是 `agent-mc-world` 客户端的提示，并非服务器维护公告。旧提示把首次数据未到、容器槽位缺失、点击待确认和超时隔离都混在一起。

## 修复

框架仓库 `jcs130/minecraft-ai-friend` 的 `main` 已提交 **826a29acb154fe3315272b9d70c4fbd8ebe4718a**，目录 `packages/agent-mc-world`：

- 补齐容器完整快照及最后一个缺失槽位到达时的恢复，防止一直锁住清单。
- 本人关闭、容器关闭和服务端主动关闭都处理实际槽位，未收到的槽位不当成空；窗口编号重用不继承旧数据。
- 已发送合成点击可能卡在 Mineflayer 等待未变化的产物槽。超时后收到新的完整槽位与光标数据，可以解除隔离；旧操作仍是结果未知，不伪报成功、不自动重放。
- 尚未发出的延迟点击继续保留隔离，避免恢复后旧操作突然发出。
- 背包、物资查询和现场读数给出准确中文原因及恢复步骤。

锁定 Mineflayer 4.37.1 的真实库存插件回归 17 项；完整包测试 **448 项通过、2 项按环境跳过**（可选查看器与本机无法建立的 DPAPI 凭据夹具）。类型、构建、公开声明和隔离的生产依赖安装包检查通过。独立 QA 真实连接正式服务器，个人大背包存入、关开、取回及原始库存恢复 **11 项通过**；四次点击各发送一次，光标为空，测试物品已清理。原始失败及随后修正测试环境的报告保留在私有维护目录。

## 可米运行端如何更新

这是客户端修复，服务器重启不能替代更新。将实际使用的 `agent-mc-world` 更新到上述提交后，按宿主原构建流程重新打包并重启该 Agent，保留原账号、环境变量、任务和记忆。若宿主仍使用旧版内嵌 `engine/`，先确认其来源，按同样修复回移，不要把新包覆盖到不兼容路径。

源码包验证命令：

```text
cd packages/agent-mc-world
pnpm install --frozen-lockfile
pnpm build:engine
pnpm typecheck
pnpm test
```

含 Web 的正式包继续使用原锁定的查看器资源构建；`build:engine` 只用于独立引擎/SDK验证。另一台电脑上的可米客户端未由本次服务器维护更新，须核对运行端版本及 `mc_bag` 的真实结果。

临时核对可用 `/mycli inventory status`（服务器实际清单）及 `/mycli inventory refresh`（只重发本人原版槽位数据）。不要连续刷新、自动重复存取，或把“已发命令”当作操作完成。
