# OptionalPayloadGuard

0.1.3 让游戏服完成原版 YSM 的首次握手。YSM 2.6.5 客户端在同一条物理连接上只确认第一次原生问候。登录服先完成这次通信时，切到游戏服后即使显示已连接，也可能只有默认模型。

代理在登录服边界截留固定 YSM 2.6.0 通道的游戏消息。正常的 NeoForge 通道声明、认证和语音消息照常通过。新连接进入游戏后，由原版 YSM 完成确认和模型目录下发。

只认可PLAY的客户端方向或双向通道，保留原有Minecraft/Common注册、连接隔离、断线清除、大小及数量限制。70项回归及原版NeoForge真实声明、模型传输通过。生产JAR排除所有测试夹具。

同一条客户端连接再次接入游戏服时，只有该游戏连接真正发出原生问候，才允许转交这位客户端此前发给游戏服的原版确认。给新回复留出短暂窗口，收到新回复即取消补发。每个替换连接最多尝试一次，断线后清除记录。使用后端原生就绪状态和客户端模型目录验证加载结果。

使用 `build.py --help` 在新的仓库外目录构建；固定现役Velocity、PacketEvents和JDK21作为输入，输出记录源码及依赖摘要。纯策略回归可独立编译 `OptionalPayloadPolicy.java` 和 `OptionalPayloadPolicyTest.java`，不会启动或连接服务器。

上一版的部署和兼容性记录见 [原生 YSM 通道修复](../../docs/YSM_NATIVE_CAPABILITIES_20261102.md)。0.1.3 的一次正常代理切换只需更换保护插件，生产验收以原 Eye 实际模型目录和画面为准。
