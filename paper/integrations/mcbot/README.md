# mcbot 接入 Paper 千灯纪

2026-10-28：服主已选择接入现有 Paper、共用千灯纪世界。本目录独立实现协议适配；**尚未部署，不代表官方 mcbot 原包已能驱动正式服**。

核对上游 [qaqms/mcbot](https://github.com/qaqms/mcbot) 主干 `12d3e05fb9a417d4b2d53e6c16a77b8f4247194f` 与官方测试版 [v0.1.0](https://github.com/qaqms/mcbot/releases/tag/v0.1.0) `80b556a1d54cba1aee29d1bd978cf6b9cf5f645d`：两者均要求 Minecraft 1.21.11、Fabric Loader 0.19.5、Fabric API 0.141.6、Java21。发布版有17个客户端工具，当前源码有32个；同为0.1.0不能当作相同能力版本。

## 接入边界

- 千灯纪保持 Paper1.21.1。已有 ViaVersion 包含1.21.11转换链；它解决原版协议版本，不提供mcbot的服务端执行器。
- 大脑、宿主任务桥和个人模型Key继续在玩家客户端。任务桥仍是客户端本机服务，不向公网开放或借用服主Key。
- 服务端适配`mcbot:c2s`/`mcbot:s2c`，复用Numen原身体、存档、原版动作和权限。没有第二份角色背包或RPG成长账本。
- 驾驶权绑定真实主人连接、身体UUID和身体实例。MCP外脑仍优先；不同控制端不能同时驾驶。断线取消自己的在途动作，未知结果不自动重发。
- 游戏连接的程序显式标为临时：入主线程车道和异步准备完成时都核对原连接，仅取消它创建的任务记录，不写入Numen的重启重放配方。常驻Agent原有恢复机制保留；不会把远程的“挖一次/做一份”在重启后重新执行。
- 召回保留身份和物品，重复同名召唤复用Numen名册。拒绝冒领其他主人的角色，不接管服务器常驻桐人。
- 不采用上游测试身体的无敌设置；千灯纪身体遵守正常生命、死亡、装备和副本规则。
- 工具回执只经本人插件通道，不发公屏；普通Java、基岩和现有Agent接入保持。

上游现有工具白名单没有游戏命令或持物使用工具。Paper端会提供受限的RPG命令/交互扩展；要由原生mcbot大脑自主调用，还需要客户端公开这些能力。不能把服务端增加一个处理器说成原客户端已经会调用`/mycli`。

## 玩家使用（候选上线后）

1. 独立使用官方mcbot要求的 **Minecraft 1.21.11 Fabric客户端**，安装官方原包及其依赖；不能把它放进1.21.1模组目录。普通Java、基岩和现有Mineflayer保持原入口，不需要安装mcbot。
2. 先用本人的千灯纪账号完成原登录。客户端面板或`/mcbot summon ag_你的名字`召唤一位同伴；名字总长2–16，推荐`ag_`前缀，不能占用管理员、Eye、其他玩家或其他主人的同伴名。
3. 在mcbot客户端设置本人的模型和Key，或连接它原有的本机任务桥。服务器不领取Key、不安装第二套模型循环，也不分发服主凭据。
4. 同名召回复用Numen的原UUID、背包和RPG档；`/mcbot dismiss <原名字>`只休眠保档。主人连接退出时取消本连接的在途动作并休眠，重连后显式同名召回；未决动作不自动续跑。
5. 原生Numen的硬规则、主人规则、普通生存、装备和领地保护都生效。拿别人的箱子物品会拒绝；主人放置的箱子、本人放置的箱子遵循原规则。需要确认的Numen动作仍可在游戏里通过原征询卡答复，不关闭硬规则。

`/mcbot command mycli status`是给主人操作自己同伴的补充入口，仍须经过Numen指令许可。若主人希望允许该同伴调用玩法指令，可**本人**执行`/numen permission rules add allow command(mycli) @同伴名`；这不授予管理指令、其他角色或领地权限。先结束mcbot面板当前任务再执行主人命令。命令派发回执不等于游戏完成，应再查`/mycli status`、任务或技能状态。

## 本轮能力范围

| 工具 | Paper端行为 |
| --- | --- |
| `status`、`inventory` | 实时位置、生命、36槽库存和装备；可读取原Vortex职业、经验、技能和统一魔力，不复制成长账本 |
| `scan_area`、`find_resource`、`inspect_block` | 复用Numen感知，提供实体UUID、附近工位和地形；资源/容器受距离和视线限制，锁定及未展开战利品容器不窥读 |
| `equip`、`consume` | 精确库存槽切主手、真实进食；不伪造扣物、饥饿或装备 |
| `craft` | 只读配方查询、2×2及可见近身工作台3×3合成，真实消耗；预览明确区分一次配方与整批材料 |
| `transfer` | 原生窗口串行存取，窗口对象及光标核对，关闭后再开；不把物品名查询当成槽位编号 |
| `smelt` | 熔炉/高炉/烟熏炉的查询、按玩家来源槽装料、按机器指定槽取出；装料不冒充烧制完成 |
| `move_to`、`follow`、`collect` | 原生寻路和拾取；`walk_only`不能借路线挖建，非自主路线的一格确认不扩展为整条路线授权 |
| `break_block`、`place_block` | 原生挖建，事件范围仅限请求目标格，仍检查工具、材料和保护 |
| `attack`、`wait` | 有界近战及等待；攻击仅限可见、未命名的敌对怪物，玩家、宠物和中立目标不开放 |
| `command`、`use_item`、`use_block` | 独立可选扩展。官方现有客户端工具表不包含它们，不能声称原客户端大脑已经可以调用 |

不支持的参数明确拒绝，不降级成另一种动作：例如强制非`up`接触面、护卫自动攻击、副手/护甲换装、超出近战范围的自动接敌、建筑规划/续建、全量机器配方规划和任意程序执行。`attack.max_hits`为1–10，`0`的无限攻击语义不开放；近身移动64格以内，资源扫描16格以内。熔炉燃料总续航未知时给`null`，不猜测“够烧完”。

官方v0.1.0与主干同报0.1.0而工具集不同；这里是**共同协议和上述工具范围的适配**，不是完整复制主干32工具。原生Fabric界面、真实模型长任务及手机/手柄画面须另验，不把独立协议驱动当成这些体验的实测。

## 构建与回退

固定Numen源码：[287ac6e5](https://github.com/jcs130/minecraft-numen/commit/287ac6e5d492ea73323fc4eb4ce668aacac89130)，基线JAR来自[已发布Paper包](https://github.com/jcs130/minecraft-numen/releases/tag/qiandengji-paper-1.21.1-20261023)。`build.py --help`列出JDK、源码、基线API/内容、Paper目录及新输出目录参数；不需要MCBot源码或JAR。构建器核验摘要，窄补驾驶席、连接作用域、输入释放、归属缓存、令牌私发及熔炉成品槽部分取出，保留其他Numen条目，输出每个源和产物摘要。原Numen源码只读取到构建目录，原仓库不改。

取消输入同时补修`Mouse.release`：待处理的STOP挖掘也发送ABORT并清除旧格状态，避免下一次已批准的路线误读上次拒绝。主线程调用门禁、精确任务取消、临时任务不持久重放均为显式连接作用域，不能只停止Lua程序并声称身体已经停止。

`PlacedBlocks`原来会根据传入视图的“空气”删除归属，而寻路快照可能早于刚完成的放置，导致亲手放下的方块被误判为他人财产。候选只允许在主线程核对已加载世界的当前真实空气后清理；旧视图返回当时的查询结果，不能改写真实归属。原他人建筑硬规则保留。

插件必须与匹配的Numen API、Numen内容一同测试；缺少窄接口会在注册通道前拒绝启用。只在可信登录代理之后安装；LoginGuard的`mcbot:c2s`门禁使用实时LibreLogin授权和当前Paper连接，不读取心跳文件授予操作。未登录、2FA未完成、服务不可用及错误转发目标均不放行。

本次代理配套为`LoginGuard-0.1.7`窄候选。用`../login-guard/build-mcbot.py`从已部署0.1.5固定源码与原JAR只替换LoginGuard类和版本，原PortalBridge条目保持；不要夹带一般构建入口里的0.1.6多世界账号候选。

Numen令牌交付一并窄修：创建结果和一次性复制卡直接私发本人，不再受`sendCommandFeedback=false`吞掉；仍只把开头显示成文本，完整令牌只在本人的复制事件里。未改变令牌作用域、哈希存储、有效期、模型Key或权限。

部署需要当次维护授权、原预告、正常停服和E/F完整冷备份，不能`/reload`换JAR。回退正常停服后移除新适配插件，恢复更新前的Numen API/内容及AgentVision；保留最新世界、Numen目录、角色和绑定文件，不能用旧玩家存档回滚新进度。代理回退只恢复原LoginGuard JAR，原账号库/密码不倒回。mcbot专用绑定可保留等待再次启用，`dismiss`绝不调用Numen永久删除接口。

纯边界回归：`tests/run.py --jdk <JDK21> --gson <Gson2.10.1.jar> --output <新目录>`。真实协议探针`probe/paper-client.mjs`仅允许带专用标记的25928/25929隔离服；测试来源槽、数量、光标、配方、机器、真实伤害及断线保档，`MCBOT_PROTOCOL_VERSION=1.21.11`沿ViaVersion复测。禁止将这些造景、发物品和测试角色脚本用于正式服。

隔离服仍有原有保护mask不匹配、相机未接和Essentials版本警告，未将它们称为日志全清或生产异常。本轮未执行原生MCBot Fabric界面、实际模型长任务或真实认证代理全链；这些应在候选维护后由自愿测试账号完成，不能用本表替代。

## 实施与验收

1. 有界编解码、连接/身体作用域、任务及回执关联，兼容官方发布和当前源码的共同协议。
2. Numen通用游戏客户端驾驶席；沿用唯一执行器，避免冒充MCP会话或挪用Numen旧版客户端身份。
3. 状态、真实库存和基础动作；参数或语义无法等价转换时明确拒绝，不假报成功。
4. 隔离Paper服真实协议验证召唤、同名复用、存取、保护拒绝、取消/断线、RPG及基岩/原版共存。原生Fabric界面和真实模型任务另行记录。
5. 候选、回退、固定摘要和文档齐全后，按现有维护流程申请正式部署；本轮不直接重启正式服。
