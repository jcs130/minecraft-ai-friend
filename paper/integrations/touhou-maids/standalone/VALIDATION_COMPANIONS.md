# 0.2.0 居民伙伴验收，2026-11-16

本版在标记为 `SYNTHETIC_STOCK_NEOFORGE` 的独立世界验收。使用官方 TLM 1.5.3、NeoForge 21.1、YSM 2.6.5、Java 21，以及一位真实连接的测试客户端。客户端未安装本扩展。原生服务端和客户端均正常退出，没有重启正式服或更改正式玩家数据。

## 可复现的源码回归

- 42 项 Java 检查：多位同行、单体互斥、自己/嵌套组队拒绝、旧契约、非法命令、冷读取、原子写失败、严格对话 JSON、不可覆写的原始经历、按对方隔离、重启后未完成对话标记 unknown。
- 8 项 Qwen Code 协议检查和 23 项原有网关检查：单轮终态、usage、原生回执、工具权限、无工具对话的原样传递、含糊输出拒绝及多实体配置。
- 3 项 Node 记忆检查：使用真实 MC 核心读写本地笔记；导入器在记账前中断后再次同步不生成新记忆；不同 NPC/玩家之间不串记忆；并发写入与共用 Scope 拒绝；外部服务中断时原始证据与本地检索仍保留，未知远端写入不自动重放。

## 线上模型与原生身体

最终一轮完整流程通过 34 项检查：

1. 真实玩家分别向灯守与禾穗发起邀请，两者答应后同一玩家同时拥有两位同伴。
2. 禾穗通过 Qwen Code 回忆玩家“阿岚”和找种子的约定；口头要求等候后，真实身体坐下。
3. 灯守实际移动跟上玩家，并用原生战斗任务击败测试尸壳。原 UUID、主人、YSM 模型及主人私人历史保持。
4. 玩家结束同行，两具原身体实际回到原驻地后才变为 available。
5. 同一位禾穗从 Qwen Code 切到原生 OpenAI 兼容链路后仍记得阿岚与种子，没有换实体或复制主人历史。
6. 灯守自主向绒铃说话并提出邀请；绒铃选择婉拒，双方各自保留这次经历。没有把拒绝计作组队成功，也没有强制改其身体状态。
7. 再次邀请灯守获得新契约。测试客户端真实断线后身体等候；正常冷重启后契约仍在，同一玩家重连，对话仍记得名字和先前经历。

这轮通过本机 LiteLLM 调用线上 `tokenplan/qwen3.8-flash`，关闭推理模式。10 次模型请求均为 HTTP 200，共 9,121 token，模型请求中位耗时 1.61 秒，范围 0.86–2.19 秒。这些是这一轮的观测值，未包含走路、作战和游戏启动耗时，也不是所有场景的性能保证。

此前联调发现并修复了三处问题：无工具社交要求双层 JSON 导致偶发解析失败；模型不清楚“等候”等动作会改变身体；退出后直接恢复农务任务导致回家途中不继续寻路。现分别使用无工具的原生内容协议、按当前关系给出的动作清单、抵达后才恢复工作的返程流程。复制模型站点时内层 id 与别名不一致的配置也会在启动时拒绝。

## PowerContext

连接已有本机 PowerContext 1.4.1，给三位合成 NPC 使用三个独立 Scope，未读取或写入已有玩家的 Scope。通过 MC 核心确认保存共 15 条经历，包括最终一轮的 11 条及较早联调的 4 条；再运行一次导入计数均为 0。远端检索及回写上下文携带原角色、对方和历史标记。原始世界 journal、核心本地笔记和复制回执都保留。

## 本轮边界

未把这一独立扩展放入正式服；它与现役 `qiandengji_maid_brain` 互斥。DSH/Codex 沿用既有 HarnessRouter 适配和配置契约，本轮真实模型联测覆盖 Qwen Code 与原生 OpenAI 兼容链路，未宣称 Codex 已完成实服联调。NPC 之间的邀请/婉拒已实测，实际 NPC 领队带多位 NPC 行走仍需专门场景验收；多人队伍底层与玩家同行共用契约机制。

新菜单采用原版容器；真实基岩手柄、网页投影、新对白的语音听感、复杂地形以及跨维度/副本随行不在本轮通过项中。原始本机测试记录含路径、运行令牌或世界状态，不提交公开仓库。
