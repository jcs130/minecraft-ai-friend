# 千灯纪 Windows 常驻运行入口

这里保留 0.3.0 实际使用的三个启动源文件，便于复核与后续更新；路径、启动器摘要和本机端口是此部署的固定值，不是另一台机器可以直接运行的安装器。

`aincrad-residents-lifecycle.ps1` 由现有 `E:/MC/ops/manage-server.ps1` 引入，在原 `Start-Server` 与 `Watchdog` 的女仆技能策略检查后调用 `Ensure-AincradResidentServices`。不建立第二套定时任务。依赖既有 `Start-IndependentProcess`，以隐藏窗口启动；同一角色有多个进程、端口被别的进程占用或记忆写入锁待核对时拒绝启动副本。

网关仅监听 `127.0.0.1:19105`。Qwen Code 配置、LiteLLM 凭据、PowerContext 密钥、角色 Scope 和本地记忆位于主机私有目录，均不随本仓库分发。网关为每体配置的 harness 转发请求，模型凭据不会发送给 Minecraft 客户端。记忆同步复用 `agent-mc-world` 的 GameMemoryService，角色身份和原始行动账本不依赖模型或 harness。

替换启动器或运行路径时，须同时更新并审核生命周期脚本中的摘要；不得删掉校验来强行通过。游戏 JAR 更新仍走现有维护锁、当前无真人/活动挑战的窗口、180/60/10 秒预告、正常存档停止与 F 盘当次完整冷备。遇到锁占用可在有界期限内等待，不能删除锁或停止锁的拥有者。

TLM 会在启动时重新排版 `sites/llm.json`。安装前仍校验候选文件摘要；启动后使用 `verify_native_json.py EXPECTED ACTUAL` 比较完整且保留类型的 JSON，而不是要求排版字节不变。所有密钥、地址、数组顺序、布尔值和缺失字段均参与比较，不打印值，也不忽略未知字段。JAR 与启动脚本继续严格校验 SHA256。

正式发布与角色投放是两个独立步骤：启动扩展只登记居民，不自动生成实体或家具。新角色的原生 UUID、召唤、住房安装与模型选择各自保留回执。结果未知时查询原 UUID/请求，不重放一次性配置脚本；回退只更换代码和明确配置，不回灌世界、身份、物品、认证或记忆。
