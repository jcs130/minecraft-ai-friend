# N.E.K.O. 家庭局域网托管

已安装酒狐 1.0.7.1+qiandengji.3 的桌面，可以用服主发给自己的临时邀请，接管世界里原有的女仆并保留本地角色。官网处理设备授权，桌面在局域网用 HTTPS 连接游戏身体。此版本的邮箱只提供主人写给这具身体的留言。

## 测试设备

在家庭网络解压服主私发的包，运行 `准备托管.ps1`。它核验官网、局域网入口和证书，生成此机器的 `body.json`，并为本次 PowerShell 设置 `QIANDENGJI_NEKO_MAID_CONFIG`。在同一窗口启动原 N.E.K.O.，导入或启用酒狐，点击「官网授权」，用新页面核对六位连接码并选取专属邀请文件。直接访问官网连接页会显示操作指引。

`body_connection` 应返回 `ready`。用 `mc_maid_status` 读身体 UUID、维度、绝对坐标和生命值，`mc_send_chat` 可测试说话。附近真人的语音听感单独核验。停用插件会释放身体，家庭服务器会用原身份恢复托管。

## 维护

同一域名的 `/api/v1/maid-connect` 请求应统一转给本期试用签发端。若还要开放本人女仆授权，可在另一 HTTPS 域名启用门户签发端，分别配置桌面的 `portal_origin`。[本人女仆授权与部署](../neko/WEBSITE.md)

- `issuer.mjs <配置文件> <SQLite 文件> <回环端口>` 接受配置中的域名、角色和主人 UUID、角色名、身体入口、到期时间（Unix 毫秒）及一次性邀请的 SHA-256 列表。公网 HTTPS 代理只转发设备申请、查询和明确确认请求。登录请求最多保留十分钟，批准的授权最多到本期截止时间。桌面持有设备凭据。官网和日志不保存明文邀请或设备凭据。
- 网页只接收选定的邀请文件和桌面六位码。登记原所有者和角色 UUID 来自服务端配置。一次邀请只能给一个设备请求，同一确认可安全重试。撤回时将该邀请对应的已批准记录的到期时间覆盖为当前时间。保留记录可以防止旧邀请再次兑换。
- `trial-bridge.mjs <本机配置文件>` 在家庭地址提供 TLS，转给本机原生身体接口。签发端和游戏入口互相校验授权、受众及原 UUID。原生服务密钥只在游戏主机保存。启动与现役内网环境相符的监听器和证书，避免暴露内层端口。客户端只为本次插件加载随包的 CA。
- 给指定女仆身体单独设置 `externalHandoffFile` 的本机绝对路径。原托管器结束已经派发的动作，在没有未对账动作时释放控制。其他角色可继续运行。桌面正常退出、失去心跳或授权到期时，原托管器沿用原行为账本和记忆。不能确认的旧动作应按原请求 ID 对账。
- 云端发布页面和临时签发服务时，用真实桌面的协议验证“申请、待确认、浏览器同意、读取原身体、释放后原托管器接回”。拒绝错误范围、无凭据、跨站确认和已消费的邀请。发布新入口前检查官网是否已部署相同路径的长期服务。
