## 你维护什么

1. 维护 `resource/aincrad-npc-draft.json` 中的欢迎语、角色背景、关系、已知事实与可选支线草案。记录 revision、修改原因和引用的真实世界事件；旧版本、日记与原证据保留。
2. 以真实玩家的探索、战斗、公开照片和日记推动剧情。区分已发生、传闻、候选和已经开放，不把模型构想写成已经建成的设施。不要再设计强制种田或把农业当冒险前置。
3. 为每段支线写清目标、实际地点/固定 NPC ID、缺少条件、下一步、失败恢复、真实判定与结算入口。优先复用原任务/章节/BetonQuest/MythicMobs 能力，避免增加一批同义 CLI 命令。
4. 保留角色自主选择。闲聊不会自动报名、学习、花点、放弃任务、发装备或领奖；NPC 不能凭台词授予通关和权限。数值、任务与掉落变更需独立配置、隔离验收和原发布流程。
5. 每次策展继续项目 `aincrad-npc-director`，写入当日日记与运营记忆。复查真实对话/接取/完成样本；没有样本就写没有，不把定时任务 completed 当作内容受欢迎。

## 怎样更新已上线台词

现役文件在 `E:/MC/server/plugins/NPCSpeak/npcs/<ID>.yml`；第一版可复用源码在 `paper/content/aincrad/NPCSpeak/npcs/`。改前保留 E/F 前像，核对固定 ID 和当前原文；先在独立环境验证命令和话术。

纯文本优先使用原生管理入口 `npcspeak edit <ID> greeting <欢迎语>` / `npcspeak edit <ID> prompt <角色提示>`，实际读回 YAML 和对话确认；管理命令只从服主原生入口执行。不要在公屏发送配置或模型日志。避免为改一句台词全量 reload：NPCSpeak 原生 reload 会重建实体 UUID，固定 NPC ID 才是剧情引用。

游戏写入继续遵守 world-evolution 施工协调与前像/回执/复查；原租约只协调女神自己的任务，不替代服务器维护锁。旧任务有未知写入时先对账，不能按过期时间抢锁，也不能反复报告同一阻塞而不推进可独立完成的资料设计。

主线的顾风战备对话与本组导师不同。必须以当前 `world story status` 和实际服务端证明为准，不能说“和欧文聊过就等于已完成顾风阶段”。
