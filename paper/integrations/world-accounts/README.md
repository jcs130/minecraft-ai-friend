# 多世界账号原生适配器

候选：`qiandeng-world-accounts 0.1.0`，NeoForge 21.1.250 / Minecraft 1.21.1 / MixAuth 1.3.3。服务端专用，客户端不需要加装本组件。现役 FOM 的 `maw-fom-support 0.2.0` 提供加入中状态和认证会话检查；缺少该检查时不接受认领证明。

本组件只处理网站的限定账号请求。MixAuth 继续管理原生密码、登录、锁定和正版策略；不直接修改 H2，不执行任意命令，不创建游戏身体，不共享模型 Key，不改变原有访客策略。

## 构建与配置

用 `build.py --server <FOM服务端目录> --jdk <Java21目录> --output <新产物目录>` 构建。脚本固定已审计的 MixAuth 字节和 NeoForge API，记录源码、依赖与产物摘要。JAR 和运行配置不提交仓库。

将 `config.example.properties` 填成私有的 `config/qiandeng-world-accounts.properties`，设置唯一、稳定的小写 `serverId`、绝对 IPC 目录和 32 字节随机密钥文件（64个十六进制字符）。默认关闭。密钥仅服务账号、SYSTEM 和管理员可读，备份也保持同样权限。

网站与本机不共用主密钥。本机 `scripts/sync-server-accounts.mjs --config <绝对私有配置路径>` 只向现有网站 HTTPS 出站，使用该世界单独的 `acc_` 凭据和远端 AES 密钥重封装。无新增监听或公网端口。网站配置见 [多世界账号](../../docs/NETWORK_ACCOUNTS.md)。

## 原生约束

- 创建只允许普通 `ag_` 名称。管理名、OP 和 Eye 保留原认证。已有名字、UUID、玩家存档、正在登录者和大小写别名不能覆盖。
- 密码使用 MixAuth 自己的策略校验、异步哈希、插入/保存及读回接口。旧密码错误遵守原生临时锁定；密码从不进入普通日志。
- 已有角色由已认证、已注册且使用独立密码的原身体执行 `/portal bind 请求ID 凭据`。访客、弱默认密码和旧会话不构成证明。回执仅发给本人。
- 统一管理的角色，原生自助改密提示转到网站世界大厅；原生管理员恢复命令保留。管理员恢复后须核对统一凭据状态，不能直接宣称所有世界仍已同步。
- 单个后台工作线程，队列8、每次最多4个请求；哈希和磁盘读写不在 tick 上执行。主线程只核实活跃会话和 OP 状态。
- 每个请求先持久化 `running` 再写原生账号；进程中断后变成 `unknown`。同一请求永不重做账号写入。Windows 临时文件锁仅重试原子回执写入，最多十次，不重试账号操作。

## 验证与上线

`tests/AccountMailboxTest.java` 验证加密、幂等、未知结果、只读核对与认领。`tests/live-native.mjs` 只允许带隔离标记且绑定回环39986的测试服，验证真实 MixAuth、标准 Mineflayer、UUID/三枚铁锭保持、冷启动、OP 拒绝和本人认领。

生产安装须先获本次维护批准，预告、正常停服并完成双盘冷备份。FOM 使用自己的服务控制器；在当前冻结模组清单中只增加这个 JAR，生成新清单并核对其余文件不变，不能绕过模组摘要门禁。Paper 核心无须为此重启；千灯纪登录代理另需 LoginGuard 0.1.6。

回退先停止网站派发和同步器，保留所有原请求、回执与最新账号库，正常停服移除本组件并恢复旧模组清单。保留最新 MixAuth 密码和玩家存档；不要用旧 H2 或世界覆盖新进度。
