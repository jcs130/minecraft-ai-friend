# 试炼塔入口与管理员

主世界集合平台的传送点是 `(-589.5, 91, -313.5)`，朝向难度按钮。技能罗盘的试炼场、`/mycli goto arena` 和地点列表使用同一个落点。锚点受阻时，只在集合平台内寻找安全位置。入口桥仍供步行玩家使用。

正门打开三格宽、三格高的门洞。两张共享补给告示横移一格，保留内容、颜色、发光与蜡封。保留原信标、箱子、按钮、护栏及试炼入场边界。

平台沿用原武备补给商的身体作为「试炼管理员」。右键菜单提供补给、装备回收、原版交易、本人进度、本人奖励箱和挑战难度。管理员向近处可见的访客私下打招呼，也能通过现有居民对话服务回应明确点名的文字或语音。装备回收商原实体转为休眠，保留其 UUID 和交易数据。楼层内的商人不参与这次整合。

管理员小屋在平台东廊，设有床、砂轮和照明。管理员使用原版寻路，白天回柜台，晚间回屋。小屋和连廊在现有试炼保护区内。大厅和住宅都不需要放开全服建造权限。

## 收集候选

`stage_homes.py --game <server-root> --output <new-directory>` 只读检查现有地形，输出逐格变更、保留锚点、插件配置候选及本次需要加到 Harness 和语音配置的登记。采集程序使用 Python 3.12、PyYAML 和 nbtlib。将 `entrance.py --game <server-root> --output <new-json>` 的告示及门洞变更与住宅一起复查。两个程序均要求将结果写到源服目录外。

`TrialHomesProbe` 仅用于有 `.trial-platform-qa` 标记且监听 `127.0.0.1` 的隔离服。它验证确切前像、注册屋的门床工位、新旧路线和移动后的告示。

## 正式发布和回退

1. 从当次正式世界重新核验全部前像、告示、原实体和保护规则。以当前正式配置为基底合并本次字段，按角色 ID 增量登记对话和语音。旧候选整份配置可能缺少新进度或新玩家。
2. 在正常维护窗口停启，F 盘核验两份插件、目标块前像、两张告示的方块实体和两位商人的原始状态。在启用居民登记前完成门洞、住宅和安全落点的回读。
3. 用普通角色验收罗盘入场、个人进度菜单、补给、回收和真实游戏对话。核对菜单和打招呼只给相应玩家，重启后只有一个可见的平台管理员。
4. 回退前让两位原实体归回各自原柜台，恢复原可见性和原 AI 设置，再恢复旧插件。旧版按柜台附近搜索实体。住处使用后须逐格核对后来发生的变化，只撤回仍匹配本批后像的坐标。保留最新世界、角色和各自试炼进度。
