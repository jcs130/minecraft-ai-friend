# AuraSkills 2.4.0 message cache hotfix

AuraSkills uses `LocalizedKey(MessageKey, Locale)` as a permanent component cache key.
`MessageKey.of(path)` returns a new capturing lambda on every call, so the original
record's object equality stores repeated copies of the same translated component.
This patch changes only the existing `LocalizedKey.equals` and `hashCode` behavior
to compare the message path and locale values. Fields, superclass, record
components, constructor, accessors and the other method signatures remain intact.

The Java agent is independent of Paper and AuraSkills dependencies. Original and
patched class bytes are embedded as resources, not loadable target classes. The
original AuraSkills JAR and its verified Paper remapped JAR are strictly pinned
by SHA256; the class resource and transform input also require the pinned original
class SHA256. Updating AuraSkills requires reviewing and rebuilding these pins.
No third party JAR or generated bytecode belongs in Git.

## Build and isolated verification

Use JDK 21. The build script consumes the installed pinned AuraSkills JAR and writes
all bytecode, fixture classes, receipts and the agent outside the repository:

```powershell
& .\build.ps1 -AuraJar 'E:\MC\server\plugins\AuraSkills-2.4.0.jar' -Jdk 'E:\MC\jdk\jdk-21.0.12.1+1' -OutputDirectory 'E:\MC\ops\repairs\performance-20261004\patch-build'
& .\test.ps1 -AuraJar 'E:\MC\server\plugins\AuraSkills-2.4.0.jar' -Jdk 'E:\MC\jdk\jdk-21.0.12.1+1' -OutputDirectory 'E:\MC\ops\repairs\performance-20261004\patch-build'
```

`shape.txt` proves identical class structure before packaging. The independent
128 MB Java fixture loads the actual official `MessageKey` and `LocalizedKey`
through a separate URL class loader, with a test-only mock of Bukkit's scheduler
and the component cache. It starts no Minecraft server and touches no server state.
Checks cover the original leak, online HotSwap, existing instances, equal path
values, different paths and locales, concurrent insertion, rollback, reapplication,
premain application, premain rollback, and strict rejection of an altered target
JAR for both startup and live attach. Every fixture process is stopped afterward.

The stub Bukkit classes and fixture launchers are never packaged in the agent.

## Online operation

Run under the exact operating system identity/token that owns the target JVM.
Use a fresh absolute receipt path for every operation. The CLI is the JAR's
`Main-Class` and detaches from the JVM in `finally`.

```powershell
& 'E:\MC\jdk\jdk-21.0.12.1+1\bin\java.exe' --add-modules jdk.attach -jar 'E:\MC\ops\repairs\performance-20261004\patch-build\auraskills-cache-patch.jar' --pid <ACTUAL_PID> --agent 'E:\MC\ops\repairs\performance-20261004\patch-build\auraskills-cache-patch.jar' --mode fix --result 'E:\MC\ops\repairs\performance-20261004\apply-result.json'
```

The agent finds the loaded Bukkit/AuraSkills classes without creating another
plugin loader, validates the target and queues the operation on the primary
server thread. It clears only the component cache, redefines the class, clears
again and verifies path/locale equality. It neither calls `System.gc` nor reloads
skills. Clearing an existing huge map and HotSwap can briefly pause a tick;
natural garbage collection subsequently releases the discarded components.
The existing map's large empty bucket table is retained.

Receipts include `success`, `mode`, `phase`, `cacheEntriesBefore`,
`cacheEntriesAfter`, `classRedefined`, `behaviorVerified` and any `error`.
Failures are explicit. A queued operation that has not begun within 30 seconds
is cancelled. Once an operation starts, the agent waits for it to finish before
returning the receipt. A failure after `classRedefined=true` must be inspected
before retrying or rolling back.

## Startup persistence and rollback

After an operator installs the agent at the selected fixed local path, add it to
the next normal server launch (server root is the working directory):

```text
-javaagent:E:\MC\ops\instrumentation\auraskills-cache-patch.jar
```

No options are required. Premain only transforms the pinned target on initial
load; a version/hash mismatch is logged and leaves that class unchanged, allowing
unrelated server startup to continue. The daemon startup check stops after the
plugin is enabled and equality is verified. Default receipts and event log:
`logs/auraskills-cache-patch.json`, `.json.txt`, and `auraskills-cache-patch.log`.
A receipt with `phase=startup-verified`, `success=true`, `transformApplied=true`
confirms activation. Pending registration alone does not confirm activation.

To restore original behavior online, use the same CLI with `--mode rollback` and
a fresh result path. Rollback disables/removes this agent's load transformer,
restores its embedded original class bytes and clears the component cache.
Original identity comparison and its leak return, so rollback is a temporary
operational fallback. To prevent application on the next launch, remove the
`-javaagent` argument or remove the opt-in JAR from the launcher's fixed location.
Online rollback does not edit launch configuration or third party JARs.
