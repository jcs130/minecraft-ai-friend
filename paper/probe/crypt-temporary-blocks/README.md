# 亡灵墓穴临时搭建验收

本目录的回放使用合成地形和真实的 `DurableConfigFiles` 文件事务。它覆盖放置、结算、离场、下一场清理以及进程中断后的账本恢复。Paper 放置事件、实际保护插件、角色和宠物、配方扣料与世界存盘仍需在隔离测试服（stage）逐项验收。本文没有实服测试结果。

## 准备测试服

使用独立世界副本、测试角色与该服自己的检查点。记录候选 JAR 的 SHA256、实际服务端版本、世界 UUID、遗迹 ID `undead_crypt` 和当前场次状态。以普通生存角色查看 `/mycli dungeon info undead_crypt --verbose`。在副本中实测允许区域与安全出口，逐格记录原始 BlockData（含 `air` 或 `cave_air` 的区别）；在盒外选一个对照格。结构详情应能确认原生结构的完整 ID 和覆盖目标格的部件。单独一个 `areaIds` 或外包盒无法证明该格属于部件。

下面是 `plugins/AgentFriend/config.yml` 的格式示例。UUID、结构 ID 和坐标均为虚构，示例保持关闭。启用测试时换成实测值并设置 `enabled: true`。每个 `reserved-boxes` 条目按 `[minX,minY,minZ,maxX,maxY,maxZ]` 排列，包含两端。`exit-feet` 是角色脚所在格，选在测试盒柱以外、世界边界内，具备固定安全地面且脚、头两格净空的位置。

```yaml
crypt-temporary:
  enabled: false
  world-uuid: '00000000-0000-4000-8000-000000000001'
  generated-structure-id: 'generated:stage:sample_crypt:100:40:100'
  reserved-boxes:
    - [102, 42, 104, 104, 45, 106]
  exit-feet: [110, 43, 106]
  exit-seconds: 1800
  maximum-cells: 16
  materials: ['minecraft:cobblestone', 'minecraft:crafting_table']
```

临时搭建的配置随插件启动读取。默认关闭的基线在从未启用且无 `plugins/AgentFriend/crypt-temporary/` 的测试副本上做。保留原有生成建筑、领地、WorldGuard 与副本保护。至少准备两名生存参战者 A、B，另备一位可合法开下一场的角色 C。确认 A/B 自带方块、一个工作台、3 块圆石和 2 根木棍，每次操作记录具体槽位、数量和目标格。

## 测试步骤与通过条件

1. **默认关闭。** 用缺省配置或 `enabled: false` 在原保护区开普通场次。手持圆石，对盒内原始空气格执行 `/mycli protect place X Y Z --json`，再按正常方式试放一次。保留 `MC_PROTECTION` 与最终游戏结果。原保护仍拒绝、目标格及库存均未变化，才可记录基线通过。若先前启用过功能，另外验证关闭新放置时保留原配置定位信息和在途账本，下一轮照常处理遗留格。
2. **第一轮正常搭建。** 在启用配置的测试副本，从首房用 `/mycli dungeon start undead_crypt normal` 正常开场。用 `/mycli dungeon status undead_crypt` 记录场次与实际参战者。A 主手持圆石，先查询再原生放一次。查询应返回 `readOnly:true`、`status:allow_likely`，查询本身不扣料、改格或占用配额。放置成功后同一格呈现圆石，A 恰好少一块。登记这一格及临近未动格。换成箱子、改到盒外但仍属保护区、尝试破坏原建筑，分别核对实际拒绝及无变化。场中另队不得并开第二轮。
3. **结算后留场与离场再回。** 第一轮正常通关，记录最终结果与场次。A 从结算起持续留在墓穴内，在 `exit-seconds` 内接着做下一项的工作台预览与放置。B 同样在场结算，随后步行越出墓穴边界，再返回同一空格试放，须拒绝且不扣料。另取同一阶段的独立副本测窗口恰好到期后 A 也失去权限；退出、跨世界或重新登录不能恢复已结算场次的放置权。
4. **工作台预览与实耗。** A 主手持工作台，在留作工作台的合格空气格查询 `protect place`。换成箱子对同格重新查询，结果应体现所持物品差异。遇 `unknown_rate_limited` 时按 `retryAfterMs` 等待重查。换回工作台，重新查询并正常放一次，验目标格和背包中的工作台数量减少 1。随后打开刚放的台子，在 3×3 合成格用 3 圆石、2 木棍预览石镐。先不取产物并收回原料，合计应无损；重新配方并只取一次，应净减 3 圆石与 2 木棍、净增 1 把石镐。预览许可、原生放置、配方预览、实际合成分别记录。
5. **所有者接管单格。** 另留一个由 A 放置的对照格。测试服所有者先在控制台执行 `mycli admin cryptrelease X Y Z`，留存 `MC_CRYPT_RESERVED_CELL ... status=released`；立即复查地形与库存应无变化。重复一次应为 `not_reserved`。此后所有者可在该格保留相同材质，下一场复原必须跳过它。由普通玩家操作同一管理入口应被拒绝。发生 `journal_unavailable` 时保留现场并停止接管。外部编辑工具要接管已登记的格，应先得到 `released`，同材质外观无法证明编辑归属。
6. **第二轮正常入场。** 遵守原入场、上轮奖励与冷却条件，由 C 从正常入口开第二轮。记录不同的场次 ID。核对上一轮除已接管格之外的每一处支撑与工作台均回到各自原始 BlockData；对照格、原建筑和已接管格保持，地面与背包均无清理额外掉落或返料。旧队伍不会自动继承新场搭建权；用确认未加入第二轮的人进行检查。第二轮实际参战者能从自身库存重新放置并正常结算。
7. **脚下有角色或宠物。** 另用第一轮结算后的同等副本，分别让旧队员、旁观生存角色、驯服的猫、驯服的狼（狗）以及服内实际使用的居民/女仆角色站在已登记的支撑上。另测玩家骑乘或实体在高一层时的情况。记录 UUID、位置、血量和下方方块，令 C 正常请求第二轮。只有在该实体证实抵达安全处后才可拆脚下支撑；也可保留支撑、拒绝开场，待占用者移开后再开。出口被挡时同样核对。任何实体坠落、受伤、消失或被留在空中均为失败。玩家通过与宠物通过须分开记录。
8. **重新启动与真实存盘。** 分两份测试副本，分别在第一轮活动中已有临时格时，以及已结算、仍有临时格时，让测试服正常停启。保存同一世界、插件配置、地下城检查点和 `crypt-temporary/` 事务目录。前一种核对恢复的场次 ID 与参战者，后一种核对重登录不重授结算留场权。用正常开场触发遗留格清理后再停启一次，重新查看原始方块、保留格与账本；已完成的清理不能重复产生掉落/返料。另在隔离副本让已登记格出现不同的第三种材质，确认新场暂缓并保留现场与账本，所有者核实、明确接管后再试。

原始记录由测试服所有者本地保留，以便核对两轮的世界、场次、角色、格位置、实际游戏事件和库存。公开验收单用“第一场／第二场”“A／B／C”“格甲／格乙”等代号写对应关系，记录 BlockData、数量变化和重启后的结果。世界与玩家标识、真实地图坐标、机器名、绝对路径及原始日志仅在所有者本地使用。对未实际执行的行填写“未验”。

合成冷启动用例将同一虚构区块内的格子分别记录代次。旧快照中的已知遗留物可以复原到其精确的空气类型。已经标记的格、被另一场占用的格、管理员明确接管的格均须保留；第三种材质或无法读取的区块会暂缓清理。实际测试服还需确认区块存盘能同时保存该格的恢复代次和方块状态。

## 重跑合成探针

在本目录用本机 JDK、Gson、JNA 及独立输出目录运行。脚本仅编译回放所需的 Java 类，并将结果写入 `lease-replay.json`，其中包含 `terrain`、`journal`、`passed` 和 `actualServerConnected`。

```powershell
.\replay.ps1 -GsonJar <gson.jar> -JnaJar <jna.jar> -ResultDirectory <独立输出目录> -JavaBin <JDK的bin目录>
```
