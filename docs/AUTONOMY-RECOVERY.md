## 恢复原则与工具

`tools/recover_survivor_orphan.py` 默认只预览。恢复前核对准确任务、原生活会话、已关闭且过期的动作租约、逐动作回执、当前原生角色空闲，以及 Qwen 容器启动晚于旧提交的证据。应用只允许在桐人控制器容器停止时执行，避免宿主与 Linux 状态写者争用。

旧控制器及相关原始记录先归档到 `server/survival-agent-state/survival/orphaned-tasks/`。旧模型轮标记为中断、最终结果未验证，不能改成完成，也不重放其中的游戏动作。之后通过已有 `control.py` 恢复自主调度；仍使用原 UUID、背包、生活 session 和聊天记录，身体由原 `BodyReconnect` 恢复。

`world/ops/reconcile_operations_cycles.py` 在现有游戏 QwenPaw 容器内运行。它核对当前原生进程身份、角色空闲和班次锁，短暂暂停对应原生 Cron，将旧占位与证据保存在 `server/agents/recovery/operations-cycles/`，然后恢复原班次。新班次可以重新观察世界，旧班次的未知结果保留。

这些工具不是模型循环，也不添加常驻进程。一个旧任务查询返回 404 本身不足以恢复；如果游戏动作仍未知、角色仍忙或进程没有更替，必须继续核对现有任务。

## 方块交互的原生回执

服务端 `WorldInteractionBridge` 保留原生 `interact_at` 的同一个 TaskRecord，由原生 Numen 执行动作，再在服务器 tick 后记录终态。管理员内部命令 `qdworld interact` 接收已持久化的动作 ID；`qdworld interaction` 只查询该 ID。提交前先保存请求，回复丢失后也不能重新派发。没有添加新的角色行为规则、AI 线程或手动实体 tick。

回执包含身体 UUID、请求 ID、原始参数、进程 epoch 与原生 TaskResult。Python 工具只有验证这些字段后才接受终态；明确点击失败返回给模型继续判断，点击成功还必须通过原有方块和库存后置检查。已受理请求跨重启未完成时仍为 unknown，原生成功或失败终态保留，不能因重启重放。提交前的明确拒绝目前不落原生日志；Python 同样不会自动重发它。

隔离实机使用实际 72 个模组及新鲜独立世界，最终通过 23 项检查：草遮挡真实失败且不消耗物品、正常放置泥土 8→7、移走已放置方块后重复同 ID 不再放置或扣物、停服最后阶段真实受理的请求跨重启保持 unknown、旧终态保持原 epoch。还使用生产 Python `_interaction` 和实际 RCON 分别验证正常响应与故意丢弃第一次 ACK：两次都只发送一次交互、一次同 ID 查询，各消耗一份泥土，查询不重放。最终证据位于 `runtime/interaction-qa-a13ef76bf7d8/result.json`；此前 13 项原生检查另保留在 `runtime/interaction-qa-e0a0557ae212/result.json`。隔离服务已清理，没有挂载生产存档。
