# FOM 全功能验收记录（2026-10-22）

结论：核心玩法已有真实闭环，**整体尚未通过全功能验收**。这轮完成现役 FOM 的完整模块盘点和主要玩法实测；没有把“模组加载成功”“API 已注册”算成该模组全部玩法通过。

范围为 Minecraft 1.21.1 / NeoForge 21.1.250 的现役 FOM，112 个 JAR、135 个运行模块，独立于旧 Paper 千灯纪。全部建造、消耗、战斗在新建的隔离世界执行；正式服保持原 owner、112 个 JAR 摘要、配置与运行状态，没有发布或停服。机器清单、逐项结果及报告摘要见 [验收证据](evidence/fom-full-acceptance-20261022.json)。

## 已定位并修复的系统问题

官方锁定 Numen API 的实际字节码显示：只有 Minecraft 主人在线时，才续期假玩家周围的原生区块加载票。外部 owner 只有 SDK 连接时，远离出生点的身体可能停在未加载区域；初次隔离测试已经出现“位置未加载”，不能把随后的物品变化当成目标模组操作成功。

候选宿主 `maw_numen_server-0.2.1.jar` 为本服务明确登记、希望在线且存活的原身体复用官方 `CompanionChunkLoader`。使用原生有限区域和自过期加载票，不全局 forceload、不另造身体或手工 tick。实际无主人客户端在线、约 500 格外的原身体已走到真实目标，并完成加工、女仆农耕等操作。

新增健康标志 `managedBodyChunkLoading`；FOM 的新宿主健康检查要求此标志。旧 0.2.0 与新 0.2.1 都必须使用各自锁定摘要，拒绝重复宿主；构建安装入口也拒绝把两个版本并排安装造成重复 mod ID。

候选 JAR SHA-256：`11a6dbabd2117b1bb94e4b5ff24ced2de57495b7c580614e7786df89134fc5a7`。

**该修复仅在隔离服通过，本轮未发布到正式服；正式宿主仍是 0.2.0。** 后续发布应走原维护入口、无人检查、双盘冷备及版本锁更新，不能直接往运行目录多放一个 JAR。客户端内容模组集合无需因这个服务端修复改变。

基岩测试还修复了测试工具的历史实体混淆：魂符阶段可能已经出现同模型的旧 actor，动作验收现在只选择本次召唤后新增的 actor。首次失败报告保留；改后完整 37 项重新通过。没有用传送冒充行走，行走另核对原生运动及下载的动画控制器。

## Agent 减少试错的操作约定

这些是本轮实际踩过并验证的调用差异：

- 先读 `operations` 的参数及 `returnTypes`，再执行。`tlm.maid.list()` 返回 Household，已加载女仆在 `.here`，不能对返回对象本身 `ipairs`。
- 食材放切菜板时先 `numen.gear.hold("minecraft:beef")`，然后调用不带 `item` 选项的 `numen.use.block(实际坐标)`。本版直接在选项传牛肉会被按消耗品拒绝；不要改成吃掉它。
- 女仆改名遵循原生姓名牌条件。任务切换前查看 `tlm.maid.info` 的 `can_switch / works_with`，实际装备后再读回确认。
- 菜单槽号属于具体窗口，不能把装备栏、玩家库存、Curios 和女仆窗口混用。锁定 TLM 1.5.3 的这一个空背包菜单中 36–39 是护甲、40/41 是手；这不是其他窗口的通用规则。当前通用布局尚缺足够的槽位语义，后续应补齐。
- 右键成功回执可能同时明确提示“没有可见变化”；`menu.nativeClick` 也不保证目标效果。完成必须以目标方块、实际槽位、产物、血量或魔力变化判断。
- 菜单更改携带最新窗口/stateId/完整组件 hash；殖民地交货携带本人最新库存完整 SNBT。旧 CAS 被拒后重新观察，不按旧内容扣料。
- 殖民地查询有原生 10 tick 间隔；连续接口调用需要处理明确的 `rate_limited`，不能把它当“没有城镇/需求”。
- 工单“受理”与建筑“竣工”、法术“开始”与“命中”分别验收。同 action_id 只对账；未知结果不换 ID 重放。

## 启动报错与稳定性

正式服只读扫描得到 315 条 ERROR 首行，其中 303 条是战利品资源引用缺失，多为 Railways 的未安装可选联动物品；不能把它们等同于 315 次运行崩溃，也不能全部忽略。另有：

- 2 个失败配方：`cosmonauticsdeepair:gravity_generator`、`cmpackagecouriers:deploying/jar_plane`，引用当前没有注册的物品。
- Tracks 的 3 个标签加载错误，包含非法大写 `Tracks:` 命名空间。
- 4 次 Sable 物理标签引用未注册 `copycats:copycat_catwalk`。

最新这批错误发生在启动阶段，本轮没有观测到 `Exception in server tick loop`。正式服 20 项、基岩桥 14 项健康及各自 panel smoke 通过；这仍不是多人负载、长期稳定性或性能收益验收。当前长期多 Agent、复杂载具、跨天殖民地生产和模型自主任务成功率都没有测过。

## 证据与收尾

本轮 42 项 Python、25 项统一适配器 Node 测试通过；实际统一适配器 5 项、冻结 SDK/WebGL 4 项、最终基岩 UDP 37 项通过。使用真实游戏服务器和原生内容，模型调用 0 次，不能给出“大模型自主完成率”。

初期被占用建城位置、错误 SDK 等待参数、返回对象字段、姓名牌和槽位前提、测试饥饿效果并发扣除，以及基岩旧 actor 的失败记录都保留。工具/夹具错误修正后有独立报告，不覆写失败历史；抽屉、终端和缺失模型仍保留为未通过。

两个 Numen 测试身体最终均休眠，原 UUID、完整库存、装备和回执保留；两个主服 QA owner 和独立基岩 QA owner 均正常退出 0，临时 TCP/UDP 端口全部关闭，测试出生点已恢复。正式服原主进程和基岩桥继续健康运行。

后续优先项是发布已验证的区块加载修复，再补抽屉/终端存取、普通 Mineflayer 的专用模组操作、殖民地显示和复杂 GUI。完成这些之后，再以一个真实模型任务跑“采集→加工→建造→补给→断线恢复”的长任务，记录轮数、实际终态和失败原因。
