# 结衣生活推进与完整游戏回复

2026-09-14 的 08:13–10:13 运行审计中，结衣的 12 次生活轮和 6 次对话都正常结束，且两次救援有真实传送回执。不过生活轮多数只读取身份、追加同样的日记；原生工作任务始终是 idle。一次对桐人的回复长 244 字、有 6 个换行，虽然模型完成，游戏单句只接受 160 字而导致整条回复失败。这是本次改动的两个具体触发点。

## 生活轮给模型什么

仍由原生 `qd-life-review-5swvhK` 十分钟定时信号触发，既有 NPC worker 消费，仍是原结衣角色、身体和生活 session。没有第二条模型循环，没有固定农耕脚本，也不修改 SOUL、Cron、模型或旧记忆。

每个新轮次在记录提交意图时，读取一次当前身份、原生任务目录第一页，以及当前实际启用的自身工具。目录只包括原生第一页（最多四项）和下一页游标；角色可按需调用 `task_catalog` 查询更多，不把百科塞入上下文。失败会明确标为不可用，不能补造任务或物品。原来的实时主人在线、原生角色空闲和串行入口检查仍执行。

首段包含当轮时间、实际坐标和新回复数量，避免官方记忆检索总是取同一个通用提示前缀。上一轮真实完成的模型任务留下最多 800 字的短摘要及完整摘要哈希，标记为模型自述，不能当成动作回执。失败轮不会覆盖上次有效续接，失败结果另外带入。旧在途请求沿用原 prompt 和提交键，不用新提示重新提交。

模型自行选择一个有价值的步骤、解决一个阻塞或有理由地休息。提示明确要求先检查工具、材料和地点，再选择原生工作；`activity=work`、`taskId=idle`、答应分工或切换模式都不等于有产出。需要新鲜证据才记录新成果；没有变化不用重复追加相同日记。生活总结保持私密，主动交流仍须真实 `party_send`。收到回复只进入下一原定生活轮，不额外唤醒。

## 长回复怎样进入游戏

模型仍被要求简短说一句话。超过单句长度的正常回答有兼容路径：

1. 原生最终文本上限 960 个 Unicode 码点。换行和制表符只替换为空格，保留原文 `sourceText`；没有摘要模型、没有删掉结尾或改写意思。伪工具语法、框架终止哨兵和其它控制字符仍拒绝。
2. 完整正文按标点或边界拆为不超过 160 字、最多 8 段。逐段拼接严格等于规范化全文。第一段保留旧回复 event ID，后续 ID 由该 ID 和段号确定。
3. 每段使用原 Minecraft `party_say`，真实身体、维度、听见范围和原生哈希校验不变。前段实际 heard 后才可发送下一段。所有段的意图在原 SQLite 事务中一起记录。
4. 某段丢 ACK 或重启后，只查询该原生 event，不重说。尚未发出的尾段可在恢复原交付时按顺序继续；拒绝或过期则停止尾段。不会给片段新建对话任务。
5. 只有每段全部实际 heard，才把消息标记 answered，并将完整回复作为一次感知事件交给后续生活轮。部分交付时，未送达的正文仍是私有草稿；公开状态只显示各段回执与交付状态。

原文/规范化正文/片段列表、每段身份及文本哈希、原生 heard 回执构成同一条证据链。短回复继续采用旧单事件格式；没有把一个片段的回执冒充全文回执。TTS 也只消费已经全部 heard 的各段，沿用既有逐 event 幂等队列；真人实际听到声音须另行验收。

## 状态迁移与部署

不改变 SQLite 表结构。新片段仍存在原 `world_speech` 表内，完整回复的 `speechParts` 和 `worldDelivery.parts` 是新增字段。旧单段请求、回复、消费记录按原校验读取，旧失败或未知记录不被改成成功。

需将两个持有队伍 Python 代码的执行进程一起安全更新：先让桐人原轮次 drain 并等待结衣当前任务及消息交付结束，备份队伍 SQLite 与生活状态；更新 survivor 镜像和 NPC 进程，确认都使用同版代码后 resume。不能在旧 survivor 仍运行时让新 NPC 发出分段回复。Qwen、MC、Cron 和人物配置无须为此重启或重建。

`party_health` 新增已加载生活推进版本与分段传输版本检查；它们只证明组件版本。已有容器 restart/watchdog 继续管理进程，没有新增常驻服务。`smoke_survivor_party` 对新分段逐一读取真实 Minecraft 回执，检查全部分段与原生最终文本绑定、身份、顺序、文本哈希和听见事实；旧单段仍可验。源文件漂移不能靠重写历史报告哈希消除。

## 验证及尚未承诺的效果

回归覆盖真实 244 字样本完整交付、部分 heard 不泄漏全文、不产生回调、中段丢 ACK 后重启只读、中段拒绝及过期停止尾段、乱序领取拒绝、原文幂等冲突、伪工具语法/控制字符限制、严格 live smoke 的片段篡改拒绝，以及生活目录按需披露、短续接和失败轮保留上次有效摘要。

这些回归与已加载版本不等于结衣已经在生产耕作。部署后应观察一个新自然生活轮：记录它实际读取的能力和选择、原工具调用、身体工作状态变化以及能核实的产出。真实分段验证要使用新消息和新原生模型任务，不能重发那条历史失败回答。最终结论必须区分正常运行、口头分工、工作配置与实际产出。
