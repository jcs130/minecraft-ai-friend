# FOM 暮色森林扩展

目标是给现役 FOM 2.42 增加一个独立冒险维度，保留当前主世界、账号和 Agent 身体。与旧 Paper 千灯纪是两个独立实例；本次不向 Paper 放置 NeoForge JAR。

**2026-10-23 已发布并运行。** 正式主服务 20 项、基岩桥 14 项健康检查通过；普通非 OP LAN Agent 登录、本人新鲜 46 槽原生库存及同 UUID 重连 3 项通过，测试账号已正常退出。没有恢复其他 Agent 的模型循环。见 [发布证据](evidence/fom-twilight-20261023.json)。

## 固定版本与客户端

- Minecraft 1.21.1 / NeoForge 21.1.250。
- Twilight Forest **4.8.3345**，官方 NeoForge 正式版，文件 7797302；不是不同 MC/加载器的较新构建。
- 官方文件：[CurseForge](https://www.curseforge.com/minecraft/mc-mods/the-twilight-forest/files/7797302)。JAR 元数据要求 NeoForge `[21.1.209,)`、MC `[1.21.1]`，无额外必装库。
- 服务端 112 → **113 JAR**。111 个已有 JAR 原 SHA 保持；另一个已有 Support JAR 仅替换 `NativeRegistryDump.class`，开放既有 OP 原生形状导出，其他类/认证实现保持。
- 原始下载、长度、SHA256/SHA512、依赖和注册表见 [版本锁](fom-twilight-20261023.lock.json)。哈希由官方 CDN 原始下载计算，不冒充上游 SHA256 声明。

Java 需要同版本暮色森林。完整干净安装包和六 JAR 增量包在 `E:/MC/发布/FOM-2.42-暮色森林-20261023`，F 盘有相同校验副本。完整包在已校验的 20261020 SmartNPC 导入包上增加殖民地五件套及暮色；普通玩家 134、客户端 Agent 137 个启用 JAR，保留作者 10 个禁用项。不是从玩过的实例打包，没有世界、启动器账号、模型 Key 或 RPC 状态。已有殖民地五件套的客户端只加暮色，不能同时留下其他版本的同名模组。

基岩只接受服务器下发资源包，不安装 Java JAR。Mineflayer 继续使用原生网关及同一个玩家连接；纯原版投影的物品 ID 不能当作模组真实身份。

## 进入与游玩

维度为 `twilightforest:twilight_forest`，主世界不重生成。地面建立 2×2 一层水池、周围围花，再向水池投入一颗钻石，按模组原生传送门进入。保留原生进度与首领解锁顺序；不默认给全解锁或装备。

当前端口不变：Java 模组客户端 `192.168.3.163:28976`，Mineflayer `192.168.3.163:28977`，基岩 UDP `192.168.3.163:28988`。管理 HTTP/MCP 仍只回环；不新开防火墙或路由端口。已有公网映射不等于本轮重新实测外网。

## 网关与可视化适配

新原生导出包含 5680 方块、6956 物品、210048 状态；网关、网页原素材和基岩资源严格绑定这一份注册表。不能只把 JAR 丢进旧服务端后沿用旧物品编号/缓存/资源包。

正式再次导出逐项确认所有状态 ID、名称、属性及其余字段相同，物品/方块/实体/组件/序列器编号一致。原始导出并非每字节相等：8 个旧齿轮遮挡边界为 Float32 等价的 Double 末位差异，频道数组仅次序差异；另外 `reactor_debris` 的方块实体轮廓依赖实例、空上下文返回随机形状，因此不宣称其轮廓/专用渲染一致。字节码确认其碰撞仍为整方块。不能把这一个随机轮廓当作整个注册表错位，也不能拿导出的空上下文轮廓冒充真实实例形状。

`native-twilight-types.cjs` 按固定 JAR 的 StreamCodec 增加 47 项物品组件和 4 项实体序列器，包括有界计数、真实 64 位值、药瓶、探矿数据、蜡烛等；未知类型仍显式拒绝，不猜长度。原生消息在原版投影前保留。

共享 `mc-visual-console` 增加 43 项经审计的持久组件转换；原生库存真实读到药瓶剂量/药水、玻璃剑冷却、旅行靴属性和探矿数据。其余 `ore_filter`、`stored_broken_attributes`、`magic_painting_variant`、`item_display` 没有足够注册上下文，明确不可用。不能把支持解码当作支持该道具的完整玩法/图形。

网页已按原 JAR 构造器审计部分普通物品，钢叶剑和空白魔法地图在真实同账号 WebGL 界面解码为图标。玻璃剑为双层原模型，当前仍提示 `NATIVE_ITEM_LAYERS_UNSUPPORTED`；药瓶、罐子、旅行靴、探矿器、拆解台等特殊物品/界面以及暮色生物专用模型仍有缺口。不得用原版相似图标或实体假装已完整兼容。

基岩新增 192 个暮色静态物品图标、2948 个暮色方块状态映射。整套现有桥覆盖 3216 方块类型/62413 状态、1461 个三维方块物品，原 241 女仆模型/声音保持。该统计不代表全部暮色动画、Boss、机关或容器界面已完成。

## 验证与边界

- 隔离平坦世界、明确管理员物料/传送夹具、0 模型调用；不是自主生存通关验收。
- 普通 Mineflayer 复用原 QA UUID/数据，登录与原生完整库存通过，真实进入暮色维度、收地形；WebGL 绘制和钢叶剑/空白地图图标实见，无页面异常。特殊渲染失败保留。
- Numen 同身体原生放置暮色橡木、实际打开 `UncraftingMenu` 通过；正常重启保留 UUID/库存，验收后休眠并释锁。投掷钻石未观测到传送门成功，不能据此宣称已验证 Numen 原生开门，也不能直接断言模组禁止假玩家。
- 实际 UDP 基岩原玩法回归 **36 项**，暮色专项 **23 项**通过，含原物品身份/图标、进入维度、地形及回到原维度。是脚本 UDP 客户端，不是手机 GPU/Xbox/WAN 新验收；正式 Xbox 校验保持开启。
- 网关全量 **330**、Python 定向 **58** 通过。共享渲染原全量 1210 通过、32 个既有条件跳过，另有 1 个暮色静态物品审计测试通过。首次缺 Pillow 的构建/测试、错误组件持久字段、旧注册表匹配失败和关闭脚本参数错误均保留原始记录，不混算为游戏功能成功。

原始包、UUID/完整库存、凭据、截图、JAR、导出素材、临时世界和一次性发布/验收脚本保存在私有 research；不提交 Git，不重放旧动作或恢复暂停的 Agent 模型循环。共享源改动归 `mc-visual-console/main`，运行冻结包仍需单独发布，网站 Paper viewer 不会因此自动变成 FOM viewer。

Mineflayer 新画面配置示例为该目录的 `client.example.json`，使用 `renderer-v3` 和本次原素材；旧 colony viewer 的注册表不能混用。主网关为 `ops/agent-gateway/twilight-20261023-v1`，基岩为 `ops/bedrock-twilight-20261023-v1` / `ops/bedrock-gateway-twilight-20261023-v1`。基岩运行目录迁移后，以相同 HKCU Run 入口/配置路径/任务名重新登记新邮箱并核对私有 DACL，没有增加一个重复启动项。仍是当前用户登录后启动，不能宣传登录前开服。

安装前发现 FOM 原实例已离线，不能把这次冷备说成刚刚正常停服。离线双盘备份 `backups/fom-twilight-20261022/before.zip`：1951 文件/140988559 字节，CRC、逐成员 SHA 和双盘归档 SHA 均通过。保留旧网关/桥目录、原 mod 锁、唯一替换的 Support JAR、所有世界与认证配置；安装前再次核对冷备源文件没有变化。

回滚须先让玩家退出、正常停服并另备当前存档。恢复原 mod 锁、Support、两个服务配置及旧网关/桥指针；暮色已生成后的存档含新增注册内容，不能只删 JAR 然后宣称安全回滚。需要回退存档时使用这份完整冷备，并明确会丢失备份后进度，不自动覆盖玩家的新发展。
