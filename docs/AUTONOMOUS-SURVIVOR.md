# 桐人：自主生存与可编程技能

用户在 2026-09-08 授权开始第一个自主生存 Agent，选用之前的桐人。目标由模型结合环境提出，执行后用真实结果复盘，并把可复用行为写成技能程序；初始生存任务仅用于验证系统，不把挖木头、造工具等固定脚本当作自主规划。

## 组成与身份

`survivor` 是一个受 Docker 监督的独立容器，镜像 `qiandengji-survivor:2.2.0-qd1` 基于已升级的游戏 QwenPaw 2.2.0，额外安装 `nbtlib==2.0.4`、`quickjs-ng==0.16.2.1` 并包含本项目源码。容器内监督进程启动原生 QwenPaw 和持久调度器，使用单实例锁；QwenPaw 退出会让服务停止并按容器策略恢复，不留下散落的裸进程。

| 入口或身份 | 当前用途 |
|---|---|
| `127.0.0.1:18091` | 桐人的独立 QwenPaw 控制台，本机免密码 |
| `127.0.0.1:19091/#survivor` | 身体状态、当前目标、物品、调用预算、技能和经历 |
| `127.0.0.1:19091/#services` | 预览并确认启停“桐人 · 自主生存”服务 |
| QwenPaw `qd-survivor` | 唯一启用的自主规划角色，显示名桐人 |
| Numen `Kirito` | 复用原生存身体，UUID `d4ac9523-4962-43ed-98c5-19b49e104048` |
| `server/survival-agent-state` | 独立模型配置、私钥、会话、预算、技能、回执和学习记忆 |

身体以登录名和实际 UUID 双重检查，避免误接同名旧记录。2026-09-08 的唤醒记录确认复用旧 UUID，20 生命、20 饥饿、等级 5、30 个库存槽位，未创建替代身份；这些是唤醒时状态，不是长期生存成果。私有记录为 `reports/survivor-body-binding.json`，唤醒前备份在 `runtime/survival-body-backups/`。

旧玩家数据中的 NeoForge 附件已绑定 YSM `qiandengji_kirito`、纹理 `skin`，本轮沿用它。原桐人本轮唤醒后的客户端外观目视仍待验证；已有临时测试角色的模型验收不能代替这次原角色验收。模型集成来源见 [人物模型集成](PLAYER-MODELS-INTEGRATION.md)。

神谕两角色仍使用 18089，运营六角色仍使用 18090。自主容器只读取运营司灯当前选中的单一 Ali Coding Plan provider，在独立目录生成新主密钥并重新加密；不会复制运营任务、会话或工具。宿主 QwenPaw 8088、旧守卫驱动和其他角色用途保持原边界；身体权限只在本容器的固定 Numen MCP 内提供。

## 规划、执行与学习

控制器约每 15 秒读取身体、任务和既有回执。身体空闲、预算允许时，向 QwenPaw 原生后台任务提交本轮目标、真实快照、学习记忆和近期执行证据。模型可以调整目标，选择一次直接动作，或者编写、测试、晋升一份技能后排队运行。

一次直接动作需要唯一 `turn_id`，只能作用于绑定身体。技能程序实现纯 JavaScript `next(state,memory)`，每步返回 `{action,memory,done?,replan?,reason?}`。程序获得新快照后只提出下一动作；实际移动、挖矿、制作、进食和装备仍由现有 Numen 执行。异步动作期间只观察，不重复派发，也不为每个动作调用模型。

技能通过 `skill_draft` 保存源码和至少两个不同输入的测试，再经 `skill_test` 和 `skill_promote` 晋升。源码、测试样例、内核版本与引擎版本共同决定可用性；新源码不能复用旧测试报告。`skill_start` 只排队已晋升的准确版本，且与同轮直接动作互斥，模型轮次结束后才由控制器运行。

程序无法访问宿主文件、网络、系统命令或 Python 回调；内核限制每次约 0.1 秒 CPU、16 MiB 内存和 256 KiB 栈，技能任务另外限制最多 32 步、900 秒。通过测试仅表示样例通过，程序自述 `done` 与真实库存、位置变化分别记录，不能把“受理”或“空闲”写成任务成功。

旧版本及晋升历史保留。需要回滚时，在有效规划轮次重新测试所选旧版本，再对该版本 `skill_promote`；当前活动版本切换到旧版本，已排队任务仍固定自己的版本，不能被悄悄换代码。若内核升级，旧测试签名失效，必须重新测试。

`remember` 保存目标、实测经验和下一关注点，每项最多 1000 字，保留最近 16 条历史。记忆和环境文字作为数据提供给规划角色，不改变系统提示或权限。这种学习是积累、测试和修正程序与经验，未训练或微调模型权重。工具契约与示例见 [运行组 API](../world/survival/README.md) 和 [角色指引](../world/survival/AGENT.md)。

## 版本选择与机制来源

本轮锁定已经审查的 QwenPaw 2.2.0，官方发布页记录该版本于 2026-09-03 发布，并列出控制台、Skills 和可靠性改进；实际接口同时核对了容器内同版本源码。升级到具体可验证版本不等于证明它在所有方案中最优。[QwenPaw 官方包发布说明](https://pypi.org/project/qwenpaw/2.2.0/)

自主目标、可执行技能库、结合环境反馈和执行错误进行迭代，参考 Voyager 的公开机制。本项目采用 QwenPaw 规划和 Numen 身体接口，技能还需要经过本项目执行门；没有移植 Voyager 的基准成绩，也没有宣称达到其长期探索能力。[Voyager 项目与论文介绍](https://voyager.minedojo.org/)

JavaScript 使用维护中的 QuickJS-NG Python 包，项目说明其兼容 `import quickjs`，支持独立运行上下文及时间、内存、栈限制。本项目显式不向上下文注入 IO 或宿主函数，并固定包版本，以便测试和复现。[quickjs-ng 0.16.2.1](https://pypi.org/project/quickjs-ng/0.16.2.1/)

## 预算与停止方式

当前模型是 `aliyun-codingplan / qwen3.6-plus`。默认滚动 24 小时最多 48 次决策，两次决策至少相隔 180 秒；并发为 1、每分钟最多 4 次模型请求，每轮最多 6 次迭代，输入上限 16384、输出上限 2048，后台任务执行上限 240 秒。自动重试、回退模型、后台记忆推理、标题生成、heartbeat 和额外定时任务均关闭。

一次决策可能产生多次模型调用，因此“48 次决策”不是“48 次请求”。健康检查、页面读取、身体观察和已验证技能逐步执行均不调用模型；规划、编写代码、修改失败技能仍消耗模型请求。面板分别展示决策数量和 QwenPaw 记录的模型请求、Token，用量记录不等于实际账单金额。

本机 CLI 示例，在项目目录运行：

```powershell
docker compose -p qiandengji exec -T survivor python /survival/control.py status
docker compose -p qiandengji exec -T survivor python /survival/control.py pause
docker compose -p qiandengji exec -T survivor python /survival/control.py mission --text "观察附近自然资源，自主选择一个可以验证的小目标"
docker compose -p qiandengji exec -T survivor python /survival/control.py resume
```

`pause` 关闭动作门，调度器停止对应原生模型任务并处理身体任务。无法确认停止、模型提交结果丢失、程序动作中断或 Numen 回执不明确时保持暂停；不得清除账本后自动重试。`resume` 要求没有未核对动作或活动模型任务，并且已检查和配置工作区域。服务启停与自主暂停是不同操作，重启服务不会重放不确定请求。

## 真实限制与验收进度

Numen 的 `goto` 可能为寻路挖掘或搭方块，`mine` 会自行寻找目标；工作区和出生地保护半径是动作预检，尚非服务端不可穿越的硬地理围栏。区域应选择已观察的自然地形，不能把预检当作允许在玩家建筑旁无条件运行。

既有 Numen 在拥有者不在线时，身体死亡不会自动复活。当前系统发现身体不可用会停止新决策，不能保证无玩家在线的长期自救。实验必须保留原生命、物资、角色身份和正常生存规则，不能用创造模式、传送、补物品或假回执制造成绩。

已完成独立运行配置初始化与离线校验，已唤醒并核对旧身体。技能内核和 MCP 的隔离测试覆盖无 IO、资源限制、错误反馈、版本晋升、暂停、单动作与不重放。第一项真实背包任务、自主技能编写及修改已验证；持续无人值守的野外生存尚未验收。

### 本轮真实实验

2026-09-08，复用原 Kirito 生存身体，使用独立 Ali Coding Plan / `qwen3.6-plus` 完成以下实验：

- 模型自己编写 `craft_sticks` 的 JavaScript 和测试，在原生 QwenPaw 会话中可核对源码。首版 3 个案例通过后，由程序调用 Numen 实际合成一次；木棍 **14→18**、橡木木板 **9→7**，生命和饥饿均为 20。程序读回库存后停止，没有创造、补物品或传送步骤。
- 模型随后修改技能并保留三个版本，测试案例依次为 **3 / 5 / 7**。新版本增加无进展时返回重新规划、区分材料变化的诊断。后两个版本通过隔离测试，没有再消耗游戏物资。模型写下的复盘属于学习记录，其解释仍需核对代码和真实证据。
- 调试期保留 **4 轮决策、19 次模型请求** 的原始账本，其中一轮主动暂停。累计输入 **172,007**、输出 **12,432** Token；没有清零失败或取消的消耗。这是本次实验用量，不能换算成未经核实的实际账单。
- 发现附近实体把静止身体推过方块边界会造成一次多余唤醒，已改为相对上次决策位置的阈值：水平 8 格或垂直 4 格。主动动作的完成证据仍独立唤醒；时间戳更新和小幅推挤不唤醒。任务、库存、生命、饥饿、明显位移和技能结果不变时进入 `idle`，超过 180 秒冷却也不固定重复推理。
- 当前管理台能查看真实库存、三份技能版本、动作观察、决策预算与累计用量。实际浏览器 DOM 和截图已检查；YSM 通过在线身体附件读回，模型为 `qiandengji_kirito`、贴图 `skin`、启用且强制显示。本轮没有新增游戏客户端目视验收。

89 项生存相关测试、113 项健康测试、49 项管理与页面测试通过。本机证据在 `reports/survivor-smoke.json`；私有学习记录与会话在 `server/survival-agent-state/`，不随源码提交。Minecraft、world、原游戏 QwenPaw 和运营 QwenPaw 在本轮保持同一容器身份及启动时间。
