- 策划的首段提示词仍一律要求货单 JSON。现在区分原 `guild_quest` 严格输出与团队内容工具入口，并同步现役技能指南。

## 当前链路

`真人公屏 → Jev 单次 choice → 女神 / npc:key / 不回应`

NPC 候选来自现有档案，最多 48 个，不允许模型自行创造身份。消息仅入原 `npc-inbox.jsonl`；原消费者核对档案版本、新鲜度、实际实体和原生同维度 48 格内听见范围，再调用 `route(target_key=...)`。公屏交易仍走原教学，不冒充私聊交割。原始聊天观察保持，真人不再同时触发旧 NPC 日志路由。

SQLite 先记录事件 ID，再发原 tellraw；成功标记只表示命令提交，不能证明客户端听见。重复与未知结果不重发，离线或远距离接收者不发话。仍是原收件箱的启动/轮转从末尾读取策略，不提供停机期间聊天补发。分类器两槽、两秒超时，过期或换句结果丢弃；低置信只保留明确且不歧义的称呼回退。

`原生策划 Cron → world_content_submit → mc-god 审批 → 原 NPC content tick → 已发布故事与原合同 → NPC 对话`

内容投影复用 `world_content.episode_lines` 的发布与目标一致性校验。`mc_guild.npc_story_lines` 只读当天实际看板，不为闲聊生成新合同。角色读与自己相关的阶段，岚读活动概览；台词带可接、已承接、已结算或已下架状态。旧日期、草案、未确认发布和变化后的目标不采用；预设结局只在明确查询全文时标注为剧情文本。

剧情慢系统写共享缘由与人物阶段线索，NPC 快速使用这些已发布文本。尚未开启全村逐句生成式闲聊，也未实现任意自然语言都能自由续写长期叙事。故事连续性与角色语气仍需策划依据真实玩家反馈逐轮完善。
