# 桐人与结衣的持续运行与调用开销

2026-09-14，对游戏 Docker 中现役 QwenPaw 2.2.1 检查并更新。继续使用现有 QwenPaw 会话、记忆、定时任务和游戏工具；没有部署第二套 Prime Agent 后台。

## 当前能力与边界

两人都在固定生活会话中由 LLM 选择目标、查询 MCP、使用工具，并保留笔记、ReMe 自动记忆和 Dream 整理。动作由游戏原生能力执行，结衣的对话经游戏接口或私聊进入感知，忙时持久积累，下轮处理。

桐人另有程序实践链路：自己草拟 QuickJS 程序、写样例、测试、晋升、在原控制器试运行，读取独立实践回执，再修订版本。结衣当前使用原生角色行为与 Markdown 技能学习，没有接入同一套程序实践账本。两者不能笼统说成已经具备完全相同的自我进化能力；记忆整理也不证明经验正确。

真实试验：桐人生成并晋升 `farm_harvest_replant`，随后在世界运行。首个版本 `2ad6b78faf5324b136acb4d516bf37931d86893e12189bbf6579cda842965f0f` 在维护前完成29次观察、没有发出农耕动作；源码读取了未被填入的 `memory.obsResult`，实际观察入口为 `state.execution.observation.result`。该次因维护自然排空而停止，不能记成超时或成功。原版本、观察及实践 ID 保留，应由模型依据真实证据修订，不手改其测试通过标记。

## 调用限制

| 项目 | 桐人与结衣实际状态 |
|---|---|
| 自主任务每日人工预算 | 无，配置为 null |
| 决策人工冷却 | 0秒 |
| QwenPaw 模型每分钟人工上限 | 0，表示不设上限 |
| 原生循环迭代上限 | disabled；现有运行适配使用无限迭代 |
| 同一角色并发 | 1，避免争用身体或重复操作 |
| 失败自动重试 | 关闭；未知副作用不得重放 |
| 单轮身体动作 | 桐人最多6个串行动作，然后由持续会话接续 |

这些模型次数与迭代限制在本次更新前已经关闭，本次没有把旧 `max_iters=12` 改成更大数字冒充解限。该旧序列化字段在 disabled 策略下不是有效迭代上限。供应商自身的额度与限流仍可能生效。

本地模型名额实际按进程内 `provider_id:model_name` 共享，同模型不同角色及记忆请求可能排队；它与身体的单动作租约是两层机制，不应混称。21:13的 `task-d7273f4104e3` 表面报 `MODEL_QUOTA_EXCEEDED`，原始 dump 却是 `_AcquireTimeoutError`：在供应商调用之前，本地 acquire 等待30秒超时，被原生异常分类泛化。没有供应商429、错误码或 Retry-After，也没有证据证明锁泄漏或套餐用尽；21:15原控制器下一轮自然成功。不能要求用户为此充值。

21:24通过 `tools/configure_survivor_queue_wait.py --apply` 将原生桐人 `running.llm_acquire_timeout` 从30秒调整为120秒，结衣原有300秒保持。默认运行该工具只预览，实际应用要求原控制器排空、角色空闲、原Cron暂停；原生PUT只提交id/name/running，完整GET回读验证仅该字段变化，失败不重试，备份与回执保留。角色名称/模型/其他运行参数不变。离线初始化模板同步120秒，未重跑旧初始化器；Qwen健康探针要求该等待不回退到短于120秒。它减少本地排队提前失败，不证明争用已消失，也不改变真实供应商限流和未知动作保护。

## 本次实际优化

结衣原 `qd-life-review-5swvhK` 定时任务从10分钟改为3分钟，仍只发布生活信号，本身不调用模型。同一角色忙时合并机会，按最新信号在原会话接续，不新增 Cron 或常驻进程。新信号带 `slotSeconds=180`；旧600秒信号、进行中任务和回执按实际时间比较，避免升级后丢失或重放。

桐人 `skill_start` 新增可选 `summary`。只有程序真正排队成功、名称/版本/turnId与当前工具调用一致、模型提供的总结与回执一致时，原生收尾器 VERSION4 才直接保存并输出该总结，免去额外模型调用。它确认排队，绝不把排队说成执行完成。旧调用兼容；参数错误、写入失败、身份不符或还有待执行工具时，不提前结束。

这针对了实际浪费：20:50的一次成功排队后，桐人又两次调用已经失效的 `remember` 才结束。现有 `remember(finish_turn=true, summary=...)` 继续保留。新版工具描述和两页实践指南已通过 QwenPaw 原生文件 API 更新到真实角色工作区，身份、模型和技能元信息未变。

结衣 `party_send` 明确要求单行文本。非法参数在入队前返回固定的字段、原因和未入队/未发送标记，不回显原文，不自动改写或重发。实际发送后未知结果仍维持原有未知语义。

## Token 与缓存

21:01的当日原生统计：结衣输入28,712,009 tokens，其中18,469,504被记录为缓存读取，约64.33%。桐人的适配器记录为0，但当前 AgentScope 对缺失缓存字段也默认计0，不能据此证明供应商确实零命中。

已检查 QwenPaw 2.2.1 源码：工具按名称稳定排序，保持固定角色文件和原会话；记忆每外部回合检索一次并放在当前输入之后，技能资料按需读取。没有为优化缓存再塞入全文资料、重排人格文件或重复增加记忆循环。

[百炼显式缓存指南](https://help.aliyun.com/zh/model-studio/explicit-cache-guide)说明了缓存标记、稳定前缀以及 Coding Plan 的 Anthropic 接入；[上下文缓存文档](https://help.aliyun.com/zh/model-studio/context-cache)列出模型支持范围。当前角色使用的 OpenAI 路由尚未验证显式标记，本次保持原供应商/模型/协议。下一步应先采集原始缓存字段是否存在及计数、请求组成的哈希和长度，再独立测试显式缓存，避免记录请求正文和密钥。

[Coding Plan 官方 FAQ](https://www.alibabacloud.com/help/en/model-studio/coding-plan-faq)按模型调用次数计算套餐额度；缓存比例不能等同于节省同样比例的调用额度或费用。优先减少无效收尾调用、空轮询和重复上下文，保留有用的自主行动。
