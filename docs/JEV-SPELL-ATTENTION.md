# 女神意图分流与方块级城镇保护

这一轮复用现有 `player-commands`、铁魔法适配器、QwenPaw 角色和 `qiandeng_irons_bridge`，没有增加后台服务。Jev 只做固定选项分类；游戏执行仍以原生回执为准。

## 私聊与语言接口

`/mycli`、完整技能名和已定义短语直接进入原执行器，不请求 Jev。“咏唱烟花术”“火焰箭”等沿用语音入口的完整匹配规则。需要参数的动作继续使用明确命令，例如 `/mycli cast tp distance=10 direction=东`；参数仍由现有解析器校验。

自然语言私聊在一次 Jev 请求里同时选择流程和技能：施法、答疑/聊天、祈愿、确认或不确定。候选只来自当前精选目录；推断只支持无参数技能及原生法术映射，不让模型编写命令、目标或距离。流程置信度与选中概率均至少 0.75；施法候选两项均至少 0.85。否定、问句、引用、假设即使收到高置信施法答案，也不能执行。

旧入口按包含技能关键词调用施法，可能把“火球怎么用”当成咒语。这一路径已经撤下。分类失败不会退回关键词/向量自动施法；普通求助保留原祈愿裁决，其他内容进入私聊答疑。已学、等级、魔力、装备来源、冷却及执行结果仍走现有校验，不因 Jev 判定而解锁技能。

守护天使代施仍必须使用 `guardian-cast`。语音的举杖授权、录音时间及原生咏唱约束保持原路径，不能通过聊天分类绕过。

## 公屏由谁回应

正常真人公屏通过 Jev 判断是否向女神交流。另一角色的名字可以是谈论对象：“女神，桐人在哪里？”应由女神答；“桐人，你觉得女神怎么样？”不应被女神抢答。低置信或断网时，回退保留明确称呼、祈愿/提问协议和已有求助规则，先识别句首被称呼者，包含爸爸/妈妈等现实称呼。

公屏分类只决定女神是否接话。选到其他对象不会冒充对方或创建后台 Agent 私聊；原游戏消息仍供其他角色的已有感知入口读取。私聊答复保持私聊。公屏不会因 Jev 的技能判断直接施法。

## 延迟、边界和证据

复用 Node fetch 连接，官方固定 HTTPS 地址，密钥只读挂载；拒绝重定向、无自动重试、2 秒超时、最多 2 个在途请求，不堆积推理队列。相同说话者的新消息使旧判断失效，角色或连接变化后不会派发旧动作。模型输出限制 64 KiB，验证完整概率分布及类型。心跳只统计路由、延迟与计数，不记录密钥或私聊原文。

首轮 20 条人工合成消息中，2 条精确命令跳过模型，18 次真实官方分类；高置信结果之外保留“不确定”回退。部分施法分类接近 0.9 秒，一般分类约 240–410 毫秒。此数据是端到端 HTTP 与校验耗时，不能当成官方 80 毫秒服务端推理或真人准确率。没有通过降低阈值掩盖模糊意图。

健康探针 `tools/jev_intent_health.py` 检查新鲜心跳、官方配置、并发上限及测试来源；沿用 world 容器守护和总面板冒烟。

## 城镇保护

保护范围仍为主世界 X[-715,-375]、Z[695,1035]。普通拆建从整区封锁改为固定方块名单：合并已验收施工记录、保留设施的正式存档投影和两盏路灯的清理修正，去掉空气，压缩为 11,896 条区间、88,134 个方块。保留设施名单包含其地下基础；没有把全城自然地形锁入名单。

建筑、道路、公共设施及原有床的坐标继续保护；空位可以放床和搭建，玩家新增方块不会自动加入保护名单，能够拆除。多方块放置逐个检查目标，活塞检查来源和目的地。公共农田继续允许成熟收获、补种；门、箱子与交易正常使用。火焰、流体和危险桶操作仍按原安全区域约束，不把建筑开放等同于取消安全区。

名单随桥接 JAR 发布，启动时读取一次，方块查询用集合查找。缺失或损坏时回退整区保护，并由健康探针明确报错；禁止悄悄裸奔。`qdworldprotect status` 输出 schema 2、保护模式、数量及名单 SHA-256。更新公共建筑时应重新生成和验收名单，不自动锁定所有玩家新建筑。

离线测试与真实隔离 NeoForge 测试分别记录。隔离服使用相同候选 JAR 和保护名单，真实假玩家走原生放床、拆除、农耕、交互和爆炸逻辑；不是向生产城镇尝试破坏。测试夹具与带物品的世界存档留在私有运行目录，不进入生产 JAR。
