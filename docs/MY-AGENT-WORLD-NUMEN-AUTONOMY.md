# Numen 自主运行验收与排障

测试使用 Minecraft 1.21.1 / NeoForge 的完整现役模组集、官方 Numen 0.1.4.1、服务端 `NumenPlayer` 和官方 `AgentLoop` / `SerialCalls`。线上模型为 CodingPlan `qwen3.7-plus`。Mineflayer 普通账号仅用于建立主人会话和提交配置，不负责测试身体的规划或动作。没有连接 QwenPaw Agent。

长期常驻 Agent 的分工与新桐人方案见 [常驻桐人设计](MY-AGENT-WORLD-RESIDENT-KIRITO.md)。该设计尚未部署；本文的七类独立目标验收不代表目标自动续接、长期记忆整理或全天自主生活已经完成。

## 两种验收

默认合同测试不调用付费模型：

```powershell
python tools/smoke_numen_server.py --full-pack --node <node.exe> --output <运行目录/research/新目录>
```

需要验证现役登录策略时，加 `--mixauth-jar <已校验的 MixAuth JAR>`。检查新离线账号先游玩、游戏内设置密码、已有密码账号重新认证、未登录原生频道隔离，以及正版身份冒充被拒。真实微软账号和手机需要另行验收。

线上自主测试必须显式启用，并使用被 Git 忽略的私有凭据文件：

```powershell
python tools/smoke_numen_server.py --full-pack --live-autonomy --credential-file <私有凭据.json> --node <node.exe> --output <运行目录/research/新目录>
```

凭据的 `base_url` 为 `https://coding.dashscope.aliyuncs.com/v1`，`api_key` 为本人的有效 CodingPlan Key。不要把真实 Key 放在命令行、文档或提交中。测试在独立世界、回环地址和测试端口运行，默认测试不改变正式服的模型配置、身体或世界。

七个目标为 `navigation`、`survival_tools`、`chest_deposit`、`chest_withdraw`、`farmers_delight_cooking`、`create_milling`、`ars_native_healing`。可以用 `--autonomy-goals` 传入逗号分隔的目标 ID，只验收其中一组。

测试提供并记录障碍、树木、空箱、烹饪原料、带动力磨石和法术学习材料；不替模型派发操作步骤。单独验收箱子时会明确提供木板。因此模组验收证明的是模型能够操作这些设施，不能证明自然生存已采齐材料、搭好完整动力链或自主发展殖民地。

## 判定与证据

`live-autonomy.json` 分别记录：目标是否尝试、模型是否正常结束目标、实际后置条件是否成立、耗时、请求次数、最后请求字节数和停止原因。木镐、熟米饭、面粉等按真实库存判断；存取按真实箱子槽位与库存判断，不能用“我完成了”的回复代替。

治疗验收先等待出生保护结束，只施加一次已披露的测试伤害，并轮询确认实际生命减少后才派发模型目标。`healingFixture` 保存伤害前后生命；若伤害未生效直接拒绝测试。原生 `castConfirmed=true` 和魔力消耗只能证明施法，治疗通过还必须有真实生命恢复。

目标需要正常结束且实际结果成立才算通过。单目标预算暂停时，即使已经制作出物品，也保留“结果成立、目标未正常收尾”的区别。没有待定请求或动作的已知单目标预算暂停，可以进入预先声明的下一个独立目标；不会重投前一个目标。HTTP 拒绝、传输未知和观察超时会中止本轮。

每目标默认最多 24 次模型请求，每身体每日默认最多 100 次，全服并发最多 2 个。测试在累计 80 次后不再开启新目标，每个目标观察最多 420 秒。没有完成的项目不得标记通过；跳过的目标也不得计入通过数量。正常结束后仅停止本轮隔离身体和进程。

托管脑单目标预算默认仍为 24。运维可在服务端配置中明确设置 `modelCallsPerGoal`（整数 1–100），重启生效；不接受模型自行修改。隔离工具的 `--goal-model-budget 48` 会把测试预算写入独立配置和 `live-autonomy.json`，不会修改正式服上限。较长测试与先前预算内未完成的结果分别保留，不用新结果覆盖旧失败记录。

`acceptance.json` 保存真实 MCP、租约、动作去重、取消、断线、重启、原 UUID 和库存恢复、死亡复活、未知动作不重放等合同检查。`server/world-server-numen/maw-numen-server/` 保留完整动作账本和对话。私有证据、Key、存档、第三方 JAR 不提交 Git。

脚本的历史字段 `paidModelRequests` 记录本地派发/尝试计数，不是供应商账单或剩余额度。服务器不可用时，清理失败单独记录，仍读取原脑记录核对次数并保留首个错误。旧测试清理未成功时的零计数不能当作零调用，应以私有对账记录说明。

## 连续目标和模型上下文

完整 SDK 状态与动作账本保留原来的 `before`、`after`、原生菜单和完整物品组件。仅发给服务器托管模型的视图省略重复的 `before` / `nativeState`、空槽位与动画采样，保留真实槽位编号、非空物品完整 SNBT、菜单容量与光标、血量、魔力和装备。

需要完整菜单时用 `mod_query` 查询；`operations` 支持按组或完整函数 ID 查询参数、示例、注意事项及 `returnTypes` 字段说明。不要假设返回值含 `count` 或 `item` 等字段，也不要把 MCP 工具名当成 Lua 全局函数。

`returnTypes` 从原生类型注册表解析记录、联合类型及其引用字段；例如点击物品既可能返回普通点击结果，也可能返回服务器菜单。模组能力通过独立的 `mod_operations` 发现，再使用 `mod_query` / `mod_action`，不能只在 `numen.*` 中寻找。

菜单是否打开以真实 `menu.containerId` / `menuType`、`slotRoles` 和动作回执的 `observedEffects` 为准。原生点击日志的 “nothing visibly changed” 没有覆盖所有 GUI 变化，不可用它断言菜单未打开。`numen.time.wait` 的参数单位是秒，等待三秒应传 `3`，不是 `3000`。

固定版本 0.1.4.1 的 `use.item` 声明为 `Clicked`，但打开菜单时原任务实际返回 `GuiOps.Window`，会引发记录序列化异常并退出服务器 tick。服务端附加模块只把这一项返回契约修正为原生 `Clicks.Pressed` 联合类型，与 `use.block` 相同；动作、权限、真实返回内容不变，官方 core / API JAR 保持原 SHA。验收包含实际打开箱子后调用 `use.item`，并核对服务器继续响应。

显式新目标会归档上一目标的工作对话，保留上一回复摘要并重新读取当前世界。旧对话和动作不会删除，未知请求仍禁止启动新目标。这个边界用于控制工作上下文大小，不代替外部 Agent 的长期记忆系统。

## 失败分类

| 情况 | 处理 |
|---|---|
| 本地请求超过 512 KiB | `model_context_limit_request_not_sent`，已知暂停，不派发 HTTP、不消耗请求计数 |
| 收到 HTTP 401 / 429 / 503 等 | `model_http_<状态码>_no_automatic_retry`，已知暂停；429 本身不能说明总额度耗尽 |
| 收到无法解析或超限的响应 | 明确记录响应格式或大小问题，不执行其中不明的工具调用 |
| 网络超时、连接中断、发送后取消 | `unknown`，保留待定请求，不自动重发 |
| 单目标或每日预算达到上限 | 已知暂停，计数保留，不悄悄扩大预算 |
| 身体脑状态无法写入磁盘 | 只暂停对应托管脑，拒绝后续目标；模型派发前写入失败不发送 HTTP、不增加请求数，已派发请求的不确定记录保留 |

排障先读原身体的状态、停止码及原 `action_id` 回执。不要清账本、换身体 UUID 或删未知记录来恢复运行。

## 宿主意外重启

状态 JSON 先写临时文件并同步落盘，再原子替换；暂停标记和动作账本也同步落盘。落盘同步降低缓存数据未写入的风险，不能保证硬件故障时绝不损坏。

Numen 私有状态发布遇 Windows 短暂文件占用时，只对同一个已同步的临时文件做有限重命名重试，最长等待 31 毫秒；不降级原子替换，也不重试游戏动作。持续写入失败保留异常原因和旧文件，托管脑停止派发，需运维检查后恢复。隔离验收会主动阻止一次脑状态发布，确认零模型请求、原记录仍在、其他连接继续响应；该故障注入日志不代表正式服磁盘故障。

发现坏 JSON 时保留原文件，核验备份哈希与身份后恢复；原动作账本、模型任务和暂停标记保持。监督进程的重启次数耗尽后，在修复原因后使用现有 `maw_service.py resume` 重置重试预算；这不会解除游戏 Agent 的 `autonomy.paused`。

当前 HKCU Run 启动方式依赖此 Windows 用户登录，不保证登录前开服。整机异常重启的原因需另查 Windows / 硬件记录，不能由 Numen 测试通过来证明宿主稳定。
