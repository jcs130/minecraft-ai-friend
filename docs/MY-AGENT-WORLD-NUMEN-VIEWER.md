# Numen 身体的常驻 Web 观战

2026-10-11。入口：http://192.168.3.163:28984/numen/view/ 。在家中局域网打开，输入本人已有的 Agent 接入令牌，选择自己的身体。无需主人 Java 客户端或额外摄像机玩家。休眠身体由原控制器调用 `restore_companion` 恢复；网页不会自动恢复或重放动作。

同一页面可以切换第一人称、第三人称、地下城视角与 OBS 覆盖。这里的“只读”表示网页只观察游戏身体；游戏中的移动、施法和菜单交互继续由原 Agent SDK/MCP 执行。它没有取得控制器租约。

## 数据从哪里来

复用 `jcs130/mc-visual-console` 当前源码构建的原生渲染器、已校验的 1.21.1 原贴图、模型及中文资源。现有 MawExplorer 页面仍在 `http://192.168.3.163:28984/`。

`NativeViewerAccess` 在服务端主线程读取实际 Numen 身体的 UUID、实体 ID、维度、相机位置/方向、血量、饥饿、经验、背包、装备、魔力及当前原生容器；Curios 分页和 Domum 原生预览通过同身体既有只读接口补齐。区块、实体生成、完整元数据和装备使用原生 clientbound 编码，再交给现有模组协议解码器。不会消费实体的 dirty 更新、截取其他玩家的收件箱或模拟另一个玩家登录。

每个登录会话只列出所属账号的身体。URL 不含令牌，令牌仅保存在 worker 内存中，浏览器使用 HttpOnly、SameSite=Strict 的短时 cookie。新登录同一令牌会撤销旧观战会话；同一会话的多个标签页共享身体快照。所有权校验在服务器每次采集时再次执行，令牌撤销会关闭画面。

## 当前边界

- 活跃画面最高每秒采集 5 次，不重叠请求；周边最多 25 个已加载区块列、96 个实体。不生成新区块，不加载远方世界；区块轮询更新，不能承诺每一帧方块变化零延迟。
- 同时最多 4 个观战登录、4 个身体画面。一个令牌仅保留一个登录会话，原身体数量上限仍受 Numen 配置约束。该上限不是长期容量压测结果。
- 已实测移动、受伤、本人魔力/背包、原生 Curios 菜单开关/分页、死亡后同 UUID 新实体自动跟随与跨账号拒绝。
- 这是原生数据驱动的网页观战，不是 Java 客户端视频流。瞬间打开又关闭、持续时间短于轮询间隔的菜单可能漏过；聊天、标题、声音、粒子、完整装备层、全部模组动画和所有专用界面尚未全部接入此 Numen 通道。
- 现有 YSM Steve/Alex/Default Boy 原模型支持范围保持；未知模型（包括 `default/default`）明确报告不可用，不能用近似人体替代。浏览器验收使用隔离身体通过原 YSM 普通玩家接口切换到已支持模型；没有替换正式玩家外形。
- 只开放当前家庭网段。公网 HTTPS、外部准入与实际异网体验单独验收，不把整个 worker 直接映射公网。

## 部署和运维

入口随现有 `maw-agent.mjs` worker 启动，仍由主 Supervisor 的 Job 管理，不新增常驻进程、游戏账号或监听端口。服务器需要同次构建的 `maw_agent_bridge` 与 `maw_numen_server`，以及 viewer 源码目录；运行 JAR、账号令牌、世界和原始包不得提交 Git。

每次 worker 启动由当前源码构建浏览器 bundle。`/build.json` 与当前身体的 `status.json.build` 提供源码指纹、实际服务 bundle SHA256 与注册表 SHA256；更新源码后按既有维护流程重启 worker，不能把 `git pull` 当成运行画面已经更新。

只读体检：`python world/ops/health/health_mon.py --society-numen-viewer-smoke`。该检查验证最新源码和实际下发 bundle、入口认证、原生桥及 Supervisor，不唤醒身体，也不调用模型。正式维护仍按零玩家、优雅停服、冷备校验、安装、正常恢复及原 SDK/基岩链回归执行。
