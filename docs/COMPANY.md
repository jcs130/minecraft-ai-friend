> 这个架构是可以复用的。全员基于 QwenPaw 底座。

## 二、汇报线与升级路径

- 运营日报 → 主开发（天神消化，不转交造物主）；重大事项（开活动/新技艺/排障）才请示造物主。
- 测试发现缺陷 → 运营归档为工单 → 主开发认领；紧急（崩服/卡死）直达主开发。
- 策划产出内容 → 主开发部署入世界 → 运营验收并向玩家发布。
- 玩家侧一切求助 → 运营首接；运营裁量 → 天神裁决引擎（分层：已习得技能自助，未习得上达）。

## 三、五条流水线（公司的骨架）

1. **工单流**：需求/缺陷 → 工单台账（状态机：受理→认领→修复→验收→闭环）→ 运营回访玩家。
2. **内容流**：策划文案/活动 → 内容仓（人设/榜文/对话树/事件日历）→ 部署（mc_npc persona / 任务板 / VNDialog / god-fx）→ 发布编年史。
3. **测试流**：新功能/新版本 → 测试清单 → 桐人鸣人验收玩 → 缺陷报告（步骤/复现/期望/实际）→ 回归。
4. **发布流**：测试服（Docker mc-isekai）冒烟 → 预生产 → 切换 → changelog + 回滚预案。
5. **数据流**：world.db + 编年史 → 运营周度报表（活跃/陨落/祈愿/供奉/委托/经济）→ 需求与异常输入工单流。

## 四、项目无关骨架（复用层）与项目要素（千灯纪层）

- **复用层（换项目直接搬）**：本宪章、QwenPaw 底座 + agents 编制、Docker 全栈
  compose（mc / world-process / oracle / npc / guard / qwenpaw / memos / auth）、
  五条流水线的机制、运维手册（mc-ops）、裁决引擎。
- **项目层（每项目重写）**：世界观正典、技艺表、众生册、风格领地、叙事与命名。
