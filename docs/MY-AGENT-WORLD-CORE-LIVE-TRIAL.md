## 实跑补齐

只读查询的 `MOD_CALL_ARGUMENT_INVALID` / `MOD_CALL_ARGUMENT_UNSUPPORTED` 现在返回字段、缺参和 `mc_help` 指引，供模型修正。变更操作、网络未知、损坏账本仍结束试玩，不转成“可重试”的普通输入错误。两项回归测试覆盖这条边界。

宿主在进入模型前读取实际操作索引，按需查完整签名，减少模型为了发现基础动作而反复翻页。完整的大结果保留为带SHA的私有制品，可按字段读取；对话持久保存，恢复时保留此前工具结果。当前状态包含选中快捷栏，避免让模型猜持有物品；停止状态使用明确的 `stopReason`，不把最后一条行动意图当作停止原因。

这些是调用与宿主能力补齐，不代表模型已熟练使用全部接口。本次大量请求用于学习签名、读取手册和修正CAS条件，行动效率仍低；还需要把常用采集、制作、交付流程整理为可复用的高层游戏技能，并验证委托闭环、连续生活目标、应急反射和长期记忆。

## 启动和健康

```powershell
python tools/start_agent_mc_trial.py --config <绝对私有配置.json> --credential-file <现有CodingPlan提供器.json>
python tools/maw_agent_mc_trial_health.py --state-directory <角色的绝对状态目录>
```

启动器复用已有有限进程主管、私有密钥读取器和模型请求账本；只在进程内解密现有Key，不调用QwenPaw HTTP或修改提供器。Node 22；模型固定为qwen3.7-plus，没有本地模型、备用供应商或自动重试。

私有配置除 `stateDirectory`、`username`、`node`、`nodePath`、`runnerFile`、`durationSeconds`、`maxModelCalls` 外，还需 `worldPackageFile` 指向已安装宿主入口，`worldConfigFile` 指向[原生SDK连接配置](MY-AGENT-WORLD-AGENT-MC-WORLD.txt)，`objective` 给出目标。凭据不进入配置模板、命令行参数值、源码或公开报告。

试玩不自动永久常驻，不重置累计模型计数。续跑需要由上层调度对账并设置新的累计上限，仍使用同一个状态目录、原生账本和身体。角色离线不等于进度丢失；不要复制新目录绕过未知动作或模型请求。

`status.json` 每5秒更新，`stop.requested` 请求正常停止。主管只管理自己启动的子进程，心跳失效或超过时限才收口；未知请求保留供对账。手动健康检查10项通过，包括角色绑定、请求预算、生命周期，以及原服务与MawExplorer的保留检查；它本身不调用模型或执行游戏动作。

此次未新增端口、网页、OP或防火墙规则，未重启正式游戏服、基岩桥或现役Agent。现有28984仍是MawExplorer的画面，不能把它当作KiritoCore的第一人称；本次没有新增视觉验收。原角色保持暂停第464轮、旧账本前缀不变，两生产owner保持健康。

## 扩大测试与系统性修复

用户随后要求继续测试、减少限制并关注系统性问题。沿用同一个KiritoCore UUID、世界物品、会话、模型请求和原生动作账本，把累计调用上限从48扩大到256，单次观察窗口设为一小时。本阶段新增158次请求，累计206次均正常返回HTTP200；最终是模型自行调用host_finish，未耗尽调用额度。进程正常退出，角色进度保留。

脱敏证据见 [core-systemic-trial-20261013.json](evidence/core-systemic-trial-20261013.json)。

- 实际完成两次原木购买（各6灯币）、木板/木棍合成、工作台合成、真实放置以及原生3×3菜单打开。首个委托maw:first_workbench完成一次，奖励8灯币/5声望；最终余额36、声望5，石器委托仍未完成。奖励流水的economycraft:admin_add来自预设SimpleQuests奖励函数，不是运维赠送。
- 共79个原生动作受理，42成功、36明确失败、1个历史未知。失败数量包括模型猜错材料、槽位、方块或站位条件，不能把受理或退出码当作全部玩法成功率。
- 最终位置(-438.3,63,421.7)，生命20/20、饥饿20。角色挖进坑里后，因工具准备和脱困规划不足自行结束；未传送、补材料或授OP救场。模型报告的effective_mining_without_tool是其判断，不代表服务器应该允许徒手石头掉圆石，也不证明已有移动/采掘接口缺失。

本次修复集中在宿主与SDK共用机制：

1. 已学操作签名从实际provider重新读取并保留在后续上下文；允许角色持久记录自己的计划。上下文按序列化字节裁剪，完整会话与SNBT保留；大文本或数组可按范围读取。
2. 寻路的NoPath/Timeout等普通路线错误现在先停止路径、释放按键，核对同身体实际服务器位置，再返回已知的未到达/部分进展。断线、换身体或无法确认停点仍保持未知。首次旧移动kirito-56-move-explore的unknown结果未改写：原进程退出后，同身体三次只读稳定状态作为离线审计证据，仅允许独立新动作，该旧ID从未重放。
3. 完整返回但JSON格式错误的模型响应在派发前反馈，不直接杀死宿主。CodingPlan显式使用[官方JSON Object格式参数](https://help.aliyun.com/zh/model-studio/qwen-structured-output)；宿主仍校验工具和参数。reason只作为宿主诊断字段，可从工具外层arguments归位，不改任何游戏动作参数。重复错误示例从上下文视图合并，原文和错误日志保留。修复前的27次语法拒绝和34次外层字段拒绝均保留；最后41次调用均形成有效决定，无格式拒绝。
4. 每个受理动作收口后刷新本人任务与余额。异常退出也重新采集身体及公会状态，标明采集时间；读取失败时报告不可用并区分lastKnown，不把开场快照冒充最终结果。host_finish声明持久保存且标注未独立验收。

本阶段88项Node测试通过，0失败/0跳过；试玩10项健康检查、分发10项哈希和依赖检查通过。最终原主服与基岩owner不变，35个JAR未动，原MawExplorer仍暂停第464轮，旧unknown及账本前缀保留。没有新增服务端重启、网络端口、视觉验收或Wandscape发布。DPAPI CurrentUser访问拒绝仍是既有独立缺口。

当前配置仍是有限测试，不是全天常驻。下一步应验证角色能依据回执调整工具与材料准备，并完成实际模组生活链；不能把本次工作台闭环说成女仆、Create、殖民地或全部玩法均已自主通过。续跑使用同目录与原累计计数，任务结束声明和失败原因应进入后续记忆，不删账本或更换身体绕过未知。
