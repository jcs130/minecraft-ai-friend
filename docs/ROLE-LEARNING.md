# QwenPaw 原生技能与角色学习

通用能力优先使用 QwenPaw 2.2.0：技能正文由原生 SkillService 管理，定时任务由原生 CronManager 执行，读写文件与创建技能使用官方工具。`world/ops/native-role-skills.json` 锁定采用的官方技能原包；项目技能只补充游戏接口、职责与实际验证要求。原生技能和项目技能都在对应 Agent 的技能页显示。

玩法知识使用 [渐进式游戏资料](PROGRESSIVE-GAME-KNOWLEDGE.md)：游戏角色启用 `qd-minecraft-guide`，常驻仅名称/简介，任务相关正文及参考页通过原生 Skill、read_file 分步读取；配方查询复用 Numen 当前服务器数据。

游戏 18089 与运营 18090 分开管理。每个角色只使用自身的工作区、技能与任务。宿主 8088 继续用于原有其他工作。工作区内置工具使用 Qwen ToolGuard 做执行前检查，这不是操作系统级文件沙箱；不把任意容器 shell 开放给游戏角色。

## 个人文件与经验积累

游戏七个现有角色（含独立女仆）和运营六角色均启用官方 `read_file`、`write_file`、`append_file`、`edit_file`。可以直接保存本角色的经验、失败复盘、玩法参考和代码草稿，无须为普通笔记另建 MCP 或反复请求写入许可。推荐 `notes/index.md` 保留短索引、`notes/` 按主题存资料、`drafts/` 存草稿；当前任务需要时只读索引与相关页面。`qd-skill-evolution/references/notes.md` 按需提供记录和修订方法，不把全部笔记装进常驻上下文。

文件保存在各自持久化工作区：游戏为 `server/agents/work/workspaces/<role>/`，运营为 `server/operations-agent-state/work/workspaces/<role>/`；容器内均为 `/state/work/workspaces/<role>/`。重建 Qwen 容器继续使用同一工作区。共享村民和兼容女仆角色沉淀通用方法，人物事实按已核验身份分开；独立女仆维护自己的记忆。

新注册女仆也会立即取得以最终角色 ID 绑定的原生文件工具和同一份个人资料说明，避免复制模板后重新关闭文件能力。游戏职责技能仍由后续学习同步安装；尚未安装的技能不在注册提示中冒充可用。

工具成功回执和必要的读回用于确认文件已保存。普通记录可以不断修订，可执行游戏程序仍使用已有测试与晋升流程。`tools/smoke_role_files.py` 通过原生文件工具及角色权限执行真实读写验收，零模型、零游戏动作；它只清理自己创建的唯一 QA 文件。工具实测与模型是否主动总结、经验是否长期有效分别验收。

## 两种技能

- 普通说明与工作流程：优先复用官方 `make-skill`、文件工具及合适的市场技能。原生创建仍经过 Qwen 的技能扫描与登记，不需要另一个技能服务。
- 可执行的 Minecraft 行为程序：桐人继续使用 `skill_draft → skill_test → skill_promote`。有实际世界副作用的程序不能只凭 Markdown 格式检查就宣布学会。

`qd_learning` 是 Qwen 管理的角色专用 stdio MCP，提供流程草稿、版本、反馈、回退和市场参考。它不是新的 Agent 进程管理器或模型代理。`learning_validate` 只验证流程格式与工具范围，不能证明挖矿、交易、种地等任务成功；两次失败停用机制基于角色提交的反馈，报告明确标注证据来源。

## 定时任务与费用

使用原生 Qwen 周任务，不另外建立宿主计划任务或守护脚本。每位角色可查看、暂停、恢复自己的任务，通过 `learning_schedule` 修改已有周任务时间。游戏周维护只检查本地技能状态，不请求模型；桐人的日常决策由现有游戏控制器触发，避免另一条定时模型循环同时操纵身体。

运营角色有新任务证据时才做周复盘，与既有运营派工共用滚动 24 小时 4 次、30 分钟冷却的账本。没有新证据不调用模型；超时或结果未知不自动重试。Qwen 原生执行器前的检查随 Qwen 主进程加载，不另开调度进程。桐人的滚动 24 小时 48 次决策预算继续保留。

## 市场复用

市场技能需要同时匹配角色任务与实际可用工具。可先在 Qwen 原生市场或角色市场工具中查找，审阅来源、正文与附带依赖，再按角色安装。外部正文是参考资料，不能改变角色身份、凭据、预算或工具权限。带有脚本、浏览器或外部账户依赖的技能不能仅因为列表中出现就算可用。

## 同步与检查

`tools/sync_role_learning.py` 在精确对应的 Qwen 容器停止后离线调用 `world/ops/sync_role_learning.py` 的原生服务，保留模型即时选择、历史、用量与用户已有的周任务时间/暂停选择。执行前备份工作区；不得重新迁移历史来更新技能。

`tools/audit_agent_runtime.py` 检查真实 API 中的角色、激活技能、MCP、周任务与 Docker 守护。`tools/smoke_agent_learning.py` 区分原生工具暴露、真实 MCP 协议、零模型检查与另行显式执行的模型实验。技能显示成功不等于角色已经完成生活目标。
