## 部署

1. `tools/configure_party_life.py` 默认只读预览；`--apply qiandengji` 通过原生 PUT 创建固定 ID、初始暂停的 Cron，不改人物文件或模型。
2. 在既有任务和身体动作安全收尾之后，让 Qwen 启动进程实际安装 Cron guard 3，并让 NPC 载入新的消费代码。仅替换 `/ops` 挂载文件或重载 MCP 子进程不会更新已经加载的 Qwen Cron Python 函数。
3. `--apply qiandengji --enable` 会核验实际 Qwen 进程 PID/start ticks、guard 3 与 `partyLifeSignalVersion=1`，以及 NPC 公开状态存在已加载的 `life` 消费者，再原生启用。既有有效 Cron 的开关不因普通重复配置被重置。
4. 首次可由原生 Cron 的“立即运行”产生一个普通信号，或等待第 7 分钟自然运行。不再额外手工提交一份相同模型目标。原 QwenTasks 首次预留的 `requestId` 会与稳定 key 一起持久保存；重试查询保留它，不能改 key 重新发一份。

当前状态位于原 `server/panel-state/party.json` 的 `life` 字段；详细消费状态、逐轮回执分别位于 `server/mcdata/village/party/life/controller.json` 和 `life/receipts/`。这些均为本机运行资料，不提交公开仓库。
