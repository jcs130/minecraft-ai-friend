# 可执行技能库与 Jev 选择闭环

本轮把库级选择接到已有执行器：QwenPaw 保留目标、规划、复盘与程序改进；Jev 选择已测试程序，Numen 执行原生动作。没有新增守护进程、生成式模型接口或另一份经验库。

```mermaid
flowchart LR
  P[当前目标与身体] --> I[catalog.json 可用技能索引]
  I --> F[已晋升版本与当前内核测试]
  F --> E[意图筛选与 QuickJS 首步预览]
  E --> J[Jev：最多7个程序加慢规划]
  J --> B[再次核对身体、目标、版本、租约]
  B --> Q[原 skill-job]
  Q --> N[原控制器与 Numen]
  N --> R[原动作ID、终态与实际效果]
  R --> L[PracticeStore 实践记录]
  L --> S[Qwen 复盘、refinement、draft/test/promote]
  S --> I
```

## 初始程序

新增27个 `base_*`，安装器跳过已有同名程序，保留 Agent 后续修订与旧程序。

| 类别 | 数量 | 自动候选与参数 |
| --- | ---: | --- |
| 进食 | 1 | 饥饿≤16且有安全食物；成功须确认进食与饥饿恢复 |
| 装备 | 10 | 镐、斧、铲、锄、剑、四部位护甲、盾；须匹配当前目标并已有装备，核对装备栏 |
| 背包合成 | 4 | 木板、木棍、工作台、火把；须目标相关、材料足够，核对产物增加 |
| 工作台合成 | 9 | 面包、箱子、熔炉、木/石/铁镐、石斧、铁剑、盾；须 `memory.table`，先观察已放置且可触及的工作台 |
| 空间任务 | 3 | 短程导航、收获补种、睡觉；须 `memory.target`，补种还须 `memory.seed` |

自动筛选当前覆盖前15项。后12项通过原 `skill_start` 传入参数；不从目标文本猜坐标，不因背包有工作台就假定它已放在附近。脚本不是原生配方数据库，改版/模组配方应先查询真实配方，再依据拒绝与效果修订。睡眠回执只证明开始睡眠。

## 执行与学习边界

技能目录改为每库一个 `catalog.json`：记录名称、当前/草稿版本、描述及路由条件。正常读取不枚举目录，按名称只加载相关版本；草稿、晋升、共享发布在原锁中原子更新索引。首次迁移仅扫描专用技能库一次，外部恢复需要显式 `rebuild_index()`；损坏时报告错误，不在每轮偷偷重扫。索引不能授予执行资格，候选仍核对真实 active 版本、版本内 routing 与当前内核的测试报告。共享库发布有独立锁，本地修订有自己的版本历史。

展示目录最多缓存30秒，开始选择前强制读取最新索引；候选准备后重新读取身体，收到选择后只复核选中版本，保留原5秒有效期。这也修复了最初实服扩大技能库后重复读取目录导致的接收超时。

- `routing={intents:[关键词],maintenance:false}` 是可选的版本内容，版本哈希覆盖元数据。需至少一个空 memory 正例和一个拒绝反例；只有真实测试通过并晋升的版本可路由。旧程序不自动加入。
- 库级选择复用 SystemOne 和 PolicyWorker；候选携带程序的确切首步动作，模型不能生成参数。置信度仍须≥0.75，未降低门槛换取演示成功。
- 分类期间每250ms查看结果，正常程序每秒推进，原生动作跨游戏tick执行。没有重复提交身体动作；其他社交分类不能覆盖未消费的选择。
- 当前目标/版本/身体条件变化、超过5秒、存在未知动作、未结实践、活动身体任务、认知/交流任务或待复盘时，不启动新脚本。暂停和重启丢弃未执行的选择。
- 每次慢系统决策或目标修订最多自动选择一个程序；成功与失败都交回原认知流程，避免同一目标无限合成或失败重试。当前版本不宣称可无需慢规划地连续完成任意任务。
- 首次派发通过已有 `system_one_choice → system_one_dispatch → action-receipt` 精确审计；程序所有步骤仍写 PracticeStore。自动实践的 checks 检验首步动作完成，合成还检验产物增长；这是有界实践证据，不是整个长期目标或多步骤技能掌握证明。
- 现有 `skill_read` 暴露实际 runId、动作回执、目标观察。Agent 可附 refinement 引用失败/成功证据，修订、测试和晋升；新版本自动进入下一次候选。初始化脚本数量不是 RSI 收益，仍需跨任务与保留场景对照。

## 下载的参考与本项目适配

已实际下载并查阅 [Voyager](https://github.com/MineDojo/Voyager/tree/55e45a880755d0c8c66ca7fb5fe7962ac8974f89) 的 `agents/skill.py`、`control_primitives/craftItem.js`，参考持久化技能目录与按需检索。其 Mineflayer 技能需要适配 Numen、纯函数 memory 及原生完成回执，不能直接安装执行。新增27个程序是本项目的适配实现，安装走真实 draft/test/promote，保留同名旧版本。

[SkillOpt](https://github.com/microsoft/SkillOpt/tree/79124b37e9a6371e13b753f8bcd7adb1e493ade1) 的 `engine/trainer.py`、`evaluation/gate.py`、`prompts/meta_skill.md` 展示基于轨迹修改、同任务验证和迭代策略记忆。代码也支持 `use_gate=false` 和慢更新强制接受，未照搬这些路径。它优化的是文本技能，不等于训练 Jev 权重。

[ModularRSI](https://github.com/IQuestLab/ModularRSI/tree/06fdcce711cb588f75630bc8ac847074ac80e13c) 的 `self_evo/proposals.py`、`review_verdict.py` 区分方向失败和实现失败，并从结构化提交读取评审结果。本项目复用原工程角色/评审流程，未复制其限非商业研究代码或引入另一套运行时。

研究方法已适配为原 `qd-skill-evolution/references/evidence-driven-iteration.md`，按需加载；包含前置条件、保留场景、新旧版比较、真实回执和模块级升级条件。该指南不是新增的自动收益门禁，当前仍需积累跨任务对照证据。
