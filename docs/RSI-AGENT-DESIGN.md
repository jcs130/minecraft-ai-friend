# 真正的 RSI Agent · 合并设计（ModularRSI × mc-agent-neko × 千灯纪现状）

## 2026-09-20 方向确认：面向 RSI 开放可组合的原生控制

用户明确项目目标是落地 RSI，并提出开放更原生的控制，让 Agent 有更大空间创造技能和学习。架构判断：应该扩大游戏内可编程动作空间，同时保留已有高层工具供 Agent 选择。以下为源码核对后的设计补充，尚未部署新接口；后文历史阶段中“新建仲裁器/监督层”等内容以[最新复用审计](PREIMPLEMENTATION-REUSE-AUDIT.md)为准。

### 当前真正的能力边界

`world/survival/skill_library.py` 的程序可以计算、分支、保存 memory，再提出动作/观察；动作被限制在 `numen_gateway.TOOLS` 的 17 类中，观察提议限 `inspect_block` / `inspect_container`。MCP 的 `move` 实际调用 `goto`，`look` 是读取周边状态，并非自由设置按键或视角。这允许组合现成动作，但不能据此称 Agent 已获得全部原生控制。

Numen 源码已有并注册 `interact_at`、`interact_entity`、`inspect_gui` 等通用交互。`interact_at` 可表达物品使用、方块/流体点击及按住；`interact_entity` 自带接近和交互逻辑，不是纯粹的单帧输入。这些接口没有全部进入桐人现有 MCP / 程序动作表，应优先检查现役契约并适配，避免每遇到一种新用途就新增一份专用玩法工具。

更底层的 `InputDriver`、`Input`、`ExecHarness` 已处理移动、跳跃、潜行、视角和点击，但属于 Java 内部实现，尚不能直接等同稳定的外部原语 API。尤其 `ExecHarness` 的导航右键、挖掘和疾跑语义各有限定，不能把它的按键枚举直接包装后宣称等价完整玩家操作。

### 建议开放的层次

| 层次 | Agent 的创造空间 | 执行方式 |
| --- | --- | --- |
| 高层工具 | 继续选择现有导航、采矿、合成等已实现能力 | 原 Numen 任务与现有网关 |
| 可组合原语 | 使用手中物品、目标/实体交互、视角、移动输入、跳跃、潜行、切槽、输入释放；逐项核对哪些已有 | 先适配现有工具；不足处在原任务体系补稳定、有时长与停止语义的接口 |
| 学习到的技能 | 编写带状态、条件、循环、失败恢复的程序；原语和高层工具可以混合 | 复用现有版本库、沙箱、实践账本；高频局部控制需在本地执行，不能每 tick 调用 LLM 或逐次经 RCON 往返 |
| 可演化机制 | 根据成功/失败轨迹改进工具封装、观察选择、上下文压缩、执行/重试策略等模块 | 复用已有提案和隔离修改通路，对照验证后形成新版本 |

控制接口需要与感知一起设计：输入持续 tick 数、身体朝向、落地/碰撞/使用状态、实际命中、任务归属和终态必须可观察；返回受理不等于动作已完成。短输入片段在停止、失去所有权或角色失效时释放按键；需要条件反馈的控制不能退化成盲目播放长按键序列。现有外层 15 秒观察周期不适合细粒度闭环，应核对原生任务扩展点，复用已有 tick 执行生命周期。

例如，Agent 应能使用“持桶 → 瞄准水源 → 使用 → 检查桶中物品”的通用原语组合，自行形成取水技能，并在失败轨迹中修改瞄准与站位策略。该例是目标用法，不是本服已验收成果。若通用原生交互已满足，维护者无需再硬编码专用 `fetch_water`。

### RSI 的完成标准与下一步

开放底层动作扩大探索空间，技能库增长本身不足以证明递归自我改进。[ModularRSI 官方说明](https://github.com/IQuestLab/ModularRSI#how-it-works)的重点包括执行经验、轨迹对比、模块改动、运行验证、不可变世代和未见任务评估。借鉴到本项目，候选不仅可以改技能，也应能在申报范围内改进产生、执行和学习技能的机制。

每次改进应绑定旧/新版本、相同任务与可比初始条件、模型配置和成本，验证真实产出、成功率、耗时及损失；再用未参与该次修改的场景检查迁移。验证逻辑也可以提出改进，但候选不能自行改写原始回执、最终验收事实或比较基线来证明自己更好。世界权限和原生物理保持独立执行，使能力提升能够归因于策略。

实施计划因此增加一项明确的接口盘点：**已接通 → 原生已有但未接通 → 原生缺少**。优先完成已有技能测试资格和任务回执修复，再用一个通用原语的接通及 Agent 自主创造的新技能走通最小闭环，最后按实际失败证据决定是否需要更低层输入。接口选择不能永久停留在固定 17 类动作，也不需要一次性暴露全部 Java 内部对象。此轮只记录方向与核对结果，没有扩大生产权限或改动执行代码。

## 二、目标架构（五层 + 三元纪律）

```
① 元层（政策与世系）   evolution-policy  ── 谁能改什么 / 反事实纪律 / 世代与谱系
                          ↑ 提议（带反事实）
② 记录层（度量的心电图）metrics + act_trace + coherence + transcripts + death_log
                          ↓ 证据
③ 归因层（改动怎么被判定）k-roll 同任务同代码 → 对比配对 → 发现项（含反事实）
                          ↓ 提案
④ 实现层（谁来动手）   隔离 lane 实现 → 四道门控（静态/差异/冒烟/激活）→ 晋升
                          ↓ 生效
⑤ 驱动层（身体怎么动） WorldModel 黑板 → Arbiter（唯一意图+迟滞）→ BodyGate 独占 → 原语/技能
```

**三元纪律**（贯穿五层）：
1. **同任务同代码**——不冻结其余变量，就不许宣称"这条改动让它变好了"；
2. **反事实必填**——说清会让哪个**真实指标**动；写不出就是 `no_verdict`，**不是错误**；
3. **无效即回滚**——门控自身故障要放行，但**改动无效必须回滚**（现在缺这条）。

## 三、分阶段实施（每阶段带验收与"比原来更好"的凭据）

### P0 已完成（本夜）
- 元层可见 / 提议通道 / 反事实纪律 / scope 卡 / 度量与基线 / 班次跑通（3 草稿 2 启用）

### P1 归因最小闭环（**下一步**）
- **做什么**：把"同一角色同一任务的成功/失败回执"配对（先做**桐人**）：
  - 数据源：以 `action-receipts/*.json` 的持久回执判终态；`actions.jsonl` 是阶段日志，`action_observed` 也不是成功。辅以 episodes、death_log 与 coherence。
  - 同参数成败只能用于观察性分析；受控对照还必须绑定任务、初始存档、bundle、模型配置和预算。
  - 新增：`stuck_loop(Nx)` = **同一动作参数的最长连续重复**（补现有"重复占比"）
  - 产出：一条结构化**发现项**（`task / divergence / evidence / would_change / suggested_change`），
    走**工单**（`category=improvement` ✓ 复用现成载体）
- **验收**：①同一任务确有成/败两条轨迹被配对 ②发现项里每条引用都能逐字回溯到账本（防编造）
  ③**拆前/拆后**：桐人"最长重复连击"这个数**先被量出来**（现在是"重复占比 1.00"，还没有最长连击）

### P2 世系与回滚
- **做什么**：每个"改动"落成**世代**（`generations/<gen>/`：改了什么、由谁提、依据哪条发现项、验收结果）
  + `archive.json`（superseded / excluded）+ 失败即标 `superseded`
- **验收**：任一当前生效的旋钮，都能回答"它是哪一代、依据哪条证据、由谁批准"

### P3 模型决策与可续做的程序执行
- **做什么**：高频动作由原生 AI 与验证过的技能执行；LLM 保留目标选择、计划、现场判断、交流与反思。
  按 Cortico 的任务/步骤回执处理暂停、未知结果和续做，减少无变化观察的重复上下文。
  不能把自主 Agent 限成只会聊天、求援和提案，也不能用硬编码日程代替角色决策。
- **验收**：①动作提示字节数**下降**（拆前/拆后对比）②动作成功率/闭环率**不下降** ③学习产出**不下降**

### P4 单一仲裁器 + 身体独占（neko §4.1）
- **做什么**：把散落的 shouldX 收成一个纯函数 `arbitrate(state, proposal) -> 唯一意图`（带**迟滞**：
  最短驻留 + 进入/退出阈值不对称）；`BodyGate` 让"只有持令牌者能动身体"
- **验收**：①同时抢身体的路径数从 N 降到 1（可观测）②振荡（进出同一状态）次数下降
  ③**给现有自动收尾加迟滞**：区分"idle 等待"与"真 hang"（照 neko 教训：**误杀比漏杀更糟**）

### P5 真规划脱困（治桐人"卡住"）
- **做什么**：用全知方块查询做**逃生规划**，替换启发式；把昨晚的 `candidates=[]` / `requested_height_unsupported` 变成"规划出的路"
- **验收**：人为把他埋进三种地形（土洞 / 石穴 / 崖底），全部 **≤2 分钟**自主脱困（照 ModularRSI 的验收写法）

## 四、今天就该改的一处（自我纠错）

**我的 `reconcile_never_submitted`（30 分钟自动收尾）缺迟滞** ✗ —— 按 neko 的教训：
> **误杀的代价可能比漏杀更糟**；必须区分「idle 等待」与「真 hang」。

**改法**：①窗口内**两次**观测到"仍不可观测"才动手（单次不动）②收尾前先问一次"是不是在等下一个整点"
③所有自动收尾都写清**它凭什么判**（现有：无 taskId / 404 / 超窗 ✓，要补"连续两次"）。
