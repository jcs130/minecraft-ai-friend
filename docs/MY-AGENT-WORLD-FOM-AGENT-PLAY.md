# 整合包世界与通用 Agent 接入

2026-10-15。现役世界是 FOM 2.42 / Minecraft 1.21.1 / NeoForge 21.1.248。

## 技能体系与 Agent 身体是两层

旧千灯纪的 RPG 技能是服务端代码。Paper 版 `AgentFriendPlugin` 注册 `/mycli`，结合 AuraSkills、MagicSpells，处理实际魔力、冷却、伤害、学习、粒子和声音；部分命令按玩家本人身份调用。它不是一个仅靠 OP 指令模拟全部技能的机器人。后续 NeoForge 版也有原生服务端实现与模组接口。

Agent 的规划、记忆、目标和工具调度由独立 `agent-mc-autonomy` / `agent-mc-world` 承担。统一身体适配器可以选择 Mineflayer、Numen 或已经登录的真实 Java 客户端。模型与身体分离，因此不同整合包可以复用同一个核心；身体能力仍按实际目录发现。

当前 FOM 尚未迁入旧服的 `/mycli`、工会、领地、试炼与技能数据。客户端桥新增了物品、配方、界面读取，不会凭空在另一台服务器生成旧服的技能规则。

## 当前可用的客户端方案

完整原作者客户端安装 MAW Client Bridge 0.5.0，可选 Baritone 1.11.3 / Minescript 4.0。桥只在客户端加载，不要求服务端安装对应 JAR，也不注册游戏自定义频道；本机 Agent 用随机回环 RPC 控制同一个已登录玩家。游戏连接可以跨公网，控制 RPC 不需要开放公网。

- 真实状态：UUID、维度、绝对坐标、生命、饥饿、装备、实际物品组件、菜单槽位及当前操作。
- 真实内容：本连接物品注册表、当前语言显示名、原生 tooltip、服务器实际同步的配方及材料。serializer 可编码时保留模组原始字段，不可编码时明确标记。
- 真实执行：原生输入、挖掘、使用、菜单点击、可选路径规划及有限 Python 脚本。全部使用稳定动作 ID 和原回执。
- 真实画面：原客户端 Framebuffer PNG，包含其实际材质、模型、粒子与模组界面；文字模型试验不假称已经使用图像推理。

这不绕过整合包检查。目标服务器要求的 Minecraft、加载器、模组、账号和自动化规则仍需满足；当前桥实现针对 NeoForge 1.21.1，其他版本或加载器需要相应构建。服务端未同步的机器内部数据、隐藏任务、保护配置不会自动出现在客户端。

原生注册表告诉 Agent “是什么”，配方和菜单告诉它可见的操作条件；接口可读不等于所有模组玩法已经掌握。多方块机器、动力网络、任务脚本与特殊战斗仍需逐项验收。

## 后续可选服务端组件

可把旧技能机制整理为 Agent Friendly Kit：服务端负责真实技能、状态、保护查询、任务及交易，客户端与 Agent 使用统一接口。第一阶段采用原版物品、组件、容器、粒子、声音和可选负载，不新增必须由客户端识别的方块、物品或实体注册项。

同一套业务规则需要 Paper / NeoForge / Fabric 各自适配加载器；Paper 插件 JAR 不能直接放进 NeoForge。不同整合包的魔力、装备和任务也需要对接它们实际 API。目标是复用机制与协议，而不是替所有整合包虚构一套状态。

NeoForge 的可选频道允许没有该接收端的连接，但有要求的网络频道或注册内容仍会影响兼容性。参考[官方网络文档](https://docs.neoforged.net/docs/1.21.1/networking/)与[官方网络重构说明](https://neoforged.net/news/20.4networking-rework/)。本轮没有给生产服添加这个后续组件。

## 本轮线上模型验收

模型明确配置为 Aliyun Coding Plan `qwen3.7-plus`，没有本地模型回退，未接 QwenPaw Agent。自研核心控制非 OP 的 KiritoFOM，通过完整真实客户端进入现役 FOM。

任务是在管理员提供的 4 个安山合金等材料中，查询实际 `create:shaft` 配方并制作、领取至少 4 根传动杆。它验证内容读取与自主操作，不是自然采集、生存或完整工厂验收。成功条件只统计实际已领取物品，排除合成槽第 0 格的结果预览；另需服务端核对库存。

前五次失败均保留：模型猜错 Minescript Java API，查询入口与参数发现耗尽预算，原版队列提示与 operation 身体接口冲突，上下文不足、长推理中的租约过期，以及菜单截断和逐格点击的光标参数错误。不能删掉失败记录或把不同预算、提示及版本当成受控 A/B。

修复包括四个原生知识查询、只读错误的正确路由、参数 schema 回传、空目录的实际前缀提示、直接暴露读操作与原动作回执、按身体契约生成提示、动作派发前显式续租，以及退出时核对原动作终态。未知结果仍保留原 ID，不重放。

第六轮成功：14 次线上模型调用、86.516 秒，模型使用真实 `craft.recipe` 合成一批。服务端 `data get entity KiritoFOM Inventory` 独立确认 4 合金消耗 2 个、获得 8 根传动杆；本人不是 OP。前五轮累计 145 次调用保留，因此全部探索共 159 次，不能只展示成功轮来宣称整体成功率或效率提升。该轮没有图像输入，截图功能不是本次推理来源。

早期一次关闭客户端后，原合成格和光标中的 4 个合金未在重连背包中找到，去向尚未核清；第六轮另提供 4 个测试合金并记录这次补给，没有把它算成自然采集或物资无损恢复。后续退出要先核对空合成格、空光标和背包。完整长期生活及退出时物资保全仍需单独验收。

最终次数、实际库存、版本与验收限制以 `docs/evidence/fom-agent-play-20261014.json` 为准。私有模型请求、连接令牌、动作原包、存档与第三方 JAR 留在本机，不提交。

## 维护入口

客户端桥随真实 Minecraft 客户端启停。已有客户端健康探针新增知识接口断言；注册入口可用环境变量明确选择本次分发与本人配置：

```powershell
$env:MAW_JAVA_CLIENT_MANIFEST='E:\QiandengJiSocietyLab\integrations\java-client-bridge\v9-native-crafting-release-20261015\installation.json'
$env:MAW_JAVA_CLIENT_CONFIG='<本机本人SDK配置绝对路径>'
python world/ops/health/health_mon.py --society-java-client-smoke
```

共享默认安装清单没有切换。测试选择独立命名分发和已有身体账本，不覆盖旧 Agent 的暂停、身份或 unknown。生产游戏服务继续由原 FOM Supervisor 管理；本轮只重启受控测试客户端，没有重启服务器或改路由器。
