# 可米与独立 MC 自主运行层的差异

核查日期：2026-10-14。用户 fork `jcs130/Cortico@8c00fbb` 的
`bots/cortiv/persona/ORIENTATION.md` 明确自称“可米 Cormy”。以此作为用户所指组合的
源码对照，未声称取得其那次成功运行的完整部署、模型配置或轨迹。独立测试基线为
`agent-mc-autonomy@7431bfd`，身体仍为明确固定的 `7889ce2` headless 构建。

## 结论

仅迁移 Mineflayer 身体、工具、队列和事件，不等于迁移原组合的完整自主能力。
目前存在已复现的宿主接线缺陷，也有尚未迁移的上层能力；没有证据把整体失败单独归因于模型。

| 环节 | 可米源码 | 独立运行层基线 | 影响或限制 |
| --- | --- | --- | --- |
| 工具说明 | provider `transport/history.ts:mapTools` 原样传递说明与参数 | 常驻大参数表，删除部分长字段语义；详细帮助按需读取 | 输入中有许多无关字段，却缺少部分字段的使用条件 |
| 近期交互 | foreground 投影完整工具轮，至少近期轮次及必要输入；原始会话持久保存 | 最多 8 组内存历史，预算拥挤时常只留 1 组，重启不恢复规划历史 | 查询一次帮助后再读背包，前面的操作依据容易被挤掉 |
| 预算 | provider 可提供估计；默认按文字估计 token，保留最近真实 usage | 整个消息/工具 JSON 的 UTF-8 字节当作 token 上界 | 实际约 9k token 即接近 32k 字节预算，丢掉仍用得上的事实；不是服务端真的溢出 |
| 活动与经验 | `activity_plan`、`pending_work`、续做笔记、按世界隔离的记忆索引、方法来源与证据 | 自然语言目标邮箱、原始回执和复盘端口；没有等价的活动/经验工作区 | 有日志可查不等于已经形成下一轮可直接使用的工作记忆 |
| 参数失败 | 同一工具循环向模型返回失败并可修订 | 原生 MCP 预校验错误没有 structuredContent，动作侧误判为未知派发；具体失败未传入战略复盘 | 01:50 的非法字符串 steps 导致保护退出；高层主脑拿不到具体受阻原因 |
| 主脑组合 | Persona 主会话直接拥有游戏工具并处理持续事件 | 当前现场为独立 HttpPlanner 决策；Neko 经 ReviewPort 给阶段目标和演出 | 是不同的组合，不能把 Neko 高层通知接通当作原主会话闭环等价 |
| 模型与采样 | provider 可传模型、temperature、思考配置、输出上限 | 现场 Q2_0、32k、2048 输出；HttpPlanner 未显式传 temperature | 成功部署的配置尚未确认，不能进行单变量效果归因；本轮不切模型 |

源码入口：Cortico 的 `bots/cortiv/persona/foreground-context.ts`、`foreground-epoch.ts`、
`ORIENTATION.md`、`src/core/loop.ts`、`src/providers/transport/history.ts`；本仓库
`packages/agent-mc-autonomy/src/agent_mc_autonomy/{controller,context,planner,review,mailbox}.py`。
以上能力是否在用户成功部署中启用仍需具体配置/轨迹确认。曾发现的本机 kirito 历史部署并非
可米成功会话，不能拿其中 IQ3、temperature=0.6 等配置冒充相同实验条件。

## 本轮已定位的修复点

1. `2dcc218` 在派发前按发现的原生 schema 校验整个模型批次，并对邮箱直接派发再次校验。
   不把错误字符串自动转换为动作，不根据报错措辞解除真实未知；原 MCP 未确认动作仍保持保护。
   使用新鲜网络禁用回归核实：错误 steps、布尔 count、高级工具越界、外部 schema 引用均不产生动作。
2. `0.1.13` 将跨技能的常驻参数大表改为稳定的步骤封套、技能选择与依赖控制；完整原生定义
   保留给校验器和按需帮助。不会在插件中复制规则，不更改身体任务或模型。真实上下文回放在
   相同 32768 预算内从 1 组近期交互、13 类事实省略改善为 3 组交互、当前事实全部保留。
3. `0.1.14` 将规划器已知的未解工具错误和原始请求/决策索引传入中立战略复盘端口。
   旧版状态只公布通用 `planner_error`，具体 rays 参数错误仅留在规划器内部；一次成功
   的帮助查询会清掉通用错误，主脑 inspect 仍看不到原始拒绝原因。新增反馈保留原文
   限长错误，不传参数大表，不通过额外模型摘要；查询成功不会清除尚未解开的执行问题。

0.1.13 在 02:51:46–02:59:46 的 17 个自然样本中保持连接，未再次因错误参数退出，
但食物仍为零、位置与库存不变。射线角度错误重复后最终改正，随后仍以查询为主；
Neko 高层多次继续等待“已送达正在规划”的阶段。工具帮助和错误的离线构造回放保留
了角度限制，所以不能继续仅用“上下文被裁掉”解释剩余行为。0.1.14 新增四个回归在
修复前全部失败，修复后全包 162 项、Ruff、wheel 和隔离消费探针通过。现场主脑决策
变化与生存进展仍需独立观察；有错误信息不保证模型一定会选对后续策略。

0.1.14 已于 03:05:30 部署，03:06:17–03:09:17 的七个自然样本确认超限观察和帮助
参数错误连同原始回执索引进入了复盘 evidence。运行层连续在线，决策计数 3→11，
位置、库存、生命和口粮仍未变化，口粮为零；这是三分钟接口观察，不是通过生存验收。
期间主脑仍多次选择 continue。现有日志没有记录每次 inspect 的完整输入，不能仅凭
复盘数据库中有错误就声称模型已经读到并采纳。最后一项复盘尚无确认回执。

同一现场还显示，部署前停止操作已经把旧阶段标记为 cancelled，当前目标为空；主脑
理由却继续引用旧的“已送达正在规划”。数据库并没有把取消目标当作活动目标恢复。
这提示还须对齐宿主的实际工具调用和跨轮记忆，不能把过去的主脑判断当作当前事实，
也不能通过复活已取消目标来掩盖差异。

回放只能证明输入保留范围，不能证明模型一定行动正确。现场参数错误、无进展和生存目标结果
另按自然运行窗口验收；不把测试数、HTTP 成功、健康或模型台词作为食物/住所完成证据。

## 尚未解决的架构边界

完整的活动阶段、受阻条件、事实来源、按世界隔离的经验与可复用方法，应在中立自主框架中
逐项迁移和验证，由 Neko 等宿主提供人格和高层意图。不能复制 Cortico Persona 或让插件拥有
第二套队列。精确 tokenizer/预算端口、完整模型参数兼容、重启后有来源的续做上下文也仍待完善。
当前生存测试没有通过；这些差异不能用更多“观察一下”的提示词代替。
