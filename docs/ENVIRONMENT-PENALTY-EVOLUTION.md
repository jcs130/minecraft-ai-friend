# 环境即仿真：把环境惩罚接成进化诱因（2026-09-17 立项）

> 造物主谕（2026-09-17）：**「游戏环境应该是个完美的验证环境（类似于仿真），比如扣血、卡死都应该是进化的诱因。」**
> 本文把这条立成设计，并给出**已实测**的信号盘点与落地位置。

## 一、为什么这比"内部推断"强

现有进化触发是**内部推断**：动作重复（crystallization，已上线）、目标停滞（pivot，P1）。
两者都要*猜*——猜"重复是否有价值"、猜"目标是否在推进"，因此**必然有假阳性**。

当日实例：桐人修复后在田块间正常走动，`crystallization` 仍报 `goto×6 repeats=3`。
他没错，是检测器把"干活中的移动"看成了"打转"。

**环境惩罚是地面真值，不是猜测**：血掉了就是掉了，方块没出现就是没出现，背包没涨就是没涨，
被拒了就是被拒了。世界说的，不是他想的。**零假阳性**。

所以触发应当**以环境为准、以内部推断为辅**，而不是反过来。

## 二、地面真值信号盘点（已实测，不是设想）

| 信号 | 所在 | 实测证据 |
| --- | --- | --- |
| **扣血** | `episodes.jsonl` → `action_observed.hp`（逐动作采样） | 24h 内 **68 次 HP 下降**；含 `20.0 → 2.0000014 during goto`（濒死）与 `18.4 → 13.6 during goto` |
| **受伤事件** | `perception.py` → `damage_observed`（**当前被归为低优先级**） | 事件类型已在，优先级定位低估了它 |
| **卡死/徒劳** | `action_observed.positionBefore/positionAfter` + `inventoryDelta` | 字段齐备（位置无位移、背包无增量可直接判） |
| **被拒** | 动作回执 `code`（`action_rejected` 等） | 24h：**farm 88、place_block 31、craft 28、game_cast 17、eat 11、sleep 4** |
| **路径失败** | `navigationOutcome.state/reason` | `walk_target_too_far` ×20/24h、`no_walk_only_path` 亦有 |
| **死亡** | numen 死亡事件链（`numen_gateway` / 世界事件） | 通路在；作为最强调用未接进进化 |

### 88 次 farm 拒绝的真实构成（值得单独看）

| 原因 | 次数 |
| --- | --- |
| `aim <pos> is blocked from here — the crosshair lands on wheat at …` | **约 66** |
| `world_effect_not_verified: native interaction ended; inspect current state` | 12 |
| 其余 | 10 |

操作分布 plant 55 / harvest 25 / till 8；坐标 y **=64 占 87 次**、y=65 仅 1 次。

两条结论：
1. **工具契约本身是好的**——这条消息把病因说得很准（准星落在小麦上）。问题不在于消息不够，而在于
   **没有任何机制把"同一种拒绝反复出现"当作信号**，于是一次又一次重试。
2. **66 次/天是系统性的可达/瞄准问题**，不是偶发。它是研究文档第五节 D 项（闭环接近原语）的硬证据，
   但形态要修正：不是"精确落到某格"，而是**"落到一个能瞄到目标面的位置"**。

## 三、分层触发设计

### 层 1 · 环境真值（零假阳性）——直接触发

| 信号 | 触发条件 | 诱因（做什么） |
| --- | --- | --- |
| 扣血 | 相邻 `action_observed` 的 `hp` 下降 | 记"位置/行为 → 伤害"因果；若同址复发 → 危险知识 + 规避 |
| 濒死/死亡 | `hp` 跌破阈值 / 死亡事件 | 最强触发：事后复盘（死因 → 教训 → 路线/技能变更） |
| 徒劳 | 动作 `ok=True` 但 `inventoryDelta` 空且期望有产出 | 手段-目标不匹配 → 换手段，而非重试 |
| 同一拒绝码复发 | 同一 `code`（或同一 `message` 前缀）连续 N 次 | **契约/坐标语义修正**（P0 的通用化）；N 取 3 |
| 同址无进展 | 连续 N 个回合位置在动、**但目标相关世界状态无净变化** | 停滞重定向（这是今天那个循环的正确判据） |
| 路径失败复发 | 同一目的 `navigationOutcome` 连续失败 | 路线修正或放弃该目的 |

> **注意**：今天的案例说明"卡死"**不能只判位置不动**——他位置一直在动，动的是"同一格来回"。
> 判据必须是**目标相关的世界状态无净变化**（期望方块未出现 / 背包未涨 / 任务未完成）。

### 层 2 · 内部推断（有假阳性）——加阈值与冷却

动作重复（crystallization，已有）、目标停滞（pivot，P1）。
保留，但**降为辅助证据**：层 1 命中时层 2 用于*解释*；层 2 单独命中时只提示、不强制改向。
当日 `goto×6 repeats=3` 的假阳性就是必须给它加"环境无惩罚"滤网的理由。

## 四、环境作为验证器（这条是最有价值的推论）

既然环境给真值，那么**每一次行为改动都可以由环境验收**——这正是今天 P0 的验收方式：

> 「代码对」不算数。`(-639,65,1054)` 里长出小麦才算。

可操作化：
- 技能/路线/提示的改动 → 用 `episodes.jsonl` 的前后对比做判据（扣血次数、拒绝次数、单位时间产出、探索半径）
- 拒绝改动的判据同样客观：若改动后同类拒绝率未降，则回退
- 这给 P2（共享技能库）一个客观准入：**技能要能被环境验证过才进库**，而非"作者说好"
- 也给 P5（RL）天然的 holdout：历史 episode 就是评测集

## 五、落地位置

| 环节 | 落点 | 说明 |
| --- | --- | --- |
| 采集 | 已有 | `episodes.jsonl` + `perception.py`，**无需新增采集**——这是本设计最便宜的地方 |
| 检测 | `world/survival/pattern_detector.py` 旁新增环境惩罚检测器 | 与 crystallization **并列**：一个看内部推断，一个看环境真值 |
| 路由 | `world/survival/adaptive_router.py` | 环境惩罚命中 → 升 THINK/PLAN |
| 注入 | `world/survival/review.py`（Dream/复盘） | **复用已验证的 crystallizationHint 通路**，不塞主循环 prompt |
| 提级 | `perception.py` 的 `damage_observed` | 当前被标低优先级；复发时应提级 |

## 六、验收

1. **回放 2026-09-17 循环**：以当日 `actions.jsonl` 为输入，层 1 的"同一拒绝码复发"应在
   第 3 次即命中（实际循环 15 次 / 20 分钟），即**把发现时间压到分钟级**。
2. **零假阳性**：同一批数据里，他修复后的正常往返（5 个不同 goto 目标、有 farm 产出）**不得触发**。
3. **扣血不误报**：正常战斗/夜间遭遇不应被当作"进化诱因"，除非同址复发或濒死。
4. 不新增主循环 prompt 负担。
