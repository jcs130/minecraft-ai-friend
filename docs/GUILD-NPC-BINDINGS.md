# 公会 NPC 身份与每日委托

`config/guild-npc-bindings.json` 只登记本轮核实的六位现有村民：岚、静水、石磊、烛九、小满、禾叔。`tools/bind_guild_npcs.py` 默认只读检查；执行模式要求 NPC 侧车已停，备份完整旧档案后向既有 UUID 添加角色标签。它不召唤、删除、传送或清理实体。

档案中的 `entityBinding` 指定原生村民类型、UUID、维度和历史位置。运行时同时匹配类型、UUID、角色标签；旧 `spawn` 坐标不再触发已绑定角色的自动传送。其他 29 份角色档案及旧皮肤记录保留。

新一天的收购单仅从这六位中已绑定、职业匹配且拥有原有货单模板的角色选取。讨伐仍由农人禾叔、守夜人烛九和牧羊女小满发单，朝圣由神官静水发单，公会看板需要接待员岚。职业或绑定缺失时不向旧实体类型回退；缺少合适角色会记录 `availability.reason`。已经生成的每日货单和看板不重写；损坏的既有货单需要核对，不会自动覆盖。

生成过程只检查注册绑定，不加载区块。实况位置只用于接取和交付的同维度、近距离验证；区块未加载时可提供明确标注的历史位置，但不能因此批准交易。健康检查区分 `online`、`chunk_unloaded` 与 `missing_in_loaded_chunk`，不使用强制加载。

交付前核对材料和奖励容量；收货、发奖后核对真实物品数量差。满包在扣货前拒绝，结果不明不会重复扣货或发奖。自动讨伐/朝圣奖励在尚未发出任何奖品且容量不足时保持待领取；发生未知发奖结果后停止自动重试。

审计同时发现旧城附近大量同标签历史分身。本轮不加载或删除该区域，也不通过最近实体或标签数量猜测本体。
