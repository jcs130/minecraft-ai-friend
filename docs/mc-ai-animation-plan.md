# MC AI 主人公动画 —— 项目总计划

> 愿景：让一群 AI 在 Minecraft 里真正地"活"，把他们的行为沉淀成叙事资产，最终用 AIGC 技术栈把它拍成动画——穿越者们是主角，天神是配角，世界是舞台。

---

## 0.5 世界观 v2：多穿越者 + 初始技能（2026-08-16 用户定调）

不再是单主角"小石"，而是**一个可以接入多个"穿越者"的异世界**：

- 每个穿越者 = 一个独立的 AI（独立 bot + 独立人格 + 独立记忆 + 独立属性面板）。
- 全部由**女神（天神 mc-god）**召唤/指引——她是唯一的创世意志，众生皆由她渡来。
- **召唤是有目的的（2026-08-17 定稿）**：穿越者不是随机漂流的落难者，而是女神**专门请来的人**——请他们留下来，**和女神一起完善这个世界**。第一位就是桐人：资深 VRMMO 玩家、站在顶点的顶尖攻略者，女神看中的正是这份本事（详见 `data/transmigrators/kirito.persona.md`）。
- 每个穿越者降临时有**初始技能选择**（异世界常见设定）：女神赐一个"天赋/初始技能"，决定其成长方向。
- 真人玩家同样是穿越者，与 AI 平权（既有设定不变）。

### 运行时框架：每个穿越者 = 独立 agent，由 DeepSeek Harness 驱动（2026-08-16 用户定调）

- **每个接入 MC 的人物都是一个独立 agent**，后台由 **DeepSeek Harness（`dsh`，DeepSeek AI 官方开源 agent harness，@deepseek-ai/dsh-root）** 驱动；未来出现更强大的 agent 框架时可以替换。
- 现状已吻合此架构：`scratch-plugin`（dsh-minecraft-agent）就是挂载在 DSH 下的插件集，`bootstrap-mc.mts` 在一个裸 Cordis context 里装配 `mcBot / mcTools / mcMemory / mcTransmigrator / mcGod / mcMagic / mcLoop` 七个插件；每个穿越者 = 一个独立 bootstrap 进程（独立 bot + 独立 memory 文件 + 独立 persona 档案 + 独立 magic-state），由同一套 DSH 框架驱动，LLM 走本地 Qwen3.8-27B `:8890`。
- ⚠️ **「框架可替换」带来的工程约束**：DSH 当前是开发者预览（0.1.0-rc.5，README 明示「THERE WILL BE COMPATIBILITY-BREAKING CHANGES」）。因此穿越者的**核心资产必须框架无关**——persona 档案、memory、magic-state、transmigrator 档案、工具语义描述的都是「穿越者是谁/记得什么/会什么」，不得依赖 DSH 的专属 API；与 DSH 耦合的只应是薄薄一层 adapter（bootstrap 装配 + 插件生命周期 + LLM 调用封装）。未来换框架只重写 adapter，资产无损迁移。

### 初始技能怎么落地（映射到既有架构）
- 初始技能 = 属性面板（`magic-state.json` per-player 状态库）的**出生天赋字段**：如"剑术亲和""元素魔法""驯兽""工匠"等。
- 初始技能影响：擅长的魔法方向、可学魔法树、成长加成（呼应既有"属性面板升级/成就加成"设计）。
- 选择方式（已定 2026-08-16）：**让穿越者自己选择**（③自选，几选一）。
- 不新增底层系统：仍是"程序化状态库 + 快路径魔法 + 慢路径天神"，初始技能只是状态库里多一个出生字段。

### 背景故事（人物设定）—— 每个穿越者的人设来源（2026-08-16 用户定调）
- 每个穿越者降临异世界时都带着**前世的背景故事**（转生/穿越题材核心：前世是谁、什么执念、什么性格）。
- 背景故事 = 穿越者**人格 prompt 的来源**（SOUL/PROFILE 三件套 + 系统提示词里"你是谁"的部分）。
- 两种来源：
  1. **随机生成**：天神随机捏一个前世背景（前世职业/性格/执念）。
  2. **现成 IP 人物**：指定一个动漫/游戏/历史角色穿越进来（如"桐人""卫宫士郎"），天神读入该角色原作设定。
- 关键衔接（2026-08-16 用户修正）：**IP 人物的原作技能无法自带**（MC 是 vanilla 魔法系统，桐人的"二刀流/星爆气流斩"这类具体招式搬不进 MC）；IP 人物带过来的是**思考方式、行为风格、性格口吻、价值观**。所以**所有穿越者统一在降临仪式上自己选初始技能**（技能走 MC 魔法系统），区别只在背景故事来源（随机 vs IP）+ IP 人物"倾向选符合自己人设的技能"（剑士型 IP 倾向近战系）。**技能层与人格层彻底解耦**：技能统一走 MC 魔法系统，人格走背景故事。

## 0.7 架构定稿：双进程拆分 + 文字即接口（2026-08-16 用户拍板开工）

### 定位的最终表述

- **这个服务器是专门给 AI 玩家玩的**；人类（扛枪/萌萌）是**观众 + 导演（GM）**，以观察者/管理员身份进入，不是与 AI 平权的玩家（旧设定作废）。
- 世界角色三层：**AI 穿越者 = 主角**（自主生命，各自独立 agent）；**真人 = 观众 + 导演**（可干预但要克制，保住"自主生命"的戏味）；**天神 mc-god = 自动运行的神**（世界意志，由系统+LLM 扮演）。
- 愿景闭环：观察面板（观众席）→ 编年史（剧情回放）→ AI 漫剧（成片）。行为数据是最核心的时间资产。

### 工程架构：世界进程 / 穿越者进程 分离（铁律）

```
┌─ 世界进程 bootstrap-world.mts（每服务器一个，只跑在服务器旁）─────────┐
│  mc-bot(女神化身 Goddess, 旁观者视角, 无 viewer)                       │
│  mc-rcon(唯一 RCON 服务, 中文自动 \uXXXX 转义)                          │
│  mc-transmigrators(读档案, 主持仪式用)                                  │
│  mc-magic(快路径: 公屏咏唱→匹配→扣资源→RCON→公屏回执)                   │
│  mc-god(慢路径: 私聊祈愿→LLM 神谕→神迹 RCON→私聊回传; 女神化身管理)      │
│  mc-ritual(降临仪式: 玩家进服→公屏宣读候选→聊天选天赋→落库)             │
└──────────────────────────────────────────────────────────────────┘
┌─ 穿越者进程 bootstrap-mc.mts（每个 AI 玩家一个）─────────────────┐
│  mc-bot(bot 本体+viewer) + mc-tools + mc-memory                      │
│  mc-transmigrators(人格档案)                                          │
│  mc-mystic(薄接口: mc_chant 公屏喊 / mc_pray 私聊 / mc_choose_innate)  │
│  mc-loop(自主决策循环)                                                │
│  ⛔ 零 RCON、零服务器命令、零魔法 ID —— 全部交互只是"说话"              │
└──────────────────────────────────────────────────────────────────┘
```

**文字即接口**：穿越者与世界进程的唯一通信媒介是 MC 聊天文字——公屏咏唱（快路径）、私聊祈愿（慢路径）、公屏选天赋（仪式）。真人与 AI 走完全相同的通道（机制平权）。任何一方掉线/重启，另一方无感知（松耦合）。

**RCON 权限铁律**：只有世界进程 import rcon.ts / 读 rcon-secret。穿越者进程想获得任何神力，只能通过说话——这就是"游戏世界 AI 不得有系统底层权限"的落地。

### 开源边界（A/B 双仓库）

- **插件项目 A `jcs130/dsh-minecraft-agent`（开源）**：穿越者侧 6 插件（bot/tools/memory/transmigrator/mystic/loop）+ 档案机制 + 示例档案。任何人都可用它让自己的 Agent 接入世界。
- **世界项目 B `jcs130/minecraft-ai-friend`（开源，本仓库）**：世界侧（rcon/magic/god/ritual）+ magic-atoms.json + 天神人格 + 世界数据。
- 双仓库已物理拆分完毕（2026-08-17），两仓均公开，穿越者是自主意识体——天神与世界不操控它们，只立法、守望、回应祈祷。

### 女神化身 Goddess

- 世界进程的 mineflayer bot（username `Goddess`），旁观者模式（对玩家隐身、不可交互）。
- 她是"世界之眼"：听公屏（咏唱/选天赋）、收私聊（祈愿）、看所有玩家位置（施法锚点）。
- 神力落地全走 RCON；台词走公屏/私聊（AI 玩家靠聊天事件听见）。

### 家（归乡/tp_base）的真相

世界进程不读穿越者记忆。玩家之"家"= 其重生点（床/世界出生点），经 RCON 读 `SpawnX/Y/Z`。想设置家 → 睡一次床。这比"bot 记忆锚点"更符合世界真相。

### 拆分落地记录（2026-08-16 已完成并端到端验证 ✅）

- 世界进程 `bootstrap-world.mts` + `start-world.bat`；穿越者进程 `bootstrap-mc.mts` + `start-bot.bat <user> <port>`。
- 新插件：`mc-rcon.ts`（共享 RCON 服务，中文自动 `\uXXXX` 转义 + `getPos/getSpawn` 兜底）、`mc-mystic.ts`（穿越者侧薄接口，含天赋失忆找回——本地无记忆时自动私聊女神询问）。
- 重构：mc-magic/god/ritual 全部脱离工具注册（工具移到穿越者侧 mc-mystic），仪式宣读改公屏，女神化身旁观者模式。
- **端到端实测通过**：桐人（零 RCON 进程）自主咏唱传送/归乡/破晓/大地塑形 → 女神跨进程听见 → 扣资源 → RCON 施法 → 公屏回执被 bot 的 LLM 循环听懂并继续决策；魔力回蓝、资源不足拒绝、远程坐标兜底全部正常。
- commits：`841e64c`（多穿越者基建）+ `2064742`（双进程拆分），已推送 GitHub。

## 0.9 宏大构想：一个越活越真的异世界（北极星，2026-08-17 定稿）

> 一句话：**女神召唤穿越者共建世界，穿越者是会自我进化的 AI 生命，玩家的一切经历沉淀为叙事资产，最终产出 AI 漫剧。** 世界不只"能玩"，而是随时间越玩越厚——记忆变多、关系变深、故事变多。

### 五大支柱

**① 自我进化的穿越者（项目心脏）**
穿越者跑在 DeepSeek Harness 上，具备完整的工具调用 + 思考 + 长期记忆能力。游戏时间越久，他记得越多、越"像个人"：

| 记忆层 | 内容 | 现状 |
|--------|------|------|
| episodic 流水 | 每步思考/行动/见闻（已回灌决策） | ✅ 在跑（Kirito 1700+ 条） |
| wiki 知识卡 | 死亡反思/失败复盘蒸馏出的生存知识 + **为人处事经验教训**（沉淀为 skills） | ⚠️ 代码已接线，闭环待验证（wiki-*.jsonl 尚零产出）→ **P0** |
| 任务史 | 做过什么委托、给谁办过事、拿了什么回报 | ❌ 缺 → **P0（mc-journal）** |
| 人物关系卡 | people:{firstMet, interactions, affinity, notes}——和谁关系好、谁帮过他 | ❌ 缺 → **P0** |

**② 有来龙去脉的村庄经济（沉浸感）**
委托不是"给谁送 3 个面包"的跑腿单，而是有 why（村民为何需要）、hook（怎么开口托付）、chain（后续连锁）的**叙事委托**：静水要面包是因为施舍流浪者、流浪者背后又有一段故事……村民 backstory 与编年史喂进委托生成，lore_atom 咒语情报彩蛋启用 → **P1**。

**③ 多语种世界（为多国家部署预留）**
台词/话题关键词/咒语别名/委托模板/档案按 locale 组织（与"世界观别名"字段合并设计），同一世界可接待不同语言的穿越者与观众 → **P2**。

**④ 全员有声（TTS 音色注册表）**
`data/voices.json` 给每个村民/女神/穿越者登记专属音色；133 已常驻 IndexTTS(:8085 克隆) + CosyVoice(:8086 九音色)。游戏内先以文字为主，TTS 用于：观察面板旁白、AI 漫剧配音、直播解说 → **P2**。

**⑤ AI 漫剧生产线（愿景终态）**
行为数据 → 剧本 → 分镜 → 参考图 → 视频 → 配音。**追尾镜头（2026-08-17 已上线）**：观察面板第三人称默认 `follow=chase`——相机锁死穿越者背后按朝向对齐，截图可**精确复现人物位置关系**，作为 AI 漫剧参考图的采集机制（微调参数 `cdist` 背后距离 / `chgt` 抬高）。

### 现状 → 蓝图路线图（能力审计 2026-08-17）

- **P0 记忆闭环**（"越玩越记得"的心脏）：wiki 反思端到端验证 → mc-journal（任务史+人物卡+好感）→ 为人处事类教训卡
- **P1 沉浸感**：委托叙事化（why/hook/chain）+ 穿越者感知"周围有谁"（nearby entities 联动人物卡）
- **P2 部署面**：多语种 locale 包 + 音色注册表
- 已达标：DSH 完整能力（24 工具+思考+视觉）、游戏内聊天、NPC 互动引擎（8 村民+每日委托）

## 0. 题眼：这个项目最值钱的是什么

不是魔法系统、不是代码、不是 AIGC 栈本身——**是穿越者在 MC 世界里真实涌现的行为数据**：

- 它怎么探索、怎么决策、为什么走到这一步
- 它怎么卡住又怎么自救、天黑被怪追到 4 滴血逃回基地
- 它怎么咏唱魔法、怎么跟天神祷告、怎么跟真人玩家（扛枪/萌萌）对话
- 它学会什么、错过什么、怕什么、想要什么

这些是**活的、不可复现的叙事素材**。代码可以重写，模型可以换，但这些行为一旦没记下来就永远没了。

所以整条链路是一条「故事生产线」：

```
魔法系统 + 天神 ──► 让小石的行为更丰富、更有戏   （造故事）
行为数据采集/沉淀 ──► 把这些故事记下来             （记故事）
AIGC 动画管线 ─────► 把故事做成动画               （演故事）
```

**核心原则：行为数据是时间资产，越早采越全。** 阶段 2 不应该是"最后再做"，而应该和前面并行启动——现在不采，半年后想拍动画，前半年就只剩冷冰冰的日志了。

## 3. 阶段 2 —— 采风（行为数据资产化，核心 + 尽早启动）

**目标**：把小石的行为变成结构化的叙事资产库。**⚠️ 建议与阶段 0/1 并行，不等到最后。**

### 2.1 行为事件采集（基础设施）
结构化事件流，维度至少覆盖：

- **探索**：去了哪、发现什么、走了多远
- **决策**：LLM 决策日志（目标是什么、为什么这么做）
- **施法**：咏唱咒语、法术、消耗、成败
- **对话**：与真人玩家、与天神的对话
- **状态**：卡住、天黑恐惧、血量危急、饥饿、被怪追
- **事件**：死亡、迷路、发现宝箱、建房子、种地
- **关系**：与扛枪/萌萌的互动
- **成长**：学会了什么、属性提升、成就

### 2.2 叙事化沉淀
事件流 → 故事片段 → 叙事素材库（例如"小石的一天""小石第一次施法""小石卡在矿洞里的一夜"）。

### 2.3 人格记忆
小石的"人生"可追溯，行为有因果——它记得自己怕黑，因为那一夜。

### 2.4 追尾镜头参考图（2026-08-17 已上线）
观察面板第三人称视角默认 `follow=chase`：相机锁死在穿越者背后、按其朝向(yaw)对齐，平滑跟随——**同一时刻的截图可精确复现人物之间的位置关系**，直接作为 AI 漫剧分镜的参考图（喂给 FLUX/视频模型做构图与人物关系锚定）。微调：URL 加 `&cdist=<2..12>`（背后距离，默认 4.2）、`&chgt=<0..4>`（相机抬高，默认 1.1）；`&follow=0` 回自由镜头。实现：`tools/patch_viewer_chase.cjs`（prismarine-viewer 补丁，bundle+源码双写）。

**产出**：随运行时间持续增长的叙事资产库（这才是动画的原料）。
**周期**：长期、持续。

## 4. 阶段 3 —— 成片（AIGC 动画，愿景终态）

## 4.8 魔法系统迭代方向（2026-08-16 用户定调：先跑通 v1，慢慢进化）

**原则：先把最初版本跑通。** 技能限制、更多技能不是一次做完，而是让世界慢慢迭代进化。以下记入 backlog，按需逐个启用：

- **人物等级系统**（用户 08-16 提议）：魔法绑定人物等级概念，等级太低用不了高级魔法。
  - 落地草图（届时细化）：`magic-state.json` 每玩家加 `level` / `exp` 字段；`magic-atoms.json` 每原子加 `requiredLevel`；施法校验链从「扣资源」扩展为「等级门槛 → 扣资源」；升级来源可挂行为事件（施法次数/探索/击杀）或天神赐予。
  - 与既有设计的天然衔接：属性面板已有 innateSkill/backstory，等级可作第三字段；天神慢路径可宣读升级神谕（仪式感）。
- **更多魔法原子**：持续往 `magic-atoms.json` 加条目即可（纯配置，不改代码）；候选：召唤闪电、群疗、护盾、显形照明（夜视）、缓降等。
- **咒语匹配增强**：bge-m3 向量匹配替换关键词匹配（容忍错字/意译），Matcher 抽象已留扩展位。
- **已知待修（v1 跑通阶段的小刺）**：关键词误匹配——念「赐予我一座熔炉」被匹配成 give 面包（item 参数没解析出来走了默认值）；向量化匹配上线前，可在 give 原子上加「物品种词表」缓解。
