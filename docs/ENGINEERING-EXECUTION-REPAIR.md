## 本轮实现

- 仅精确的 `game/qd-engineer` 工单派工，凭写入在先的 helpId、原 case/version/session、请求摘要、现役宿主映射及运行补丁标记，使用无总截止的原生后台任务。角色、模型、原会话与允许工具不变。
- QwenPaw 2.2.0 原生 console 源码按完整 SHA 固定后在镜像构建时应用小补丁；其它后台请求仍走原时限。取消、stream idle、TaskTracker 和任务终态仍由原生实现处理。
- Cron 和 A2A 共用 `/team/cycle-operations-mc-god.lock`，A2A 的锁持有到原生任务结束。忙时在创建 chat/task 和调用模型前返回明确 `409 engineering_busy`，原工单保持待办，回执为 `deferred`。后续正常工具调用可以对同一个 helpId/工单版本重新检查准入，不新增循环或自动重试；已受理、丢失回执、未知状态绝不重复提交。空闲文件锁也不能绕过尚未核实的 `running/unknown` 原工程周期。
- 受理回执必须显式返回 `timeout: null` 才确认新工程策略；旧服务忽略策略时，保留已接受 taskId 并标为策略未核实，不自动再发。
- 运营账本保留全部未决记录，并按真实完成时间保存最近 100 条终态。修复了“pending 放首行，刚完成后被尾部截取删掉”的问题，不修改任何历史终态或旧验收哈希。
- 司灯原 `qd-world-daily-default` 日报只可与完整证明仍在执行的当前天神 Cron 并行：原生状态、精确原周期/占位、Qwen 进程与内核锁及起始时间关联必须全部成立。新日报行记录原工程 run 的准入证据；同角色、其它任务、旧宿主及未知占位仍阻止准入。工程健康也核对该精确日报关联，避免合法并行本身造成误报。
