# Jev / QwenPaw 快慢控制

2026-09-21。部署验收记录见本文末尾。代码沿用 survivor、SkillLibrary、PracticeStore、QwenPaw 原生任务和 Numen 身体网关。

## 控制分工

| 执行层 | 工作 | 触发方式 |
| --- | --- | --- |
| Numen 原生任务 | 导航、移动、交互及游戏 tick 内的执行 | 接受一次有界动作后持续运行，查询原任务回执，不重复派发 |
| 已测试程序 + Jev | 程序处理确定性步骤；有多个合理候选时让 Jev 分类 | 身体空闲且上一动作已结算，构造当前状态与完整候选；单个异步请求 |
| QwenPaw 认知 | 小目标、技能程序、前置与终止条件，失败后的规划与复盘 | 目标变化、程序完成/失败、低置信、服务不可用等现有触发 |
| QwenPaw 交流 | 回应已听见的信息，使用独立的只读交流会话 | 与程序、Jev 等待和原生动作并行；不能借身体租约行动 |

程序返回的 `choose` 新增可选 `context` 对象，最多 2048 字节，用于任务局部事实，如距离、可见障碍、上次动作后的实际进展。调用方应核对感知来源、新鲜度；没有自动拷贝整个场景、聊天历史或思考过程。控制器同时提供候选的确切 tool/args，避免仅用模糊文字描述动作。总状态仍限制在 8192 字节，候选仍为 2–8 个。服务没有会话 KV 增量协议，因此每次仍发送小型当前快照，不声称实现了跨请求缓存。

`policy_worker.py` 只做推理，没有 gateway、租约和写盘接口。一个工作线程、一个在途槽、一个长期 HTTP 客户端；忙时不能排第二个请求。只有主控制器能复核并执行结果。等待不推进程序 memory/steps；重启后重新观察和分类，不恢复旧选择。已经派发的动作仍按原 dispatching 标记、原生任务 ID 和回执处理，未知效果不重放。

结果绑定提交时的完整技能作业、目标、记忆代和控制意图。接收时复核身份、维度、原生任务、库存、装备、生命状态与位置（允许不超过 0.5 格的被动位移）。暂停、维护 drain、离线、原生任务变忙或慢系统取得身体时丢弃待接收结果。分类超过 5 秒或身体前提改变，最多重新观察两次；再失败交回慢系统。网络忙槽也有 5 秒等待上限，不能永久卡住自主运行。

主服务在等待分类时目标轮询间隔为 250 ms，程序/原生动作/交流活动时为 1 秒，其他情况保留配置间隔。这些是调度目标，完整观察与发布有自身耗时；不是 4 Hz 模型调用保证，更不是游戏物理频率。身体仍由 Numen 连续运行，暂未增加通用 WASD/鼠标输入片段，也未实现原生任务执行中的 Jev 抢占或多问题批量分类。这些要先有任务取消/所有权和独立场景证据再扩展。

## 80 ms 与本机测量

[官方发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)给出的端到端范围为约 70–500 ms，并说明其测试主要在服务所在的美国西海岸进行。80 ms 不是任意地区、任意输入的延迟保证。本机不能消除跨地区网络往返。

本次从实际 survivor 容器调用官方 `jev-latest`（返回 `jev-1.13.0`），每次重新读取真实身体，只运行影子分类，未派发动作。交替执行冷连接与持久连接共 7 对，排除第一对预热后各 6 次；1929 字节状态、1180 输入 token、33 输出 token，模型与请求结构相同。

| 连接方式 | 中位数 | 最小–最大 | 样本 |
| --- | --- | --- | --- |
| 每次新建客户端与连接 | 816.55 ms | 636.04–1072.36 ms | 6 |
| 同一个客户端复用连接 | 278.50 ms | 262.78–321.17 ms | 6 |

这组小样本中位耗时下降 65.9%。冷请求 TLS 阶段约 325–646 ms；复用样本均未重新建连。分阶段计时只保存事件名与时间，不保存 HTTP 头和认证。`responseHeadersMs` 包括网络与服务端处理，**不能当作模型纯推理时间**。首次连接或闲置超过 60 秒仍可能重新握手，无额外付费心跳或隐式重试。

这些样本均选择/触发回慢系统，不作为策略质量或游戏任务成功证据。分阶段原始计时见 [测量记录](research/jev-fastslow-latency-20260921.json)。公共状态现在可显示 provider、状态字节数、连接/TLS/HTTP、请求到接收耗时与等待接收耗时；避免把 API 时间混为完整动作时间。

## 验收

源码隔离验证：112 项具身冒烟、34 项实践冒烟、73 项控制器回归、14 项快技能回归通过，部分测试集合有重叠。新增回归覆盖阻塞网络期间交流可用、单请求、旧结果作废、过期/忙槽有界退回、连接复用，以及原租约和回执路径。最初一项测试用 2 秒自动释放模拟阻塞，慢速测试准备阶段超过该时间导致失败；改为显式事件控制并隔离无关读取后通过。首轮源码冒烟执行期间文件变动，112 项之前的 110 项虽通过但 hash 验收失败，原报告保留，最终重跑成功。

生产验收：仅 survivor 经原管理器 stop/start，11:31 启动健康；生产字节再次执行 112 项具身/34 项实践冒烟通过，9 个保留晋升版本的 62 条 fixtures 实际重测通过后发布报告，未更改晋升历史。角色技能通过原生 Skill API 同步；10 个 profile、16 条 Cron 和 NPC 准入状态精确恢复，原禁用班次保持禁用。桐人 48/3、结衣 7/3 个原生/队伍工具可用；Jev、具身和实践相关 panel 检查通过。完整 panel 仍有既有来源/资产/部分历史验收不匹配，整体不是全绿。初次指南同步因隔离源码缺运行角色清单而在写入前退出，随后使用实际部署的清单和官方 API 完成，失败未隐藏。

维护证据在被忽略目录 `runtime/jev-fastslow-20260921/`，一次性脚本禁止重放。一次维护改造不等同于 Agent 自主 RSI 收益。补给实地实践仍在观察，最终回执另记。
