# My Agent World：功能调用验收与后续生活场景

适用：Minecraft 1.21.1 / NeoForge 21.1.248 的实验分支。本文是后续开发、测试与运营 Agent 的接力任务清单，**不是本轮通过记录，也不承诺当前全部模组可用或公网就绪**。当前模组清单、已实现接口、既有证据和缺口以 [外部接入就绪审计](MY-AGENT-WORLD-EXTERNAL-READINESS.md) 为准，不在这里重复能力大表。

**2026-10-05 用户最新标准：“把各项功能都能够被 Agent 调用就行”。** 当前优先交付功能目录、参数说明、本人原生状态、真实调用和可核验回执；不要求模型先自主采集、建城或经营。已新增 [30 项统一原生调用接口](MY-AGENT-WORLD-NATIVE-CALL-API.md)。接口适配、对外接入、渲染、基岩与长期自主生活分别记录，不能相互替代。

下文 P0/M1–M11 保留为后续场景清单。其中自然采集和长期自主目标是可选扩展，**不再是当前接口交付门槛**；社会岗位、魔法编书、复杂机器等真正缺少的动作仍需开发。每项接口先在独立普通账号验证“发现 → 读取前置条件 → 调用 → 实际效果或已知拒绝”，允许明确标注的场景/材料夹具；未派发、失败与未知结果分别保留。目录存在不等于当前服务器支持，只有测试过的明确范围扩大已验证清单。

## 接力与结算规则

- 使用独立普通非 OP 账号、世界/副本、状态目录、会话、任务与行动账本。不要第二次登录常驻角色或共享窗口、女仆、物品 SNBT、任务 ID。
- 自然材料可以来自采集、制作、正常交易和真实已完成的生产任务。管理员给物、传送、无消耗施工、改生命/魔力或直接授予技能只适合标明的契约夹具，不计自主完成。模组正常入服初始道具单独记录来源。
- 每个场景保存版本/桥 SHA、账号 UUID、维度/epoch、时间、请求 ID、原始失败原因、实际前后状态和干预记录。完整私有组件及模型凭据留在运行目录；仓库只保存脱敏摘要和复现说明。
- 命令受理、`ok`、模型自述、网页健康或产物图标都不是完工证据。物品要核验真实注册 ID、完整组件及本人库存；建筑要核验等级、建成标记、工单；劳动要核验真实作物、原料与产物。
- 场景达到明确节点后结算，依赖缺口出现就停止该支线并登记，不不断重试。其他独立场景可继续。运行窗口、回合/动作/模型预算在开始前写入该次计划，结束时记录完成、失败或未完成，不给无期限成功承诺。

所有里程碑共用未知恢复流程：发现写动作超时、断线、死亡、重启或 `outcomeUnknown` 后，先停止依赖步骤并保存原意图/回执；用**只读**真实世界、本人库存、工单/任务核对。精确人工审计须保留原行动 ID、证据和未确认部分，不把旧结果改成功，不用新 requestId 重做。已确认无副作用的拒绝可以在条件改变后重新计划；“没看到结果”不等于“没有执行”。未知仍未核实时，该支线不通过。

## 前置 P0：身份、原生观察和碰撞

普通账号先独立连接实验网关，挂接自己的原生客户端，读取本人 UUID、实际菜单/组件、实体身份和工具目录。声明目录的来源和可执行范围：本地目录不是远端支持证明，底层 SDK 也不是完整计划执行器。

**复杂导航的前置是 collision shape；当前原生查询可以单独作为调用接口验收。** 身体适配仍未完成，不能使用 `occlusionBoxes` 替代。接口与白名单见 [原生碰撞契约](MY-AGENT-WORLD-NATIVE-COLLISION.md)。遮挡、渲染几何与碰撞是三种数据；查询绑定完整原生属性、绝对位置、本人姿势及邻居上下文。当前 `physicsIntegrated=false`、`pathfinderIntegrated=false`，未知类和动态形状明确不可用，不静默退回原版代理整方块。身体集成不是站定菜单、施法或专用社会接口交付的统一阻断项。

验收场景包含原版门/阶梯/半砖、FD 薄切菜板、Create 轴/机器、Macaw 桥和屋顶、Domum 组件方块，以及邻居状态改变、流体、坑和屋顶下行。让普通账号真实走过、站稳、跳跃/下行，并核验实际脚下 XYZ、服务器位置纠正、卡住/超时及可达判定；场景摆放夹具与自然导航另列。动态运动结构未接通时必须返回明确不支持，不计完整 Create 可达通过。

过门条件：原生形状确实进入该账号的 physics/pathfinder；支持场景中到达由真实三维位置判定；不支持场景不会错误宣称可达或到达；撞墙/落入坑/死亡后不继续旧计划。未完成此节点前，可以做站定菜单与机器契约测试，不能把复杂自主建城或地下城导航判为全面通过。

## M1：普通生存与材料供应

普通账号从独立自然世界出发，使用线上指定模型。先采木、拾取、制作工作台与工具，再取得可稳定续产的食物、床/避难处和普通储物箱；自然取得后续需要的石材、铁/铜等材料。

实际后置证据：工具/容器确实由材料消耗合成并进入本人库存，方块真实放置；采集既证明破坏也证明拾取；进食只消耗应消耗数量且身体数值变化；休息/避险不是执行器补血或传送。缺工具、背包满、无配方、无燃料、打不开门与错误高度都要有明确回执。

过门条件：Agent 能从真实材料持续推进目标，在至少一个昼夜变化或可记录的生活周期内取得补给并回到储物/避难点。具体窗口在运行计划中限定；一次采木或一次进食不能替代这条链。未知消费/合成用完整库存和结果槽核对，不能再次点击猜测。

## M2：Domum 精确制板与殖民地供料

前置接口：按建筑分页读取完整真实需求模板/SNBT；Architect's Cutter 的原生配方、菜单/材料选项与输出组件可读取并操作。新增接口见 [切割台契约](MY-AGENT-WORLD-DOMUM-CUTTER.md)。需求模板不是 `stockResource` 的本人库存 CAS，交付前仍重新读取本人实际物品。选项来自真实组与分页变体，不按显示名猜材料；选择后通过原生结果槽取出，才证明实际产出及耗料。

本次已有明确夹具的普通非 OP 契约证据：真实切割、完整组件匹配、错误材质/过期 SNBT/超量拒绝，以及关联货架计数 0→3；这是接口阶段通过。自然材料、设备自制、工人施工使用及完整 M2 过门条件仍待完成。

普通账号用自然所得材料制作加工设备和建筑需要的组件板材。先从真实工单取一项带材料组件的 Domum 需求，按实际配方加工，核验输出完整组件，再交给指定建筑工。另做隔离反例：同 ID 不同材料、同组件不同数量、错槽/变更 SNBT 均不能错交或误扣。

实际后置证据：分页覆盖总需求且没有跳过被预算阻断的条目；材料减少、组件正确的产物增加；本人交付数量与建筑库存/需求对应；工人实际使用而不是只“收到”。分页期间需求变化要重新读取并核对，不将 offset 分页误当冻结快照。

过门条件：至少一个真实组件需求从自然材料加工到交货和施工使用走通，原生条件拒绝不产生错扣。某个超大组件无法在预算内表达时，返回明确原因并保持该条未通过，不能裁组件后当作完整。

## M3：建筑工与住宅完工

普通账号正常制作市政厅、建筑工和住宅物品，在原生距离/地形/权限规则下建镇、登记并生成施工单。可先用供料副本复核接口，再在自然材料链中重做。选择当前已支持蓝图/风格，尚未接入任意 Build Tool 不算任意风格通过。

按真实需求供应建筑材料、工具和食物，观察实际建筑工施工；不能由运营者把完成建筑直接放入世界。真实居民若尚未出现/分配岗位，补合法原生入口并记录，不用管理员伪造居民进度。

实际后置证据同时包含目标 `level`、`built=true`、`constructionPending=false`、对应工单消失及实体/方块的实际建成状态；库存搬入、工单创建、四分钟等待结束都不能替代完工。

过门条件：自然材料完成一级建筑工与一座住宅；重复/变更请求、缺料、工具损坏和重启持久性均有明确结果。施工中断后只读核对原工单和材料，再决定新阶段，不重新开重复工单。

## M4：居民岗位、农场与供餐

前置接口：真实招聘/岗位分配、岗位容量/招聘模式、工人暂停与状态、所需生产配置可按原生权限读取和设置。不要把 `workerModules` 可读当作可配置，也不要先固定虚构居民职业。

普通城主正常取得/招募居民、分配农夫和厨师，建成对应设施，提供自然种子、工具和设备。居民真实种植、收获；玩家或工人通过真实料理链加工并供餐。女仆可以协作，但保持不同主人/岗位/库存事实，不替居民伪结算。

实际后置证据：公民工作建筑/任务与分配一致，真实农田生长/收割/补种，库存有原料和餐食变化，居民取得食物及实际饱食/工作状态改善；“请求清空”还要区分物品已交、待工人取货、真正消费。

过门条件：一次完整农作周期和供餐走通；缺种子/工具/食物、角色睡眠或非工作时间的等待原因明确。运行计划给出等待预算，未完成生长不能改作成功。未知岗位/交付用居民和请求状态核对。

## M5：仓库、快递与生产物流

前置接口：原生仓库/快递岗位、库存的完整组件分页、生产任务/配送请求与限制可发现。成员看不到的库存和配置要尊重权限，不用管理员控制链绕过。

普通城主建仓库与快递员小屋，合法分配工人，把农场/厨房/建筑工至少三类端点连接起来：产物从生产点进入仓储；缺料工单触发真实配送；建筑工/厨师实际取用。再加铁匠完成一种真实工具或装备生产任务。

实际后置证据：同组件物料在源/目的库存中的减少/增加、原配送任务状态和实际快递员行为、最终使用或产物；物料账目守恒，不能只按通用 ID 合并不同材料的 Domum 块或不同附魔装备。

过门条件：至少一条生产→仓储→需求端的闭环，以及一件最终生产物进入合法库存。仓满、来源缺货、目的地满、路径不可达、并发需求/重启分别返回实际原因，不能丢物或伪称已送达。

## M6：Create 动力与多机器加工

在 M1/P0 底座上，普通账号用自然材料制作动力、传动和加工设备。由真实配方目录选择目前明确支持的加工链，先完成单机输入→动力→缓冲输出→本人取入，再做至少两种不同机器和真实运输组成的连续产线。磨石通过不代表碎石轮、机械锯、压片机、混合或自动厨房通过。

实际后置证据：布局/状态与真实原生方块吻合，转速/压力/超载及输入输出可读；产物使用完整组件与概率定义核验。随机未掉出额外物品不是失败，不能以显示用第一产物代替全部结果，也不能由查询函数滚奖励。

过门条件：实际完成一种多机器成品，且机器停止/动力反转/超载/错误原料/输出阻塞可被理解和恢复。先 read-only 查工况再改布局或补材料；未知右键/领取用源输出和本人库存核对。Dragons Plus、Central Kitchen、Ars Creo 的独立联动链另立场景，未测就继续列未支持。

## M7：Create 流体与复杂生产

前置接口：真实流体身份、完整组件、存量/容量、连接/泵方向、过滤/配方条件和原生操作回执。桶里的普通物品身份不能替代罐/管道真实流体状态；不能由 `definitionAvailable=true` 推断流体可操作。

普通账号制作并使用桶/储罐/泵/管道，从合法水源或实际原料获得流体，完成一条真实填充/排空/加工链。更复杂盆地混合、流水装配、机械合成、联动厨房分别建子场景，不借一桶水覆盖所有流体。

实际后置证据：源/管网/储罐/目标的流体量与身份变化、原料/容器保留物、最终产物完整组件；依据配方核算守恒。管路断开、满罐、错误流体/组件、失去动力和重启恢复分别测试。

过门条件：支持链的流体真实转移与成品取得；未支持特殊流体谓词/动态处理器明确阻断。未知搬运必须同时核对物品与流体，不能因为空桶没有变化就认定整条操作未执行。

## M8：Ars 学习、编书与魔法生活

前置接口：真实书 tier/已知 glyph/解锁条件、学习或制作设备、编书槽位/配方、仪式条件和相关原生菜单/负载。现有手持预配置书 `list/explain/cast` 只是施法入口，不代替学习。

普通账号从自然材料制得法术书，合法制作/获得并学习 glyph，读取真实前置条件，编成一种自愈与一种敌对攻击法术，再扩展一种资源或生活法术。使用本人魔力/冷却和合法目标，不由 bridge 直接赋予已学法术。

实际后置证据：学习材料真实消耗、已知 glyph/书组件变化、编书配方与本人主手实际一致；治疗有血量效果，攻击有合法目标 UUID、受伤来源和实际伤害；生活法术有世界/库存终态。扣魔只证明施法发生，不证明命中或治疗。

过门条件：制书→学习→编书→实际生效走通，且未知/锁定 glyph、魔力不足、冷却、事件拒绝和友方保护正确。仪式、附魔装置、魔法伙伴/生产分别扩展；非空粒子 timeline 或其他协议未适配时不可称全部 Ars 内容通过。

## M9：女仆多种生活劳动

普通账号按合法玩法取得自己的女仆，读取真实可用任务/工具/装备条件，再完成至少三种已发现的不同劳动场景，例如农田、搬运拾取和一种实际可用的生活/生产任务；具体第三种由锁定包真实任务目录选，不能预设不存在的任务。

由玩家自然准备工具/材料与工作区，真实操作女仆背包并关闭原菜单让 Brain 恢复。核对本人所有权、任务启用条件、实际日程/状态；好感、餐食和库存不得由保留 `hunger=0` 字段猜测。

实际后置证据：任务设置、实际女仆位置/劳动、源材料/背包/结果变化及可观察的原生进度。一次单株收割不代表长期农田；菜单打开暂停劳动需有可解释状态。

过门条件：各任务至少一个完整产出周期；睡眠、缺工具、背包满、原生任务禁用/权限、主人断线和重连有明确处理。另一玩家不能改主人女仆的任务/背包；未知 task_set 或交料只读核对，不重复写。

## M10：地下城自然攻略与战斗

前置：P0 的真实碰撞/导航、合法模组敌对分类、基本装备/补给、远程/近战与机关交互确实支持。敌人身份从原生 UUID/类型/关系取得，不能因为代理显示 zombie 就攻击；玩家、村民、居民、宠物和女仆继续受友方保护。

普通账号在自然未生成区域寻找一座实际存在的地下城，正常走入、理解多层/高低差、操作真实机关、战斗/补给、取得合法战利品并回到安全储物点。分别安排 Dungeon Crawl、YUNG 结构、Fantastic Dungeoneer 的场景；一座原版砖石通道不能代表自定义 Boss/机关通过。

实际后置证据：实际发现路径/位置、房间与机关状态变化，敌人 UUID/生命/攻击目标/受伤来源，死亡/掉落/奖励真实库存及完整组件。不能运营者先杀怪或给奖励后声称攻略；原生怪物互殴和无攻击 AI 要单独记录。

过门条件：宣称支持的地下城种类分别完成一条自然攻略链。卡门、陷阱、熔岩/水、逃跑/补给、死亡与重连恢复要按真实机制处理；没有原生续关就明确不能续关，不凭旧 Paper 试炼塔规则假定新模组支持。

## M11：真正外部身份与多 Agent 并发

先开发并验证账号所有权与实际认证，再变更任何公网监听/映射。当前离线用户名及前缀过滤不构成认证，客户端 `playerUuid` 也不是替外部客户端证明所有权的凭据。实验服务与旧正式服务持续隔离。

至少两个独立普通账号从不同客户端进程接入，拥有不同会话、账本和原生客户端；其中一个最终须走实际外部网络/认证入口，不用宿主回环测试替代公网。框架不应依赖 QwenPaw 私有角色或常驻玩家文件；线上模型账号/密钥由各自宿主管理。

并发场景覆盖：同箱不同槽/同槽竞争、不同完整组件、城镇成员与访客、不同主人女仆、同时施法、不同窗口 requestId、断线/死亡/重启。私有状态和回执只能到所属连接；错误身份或前置条件必须明确拒绝且无扣物/跨账号副作用。通用频道、本人数据和实际收到的负载分别核验。

记录真实消息/带宽、tick/MSPT、动作回执延迟、模型等待、限流、断线/重连与队列。容量从已实测账号数逐步增加，不能因为 `max-players` 数字更大就宣称承载量提高。普通客户端闭合后禁止继续派发旧连接写动作。

过门条件：认证和真实外部连接通过；独立账号能发现并完成宣称范围，私有隔离/CAS/并发/未知恢复成立；对可玩范围、容量和未支持能力给出实际限制。此节点通过也不自动意味着基岩全部模组功能或网页完整 1:1 通过；两者沿独立验收轨推进。

## 最后收口：逐项声明支持，不给全包空承诺

每个任务完成后在 readiness 文档追加该次运行结果，并更新已验证能力清单：模组版本、功能/配方/机器/任务/实体种类、可读/可操作/自然自主/渲染四种状态、失败边界和恢复方式。新增方块、组件、实体或自定义负载先验证其真实语义，再扩大范围。

安装包内宣称可调用的功能要有对应的发现、读取、原生执行及边界证据；公开开放另需外部身份/并发/维护验收。上文自然目标完成不再是当前调用接口验收的必要条件。尚未适配的附属联动、装备槽、指南或机关保留明确 unavailable；通用菜单和一个代表场景不能冒充它们的完整实现。

发布仍沿 [常驻维护指引](MY-AGENT-WORLD-PERSISTENT-SERVER.md) 的 owned stop/resume、任务/行动核对、备份和运行读回；旧未知动作、暂停原因与原失败记录不清除。把“接口修复”“供料实测”“自然目标完成”“新版本发布”分别写清楚，接班 Agent 就能知道下一步真正缺什么。
