# My Agent World：普通 Agent 发展链验收

日期：2026-10-05。适用 `experiment/agent-society-1.21.1`，Minecraft 1.21.1 / NeoForge 21.1.248。原 Paper 千灯纪不参与这些测试，也没有迁移其整套公会、试炼塔和 `/mycli`。

## 判定方法

将三个层面的证据分开记录：普通模型 Agent 自主完成的行动、提供材料的隔离原生玩法测试、代码和锁定模组 API 的契约测试。模型计划、请求提交、成功加载网页、服务器常驻，都不能替代真实库存、工单和建筑后置状态。

## 普通生存实测

`MawLifeQA` 使用线上 `maw-aliyun-codingplan/qwen3.7-plus`，独立 QwenPaw 角色、会话和账本。测试世界 `world-lifecycle-20261005` 是独立生成的自然世界，原生出生 `(90.5,66,68.5)`，未给予 OP、测试材料或传送；模组默认发放的指南和召唤道具保留并明确记录。旧研究世界、常驻 `world-life` 和其他服务没有重生成。

实际完成：发现可见白桦 → 挖下木头 → 走近拾取 → 制作木板、木棍和工作台 → 放置并打开工作台 → 合成木镐和木斧。前 28 轮零死亡，真实背包和网页均可见两件工具。

失败也保留：第一处树干不可见；首次掉落未立即拾取，后续走近才收到；打开工作台曾被节流，等待后重试成功；Agent 挖进坑后导航曾误报到达，放置避难所顶部失败。它尚未自主完成石制装备、稳定食物、住宅、建立和扩展殖民地，不能称为完整长期生活验收通过。

证据在运行目录 `research/lifecycle-qa-20261005/`：`qa-progress.json`、原始 `agent/actions.jsonl`、模型任务账本、`natural-tools-inventory.png`。只保留私有运行目录；模型密钥、完整私有观察和账号会话不提交仓库。

## 本轮修复

- 长期发展目标单独保存在配置的 `objective`，每轮提示都带上；模型的阶段 `goal` 不得覆盖它。
- 等待和只读查询依据已安装执行代码分类，真实派发的游戏写包仍触发未知结果保护。死亡取消等待不会再被永久当作未知交货；真正合成、放置、交货的未知结果仍禁止盲目重做。
- 重启同时检查未结算行动意图和已经写下的未知结果，避免进程恰在结果入账与暂停标记写入之间退出时漏掉写动作。手工核对必须留下精确行动 ID 和退役记录，不能篡改旧回执为成功。
- 普通导航核对真实三维终点和高度；接近掉落物的半径结果单独标明，不把原地或楼层不一致视为精确到达。
- 可见表面提供可选择的方块内瞄准点，但只作为客户端采样；服务端实际首个准星命中仍是授权和挖掘依据。阻挡方块信息保留，不能自动改挖挡块。
- 服务端准星回执提供真实 `requiresCorrectToolForDrops`、`canHarvestWithMainHand`、`destroySpeed` 和 `mainHandItemId`。`gather` 要求可正确采收；`dig` 允许玩家有意清障而不保证掉落。

## 殖民地发展入口

普通玩家的 `colony.status()` / `capabilities()` 即使尚无殖民地也返回 `constructionOptions`：真实建镇距离限制、当前位置条件、原生权限、固定 Original 结构包、可用蓝图和各小屋真实物品 ID。不能硬编码“住宅物品叫 blockhuthome”；该版本实际为 `minecolonies:blockhutcitizen`。

新增 `placeHut({hutType,position,inventorySlot,expectedSnbt,requestId})` 支持建筑工、住宅、农场、仓库、铁匠、厨师和快递员小屋。它使用服务端锁定原生 Original 1 级蓝图，核对完整真实物品、八格交互距离、城镇范围和原生建造权限，消耗玩家材料；尚不接受任意蓝图、旋转和自定义风格。

`requestBuild` 必须查到**唯一新产生的原生 WorkOrderBuilding**，且目标位置、下一等级、指定建筑工都吻合，才返回成功工单。旧工单、未生成、含糊多个工单或空建筑工哨兵值都不算成功。后续仍须供料、解决工具和居民请求，观察真实施工。

同一账号的 `requestId` 与完整规范化请求绑定；同内容可重取原回执，改变动作、位置、数量、完整 SNBT 或其他字段返回 `request_id_conflict`，不执行新动作。客户端同时核对成功回执动作。缓存有 32 条上限且仅进程内有效，未知结果不允许靠新 ID 重试，跨重启仍依赖宿主持久行动账本。

建筑完工证据至少同时包括 `level>=目标等级`、`built=true`、`constructionPending=false`、对应工单消失。提供材料的原生建筑工一级完工历史测试已存在，但不是本轮普通 Agent 从零获得全部材料的证明。原生居民工具/食物请求可查询和交付；独立的岗位招聘、全套工人配置、完整原生 BlockUI 管理操作和任意风格尚未接齐。

锁定蓝图锚点、原生权限、工单语义和回放验证见 [MineColoniesConstructionAudit](../world/society-bridge-src/research/MineColoniesConstructionAudit.md)。

## 可视化与其余缺口

网页以同一玩家连接的原生注册表、模型和贴图为准。本轮新增普通殖民地小屋渲染规则，锁定版本的 48 种小屋通过真实 Java 继承和空特殊渲染器审查；10 种资源条件满足，可加载原始静态模型。市政厅、建筑工小屋存在木板贴图优先级冲突，其他一些有未支持的自定义加载器或资源条件，继续明确拒绝近似替代。居民专用模型和完整管理界面仍需适配，不能声称与 Java 客户端所有画面一致。

农夫乐事、Create、东方女仆、Ars 和原生合成已有分别测试的操作入口，但普通 Agent 从采集食材到生产、装备、殖民地运转和任务完成的全链仍未整体验证。高阶 Create、复杂流体/机械、模组碰撞与导航、多 Agent 生活和仓库配送闭环也需要实际场景验收。新模组服的基岩登录、公网认证及旧公会/技能体系迁移单独列为未完成。

后续优先让普通 Agent 稳定拿到食物、石制工具和避难所，再用自己制作的建镇物品完成建筑工 → 住宅 → 农场 → 供餐 → 仓库/快递员 → 铁匠装备生产。每阶段保存配方、原生库存增减、居民请求和建筑工单证据；缺接口返回明确能力缺口，不用管理员物资模拟自主发展。

## 部署和复测记录

本轮已经完成如下验证和部署：

- 普通 Agent 与殖民地客户端回归 163/163、网页全量 438/438、锁定 Java/API 回归 6/6 全通过，无跳过；网页双端 typecheck 与最终 Java 21 桥编译通过。
- 最终桥 JAR SHA256：`a0da152597b4528feb0cebd0c6fc228ae35583f83a9aea25dd5889abd80dc2e4`，源码构建记录、锁文件、两实例安装逐一核对。网页资源 `native-20261005-v9` 验证 39127 个文件；桥无游戏资源，只有桥来源和锁文件 SHA 更新，其余模组、客户端、模型、贴图和号表逐字保持，资源优先级与完整画面一致性仍为未验。
- 殖民地在独立 `world-colony-fixture-20261005` 副本测试，使用普通非 OP 城主，但材料由隔离实例控制台提供，测试落点也由控制台安排，不计自主采集/导航成功。住宅 `(620,63,610)`、农场 `(651,64,613)`、仓库 `(620,65,650)` 实际消耗原生小屋物品并登记；真实工单分别为 1、2、3，均认领到建筑工 `(603,64,600)`，目标等级 1。相同请求回放逐字一致，改变位置返回 `request_id_conflict`，无第二次扣物。没有取消权限和真实地面条件。
- 首次发现 `capabilities` 客户端存在而服务端返回 `unsupported_query`，已补齐真实服务端分支并冷重启复测。住宅首次地面高度错误、农场首次选到叶片均被拒绝，原失败保存，不把后续成功改写回首次记录。
- 居民后来产生木斧请求，经真实 token、本人完整 SNBT 和 `deliver` 成功送入一把，`accepted=1`。四分钟住宅供料观察**未完工**，仍是 `level=0/built=false/constructionPending=true`。需求为带橡木组件的 `domum_ornamentum:panel`，查询只提供 ID 和显示名；给出的无组件板材被 `item_not_needed_for_construction` 拒收。测试控制器错误地优先重复首项，累计 215 次已知拒绝且没有成功扣物，原记录保留；这是测试控制器的退避/候选切换缺口，不是模型自主行为。不能把控制器 `ok:true` 的正常结束解释为完工。
- 由另一非 OP 访客实测原生石头：实际手持 TLM 召唤道具时 `canHarvestWithMainHand=false`，采集预条件拒绝；换到真实木镐后原生字段变 true。此次只验证采集条件，不派发挖掘，不计石头采集完成。该访客未拥有殖民地，附近城镇仅返回非成员及拒绝建造权限；无城 `colony:null` 分支由 JVM 回归验证。
- 常驻 `MawExplorer` 重新连接并继续线上模型轮次。旧中断的等待按只读取消退役，旧已被操作员核对的未知采集追加明确审计事件，原始未知结果未改成成功且未重放。两次维护标记均已审计退役。常驻仍遇到屋顶找不到下行路径，能明确返回失败而非假称到达；这是后续地形/导航与决策缺口，不能称长期自主生存已通过。

新的具体缺口：殖民地资源需求必须提供完整真实 ItemStack/SNBT 和分页读取，而不是仅给通用 ID（目前 15 项中的 12 项被返回）；Domum Ornamentum 的材料组件、原生加工配方与真实物品组件需要贯通。岗位操作、工人搬取与仓库物流、食物生产和复杂导航也需要后续场景。`needs_item` 可以表示已经完成的请求尚待工人取货，不能仅因某时 `requests=[]` 就认定漏请求。

私有证据：`colony-expansion-trace.jsonl`、各次失败/部分成功 JSON、`colony-expansion-result.json`、`colony-supply-result.json`、`native-harvest-result.json`、两次部署报告与冷备。隔离 QA 三进程和监督器已结束，原生测试副本、自然测试世界与证据保留，未来配置恢复到自然测试世界且决策暂停；只有常驻角色持续运行。
