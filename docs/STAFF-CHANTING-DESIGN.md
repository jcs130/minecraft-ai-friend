# 自有言灵法杖：举杖、咏唱、松手释放

更新：2026-09-07。本轮按用户最新要求实现：**自制法杖是语言施法入口；长按使用显示不阻塞操作的 HUD，默认语音模式，可用肩键选择 8 个快捷槽，松开后施法。** 本文记录设计和实现边界，实际部署与真人体验验收以对应报告为准。

## 玩家交互与道具

| 环节 | 本轮约定 |
|---|---|
| 开始 | 长按言灵杖使用键，仅进入准备姿势，每次默认语音模式 |
| 提示 | HUD 显示可说的咒语、当前模式和 8 槽；镜头与瞄准保持可操作 |
| 选择 | 左右肩键循环“语音、1–8 槽”；键盘备用 Page Up / Page Down，可改绑定 |
| 提交 | 松开使用键；语音等待有效识别，快捷模式提交所选槽位 |
| 编辑 | 技能罗盘 → 编辑快捷栏 → 槽位 → 已学秘术；可清槽和恢复推荐 |
| 取消 | 开菜单、换物品、失去有效操作环境、死亡/旁观/离线等使当前手势失效 |

选择快捷槽不会当场施法，编辑快捷栏也不会施法。快捷模式停止本轮自有法杖附加的 PTT，保留用户独立的 SVC 设置；迟到语音不能覆盖所选快捷槽。切回语音需要切换后录制的咒语。当前 8 槽编辑范围是精选、已学、非被动的旧主动秘术，尚不支持直接配置原生 Iron 法术 ID。

`qiandeng_chanting` 是双端共享 mod，包含两个原创新物品：

| 注册 ID | 名称 | 配方 |
|---|---|---|
| `qiandeng_chanting:whispering_staff` | 旅人言灵杖 | 两根木棍、一个紫水晶碎片 |
| `qiandeng_chanting:resonance_staff` | 千灯共鸣杖 | 旅人言灵杖、三个金锭、一个末影珍珠 |

两杖使用各自几何模型和已确认存在的原版纹理；目前输入规则相同，共鸣杖没有额外伤害或免费魔力加成。物品继承原版 `Item`，不继承 Iron 的 `StaffItem` 或 `CastingItem`，不添加 `CASTING_IMPLEMENT`。`use` 只发起 `startUsingItem`，准备姿势使用 BOW 动画；没有在右键开始时提前执行半次法术。

## 服务分工

| 部分 | 责任 |
|---|---|
| `world/chanting-items-src` | 物品、资源、HUD、模式选择与松手输入；服务器真实手势状态和一次认领 |
| `world/god-voice-src` | 在原 SVC 插件上记录实际采音起止；保持原播音逻辑和录音名单 |
| `world/sidecar/mic_asr_watcher.py` | 检查 schema 2 录音身份与区间，ASR 转写，保留原时间输出 |
| `world/src/application/spoken-commands.ts` | 解释明确咒语，等待松手条件，进入同一个玩家命令服务 |
| `world/src/application/player-commands.ts` | 技能栏配置、现有 CLI/技能执行；保留装备、进度、法力与冷却规则 |
| 既有 Iron 桥 | 按实际可施法列表调用原生法术，接收原生拒绝与动画状态 |

Agent 的 CLI 继续调用现有应用服务；法杖交互服务于真人玩家。自有输入层不另建人物等级、魔力或法术书体系。

## 录音必须与完整手势关联

旧录音模组在最后音包静默超过 1.2 秒后切段，原 metadata 的 `ts` 是切段落盘时间。只拿这个时间寻找“最近举杖”，会把前一次咒语认到迅速重新举起的下一次法杖；快捷技能已释放或旧手势取消时，也可能误消耗新手势。旧实现调查和首次独立语音冒烟不能证明这项关联。

本轮录音 schema 2 分开记录首包、末包和落盘时间。`MicCapture` 在首个有效 PCM 包记 `ts`，后续包仅推进 `recordingEndedAt`；切段时把两个时间与 PCM 一起取快照。Simple Voice Chat 的空结束包在解码前立即切段；1.2 秒静默作为兜底，新包追加前仍检查静默边界。输出另保留 `emittedAt`，文件名采用落盘时间加 UUID，避免同一毫秒重名。

ASR 拒绝旧/缺失 schema，不根据文件时间或样本数猜测首包时间。要求 `0 < 开始 ≤ 结束 ≤ 落盘 ≤ 当前时间`，三个时间都是安全整数，开始时间在 120 秒内。转写输出中的 `recordedAt`、`recordingEndedAt` 和 `emittedAt` 原样保留；`ts` 单独表示识别完成时间。

服务器用整个 `[recordedAt, recordingEndedAt]` 区间检查手势：

- 录音开始必须在这次举杖已经开始之后；MC 内部两者使用同一个主机时钟。
- 区间必须唯一对应一个手势。跨举杖、取消或模式切换的录音不能换一个新手势重试。
- 多个候选即使其中一个已使用或取消，也不能任选最新的候选。
- 语音模式为槽位 `0`；快捷模式为 `1–8`。客户端只能选择自己的模式，服务器依据当前真实手势接受选择。
- 未松手时返回等待状态，识别提前完成不能立即施法。只有松手后才能最终认领。
- 认领后同一手势不能再次使用；选定快捷模式时拒绝迟到语音，切回语音也不能复用切换前开始的录音。

当前状态机保留松手后的有界音包尾部和 ASR 等待时间；这些容差用于处理已经开始的手势，不把举杖前的声音算到新手势。快速切回语音不依赖等待静默：音频线程清理旧帧并发送原生结束包，服务端按该包序号安装录音边界，确认后才恢复法杖附加的 PTT。已进入 ASR 的旧句继续受完整区间和模式检查约束。

音频边界与即时技能选择分开。原 `mode` 单槽位 payload 保持不变，快捷选择和松手不等待音频握手。新增 `audio_boundary_v1` / `audio_state_v1` 只关联本人当前手势 nonce、模式修订号和音包序号；过期确认不能恢复新手势的收音。录音器通过版本化玩家事件响应，不与法杖形成相互依赖。仅既有录音名单可获得语音确认；未就绪时停止本次语音准备，仍允许肩键选择快捷技能，不无限重试。

## 服务器接口与一次认领

本地 OP2 管理协议：

```text
qdchant health
qdchant status <唯一登录名或UUID>
qdchant claim <唯一登录名或UUID> <采音开始毫秒> <采音结束毫秒> <模式0至8>
qdchant bar <登录名> <Base64URL编码的8槽显示数据>
```

应答是一行 `QD_CHANT_JSON ` 加 JSON。`health` 的 `schema:1` 是法杖协议版本，与录音 metadata 的 `schema:2` 不同；它返回 ready 和两个物品 ID。状态应答包括 actor/actorUuid、holding/using、serverTime，以及存在时的 gestureId、物品/手、起止时间、认领状态和槽位。`status` 不消费手势，`bar` 只同步显示内容。

实际门禁核对服务器玩家 UUID、当前主副手 `ItemStack` 引用、使用手、存活和容器状态。把原杖换成另一根同名杖也会失效。客户端仅在受支持的连接上发送模式和取消 payload；取消没有目标玩家字段。GUI/焦点丢失等客户端状态通过取消信号终止手势，不仅依赖服务端是否打开容器。

无自有杖、也不与历史手势相交的有效语音可继续走已有独立 PTT；一旦与失效旧手势有关，就不能因后来放下杖而降级为独立语音绕过检查。

**认领是输入门禁，不是法术事务。** 服务器先检查并消费手势，调用方随后执行既有技能；法力不足、冷却或未知结果不会自动退票、重试或回滚。已经发生的效果也不因后来打开菜单而撤销。

## 与 Iron 兼容的边界

原生 Iron 法术仍从真实装备、法术书或卷轴中取得，继续执行原生法力、目标、事件、冷却和学习检查。言灵杖不授予法术。语音发起的是既有桥的按 ID 施法路径，而不是模拟一次原生法杖右键。

准备阶段与原生施法动画是两个阶段。只有通过最终门禁并进入原生施法后，Iron 才发出开始/结束动画状态；`casting_started` 不代表已经命中。第一人称、第三人称与 YSM 人物模型的实际呈现需要单独在游戏里验证。

### 历史调查：为何采用自有道具

以下为 2026-09-07 对本地 Iron `1.21.1-3.16.3` 的只读字节码调查，属于原生组件边界证据，不是本轮交互步骤或运行验收。调查 JAR SHA-256 为 `55a290db9b966e0c5d2f5c051d50775f3db6375cdb52730c4da528bcf5d5daa0`。

- `CastingItem` 带有 `CASTING_IMPLEMENT`；`ServerPlayerEvents.onUseItem` 会立即尝试施放当前原生选中的法术，并不等待 ASR。若同时让后来的语音再次施法，仅靠 `busy` 或冷却不能保证只有一发。
- `Utils.serverSideInitiateQuickCast` 使用原生法术槽位和 `ItemStack.EMPTY`；它与完整模拟一次手持杖右键不是同一条输入路径。
- 原生 `attemptInitiateCast` 执行目标、事件和资源检查，并发送 `UpdateCastingStatePacket` 与 `OnCastStartedPacket`；客户端再进入对应动画处理。
- 原生输入的 suppress 标志、当前选择或施法计时不宜拿来等待识别。自有道具的准备姿势不应提前调用 Iron 施法、改 `MagicData` 或伪装扣蓝。

早期的“独立 F8/PTT 说话”和“十字键左直接快捷施法”实验属于历史阶段；本轮法杖流程统一为举杖 HUD、肩键选模式、松手提交。独立 PTT 保留作原语音入口，不代表沿用早期法杖操作。

## 构建和验收

构建入口为 `python tools/build_chanting_items.py` 与 `python world/god-voice-src/build.py`。产物分别位于 `vendor/chanting-cache` 和 `vendor/god-voice-cache`。构建记录包括源码哈希、资源/字节码和纯状态机断言；录音构建另外校验原播音/入口 4 个 class 及 metadata 完全不变。两套构建均不自动部署，原 C 来源保持只读。

验收应覆盖：按下不施法、长按不连发、默认语音、8 槽选择和编辑、松手一次提交、提前识别等待、快捷模式拒绝旧语音、完整采音跨手势拒绝、菜单/换手/断线取消、资源不足和原生冷却拒绝、原存档继续加载。

真实录音名单仍仅 MengMeng，当前单解码器/单缓冲不能直接扩成多人录音。实体麦克风、真实 SVC 采音、手柄肩键/松手、播放听感及人物模型画面都需另行验证。

实际结果见 [法杖部署](../reports/chanting-items-deployment.json)、[录音构建与部署身份](../reports/recording-build.json)、[法杖手势冒烟](../reports/chanting-staff-smoke.json)、[语音效果冒烟](../reports/voice-casting-smoke.json) 和 [运行健康](../reports/runtime-health.json)。应核对报告时间、当前源码及 JAR 哈希，不能用旧版成功报告替代新协议的运行验收。

### 2026-09-07 当前验收结果

0.1.4-local 已导出，包含 87 个客户端 JAR。当前双端法杖与录音版本已成功启动；真实服务器通过 11 项法杖手势、6 项快捷栏编辑和 9 项语音链路检查。合成咒语经实际 ASR 后，在举杖期间没有效果，松手后产生 3 个烟花实体且只扣一次 5 点魔力，相同消息重放不重复施法。该测试关闭了模型接口，正常录音名单与 QA 数据随后精确恢复。

NeoForge 客户端已实际进服，两支法杖的手持模型、物品图标与八槽编辑界面截图已逐张核验。语音应用回归 60 项通过；原有角色进度、传送点与工会数据检查通过，当前健康报告为正常。真实按住时的 HUD、实体肩键、麦克风采音与听感仍需硬件验收，截图及合成音频测试不替代这些项目。
