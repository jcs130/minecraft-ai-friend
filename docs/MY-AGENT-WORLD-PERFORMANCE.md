当前只完成隔离验收，**正式服没有安装本轮四个候选优化模组**。下载和 SHA 见 `manifests/society-performance-1.21.1.lock.json`；原正式模组清单保持。

实际正式服只读 `tick query` 样本为 20 TPS、平均 1.8 ms/P95 2.8 ms/P99 3.4 ms。暂未观察到 tick 算力瓶颈，不把网络、认证或客户端掉线都归因于服务端 tick。

隔离服对照启动和普通账号登录、短距离移动、真实菜单、材料合成、同动作去重通过。低负载单次对照平均约 1.6 ms，候选组合约 1.9 ms，均 20 TPS；不是严格匹配压测，不能宣称提升比例。60 秒本地 JFR 已采集，原文件可能含环境变量，只留私有 research，不提交。

## 已实现的诊断源码

现有服务端桥中的 `ServerPerformance` 采集最近最多 1200 tick 的平均/P50/P95/P99/最大耗时、超过 50 ms 数、JVM 堆和 GC；每 5 秒单个有界写任务离开游戏 tick 线程排序和原子落盘。没有玩家名字、位置或聊天，没有新增网络端口和常驻进程。桥随原 Java 守护，不独立启动。

输出为 `server/ops/maw-performance/metrics.json`，带本次启动 UUID、进程 PID 和采集时间。`tools/maw_performance_health.py` 校验当前 owner 的真实 Java PID、20 秒新鲜度、采样边界、有限数值和已部署优化 JAR 哈希；不因单个指标告警直接重启玩家连接。

`world/ops/health/health_mon.py --society-performance-smoke` 已增加入口。当前正式服未部署该快照和优化包，因此该正式验收**应失败**；不能把隔离通过冒充正式健康通过。

## 发布边界

优化模组虽不增加装备，仍改变加载拓扑与原生网络编号。实测候选组合的 3404 个物品、2899 个方块记录与正式注册表不同。发布时必须一并刷新所有网关号表/组件、Web 原生资源注册表和基岩链路，先完成界面与模型回归。

原桥内新增只读 OP-4 `/maw_registry dumpids` 导出最终运行集合的七份号表和完成标记。导出约需数秒，会短暂占用服务器线程，只供空服维护；不作为周期探针。禁止用额外诊断模组导出的编号代替最终组合编号。

正式升级使用既有 owner 正常停服与冷备流程；保持所有维度、玩家数据、Numen 身份/权限、离线身体意图和 Agent 账本，保留自主暂停与旧 unknown。本轮没有改路由器、WAN、旧 Paper、QwenPaw、模型配置或运行世界。
