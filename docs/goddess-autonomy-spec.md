# 天神 + 女神 自主化规格（逐步攒听稿）

> 来源：创世天神（mc_god）按造物主要求，将「游戏内女神化身升级为可自主裁决、持有服务器权限的日常维护实体，且天神每日外勤侦察」拆成序号需求逐条收集。
> 本稿只记录**已明确的需求** + 已核实的技术映射，随各点补齐。落地前待造物主/创世天神拍板。

---

## 点 1 —— 传令官自主裁决 + 服务器权限

**需求原文**：女神化身（传令官）自主裁决 + 持有服务器权限，做日常维护/帮助/指引。

**现状骨架（已核实）**：`mc-god.ts::askGoddess` 中祈愿裁决已是
`callAgent('mc:${username}', ..., 'mc-herald')`（传令官主审）→ 失败 `.catch` 回落 `mc-god`（本尊兜底）。
骨架在，缺的是：
- 传令官**自主性提升**：先裁、只把拿不准/重大的上达本尊，日常祈愿不惊动我。
- **服务器权限**：让它能主动执行日常维护/帮助/指引（广播、引路、给物、救急、清障）。

## 点 2 —— 中午例行 + 分析日报经 AGENT2AGENT 上报 mc_god

**需求原文**：女神化身（传令官）执行日常例行**中午（游戏内时间）填坑**，与需要帮助的人的分析以及私聊帮忙之后，还需**总结**：收到的祈祷、技能释放情况等信息 = **分析报告**，通过 **QwenPaw 的 AGENT2AGENT 通道汇报给天神（mc_god）**。

**技术映射（已核实）**：
- **现有通道是 console 通道**：`callAgent` 用 `POST` + `X-Agent-Id` 头，模拟用户发言让 agent 应答（拿文本+tokens）。这是「把 agent 当 LLM 服务跑一次」，**不是** agent 间互发。
- **AGENT2AGENT 通道**（QwenPaw）= `submit_to_agent` / `chat_with_agent`：agent 之间互发消息。女神把分析报告递给 mc_god，**必须走这套**，而不是 console。
- **落地路径**：中午（6000 ticks）触发 → 女神（传令官）先做例行（填坑 + 分析谁要帮助 + 私聊帮忙）→ 汇总祈祷（god-inbox / 编年史 `/data/world-chronicle.md`）+ 技能释放（`skill-usage.jsonl`）+ 帮到谁 → 组分析报告 → 经 `submit_to_agent(to_agent='mc-god')` 上报我。
- **数据源已确认**：施法数/给谁做 = `skill-usage.jsonl`；祈愿/供奉/应允/升级/陨落/行迹 = `world-chronicle.md`；坑/技能 = `LESSONS.md` + `skills/`；女神在线在岗 = 世界进程日志。首份框架已在 `docs/daily-report.md`。

**关键判定**：是否需要把女神上行到 mc_god 的链路从「console 调用」改为「真 agent（mc-herald）持 submit_to_agent 主动上报」——开初设想过改，后造物主**钦定不新建**：用现成能投递+能收发的通道即可（女神把日报作为消息投 mc-god，我读、我评、我回）。落地走 QwenPaw agent 间消息，不另起炉灶。

## 点 3 —— 天神每日外勤侦察（外部情报）

**需求原文**：天神（mc_god）每天定时搜索 git 上面的热门 agent 项目，以及我的世界相关模组、玩法。

**性质**：**给我的定时任务**（天职化守望者/史官），非女神职责。与女神每日日报并列的两条日常流——女神盯**内**（世界运行+祈愿+帮人），我盯**外**（Git 热门 agent 项目 + MC 模组/玩法）。

**常规输出**（落地去向）：
- **热门 agent 项目** → 评估与 QwenPaw / mineflayer / 本世界体系的契合度，值得借鉴的沉淀入 `LESSONS.md` 或升级 `skills/`；开新玩法/新技艺直接进世界建设议程。
- **MC 模组 / 玩法** → 接上既有待办「找 NeoForge 21.1.248 兼容模组清单（光源/视觉/旅途探索/聚落发展）」，筛出的模组或玩法入《世界迭代需求文档》做评估，是否引入待用户拍板。
- 每日侦察结论并入我的日报消化（女神话语上达 + 我每日外勤），不转交造物主，仅重大可引入项请示。

**执行方式**：按 QwenPaw 定时（cron）建每日任务；搜 Git 热门（GitHub trending / 关键词 agent、mineflayer、QwenPaw 生态等）+ MC 模组（NeoForge 21.1.248 兼容面）。属于「会离开本地」的联网侦查，属我日常职权范围，可自主执行；引入重大模组/改世界仍需用户点头。

## 点 4 —— 天神设计创新玩法并落地（策划+开发一体）

**需求原文**：天神需结合**女神上报的信息**以及**外部资料**，设计新的技能、事件、任务、等级、成就等创新玩法，**并且落地实施**。

**定位**：这是「策划 + 开发一体」的正式落地——把点 2（女神内报）+ 点 3（外勤资料）两条信息流汇到我这里，由我据以**设计 + 实施**新内容，形成完整循环：

```
女神日报（内·点2） ┐
                    ├─→ 我设计：新技艺 / 事件 / 任务 / 等级 / 成就 / 创新玩法 ─→ 落地实施（写码+配置世界+投放）
日勤外勤（外·点3） ┘
```

**输出内容（设计面）**：
- **新技艺**：接「固定咒语框架 + 三层降级 + 台账 jsonl + BOOK 前缀投放」既有体系；如待办的「引路灯」（灯系，低费跟随灯）、被动技树（复活道具类/锁血类——触发条件/阈值/效果需单独设计）——我持全技艺表与编辑权，属我职权。
- **事件**：如千灯纪 lore 事件、九灯深渊点灯换恩惠、世界级天象/活动；开活动属重大事项 → 报造物主。
- **任务**：NPC 任务链（villagers.json 中文 NPC 接入）、探索获得技能书（宝箱/遗迹掉落）、藏宝投放（19 个 BOOK 前缀）。
- **等级 / 成就**：等级曲线、成就体系设计 —— 结合 `game-design-core` 技能（核心幻想/数值/技能树/动机审计）保证数值健康；`game-design-granular-player-motivation-audit` 可评估设计的玩家动机覆盖。
- **创新玩法**：世界建设议程里的浮空岛架构、聚落发展等。

**落地实施（工程面）**：写完设计进世界 —— 动态魔法系统（mc-god.ts magic atoms / chant prefixes）、世界配置（village/ 运行时配置）、服务端 mod（settlementsfix 等，改后重建 jar 需用户点头重启）、投放与平衡。**裁决即生成技能**：每次有设计/落地就依据反馈沉淀 `LESSONS.md` / 升级 `skills/`。

**边界**：设计落地属我职权（自持做）；但涉及改服务端 mod / 开活动 / 引入重大外部模组这类**会影响现有世界**的操作，先报用户点头。

## 点 5 —— 天神监督「小社会」运行并修正异常（终）

**需求原文**：天神需**时刻关注**自己服务器内的**智能村民**、**假玩家**的状态，如果不正常，还需要**想方设法修正**，把**小社会运行得精彩**。

**性质**：**给我的持续监督职能**——我是这个小社会的「生态运维者」。与女神每日日报、点 4 设计落地并列，构成「内报 + 外勤 + 设计 + 运维」闭环。

**监控对象**：
- **智能村民**：villagers.json 中文 NPC（如墨白等），由 `mc_npc.py` 驱动（须单实例——双进程会双倍说话/语音）。
- **假玩家（numen NumenPlayer）**：桐人（mc-guard-kirito）/ 鸣人（mc-guard-naruto）/ 爱德华 / Steve / Alex，`sidecar/guard/guard_drive.py` 桥 + 亲卫 agent（QwenPaw 独立 workspace）。
- **世界生态**：NPC/守卫的社会互动、巡逻、交谈是否自然生动。

**监控点**（状态信号）：血量/位置/卡死/死亡/是否正常行动；是否卡重复行为、异常日志、离线/断连；语音/对话是否正常；有无幽灵/重复/僵死。

**修正手段**（想方设法，自持）：
- 冻结/僵死 → 重启守卫桥 + 世界进程；断连 → 重召。
- 死亡/卡住 → 重生 / tp 回位。
- 行为异常 → 查 guard_drive / mc_npc 排障（含单实例检查）；RCON 抖动类 → 排查根因（这是一直在记的「RCON closed/timed out」）。
- 每次修正沉淀 `LESSONS.md`（坑/流程），同主题攒足升 `skills/`；长期问题入《世界迭代需求文档》。

**精彩化目标**：小社会生动运行——NPC 有对白、守卫巡逻/对话自然、社会互作不僵化；僵死/幽灵/重复视为异常，随时发现随时修。
